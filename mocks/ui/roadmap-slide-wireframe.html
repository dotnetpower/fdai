FDAI Roadmap - Overview

핵심 기능 5종 한눈에 보기

SRE · ARB(아키텍처 리뷰보드) · Change Management · FinOps · Chaos/DR - 결정론적 규칙(T0)이 반복 이벤트를 먼저 처리하고, 애매한 잔여 사례만 유사사례 재사용(T1)과 승인 게이트를 거친 판단(T2)으로 넘어가는 동일한 안전 루프를 공유한다.

2

Reliability

SRE

장애 탐지 → 근본원인 → 표준 대응까지 자동화해 신뢰성을 지킨다.

핵심 지표(예시)
MTTR
  • 이벤트 상관/근본원인 추론
  • 자동 대응 실행계획
  • 사후 검증 + 재발방지
근거: 감사 로그 + 복구 드릴

Architecture Review

ARB

변경 리스크를 사전 심사하고 근거 패킷을 자동 생성한다.

핵심 지표(예시)
심사 대기시간
  • 리스크 분류 + 정책 매칭
  • 근거/의존성 자동 첨부
  • 승인 이력 추적
근거: 변경 감사 + 정책 카탈로그

Safe Delivery

Change
Management

배포·롤백 계약을 표준화해 변경 실패율을 낮춘다.

핵심 지표(예시)
변경 실패율
  • 승격 레지스트리 게이트
  • 검증된 롤백 경로
  • 리드타임 단축
근거: 배포 이벤트 + 롤백 검증

Cost Governance

FinOps

낭비 패턴을 재사용 가능한 절감 조치로 전환한다.

핵심 지표(예시)
검증된 절감액
  • 이상 지출 탐지
  • 표준가 기준 절감 추정
  • 예산 가드레일
근거: 비용 이벤트 + 가격 카탈로그

Resilience

Chaos / DR

주기적 카오스·DR 훈련으로 복구 능력을 계속 검증한다.

핵심 지표(예시)
RTO / RPO
  • 스케줄된 복구 드릴
  • 페일오버 자동 검증
  • 리전 장애 대비
근거: 드릴 결과 + 복구 로그

주석
  1. ① 슬라이드 헤더 영역 - kicker(상단 라벨) + 타이틀 + 1~2줄 요약. PPT 전환 시 상단 20% 고정.
  2. ② 5열 카드 그리드 - 기능별 색상 스와치로 뒤 슬라이드(타임라인)와 색상 매핑을 통일. 카드 하단 "근거" 라인은 실제 데이터 출처를 밝혀 슬라이드가 근거 없는 주장으로 읽히지 않게 함.

주석
  1. ③ 헤더는 슬라이드 1과 동일 톤 유지 - 두 슬라이드가 한 덱임을 알려줌.
  2. ④ Phase 축 5칸 - 실제 로드맵 문서(docs/roadmap/phases/phase-0..4)의 단계명과 1:1 매핑. 날짜/분기 라벨은 PPT 제작 시 실제 일정으로 교체.
  3. ⑤ 스윔레인 5행 - 좌측 라벨은 슬라이드 1의 색상 스와치와 동일 색으로 연결. 각 칸 텍스트는 예시 마일스톤이며 실제 커밋 아님(추정치로 표기 필요).
  4. ⑥ Shadow/Pilot/Enforce 범례 - 배경색으로 자율성 단계를 표시. 이 셀 색은 실제 프로모션 레지스트리 상태를 반영해야 하며, 로드맵 문서의 "shadow-first rollout" 원칙을 슬라이드에서도 지킨다.
