Rehearsal first · governed delivery through deployment configuration

Direct Line custom channel setup boundary

FDAI posts A2 operational alerts and A4 digests into a Microsoft Bot Framework Direct Line conversation that a deployment-owned relay bot presents in a custom channel. This static mock shows the configuration boundary only. It does not collect, store, or test any credential.

Lifecycle

  1. Rehearsal is the default mode. FDAI renders and durably records the exact activity with zero external sends.
  2. A separately reviewed deployment change activates governed delivery by setting enforce mode and naming protected references.
  3. Before transport, FDAI writes the per-channel delivery record. A Direct Line activity id closes the attempt as accepted, never as delivered.
  4. An authenticated publication receipt from the relay confirms delivery. A lost acknowledgement or a relay-reflected failure such as HTTP 502 stays ambiguous and is never resent automatically.

Protected references

Binding fieldHolds
endpoint_envName of the environment variable that carries the Direct Line base URI for the bot region or hosting model
conversation_id_envName of the environment variable that carries the relay conversation identifier
secret_envName of the environment variable populated from the deployment secret store
  • Values never appear in the repository, the Console, readiness rows, audit entries, or rehearsal records.
  • The relay bot must deduplicate on the activity idempotency key, and the router is the only retry layer.
  • Unconfigured, disabled, expired, unauthorized, and unavailable bindings fail closed with bounded retries and human-review escalation.
  • This channel carries no approvals (A1), conversations, or commands (A3) and exposes no executor identity.
