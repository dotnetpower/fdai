Power Automate setup guide 10 steps

Power Automate uses the current Microsoft browser session. If it is not the workflow owner account, switch or sign out there, or open the link in a private browser window.

Open Power Automate

Complete the following steps in Power Automate before pasting the callback URL into FDAI.

  1. Verify the signed-in account

    Open the account manager in the upper-right corner and confirm the Microsoft 365 workflow owner account. The account shown in this preview is synthetic.

  2. Start an automated cloud flow

    In the left navigation, select Create. Under Start from blank, select Automated cloud flow.

  3. Name the flow and skip trigger selection

    Enter a recognizable Flow name, such as FDAI Teams Flow. Do not select a trigger in this dialog. Select Skip to open the flow designer.

  4. Add a trigger

    In the flow designer, select Add a trigger.

  5. Select the Microsoft Teams Webhook trigger

    Select Microsoft Teams Webhook, then select When a Teams webhook request is received.

  6. Allow the FDAI webhook request

    On Parameters, set Who can trigger the flow? to Anyone. The HTTP URL is generated only after the flow is saved. Anyone who has that URL can trigger the flow, so keep it secret and apply your tenant's workflow policy.

  7. Add the Teams card action

    Under the webhook trigger, select + to add an action. Select Microsoft Teams, then select Post card in a chat or channel.

  8. Configure the Teams destination and card

    Set Post as to Flow bot and Post in to Channel. Select the target Team and Channel. In Adaptive Card, insert the triggerBody() expression. The Team and Channel shown below are illustrative; select the actual notification destination.

  9. Confirm the Flow name and save

    Select the flow title at the top and confirm that the Flow name is the intended name. Update it if needed, then select Save in the upper-right corner.

  10. Copy the generated HTTP URL

    After the save succeeds, select When a Teams webhook request is received. Under Parameters, copy the generated HTTP URL and return to FDAI.

Treat the callback URL as a secret. Do not place it in source control, documentation, chat, or screenshots.

Storage and role boundaries

Teams Workflows supports outbound A2 operational alerts and A4 scheduled digests. It cannot carry A1 human approvals or provide A3 bidirectional conversations.

In the Console, an FDAI Owner submits a new URL. FDAI saves and independently verifies a new binding version, then sends one fixed synthetic Adaptive Card.

A deployment stores the URL in a dedicated Key Vault secret. The local profile stores only encrypted ciphertext in its private Operator database. FDAI verifies the saved version before testing, never returns the URL, and never prefills it. Saving and testing do not activate runtime delivery.

  • Contributor, Approver, and Owner roles can view saved-binding metadata only.
  • Only an FDAI Owner can replace the URL and send a test.
  • Reader and BreakGlass roles cannot view saved-binding metadata.
  • A missing or failed binding read remains explicit; it does not prove that delivery is ready.
