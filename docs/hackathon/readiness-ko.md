# 해커톤 데모 준비 상태

이 문서는 FDAI 해커톤 데모에서 보여 줄 하나의 간단한 이야기를 정리합니다. 쇼핑몰 결제 처리
서버 3대 중 1대가 유지보수 후 다시 켜지지 않은 문제에서 시작합니다.

> **범위:** 이 문서의 값과 리소스는 모두 합성 Sample 데이터입니다. 고객 환경이나 실제 Azure
> 작업 결과가 아닙니다.

## 데모 이야기 한 문장

FDAI가 결제 처리 서버 3대 중 2대만 실행 중인 문제를 발견하고, 나머지 1대가 유지보수 후
꺼진 채 남아 있음을 설명합니다. 다른 사람이 VM 시작을 승인한 뒤, 별도 관찰자가 VM 실행
상태를 확인해야만 문제를 완료로 처리합니다.

## 1. 대시보드에서 문제 발견

데모는 대시보드에서 시작합니다. 운영자는 다른 화면을 열지 않아도 무엇이 문제인지 이해할 수
있어야 합니다.

### 운영자에게 보이는 내용

| 항목 | Sample 값 |
|------|-----------|
| 제목 | 결제 처리 서버 1대가 실행되지 않음 |
| 서비스 상태 | 서버 3대 중 2대 실행 중 |
| 영향받는 서비스 | 온라인 쇼핑몰 결제 처리 |
| 리소스 상태 | VM 1대가 할당 해제 상태 |
| 최근 변경 | 유지보수는 끝났지만 이후 VM 시작 기록이 없음 |
| 영향 | 처리 용량이 줄어듦. 서비스 중단은 확인되지 않음 |
| 관찰 시각 | 1분 전 |
| 다음 단계 | 인시던트 열기 또는 이유 질문 |

이 카드는 `sample-correlation-001`로 이동해야 합니다.

### 현재 빠진 내용

Sample 실시간 화면에는 VM 중심 흐름이 있지만, 대시보드에는 위 문제 카드가 없습니다. 따라서
심사자는 문제를 이해하기 전에 해결 화면부터 보게 됩니다. 가장 먼저 대시보드 카드를
추가해야 합니다.

## 2. 서버 1대가 꺼진 이유 질문

운영자가 인시던트 또는 대화 패널을 열고 질문합니다.

> 결제 처리 서버 1대가 실행되지 않는 이유가 무엇인가요?

답변은 다음처럼 짧고 명확해야 합니다.

> 결제 처리 VM은 3대가 필요하지만 현재 2대만 실행 중입니다. `sample-checkout-vm-01`은
> 할당 해제 상태입니다. 가장 최근의 관련 기록은 완료된 유지보수 작업이며, 그 이후 VM 시작
> 기록은 없습니다. 이 변경이 처리 용량 감소와 관련 있을 수 있지만, 현재 기록만으로 직접적인
> 원인이라고 단정할 수는 없습니다.

답변에서 다음 내용을 확인할 수 있어야 합니다.

- 문제가 있는 VM
- 현재 VM 상태
- 상태를 관찰한 시각
- 관련 유지보수 기록
- 사용한 근거 출처
- 관련 변경과 확인된 원인의 차이

## 3. FDAI가 기다릴 수 있음을 보여 주기

별도의 Sample 사례를 사용합니다. VM 상태가 오래되었거나, 두 근거가 서로 다르거나, VM이 아직
시작 중인 경우입니다. FDAI는 무엇을 다시 확인해야 하는지 설명하고 검토 대기 상태를
유지해야 합니다.

이 사례에서는 원인이 확인되었다고 표시하거나 실행 가능한 작업을 보여 주지 않습니다.

## 4. VM 시작 승인 검토

`/approvals?data=sample`을 엽니다.

승인 카드에는 다음 내용이 보여야 합니다.

- 작업: `ops.start-vm`
- 대상: Sample VM 1대
- 이유: 필요한 서버 3대의 처리 용량 복구
- 영향 범위: VM 1대
- 중지 조건
- 롤백 작업: `ops.deallocate-vm`
- 승인 상태: 다른 사람의 승인 대기

이 승인 대기 사례는 `sample-correlation-002`를 사용합니다. 완료된 이야기와 분리하여 두
화면의 상태가 서로 충돌하지 않도록 합니다.

## 5. 완료된 흐름 확인

`/live?data=sample`을 엽니다.

핵심 패널에서 다음 순서를 보여 줍니다.

1. 운영자가 결제 처리 용량 감소를 확인했습니다.
2. FDAI가 할당 해제된 VM 1대와 관련 유지보수 기록을 찾았습니다.
3. 다른 사람이 VM 1대 시작을 승인했습니다.
4. Azure가 시작 요청을 접수했습니다.
5. 별도 관찰자가 VM 실행 상태를 확인했습니다.
6. FDAI가 예상한 효과를 검증 완료로 표시했습니다.

Azure가 요청을 접수한 것만으로는 최종 성공이 아닙니다. 별도 관찰자가 VM 실행 상태를 확인한
뒤에만 문제를 완료로 처리합니다.

## 6. 전체 진행 기록 확인

**전체 상관관계 확인**을 선택하고 다음 내용을 확인합니다.

| 확인 항목 | 예상 값 |
|-----------|---------|
| 결정 | 사람 승인 |
| 권한 | `A3-H` |
| 실행 | 완료 |
| Azure 요청 | 접수됨 |
| 독립 관찰 | VM 실행 상태 확인 |
| 최종 결과 | 효과 독립 검증 완료 |
| 복구 | 준비됨, 실행 불필요 |
| 상관관계 | `sample-correlation-001` |

Sample 안내는 계속 보여야 합니다. 이 상세 화면은 설명용 흐름이며 실제 Azure 효과의 근거가
아닙니다.

## 현재 화면 상태

| 화면 | 상태 | 다음 작업 |
|------|------|-----------|
| 대시보드 문제 카드 | 없음 | 서버 3대 중 2대만 실행 중인 문제를 추가하고 인시던트에 연결합니다. |
| 인시던트 상세 | 일부 준비 | 같은 대상, 유지보수 기록 및 완료 상관관계를 사용하는지 확인합니다. |
| 대화 답변 | 없음 | 정확한 질문과 근거에 기반한 짧은 답변을 추가합니다. |
| 검토 대기 사례 | 없음 | 오래되거나 충돌하거나 시작 중인 상태 사례 1개를 추가합니다. |
| 승인 대기 | 준비됨 | `sample-correlation-002`를 계속 사용합니다. |
| Sample 실시간 흐름 | 준비됨 | 대시보드 데이터를 연결한 뒤 다시 확인합니다. |
| 전체 진행 기록 | 준비됨 | 영어, 한국어 및 작은 화면에서 다시 확인합니다. |
| 추적 및 감사 | 미확인 | 일치하는 Sample 기록이 있을 때만 촬영에 포함합니다. |

## 작업 순서

한 번에 하나씩 완료하고 화면을 확인합니다.

1. 빠진 대시보드 문제 카드를 추가합니다.
2. 대시보드 카드를 같은 인시던트에 연결합니다.
3. 운영자 질문과 짧은 근거 기반 답변을 추가합니다.
4. 명확한 검토 대기 사례 1개를 추가합니다.
5. 승인 대기와 완료된 실시간 흐름이 서로 다른 상관관계를 사용하는지 확인합니다.
6. 추적 및 감사 데이터를 확인합니다. 데이터가 없으면 촬영 화면에서 제외합니다.
7. 영어, 한국어, 키보드 조작 및 1440x900, 993x641, 390x844 화면을 확인합니다.
8. 촬영 전에 전체 경로를 한 번 연습합니다.

## 촬영 전 확인 목록

- [ ] 해결 화면보다 먼저 대시보드에 문제가 보입니다.
- [ ] 서버 3대 중 1대가 실행되지 않는 상황을 바로 이해할 수 있습니다.
- [ ] 답변에 VM 상태와 관련 유지보수 기록이 나옵니다.
- [ ] 불확실한 사례 1개가 추가 근거를 기다리는 상태로 보입니다.
- [ ] 승인 작업은 VM 1대만 변경하고 롤백 작업을 표시합니다.
- [ ] Azure 요청 접수와 독립 효과 검증이 서로 다른 단계로 보입니다.
- [ ] Sample 데이터라는 안내가 계속 보입니다.
- [ ] 테넌트, 구독, 전체 리소스 ID, 이메일, 토큰 또는 엔드포인트가 보이지 않습니다.
- [ ] 실제 Azure 효과나 정식 성과 개선을 주장하지 않습니다.
