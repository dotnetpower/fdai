# F10-F15 준비 상태 전수 점검 및 완료 계획

이 문서는 [기능정의서](functional-specification-ko.md)와 [평가 기록](functional-readiness-ko.md)을
담당 구현 원장 및 미충족 수용 기준과 대조합니다. 아래 작업 ID를 기준으로 후속 작업을
재개하되, 로컬 테스트 통과와 운영 검증 완료를 구분하세요.

> **점검 범위:** F10을 포함해 F15까지 중분류 21개를 전수 점검했습니다. 기준은
> 2026-10-18의 소스 개정 버전 `8819a28951fd5c21858adc0a8e7a6d5278ba4745`입니다.
> 소스, 원장, 개별 이슈 상태를 대조한 결과이며 새로운 런타임 테스트나 실제 배포 검증이
> 아닙니다. F01-F09는 기존 평가를 유지하며 이번 점검으로 다시 검증한 것이 아닙니다.

## 주요 확인 결과

기존 F10-F15 집계는 Ready 13건, Partial 8건이었습니다. **Ready 10건을 Partial로 정정합니다**:
F10.1, F10.2, F10.4, F11.3, F13.2, F14.1-F14.4, F15.1입니다. 정정 후 집계는
**Ready 3건, Partial 18건**입니다. 기존 평가를 유지한 항목까지 포함한 전체 52개 중분류는
**Ready 28건, Partial 24건**입니다.

계획에는 **미완료 작업 묶음 29개**와 **연기 및 조건부 범위 7개**를 기록했습니다.
공통 작업은 한 번만 정의하며 영향을 받는 기능마다 중복 집계하지 않습니다.

실제 잔여 작업과 표시가 달랐던 원인은 세 가지입니다.

- **구현과 완료를 혼동했습니다:** 로컬 집중 검사 통과만으로는 필수 통합 검증, 인증된
  경로의 검증, 독립적으로 관찰한 수용 기준이 충족되지 않습니다.
- **실제 소스 작업을 설정으로 분류했습니다:** 요청자 정책 기반 적용, Release 상한,
  소스 배포 경로 정리, 수집원별 자체 상태 내보내기에는 구현이나 연결 작업이 남아 있습니다.
- **작업 표시와 이슈 상태가 달랐습니다:** 이슈를 닫아도 연기된 작업은 남을 수 있습니다.
  반대로 미완료 체크박스가 이미 구현된 코드를 가리키기도 합니다. 둘 다 그 자체로 완료 근거는 아닙니다.

설치 환경의 일반적인 설정값이 없다고 공통 조회 모델의 구현이 미완료가 되는 것은 아닙니다.
다만 담당 원장이 명시한 필수 운영 검증을 단순히 "설치 환경별 검증"이라고 부르며 제외할 수는
없습니다. 선택적 확장은 수용된 지원 범위와 분리합니다.

소스를 직접 대조한 예는
[보호 문서 다운로드 차단](../../../services/document-ingestion-api/src/fdai_ingestion_api_service/download.py),
[활성화 결과의 독립 조회](../../../services/document-processing-worker/src/fdai_document_worker_service/cloud_activation.py),
[보존 Pattern 전체 묶음 검증 계약](../../../services/core-control-plane/src/fdai/core/tiers/t1_lightweight/retained_pattern_bindings.py),
아래에 연결한 Release 상한과 CLI 경로입니다. 이 근거는 한정된 결론을 뒷받침하며
모든 소스 파일을 검토했다는 뜻은 아닙니다.

## F10: 지식 및 규칙 작업

담당 원장은 [수집](../../roadmap-implementation/interfaces/document-ingestion.md),

- [ ] **K01, 수집 통합 검증:** 정확한 서비스 계정, 버전, 계약에 연결된 로컬 및 배포
  서비스 5개의 증적을 보존합니다. 업로드, 악성 코드 및 보호 검사, 추출, 색인 및 인용,
  삭제, 재시작, 실패 복구를 포함합니다.
- [ ] **K02, 보호된 수집원:** 권한 관리 문서를 다운로드하기 전에 목적별 공급자 위임 권한
  증적을 추가하고 테스트합니다. 승인된 보호 및 SharePoint 계정과 정책을 연결하고 검사,
  철회, 삭제 전파, 커서 복구, 역압력 처리 결과를 독립적으로 조회해 보존합니다.
  로컬 증적, 수락, 유효 기간이 제한된 스트리밍, 보관함 표시, 운영 조립 연결은
  [#2214](https://github.com/dotnetpower/fdai/issues/2214)에서 구현하고 동작 검사 132개와
  서비스 검사 소유권 확인 29개를 통과했습니다. 승인된 외부 연결과 운영 증적이 남아 있어
  작업 묶음은 미완료로 유지합니다.
- [ ] **K03, 요청자 정책 구현:** 수용된 v2/v3 요청자 경로를 구현합니다. 요청자, 정책,
  콘텐츠, 컬렉션을 정확히 연결하고 독립적인 사전 권한, 요청 시점 및 최종 공개 시점 검사,
  자기 권한 부여와 누락 및 만료와 철회 차단, 필수 안전 조건, 독립적인 저장 결과 조회를
  검증합니다. 그전까지 수동 경로를 유지합니다.
  명시적인 인증 API 경로를 #2217에서 구현했으며 최종 집중 검사 672개와 실제 격리 PostgreSQL
  검사 24개를 통과했습니다. 수동 기본값은 유지합니다. 실제 독립 승인 정책, 배포 읽기 권한,
  운영 승격이 남으므로 이 상위 작업 묶음은 미완료로 유지합니다.
- [ ] **K04, 추출 및 답변 품질:** 숨겨진 UI, 사라진 링크와 제목 맥락, 절을 가로지르는
  표의 주의 사항, 모든 시범 수집원 보류 항목을 해결하거나 명시적으로 보류합니다. 회귀
  사례와 독립적으로 검토한 EN/KO 질의 및 주장 근거를 보존한 뒤 코퍼스 조회 준비를 선언합니다.
  #2232는 본문 및 UI 분류, 상위 요소와 인증 제어 요소의 중복 속성을 검사하는 선택적
  정규화기 `2.1.1`과 판독기 `3.1.1`을 추가합니다. 보관 바이트 업그레이드와 집중 검사
  329개를 검증했으며 기존 정규화 결과는 보존합니다. 실제 시범 수집원 보류와 독립적으로
  검토한 양언어 주장 근거가 남으므로 이 상위 작업 묶음은 미완료로 유지합니다.
- [ ] **K05, 수집원 검증:** 사용 권리, 목적에 연결된 신뢰 및 철회, 독립 검토자, 최신
  검사 데이터, 보호된 정책 마운트, 제한된 수집원 등록 근거를 보존합니다. 연결 수집,

  런타임 릴리스를 연결하며 이전 애플리케이션 키트 증적을 대신 사용하지 않습니다.

정확한 잔여 ID와 함께 Partial로 유지합니다. 근거가 없을 때는 새 결함으로 단정하지 않고
Not assessed를 사용합니다. 설치별 일반 설정과 명시적으로 연기한 확장은 검증한 것처럼
표현하지 않으면서 별도로 표시합니다.

## 소스 전달 하드닝 기록

첫 후속 전달은 [#2211](https://github.com/dotnetpower/fdai/issues/2211)에서 추적했습니다.

그 시점에는 보호 원본 다운로드를 지원하지 않았습니다. **29개 모두 여전히 미완료로
유지하지만**, 이후 #2214에서 K02 로컬 반출 계약과 운영 조립 연결을 구현했습니다.
#2217은 명시적 K03 기존 정책 API를 구현하고 #2218은 H01 신호 및 필드를 각각 3개 연결합니다.
#2228은 전체 설치 상태가 아닌 프로세스별 보호된 시작 시간을 네 번째 H01 신호로 추가합니다.
A01, 학습 통합, 나머지 자체 상태 수집원과 추가 소스 작업은 여전히 미완료입니다.
실제 환경, 사람, 공급자, 운영 표본 기준도 별도로 남습니다. shadow 전용 상한을 서명하지
않은 파일이나 테스트용 승인으로 대체할 수 없습니다.

[담당 테스트](../../../site/test/functional-readiness.test.mjs)는 기존 CI 및 Pages 검사에서
실행됩니다. 이제 기능정의서, 평가, 전수 목록, 정확한 필수 작업 열을 연결합니다.
미완료 필수 작업이 있는 Ready를 차단하고 양언어 작업 ID와 완료 여부를 비교합니다.
증적을 인증하거나 작성자가 모든 의무를 찾았음을 입증하지는 않습니다. 의무 삭제나
범위 변경에는 여전히 담당자의 검토가 필요합니다.

직접 비평 라운드 4회에서 매회 아래 관점 12개를 검토했습니다. 1회차에는 잔여 작업
검사를 추가했습니다. 2회차에는 상태 표시 중복, 표시 문구 불일치, 현지화된 미평가
처리, 불완전한 집계 검사를 수정했습니다. 3회차에는 기능 ID 교체를 차단하고 잘못된
문서 테스트가 임의 오류가 아닌 의도한 검증 오류를 요구하도록 강화했습니다. 4회차에는
게시 전 필수 검사를 적용해 표시 용어 위반 7건을 수정하고 한정된 범위를 다시 검토했습니다.
준비 상태를 바꾸거나 기능 작업을 완료로 닫지는 않았습니다.

| 비평 관점 | 최종 한정 범위의 결과 |

| 회귀 및 실행 위치 | 잘못된 전환, 상태 불일치, 작업 없는 Partial이 의도한 검증 오류로 차단되며 기존 CI에서 테스트를 실행합니다 |

최종 집중 명령은 `node --test site/test/functional-readiness.test.mjs`이며 **25개 통과,
건너뜀 없음**입니다. 4회차 이후 이 회귀 방지 검사의 한정 범위에는 확인된 Low 초과
미해결 결함이 없습니다. 미완료 작업 29개, 제품 전체, 실제 설치 환경을 Low 이하로
평가했다는 뜻은 아닙니다.
