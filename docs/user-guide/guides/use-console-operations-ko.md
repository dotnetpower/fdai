# 운영자 콘솔 사용하기(Work in the operator console)

콘솔은 FDAI가 무엇을 하고 있는지 보는 곳입니다. 인시던트, 승인 대기 항목, 실행 중인 프로세스,
예약된 작업, 프로비저닝 진행 상황, 그리고 모든 결정의 근거를 보여 줍니다. 하지만 여러분의
클라우드를 바꾸는 일은 하지 않습니다.

이 가이드에서는 실제로 사용하게 될 영역을 정리하고, 어떤 영역이 요청을 받는지 알려 주며, 브라우저
세션을 열어 둬도 안전한 이유가 되는 경계를 설명합니다.

## 콘솔은 실행할 수 없습니다

모든 화면은 읽기만 합니다. 콘솔의 API 클라이언트에는 생성, 수정, 삭제 도우미가 아예 없으며,
콘솔은 실행기 신원을 받지 않습니다. 콘솔에서 무언가를 제출하면 그것은 변경을 일으키는 것이
아니라, 평소의 파이프라인으로 다시 들어가는 통제된 요청을 접수하는 것입니다.

이 설계에는 꼭 기억해 둘 실무적 결과가 있습니다. **브라우저 세션이 탈취돼도 인프라를 바꿀 수
없습니다.** 그 사람이 읽을 수 있었던 것을 읽을 수 있을 뿐입니다. 실행 권한은 실행기 신원에
있으며, 어떤 브라우저도 그 신원을 갖지 않습니다.

## 무엇을 하려면 어디로 가야 하나

| 영역 | 하는 일 | 제출 가능 여부 |
|------|---------|----------------|
| 개요와 라이브 | 현재 컨트롤 플레인 활동을 한눈에 확인 | 아니요 |
| 인시던트 | 열린 인시던트와 구성원, 타임라인, 연결된 분석 확인 | 아니요 |
| 승인 | 사람을 기다리는 작업을 근거, 정족수, 기한과 함께 검토 | 예, 결정을 제출합니다 |
| 에이전트 활동과 판테온 | 어떤 에이전트가 무엇을 처리하는지 보고 역할 확인 | 아니요 |
| 프로세스 | 프로세스 실행, 렌더링된 화면, 저널 이벤트 확인 | 특정 프로세스 경로에서 예 |
| 스케줄러 실행 | 예약 작업 디스패치 시도 확인 | 아니요. 작업을 재시도하거나 취소할 수 없습니다 |
| 프로비저닝 | 프로비저닝 진행 상황을 스트림으로 확인 | 아니요. 프로비저닝을 실행하지 않습니다 |
| 온보딩과 준비 상태 | 어떤 기능을 쓰기 전에 무엇이 빠졌는지 확인 | 아니요 |
| 조사 | 범위가 제한된 Azure 조사를 시작하고 결과 확인 | 예, 읽기 전용 조사입니다 |
| 감사와 추적 | 상관 ID로 기록된 모든 단계를 따라가기 | 아니요 |
| 규칙, 온톨로지, 승격 게이트 | FDAI가 아는 것과 실행이 허용된 것을 확인 | 아니요 |
| 에이전트 오버사이트 | 담당 체계와 사람 의존 관계 확인, 담당자 인수인계 제안 제출 | 예, 제안을 제출합니다 |
| 설정 | 런타임, 모델, 메모리, 연동, 신원 구성 확인 | 신원과 접근 영역에서 예 |

승인은 클릭이 실제 결정을 담는 유일한 곳입니다. 그마저도 서버에서 신원을 다시 확인하고 조건을
다시 검사한 뒤에야 무언가가 실행됩니다. 그 흐름은 [변경 승인](approve-change-ko.md)에서
확인하세요.

## 역할별로 보이는 것

콘솔은 역할이 허용하는 것을 보여 주고 나머지는 감춥니다. 다만 실제로 강제하는 쪽은 서버입니다.
모든 요청에는 여러분의 신원이 실려 있고, 도착 시점에 검사가 다시 수행됩니다.

- **Reader**는 상태, 근거, 감사 이력을 봅니다.
- **Contributor**는 범위가 제한된 조사를 시작하고 변경 초안을 작성할 수 있습니다.
- **Approver**는 사람을 기다리는 작업에 대한 승인 결정을 추가로 수행합니다.
- **Owner**는 신원, 접근, 런타임 설정 작업을 추가로 수행합니다.

콘솔에서 좁게 보이는 것은 편의이지 경계가 아닙니다. API를 직접 호출해도 같은 답이 돌아옵니다.
권한 검사가 브라우저에 있지 않기 때문입니다.

## 화면을 정직하게 읽기

두 가지 습관이면 화면을 과대 해석하지 않을 수 있습니다.

- **숫자를 믿기 전에 최신성을 확인하세요.** 화면은 저장된 상태를 투영합니다. 인시던트 목록이
  조용하다는 것은 실제로 조용하다는 뜻일 수도 있고, 투영이 아직 따라오지 못했다는 뜻일 수도
  있습니다.
- **값이 없으면 알 수 없음으로 취급하세요.** 콘솔은 확인 불가한 근거를 0으로 채우지 않고 확인
  불가로 표시하며, 인시던트 상황에서는 보통 그 구분이 중요합니다.

## 아직 없는 것

여러 영역의 작업을 한데 모으는 통합 Tasks 화면과 영역 간 투영 메타데이터는 구현이 아니라 제안
단계입니다. 지금은 하나의 통합 큐에서 일하는 대신 위의 영역들을 오가며 작업합니다.
