# 담당자 인수인계 검증

담당자 인수인계 소스와 로컬 UI 테스트가 통과한 뒤 남은 검사를 준비할 때 이 가이드를
사용하세요. 실제 스크린 리더 출력은 배포 및 운영 근거와 따로 기록합니다. 준비 검사가
통과해도 접근 권한, 계획 승인, 적용 모드 활성화가 부여되지는 않습니다.

> **현재 경계:** [#946](https://github.com/dotnetpower/fdai/issues/946)과
> [#1017](https://github.com/dotnetpower/fdai/issues/1017)은 소스와 로컬 UI 전달을 완료했습니다.
> [#458](https://github.com/dotnetpower/fdai/issues/458)은 운영 수락을 위한 이슈입니다.
> 근거가 없는 조건은 열린 상태로 유지하세요. 과거 이미지나 비공개 담당 맵의 근거는 새
> 릴리스 또는 현재의 사람, 권한, 원본 상태를 입증하지 않습니다.

## 근거 유형 구분

같은 소스 리비전을 사용하더라도 다음 결과는 따로 관리합니다.

| 유형 | 성공한 결과가 입증하는 것 | 입증하지 않는 것 |
|------|--------------------------|------------------|
| 소스와 로컬 UI | 정확한 입력에 대해 선언된 결정론적 또는 합성 시나리오 통과 | 실제 음성, 현재 공급자 상태, 배포, 승격 |
| 보조 기술 | 기록된 브라우저와 스크린 리더에서 검토자가 필요한 정보를 들었음 | 다른 브라우저/리더 조합, 모든 WCAG 기준, 백엔드 효과 성공 |
| 게시 | 검토된 정확한 소스가 보호된 검사를 통과하고 병합됨 | 현재 이미지 출처, 대상 선택, 적용 승인 |
| 배포 | 선택한 릴리스가 정확히 승인된 계획과 독립 재조회로 지정된 대상에 도달함 | 신원, 문서, 복구, 도입 수락 전체 |
| 운영 | 현재 원본에 연결된 증적이 선택한 운영 조건을 각각 충족함 | 새 권한 또는 이후 승인을 생략할 권한 |

[보존된 UI 검토](../../internals/handover-ui-evidence-20260915.md)는 서로 다른 합성 브라우저
시나리오 28개와 단위 테스트 127개를 포함합니다. `UX-39`는 미측정이며 최종 점수는 없습니다.
관련 코드, 테스트, 구성, 의존성, 환경이 바뀌지 않은 경우에만 결과를 재사용하세요.
DOM 레이블, 접근성 트리 스냅샷, 테스트 재실행은 음성 근거로 세지 않습니다.

## 실제 스크린 리더 세션 준비

1. **조합 명시:** 지원되는 Microsoft Edge와 Windows 내레이터를 사용하거나 Chrome과 NVDA처럼
   다른 조합을 명시적으로 기록하세요. OS, 브라우저, 스크린 리더 버전, 음성 합성기와 음성,
   언어 전환, 스캔/탐색 모드, 안내 상세 수준, 날짜를 기록합니다. 실행 파일이 있다고 해서
   리더가 실행 중이거나 한국어 음성이 동작한다는 뜻은 아닙니다.
2. **화면 연결:** 정확한 소스 리비전, 경로, 사례/목표 리비전, 데이터 모드, 데스크톱 화면
   크기, 탐색 상태를 기록합니다. 대체 정적 페이지가 아니라 실제
   `/agent-oversight/mapping-reviews`와 `/documents?handover_goal=<goal-id>` 경로를 사용하세요.
3. **실행 장소 보존:** 전체 스택 세션에는 승인된 정상 Console `http://localhost:5273`을
   재사용합니다. 로그인은 공급자 화면에서 진행합니다. 자격 증명을 내보내거나 브라우저
   사용자를 바꾸거나 승인되지 않은 공급자 점검을 동반해 서비스를 시작하지 마세요. 테스트
   포트를 사용하면서 인증된 전체 스택 근거라고 보고해서도 안 됩니다.
4. **테스트 동작 분리:** 명시적으로 격리된 합성 검사 환경에서는 대기, 충돌, 역할 변경
   상태를 제공할 수 있습니다. 테스트 전용이라고 표시하고 임대한 포트를 사용하세요.
   테스트 담당자는 리더 세션 전에 필요한 상태를 준비해야 합니다. 이 가이드는 대화형
   Console에 테스트 데이터를 설치하지 않습니다. 실제 백엔드에서 제출, 승인, 업로드,
   장애 훈련을 수행하려면 별도로 승인된 사례와 범위가 필요합니다. UI 상태를 만들기
   위해 임의로 실행하지 마세요.
5. **점수보다 청취 먼저:** 사람이 영어와 한국어를 직접 듣고 실제 안내 내용, 순서, 키보드
   초점 위치를 기록합니다. 리더, 음성, 승인된 화면, 청취자 중 하나라도 없으면 해당
   시나리오를 중단하고 부족한 근거를 기록하세요.

로컬 세션을 협의하기 전에 스크린 리더를 켜거나 음성을 설치하거나 데스크톱 오디오를
녹음하거나 다른 사람의 접근성 설정을 바꾸지 마세요. 녹음은 승인된 비공개 저장소에
보관하고, 배경 대화나 자격 증명이 아니라 승인된 테스트 창의 내용만 수집합니다.

### 음성 시나리오

각 행을 `en`과 `ko`에서 따로 수행해 시나리오/언어 조합 24개의 기록을 만듭니다. 이는
필요한 검사 목록이지 통과 보고서가 아닙니다. 통제된 상태는 미리 준비한 격리 테스트
데이터 또는 별도로 승인된 실제 사례를 뜻합니다. 다른 시나리오의 통과로 미실행 상태를
추정하지 마세요.

| ID | 동작과 통제된 상태 | 필요한 음성 정보와 초점 관찰 |
|----|-------------------|-----------------------------|
| SR-01 | 카탈로그를 읽는 동안 매핑 검토를 열고 사용 가능 상태로 전환 | 읽는 중과 준비된 내용을 구분하며 장식용 뼈대가 가짜 값으로 안내되지 않습니다. |
| SR-02 | 범위별 필드에 잘못된 값을 입력하고 수정 링크 실행 | 필드 이름, 잘못된 상태, 유용한 수정 방법을 추측 없이 알 수 있으며 해당 필드로 초점이 이동합니다. |
| SR-03 | 선언을 추가한 뒤 제거 | 새 행 또는 남은 추가 제어의 이름과 초점이 유용하며 키보드가 갇히지 않습니다. |
| SR-04 | 허용된 범위별 요청을 제출하고 응답을 보류한 뒤 HTTP 202 반환 | 대기와 Core 처리 대기를 전달하며 승인, 병합, 적용 성공이라고 안내하지 않습니다. |
| SR-05 | 불변 사례 상세를 펼치고 검토 2개가 있는 사례 읽기 | 펼침/접힘, 검토 수, 정확한 근거를 이해할 수 있으며 검토 2개가 병합을 뜻하지 않습니다. |
| SR-06 | 만료/사용 불가 범위 근거나 접근 차단 사례를 관찰하고 수동 새로 고침 | 사용 불가/차단 이유를 전달하며 복구 시 존재하지 않는 담당 범위나 해소된 이전 오류를 안내하지 않습니다. |
| SR-07 | 체크리스트를 열고 근거 영역 6개 펼치기 | 각 영역과 미작성/연결/해당 없음 상태를 식별하고 목표/원본 상세를 순서대로 읽을 수 있습니다. |
| SR-08 | 잘못된 원본 목표 ID를 입력하고 도움말로 이동 | 필드 이름과 64자 형식 요건을 전달하며 비활성 요청을 완료로 안내하지 않습니다. |
| SR-09 | 허용된 해당 없음 요청을 제출하고 응답 보류, 충돌 반환, 새로 고침 | 대기, 충돌, 새로 읽은 근거를 구분하고 유용한 맥락을 유지하며 해소된 이전 오류를 지웁니다. |
| SR-10 | 허용된 Owner 검토와 백업 검토 제어를 각각 실행하고 각 서버 결과 관찰 | 검토와 수락을 정확히 구분합니다. 제어가 사라지면 유용한 초점으로 돌아가되 사용자가 의도적으로 옮긴 초점을 빼앗지 않습니다. |
| SR-11 | 이전 응답이 지연되는 동안 목표/계정 변경 | 이전 목표의 수락이나 이전 계정 권한을 현재 결과처럼 안내하지 않으며 새 맥락과 초점을 식별할 수 있습니다. |
| SR-12 | 키보드로 파일 선택, 다중 파일 인수인계 입력 차단, 업로드 후 연결 실패 관찰 | 단일 파일 요건과 연결 실패를 전달하며 업로드를 연결 또는 수락으로 안내하지 않습니다. |

단순한 체크 표시 대신 각 행에 다음 근거를 보존하세요.

| 필드 | 필요한 내용 |
|------|-------------|
| 식별 | 시나리오 ID, 언어, 정확한 소스 및 테스트 데이터 또는 승인된 사례 리비전, UTC 세션 시각 |
| 조합 | OS/브라우저/리더 버전, 음성 설정, 화면 크기, 실행 장소 |
| 상호 작용 | 실제 키 입력, 시작 상태, 예상 의미 정보, 결과 초점 |
| 음성 | 실제 들은 내용을 그대로 옮긴 기록 또는 비공개 녹음/시간 범위. 누락, 중복, 중간에 끊긴 안내도 포함 |
| 검토 | 검토자, 결과, 결함 이슈 참조, 보존 내용의 민감정보 점검 여부 |

`passed`, `failed`, `needs-human`, `needs-infrastructure`를 사용하세요. 실행하지 않은 검사는
통과할 수 없습니다. 음성 이력은 사람의 청취 기록을 보완할 수 있지만 복사한 DOM 텍스트로
대체할 수는 없습니다. 사람의 청취가 없으면 `needs-human`으로 유지합니다. 사용할 수 없는
테스트 기반 환경은 담당자와 함께 따로 기록하세요. 필요한 음성 근거를 모두 검토하기
전까지 `UX-39`는 `U`이며 최종 점수는 없습니다. [평가표](../../reference/ui-ux-quality-rubric-ko.md)의
점수를 완성하더라도 WCAG 인증은 아닙니다.

## 운영 근거 묶음 준비

공급자 조회나 변경 전에 배포 담당자가 비공개 대상 참조, 테넌트/구독, 환경, 지역, 런타임
프로필, 정확한 릴리스를 선택합니다. 기존 신원 또는 공급자 로그인 화면을 사용하세요.
이슈 제목, 과거 실행, 기본 구독, 캐시된 산출물로 대상을 추정하지 않습니다. 실제 대상 값과
자격 증명은 승인된 비공개 구성에만 보관하고 채팅, 이 저장소, 공개 이슈, 명령줄 비밀 값으로
전달하지 마세요.

| 조건 | 로컬 준비 | 현재 외부 근거와 책임 검토자 |
|------|-----------|----------------------------|
| OP-01 릴리스와 대상 | 정확한 소스/CI 이력을 보존하고 릴리스를 만들거나 선택하지 않은 채 승인된 산출물 경로 확인 | 배포 담당자가 완전한 서명 키트와 정확한 서비스 이미지 다이제스트를 선택합니다. 해당 릴리스의 현재 서명, 출처, 소스 CI 근거를 보존합니다. |
| OP-02 정확한 계획 | [독립 실행 계약](../../roadmap/deployment/installable-deployment-cli-ko.md)을 읽고 의도한 범위와 중단 조건 정리 | 독립된 사람이 각 현재 바이너리 계획의 다이제스트와 만료를 승인합니다. 파괴적 변경에는 별도의 정확한 확인이 필요하며 계획이 바뀌면 새로 승인합니다. |
| OP-03 비공개 실행 | 필요한 Foundation, 네트워크, 상태, 마이그레이션 증적 확인 | 전용 관리 호스트의 사용자 할당 Managed Identity가 조정기를 통해 VNet에서 실행합니다. 호스트 신원, 효과 전 기록, Foundation 인계, 정확한 마이그레이션/이미지, 상태, 동료 서비스 격리, 변경 0건의 두 번째 계획, 정리를 보존합니다. |
| OP-04 현재 사람과 임무 | 상위 저장소 맵에 실제 값을 넣지 않고 v2 구조와 서로 다른 사람 요건 검토 | 신원/담당 체계 검토자가 에이전트 15개, 서로 다른 유지관리자 2명, 자율 운영이 아닌 모든 에이전트의 현재 주 담당 및 별도 백업, 정확한 범위/유효 기간, 현재 그룹/일정 확인과 정적 대체 담당자, 별도의 역할 적격성을 검증합니다. |
| OP-05 GitHub 담당 체계 | [App과 병합 계약](../../roadmap/interfaces/agent-stewardship-operations-ko.md#배포-구성) 검토 | 저장소 담당자가 필요한 내용/PR/메타데이터/이슈 권한을 가진 App 설치와 발급 토큰의 범위가 의도한 비공개 저장소로 제한됨을 입증합니다. 보호된 키/웹후크 참조, 토큰 값 없는 갱신 결과, 독립된 사람의 검토/병합, 정확한 서명 병합 재조회를 보존합니다. 정적 개인 토큰은 사용하지 않습니다. |
| OP-06 ChatOps | A1 사람 승인을 A2 경고 및 A4 요약과 분리 | 채널 담당자가 선택한 A1 신원, 위임된 사용자 대신 실행(OBO) 흐름, 동의, 승인된 앱 설치, 정확한 팀/채널을 확인합니다. 전달, 수신 확인, 결정의 연결과 검토된 거버넌스 활성화를 보존합니다. 준비 제안이나 A2/A4 성공은 이를 입증하지 않습니다. |

| OP-09 복구 | 각 훈련, 기한, 중단 조건, 영향 대상, 복구 담당자 고정 | 복구 검토자가 아래의 소유 변경 역복구, 정상 회수, 중복, 재시작, 장애, 오래된 신원 복구 훈련에서 중복 효과나 관련 없는 변경이 없음을 확인합니다. |

Owner 전용 `GET /handover/readiness` 보고서는 기존 기록을 요약하며 유효 기간은 10분입니다.
공급자를 점검하지 않습니다. `source_gaps=[]`는 한정된 소스 요건의 완료를 뜻합니다.
`mode=shadow`와 `operationally_ready=false`는 명시적으로 유지됩니다. 부분 조회, 잘못된 행,
미측정 간격은 전체 모집단이 정상이라는 뜻이 아닙니다. 보고서를 편집하거나 역할 레이블을
현재 신원 또는 ACL 근거로 취급해 차단 요인을 지우지 마세요.

### 현행 배포 경로 사용

대상과 산출물을 선택한 뒤에만 [배포 빠른 시작](../deploy-quickstart-ko.md)을 따르세요.
`fdaictl provision azure`는 정확한 계획 검토와 Bastion으로 접근하는 관리 호스트를 조정합니다.
GitHub Actions는 소스 검증과 릴리스 게시를 수행할 수 있지만 테넌트 계획/적용/재개/철거에는
사용하지 않습니다. 과거의 봇 소유 워크플로 적용은 실행 신원 분리를 뜻하며 퇴역한 전송
경로를 되살릴 권한이 아닙니다.

정적 CLI 도움말은 대상 선택 전에 확인할 수 있습니다. `doctor`와 공급자 사전 점검은 외부
신원 또는 대상 상태를 조회하므로 오프라인 근거가 아닙니다. `--prepare-only`는 명시적으로
선택한 소스 모드에만 적용하며 서명 키트 검증의 우회 경로가 아닙니다. 현재 소스 모드는
연결된 애플리케이션 실행 전에 멈추므로 #458을 완료하는 대체 경로가 아닙니다.
존재하지 않는 `provision apply` 명령을 만들거나 직접 Terraform을 실행해 조정기를 우회하지
마세요.

적용 결과가 불확실하면 불변 기록을 보존하고 검증 전용 복구를 사용합니다. 적용을
반복하거나 기록을 피하려고 새 실행 디렉터리를 만들지 마세요. 승인과 실행 신원은 서로
달라야 합니다. 릴리스 게시, 앱 설치, 런타임 승격, 각각의 새 계획에는 자체적인 현재 근거와
권한이 필요합니다.

### 별도로 승인된 훈련 실행

각 행을 시작하기 전에 현재 대상에 연결된 계획, 전체/단계별/무진행 기한, 중단 조건,
관찰 담당자, 안전한 정리 범위가 필요합니다. 읽기 전용 검증에 장애 주입이 암묵적으로
포함되지는 않습니다. 공급자 시간 초과, 429/503, 예상하지 못한 모델 대체가 발생하면 시도를
종료하고 같은 실시간 요청을 반복하는 대신 제한된 근거를 보존하세요.

| 훈련 | 관찰 가능한 종료 조건 | 중단 또는 보류 조건 |
|------|----------------------|--------------------|
| 초안, 재시작, 검토된 병합 | 허용된 업로드 하나가 검토 전용 PR 하나를 만들고 같은 업로드 재시도와 재시작은 이를 재사용합니다. 독립된 사람의 병합으로 일치하는 알림과 Saga 병합 감사가 각각 하나 생깁니다. | App/동의/현재 원본 누락, 불확실한 전달, 후보 다이제스트 불일치. |
| 중복 전달 | 같은 서명 전달 ID를 재처리해도 효과, PR 수, 알림 수, 감사 수가 바뀌지 않습니다. | 원래 연결 정보가 없거나 최초 효과의 소유권이 불명확함. |
| 신원 장애와 정상 복구 | Graph 실패 시 마지막 성공 관찰을 갱신 없이 보존하고 만료된 데이터는 사용 불가로 표시합니다. 정확한 현재 맵에 대한 새 관찰로 복구와 전이 시에만 수행한 감사를 입증합니다. | 불완전한 담당 범위, 다른 맵 리비전, 독립된 현재 재조회 부재. |
| 멤버십과 소유 변경 역복구 | 원래 소유 변경을 독립 관찰한 뒤 새로 승인된 `recovery_of` 역변경이 같은 대상 계보와 잠금을 사용하고 독립 재조회로 종료됩니다. Core는 `degraded`이며 임무와 목표를 복원하지 않습니다. | `ALREADY_APPLIED`, 알 수 없는 소유권, 불확실한 전달, 중간 시도, 만료된 승인. |
| 정상 회수 | 현재 대체 담당 범위와 새 검토 후 IAM을 제거하고, 독립 제거 후 이전 임무를 검토해 병합하며 관련 없는 역할 수요를 보존합니다. | 고정된 대체 사례 누락, 활성 또는 불확실한 수요, 일치하지 않는 병합. 역방향 복구와는 다릅니다. |
| 문서 철회와 보존 | 현재 ACL/원본 변경으로 내용 유출 없이 적격성을 제거합니다. 법적 보존 대상은 유지하고 허용된 정리는 독립적인 부재 근거로 확인합니다. | 보존 여부 불명, 원본 사용 불가, 버전 변경, 불완전한 삭제 확인 범위. |
| 승인 연속성과 코호트 | 전달 후에 사람 무응답 시간을 측정합니다. 현재 적격 대체 담당자에게 원래 기한 안에 같은 작업을 전달하고 고정된 코호트에 모든 적격/제외 표본을 보존합니다. | 수신자 불명, 전달 누락, 오래된 예측, 기한 초과. 침묵은 승인이 아닙니다. |

배포에서 토큰 만료를 시험하려고 공급자 시계를 바꾸지 마세요. 주입된 시계의 갱신 테스트는
로컬 동작만 입증하며 실제 갱신 증적에는 승인된 제한 시간의 실제 관찰이 필요합니다.
민감정보를 제거한 조정기, 관리 호스트, 서비스 감사 기록에서 유출 징후를 검토하세요.
모든 슬롯이 유휴 상태일 때 선택한 실행이 소유한 자원만 중지합니다. 필요한 보존과 해당되는
할당 해제 금지 조건을 지키세요. 정리에 실패하면 실행은 미완료 상태입니다.

## 근거가 있는 작업만 종료

#458의 각 조건에 정확한 릴리스/대상 연결, 원본 신원, 이벤트/유효/기록 시각, 만료,
완전성, 다이제스트, 검토자, 비공개 증적 위치를 보존합니다. 공개할 때는 민감정보를 제거한
영문 요약과 비밀이 아닌 근거 참조만 사용하세요. 필요한 현재 관찰과 독립 검토가 있어야
종료 조건을 완료로 표시할 수 있습니다.

로컬 구현, 소스 게시/병합, 실제 음성, 배포, 운영을 따로 보고합니다. 운영 조건 하나라도
근거가 없으면 #458을 열어 두세요. 다음 단계에 꼭 필요한 비공개 대상 선택, 세션 준비,
공급자 화면 작업, 정확한 계획 승인만 요청합니다. 비밀이나 미래 계획의 포괄 승인을
요청하지 마세요.
