# FDAI 제안서 2막: 에이전트, 협업, 통제

2막은 운영 모델을 검토할 수 있게 만듭니다. 15개 에이전트의 이름과 역할을 설명하고, 직접 호출 대신 타입 이벤트를 사용하는 이유를 보여주며, 하나의 이벤트가 판단, 조치, 사람 승인, 복구, 감사로 이어지는 과정을 따라갑니다.

> **장표:** 전체 26장 중 9-18번
>
> **목차 섹션:** 15 에이전트 소개, AI 에이전트는 어떻게 협업하는가, 운영 시나리오, 사람이 개입하는 순간

## 15 에이전트 소개

### 9번 장표. 어시스턴트 모음이 아니라 고정된 조직입니다

**의사결정 질문:** 운영 루프의 각 부분을 누가 소유합니까?

**핵심 메시지:** FDAI는 독립적으로 실행할 수 있는 15개 에이전트를 업스트림에서 한 번 정의하고, 안정적인 책임, 객체 소유권, 이벤트 계약을 배정합니다.

**장표 문안:**

```text
Odin - 총괄 계획
  Thor - 대응과 배분       Forseti - 판단
    Vidar - 복구             Huginn - 이벤트 수집
    Var - 승인               Heimdall - 관찰
    Bragi - 설명             Njord - 비용
                              Freyr - 용량
참모: Mimir - 규칙, Muninn - 기억, Saga - 감사,
      Norns - 학습           Loki - 복원력 실험
```

- 포크는 조직을 설정하지만 에이전트를 추가, 제거, 변경하지 않습니다.
- 각 객체 타입에는 쓰기 주체 하나와 여러 읽기 주체가 있을 수 있습니다.

**시각 구성:** 운영 보고선은 실선, 거버넌스 참모선은 점선으로 표현한 절제된 조직도를 사용합니다. 활성 흐름에만 Azure Blue 한 색을 쓰고 그룹별 색상 카드는 사용하지 않습니다.

**준비할 근거:** Pantheon 문서 일치 검사와 기계 판독 원본인 `PANTHEON_SPECS`를 준비합니다.

**발표자 노트:** 이름을 모두 읽지 말고 그룹을 설명합니다. 역할 상세는 10-11번 장표에서 다룹니다.

### 10번 장표. 감지, 판단, 조치, 인터페이스 역할

**의사결정 질문:** 실시간 운영 경로에 어떤 에이전트가 참여합니까?

**핵심 메시지:** 실시간 경로 에이전트는 관찰, 판단, 승인, 실행이 하나의 신원으로 합쳐지지 않도록 좁은 책임을 가집니다.

**장표 문안:**

| 에이전트 | 쉬운 역할 설명 | 소유하지 않는 일 |
|----------|----------------|-------------------|
| Huginn | 이벤트를 수집, 정규화, 상관 분석합니다. | 판단 또는 실행입니다. |
| Heimdall | 이상, 드리프트, 예측 결과를 탐지합니다. | 수정 실행입니다. |
| Forseti | 결정과 근거 기반 분석을 발행합니다. | 승인 또는 실행입니다. |
| Thor | 타입과 승인을 확인한 조치 실행을 배분합니다. | 판단 또는 사람 신원입니다. |
| Var | 사람 승인 또는 거절을 전달합니다. | 실행자 자격 증명입니다. |
| Vidar | 복구와 롤백 경로를 실행합니다. | 자기 승인입니다. |
| Bragi | 운영자 의도를 번역하고 답변을 표현합니다. | 내부 결정을 변경하는 일입니다. |

**시각 구성:** 감지, 판단, 승인 또는 배분, 복구로 이어지는 하나의 스윔레인을 사용하고 Bragi는 사람 인터페이스로 위에 배치합니다.

**준비할 근거:** 조치 온톨로지의 역할 바인딩 예시 하나를 준비합니다.

**발표자 노트:** Thor는 대응 및 배분 역할입니다. 두 번째 판단자로 설명하지 않습니다.

### 11번 장표. 계획, 증거, 학습, 도메인 역할

**의사결정 질문:** 누가 루프를 통제하고 전문 근거를 제공합니까?

**핵심 메시지:** 거버넌스와 도메인 에이전트는 숨겨진 실행 권한을 얻지 않고 조언하거나 상태를 보존합니다.

**장표 문안:**

| 에이전트 | 쉬운 역할 설명 | 통제 경계 |
|----------|----------------|-----------|
| Odin | 충돌하는 도메인 목표를 중재합니다. | 결정론적으로 처리하고 증거를 기록합니다. |
| Mimir | 규칙과 정책 수명 주기를 소유합니다. | 품질 검사를 거쳐 적용합니다. |
| Muninn | 상태, 맥락 인덱스, 사례 이력을 보존합니다. | 기억이 판단을 대신하지 않습니다. |
| Saga | 감사 증거를 추가하고 이슈를 에스컬레이션합니다. | 감사가 실행하지 않습니다. |
| Norns | 반복 근거에서 비활성 규칙 후보를 제안합니다. | 자신의 제안을 적용할 수 없습니다. |
| Njord | 비용 이상을 탐지하고 비용 조치를 제안합니다. | 실행 권한이 없습니다. |
| Freyr | 용량을 예측하고 크기 조정 조치를 제안합니다. | 실행 권한이 없습니다. |
| Loki | 범위가 제한된 복원력 실험을 제안합니다. | 카오스 조치는 사람 승인이 필요합니다. |

**시각 구성:** 거버넌스와 도메인 전문가라는 프레임 없는 표 두 개를 사용합니다. 모든 행을 같은 비중으로 표현합니다.

**준비할 근거:** 전문가 의견 충돌 사례와 기록된 중재 결과 하나를 준비합니다.

**발표자 노트:** 학습은 후보를 만들며 운영 규칙을 바로 만들지 않습니다. 이 구분이 적용 경계를 보호합니다.

## AI 에이전트는 어떻게 협업하는가

### 12번 장표. 에이전트는 타입 이벤트로 협업합니다

**의사결정 질문:** FDAI는 에이전트 사이의 숨은 결합을 어떻게 막습니까?

**핵심 메시지:** 기계 협업은 직접 호출, 비공개 RPC, 공유 가변 워크플로 상태가 아니라 스키마 검증 발행 및 구독 이벤트를 사용합니다.

**장표 문안:**

- **발행:** 단일 소유자가 타입 객체와 상관 식별자를 만듭니다.
- **검증:** 이벤트 패브릭이 스키마, 소유권, 필수 근거를 확인합니다.
- **구독:** 권한이 있는 에이전트는 다른 에이전트 구현을 가져오지 않고 반응합니다.
- **재현:** 같은 이벤트와 설정은 같은 결정론 경로를 재현합니다.

```text
에이전트 -> 타입 이벤트 -> 스키마 및 소유권 검사 -> 구독자
```

**시각 구성:** 중앙 이벤트 패브릭과 독립된 에이전트 끝점을 보여줍니다. 에이전트 간 직접 화살표만 금지 표시합니다.

**준비할 근거:** 이벤트 스키마, 소유권 표, 재현한 합성 추적을 준비합니다.

**발표자 노트:** 이벤트 버스는 전송 기술 선택이 아니라 아키텍처 경계입니다.

### 13번 장표. 충분한 가장 낮은 판단 수준을 선택합니다

**의사결정 질문:** 적응형 추론은 언제 운영 경로에 들어옵니까?

**핵심 메시지:** FDAI는 반복 가능한 사례를 결정론 규칙으로 먼저 처리하고, 선언된 모호성에만 근거 기반 적응형 추론을 사용합니다.

**장표 문안:**

| 수준 | 용도 | 필수 통제 |
|------|------|-----------|
| T0 | 결정론 규칙과 정책 조회입니다. | 정확한 입력과 재현 가능한 결과입니다. |
| T1 | 알려진 패턴을 가볍게 유사도 재사용합니다. | 범위가 제한된 매칭과 이전 근거입니다. |
| T2 | 모호한 사례에 근거 기반 적응형 추론을 사용합니다. | 독립 검증, 근거, 스키마, 위험, 승인 검사입니다. |

- 시범 운영 기준값 전에는 고정된 비율을 약속하지 않습니다.
- 신뢰가 낮은 결과는 검토로 보내거나 차단합니다.

**시각 구성:** T0를 가장 넓게 표현한 수평 수준 세 개를 사용하고 숫자 비율은 넣지 않습니다. T2로 갈수록 근거 요구가 늘어나는 모습을 보여줍니다.

**준비할 근거:** 후보 이벤트 집합과 각 이벤트의 판단 수준 배정 기준을 준비합니다.

**발표자 노트:** 판단 수준 분포는 제품 기준이 아니라 시범 운영 측정값으로 제시합니다.

## 운영 시나리오

### 14번 장표. 하나의 신호가 통제된 결정이 되는 과정

**의사결정 질문:** 첫 신호부터 결정까지 어떤 일이 일어납니까?

**핵심 메시지:** FDAI는 맥락과 근거를 보존하면서 중복 신호를 하나의 결정 경로로 줄입니다.

**장표 문안:**

1. Huginn이 공급자 이벤트를 받고 정규화합니다.
2. Heimdall이 관련 신호를 상관 분석하고 운영 상태를 탐지합니다.
3. Forseti가 T0, T1, T2를 선택하고 근거를 검증합니다.
4. 정책이 제안 조치를 자동, 사람 승인, 차단으로 분류합니다.
5. 조치를 실행하지 않아도 Saga가 결정을 기록합니다.

**시각 구성:** 용량 위험 또는 유휴 리소스 같은 합성 예시 하나를 사용하고 모든 단계에 같은 상관 식별자를 표시합니다.

**준비할 근거:** 입력 이벤트, 정규화 이벤트, 결정 객체, 정책 결과, 감사 항목을 준비합니다.

**발표자 노트:** 아키텍처와 데모 사이에서 시나리오를 바꾸지 않습니다. 폭넓은 사례보다 일관된 사례가 더 설득력 있습니다.

### 15번 장표. 모든 조치는 자체 안전 계약을 포함합니다

**의사결정 질문:** 조치를 실행하기 전에 무엇이 충족되어야 합니까?

**핵심 메시지:** 타입이 없거나 안전 필드가 누락된 조치는 실행 경로에 들어갈 수 없습니다.

**장표 문안:**

| 안전 필드 | 답해야 할 질문 |
|-----------|----------------|
| 정지 조건 | 언제 조치를 멈춰야 합니까? |
| 롤백 | 이전 상태를 어떻게 복원합니까? |
| 영향 범위 제한 | 어떤 리소스와 규모를 바꿀 수 있습니까? |
| 드라이런 | 실행 전에 어떤 결과를 예상합니까? |
| 리소스별 잠금 | 충돌하는 동시 작업을 어떻게 막습니까? |
| 멱등성 키 | 재시도를 어떻게 안전하게 만듭니까? |
| 감사 기록 | 의도, 신원, 결과를 어떻게 보존합니까? |

**시각 구성:** 하나의 조치 계약을 깔끔한 명세서처럼 확대합니다. 필드마다 별도 카드를 만들지 않습니다.

**준비할 근거:** 데모에서 사용할 합성 조치 타입과 정확한 롤백 정의를 준비합니다.

**발표자 노트:** 안전 계약은 최선을 다하는 런타임 알림이 아니라 타입 수준 진입 조건입니다.

### 16번 장표. 결정에는 세 가지 명시적 결과가 있습니다

**의사결정 질문:** FDAI는 자율 조치와 사람 통제 사이를 어떻게 선택합니까?

**핵심 메시지:** 위험과 근거에 따라 조치를 자동 실행하거나, 승인을 기다리거나, 차단합니다.

**장표 문안:**

| 결과 | 일반 조건 | 최종 증거 |
|------|-----------|-----------|
| 자동 | 영향이 낮고 근거가 완전하며 적용 승인된 기능입니다. | 드라이런, 조치 결과, 검증, 감사입니다. |
| 사람 승인 | 영향이 크거나 목표 충돌이 근접하거나 정책이 요구합니다. | 승인 신원, 이유, 만료, 실행 또는 시간 초과입니다. |
| 차단 | 근거 누락, 허용되지 않은 범위, 검증 실패, 안전하지 않은 계약입니다. | 차단 이유와 보존된 추적입니다. |

- 승인 채널에 장애가 생기면 조치는 대기하거나 만료됩니다.
- 런타임, 환경, 포크 상태만으로 기능을 적용 모드로 바꾸지 않습니다.

**시각 구성:** 하나의 결정 노드에서 같은 비중의 세 갈래로 나눕니다. 자동 조치를 선호 결과처럼 강조하지 않습니다.

**준비할 근거:** 세 가지 분기에 대한 정책 결정 출력을 준비합니다.

**발표자 노트:** 차단은 시스템 실패가 아니라 통제된 정상 결과입니다.

## 사람이 개입하는 순간

### 17번 장표. 사람은 정책을 정하고 중요한 예외를 판단합니다

**의사결정 질문:** 어떤 결정은 명시적으로 사람에게 남습니까?

**핵심 메시지:** FDAI는 반복 조정을 줄이면서 정책, 큰 영향, 예외, 적용 모드 전환의 책임을 사람에게 둡니다.

**장표 문안:**

- 설정된 영향 경계를 넘는 조치를 승인하거나 거절합니다.
- 복원력, 안전, 비용, 용량 목표 사이의 근접한 충돌을 해결합니다.
- 정책, 범위, 역할 배정, 승인 분리를 정의합니다.
- 기능을 관찰 모드에서 적용 모드로 바꾸기 전에 근거를 검토합니다.
- Norns가 제안한 규칙 후보를 수락, 수정, 거절합니다.

**시각 구성:** 정책에서 예외로 이어지는 연속선을 사용합니다. 반복 판단은 시스템 쪽에, 책임 있는 판단은 사람 쪽에 배치합니다.

**준비할 근거:** 제안 승인 그룹, 실행 워크로드 신원, 에스컬레이션 경로, 만료 동작을 준비합니다.

**발표자 노트:** 자기 승인은 지원하지 않습니다. 사람 App 역할과 실행 워크로드 신원은 분리합니다.

### 18번 장표. 모든 경로는 증거와 담당 체계로 끝납니다

**의사결정 질문:** 운영자가 무엇이, 왜 일어났고 누가 책임지는지 설명할 수 있습니까?

**핵심 메시지:** 실행, 거절, 시간 초과, 롤백, 무조치 결과는 모두 읽기 전용 콘솔이 보여줄 수 있는 증거를 만듭니다.

**장표 문안:**

| 증거 | 검토자가 확인할 수 있는 내용 |
|------|------------------------------|
| 상관 및 멱등성 | 전체 이벤트에서 조치까지의 연결입니다. |
| 입력과 뒷받침 근거 | 결정이 의존한 정보입니다. |
| 결정과 정책 결과 | 자동, 승인, 차단 경로를 선택한 이유입니다. |
| 사람 및 워크로드 신원 | 누가 승인했고 어떤 신원이 실행했는지 보여줍니다. |
| 결과와 복구 상태 | 검증 통과 또는 롤백 실행 여부입니다. |
| 책임 담당자 | 에스컬레이션과 지식 인수인계를 담당하는 사람입니다. |

**시각 구성:** 읽기 전용 증거 타임라인 옆에 간결한 담당 체계 패널을 배치합니다. 콘솔 목업에는 실행 버튼을 넣지 않습니다.

**준비할 근거:** 완전한 감사 기록 하나와 일치하는 운영자 콘솔 화면을 준비합니다.

**발표자 노트:** 모든 통합 선택이 끝났는지가 아니라 제안한 통제 경계를 검토할 수 있는지 질문하며 2막을 닫습니다.
