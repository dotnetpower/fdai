# FDAI 제안서 3막: 범위, 효과, 데모, 도입

3막은 아키텍처를 도입 의사결정으로 연결합니다. 자동화를 시작할 수 있는 영역, 과장 없이 시범 운영 가치를 측정하는 방법, 데모가 증명해야 하는 내용, 권한을 넓힐 때 적용할 종료 기준을 정의합니다.

> **장표:** 전체 26장 중 19-26번
>
> **목차 섹션:** 운영 자동화 영역, 기대 효과, 데모, 도입 방법

## 운영 자동화 영역

### 19번 장표. 도구가 아니라 의사결정 유형을 자동화합니다

**의사결정 질문:** 어떤 운영 업무를 관찰, 자동 조치, 사람 승인으로 구분해야 합니까?

**핵심 메시지:** FDAI는 근거, 조치 안전, 정책이 특정 의사결정 유형을 뒷받침할 때만 자동화 범위를 넓힙니다.

**장표 문안:**

| 영역 | 관찰 및 제안 | 자동 조치 후보 | 사람 승인 유지 |
|------|--------------|----------------|----------------|
| 복원력 | 드리프트, 복구 준비, 실험 결과입니다. | 이전에 적용 승인된 저영향 복구 단계입니다. | 영향이 큰 장애 조치와 카오스 실험입니다. |
| 변경 안전 | 계획 드리프트, 정책 위반, 드라이런 결과입니다. | 적용 승인 후 범위가 제한되고 되돌릴 수 있는 수정입니다. | 넓은 범위, 신원, 네트워크, 데이터 위험 변경입니다. |
| 비용 거버넌스 | 비용 이상, 유휴 리소스, 예산 추세입니다. | 소유권과 롤백을 확인한 저영향 정리입니다. | 영향이 큰 약정, 삭제, 용량 상충입니다. |
| 용량 | 예측과 크기 조정 권고입니다. | 정책 안에서 범위가 좁고 되돌릴 수 있는 조정입니다. | 비용 또는 복원력 목표와 근접하게 충돌하는 경우입니다. |

**시각 구성:** 하나의 경계 행렬을 사용합니다. 중립적인 셀을 사용하고 선택한 시범 운영 유형에만 Azure Blue 윤곽선을 적용합니다. 색상 가장자리 막대는 사용하지 않습니다.

**준비할 근거:** 후보 이벤트 목록, 조치 타입, 영향 범위 제한, 담당자, 현재 승인 규칙을 준비합니다.

**발표자 노트:** 시범 운영은 의사결정 유형 하나를 선택합니다. 도메인 이름만으로는 자동화 권한을 정하기에 너무 넓습니다.

### 20번 장표. 권한은 측정된 적용 결정을 통해 커집니다

**의사결정 질문:** 기능은 관찰에서 실제 리소스 변경으로 어떻게 이동합니까?

**핵심 메시지:** 새 기능은 관찰 모드에서 시작하며, 측정 근거를 바탕으로 권한 있는 적용 결정을 거친 뒤에만 변경을 실행합니다.

**장표 문안:**

1. **등록:** 범위, 담당자, 조치 계약, 가드레일을 연결합니다.
2. **관찰:** 변경을 적용하지 않고 결정, 드라이런, 근거를 만듭니다.
3. **비교:** 정확도, 범위, 검토 부하, 롤백 준비, 정책 준수를 측정합니다.
4. **검토:** 이름이 지정된 책임자가 적용 또는 보류를 결정합니다.
5. **적용:** 승인된 의사결정 유형과 영향 범위만 활성화합니다.
6. **관찰 복귀:** 가드레일이 악화되면 관찰 모드로 돌아갑니다.

**시각 구성:** 적용 모드에서 관찰 모드로 돌아가는 화살표가 분명한 수평 성숙 경로를 사용합니다. 환경, 런타임, 포크는 경로 밖의 독립 레이블로 표시합니다.

**준비할 근거:** 적용 레지스트리 항목, 목표 측정값, 가드레일 임계값, 담당자 회의 기록을 준비합니다.

**발표자 노트:** 배포와 적용은 다릅니다. 첫날에도 변경을 적용하지 않으면서 운영 가치를 만들 수 있습니다.

## 기대 효과

### 21번 장표. 가치는 측정된 전후 변화로 정의합니다

**의사결정 질문:** 일반적인 업계 수치에 기대지 않고 시범 운영 가치를 어떻게 증명합니까?

**핵심 메시지:** 모든 효과는 현재 기준값, 시범 운영 측정, 한 지표의 개선이 새 위험을 감추지 않게 하는 가드레일을 짝지어 정의합니다.

**장표 문안:**

| 효과 측정 | 검증할 방향 | 가드레일 |
|-----------|-------------|----------|
| 신호에서 근거 있는 결정까지 걸린 시간 | 감소 | 근거 없는 결정 비율이 늘지 않습니다. |
| 이벤트당 반복 인계 수 | 감소 | 필수 승인 분리를 유지합니다. |
| T0 또는 T1에서 해결한 결정 | 근거가 있는 범위에서 증가 | 검토 및 차단 비율을 계속 확인합니다. |
| 복구 확인 시간 | 감소 | 롤백 성공과 복구 목표가 정책 안에 있습니다. |
| 검증된 개선당 비용 | 감소 | 가용성, 용량, 변경 위험이 경계 안에 있습니다. |

**시각 구성:** 기준값과 시범 운영 비교 옆에 가드레일 열을 배치합니다. 기준값 워크숍 전에는 숫자 필드를 비워 둡니다.

**준비할 근거:** 각 측정값의 기준 기간, 이벤트 집합 정의, 데이터 원본, 담당자, 보고 주기를 준비합니다.

**발표자 노트:** 같은 이벤트 집합으로 양쪽을 측정하지 않았다면 절감 배수나 자동화 비율을 제시하지 않습니다.

### 22번 장표. 첫 세 도메인에서 기대하는 결과

**의사결정 질문:** 제어 루프가 설계대로 동작하면 무엇이 개선되어야 합니까?

**핵심 메시지:** FDAI는 복원력, 변경 안전, 비용 거버넌스를 더 지속적이고 설명 가능하며 되돌릴 수 있게 만드는 것을 목표로 합니다.

**장표 문안:**

| 도메인 | 현재 제약 | 시범 운영 가설 | 성공 근거 |
|--------|-----------|----------------|-----------|
| 복원력 | 복구 신뢰가 주기적인 훈련에 의존합니다. | 지속적인 근거가 준비 상태 공백을 더 일찍 찾습니다. | 검증된 실험, 복구 결과, 롤백 기록입니다. |
| 변경 안전 | 경로와 팀마다 안전 검사가 다릅니다. | 타입 드라이런과 정책이 일관된 결정을 만듭니다. | 정책 결과, 영향 범위, 승인, 변경 후 검증입니다. |
| 비용 거버넌스 | 탐지와 수정이 별도 작업 대기열입니다. | 반복되는 저영향 기회가 하나의 통제 루프를 따릅니다. | 적격 이상, 담당자 확인, 측정된 수정, 가드레일 준수입니다. |

**시각 구성:** 제약, 가설, 근거로 이어지는 세 개의 정렬된 행을 사용합니다. 측정 전에는 큰 효과 숫자를 사용하지 않습니다.

**준비할 근거:** 시범 운영에 포함된 각 도메인의 승인된 시나리오와 측정값 집합을 준비합니다.

**발표자 노트:** 시범 운영은 하나의 도메인으로 시작할 수 있습니다. 다른 도메인을 추가해도 아키텍처는 같습니다.

## 데모

### 23번 장표. 기능 투어가 아니라 하나의 완전한 이벤트를 보여줍니다

**의사결정 질문:** 데모는 무엇을 신뢰할 수 있게 만들어야 합니까?

**핵심 메시지:** 데모는 설명 없이도 이해할 수 있는 하나의 시나리오로 이벤트에서 증거까지의 연결과 권한 분리를 증명해야 합니다.

**장표 문안:**

1. **신호:** 합성 클라우드 이벤트가 공급자 어댑터를 통해 들어옵니다.
2. **결정:** 에이전트 경로가 근거, 판단 수준, 정책 결과를 만듭니다.
3. **사람 개입:** 영향이 큰 조치가 독립적인 승인을 기다립니다.
4. **조치와 복구:** 승인된 타입 조치가 드라이런, 잠금, 롤백과 함께 실행됩니다.
5. **증거:** 콘솔이 결정, 신원, 결과, 책임 담당자를 보여줍니다.

**시각 구성:** 실제 합성 콘솔 화면을 사용한 다섯 프레임 필름 스트립으로 구성합니다. 캡션은 미디어 위가 아니라 아래에 둡니다.

**준비할 근거:** 사전 녹화 대체 영상, 합성 페이로드, 안정적인 로컬 데이터, 완전한 감사 추적을 준비합니다.

**발표자 노트:** 데모는 자동화만큼 거버넌스를 증명합니다. 시간을 줄이기 위해 차단 또는 승인 경로를 생략하지 않습니다.

### 24번 장표. 데모 통과 기준

**의사결정 질문:** 검토자는 데모가 실제 통제 경계를 보여줬는지 어떻게 판단합니까?

**핵심 메시지:** 성공한 데모는 기대한 조치와 안전하게 조치를 거절하는 경로를 함께 보여줍니다.

**장표 문안:**

- 같은 상관 식별자가 신호에서 최종 증거까지 보입니다.
- 결정이 근거와 선택한 T0, T1, T2 수준을 보여줍니다.
- 안전 필드 누락 또는 허용되지 않은 범위가 명확하게 차단됩니다.
- 영향이 큰 조치는 별도 승인자 신원 없이는 계속되지 않습니다.
- 재시도가 조치를 중복하지 않고 리소스 잠금이 충돌을 막습니다.
- 결과 검증과 롤백 상태가 감사 타임라인에 보입니다.
- 운영자 콘솔은 읽기 전용으로 유지됩니다.

**시각 구성:** 하나의 증거 타임라인 옆에 단순한 체크리스트를 배치합니다. 성공만 녹색으로 표현하지 않습니다. 차단 검사는 기대하는 증거입니다.

**준비할 근거:** 통과 또는 실패 결과와 각 산출물 링크를 포함한 데모 검사 기록을 준비합니다.

**발표자 노트:** 실시간으로 보여주지 못한 기준은 잔여 작업으로 기록합니다. 누락된 근거를 설명으로 대신하지 않습니다.

## 도입 방법

### 25번 장표. 경계가 있는 단계로 도입합니다

**의사결정 질문:** 첫 통제 자동화 전에 어떤 작업이 필요합니까?

**핵심 메시지:** 담당 체계, 범위, 읽기 전용 근거부터 시작해 측정된 의사결정 유형을 한 번에 하나씩 확장합니다.

**장표 문안:**

| 단계 | 작업 | 종료 근거 |
|------|------|-----------|
| 0. 기준값 워크숍 | 이벤트 집합, 측정값, 담당자, 후보 범위를 선택합니다. | 서명된 범위와 기준값 계획입니다. |
| 1. 기반 연결 | 공급자, 신원, 이벤트 패브릭, 상태, 읽기 전용 콘솔을 연결합니다. | 종단 간 합성 추적입니다. |
| 2. 관찰 시범 운영 | 변경을 적용하지 않고 규칙, 정책, 조치, 어댑터를 연결합니다. | 측정된 결정 및 가드레일 보고서입니다. |
| 3. 적용 검토 | 저영향 의사결정 유형 하나의 근거를 검토합니다. | 기록된 적용 또는 보류 결정입니다. |
| 4. 통제된 확장 | 범위 또는 다른 도메인을 독립적으로 추가합니다. | 새 기준값과 그대로 유지된 안전 계약입니다. |

**시각 구성:** 번호가 있는 다섯 단계를 한 줄에 배치합니다. 연속 가속 화살표가 아니라 단계 사이의 결정 게이트를 보여줍니다.

**준비할 근거:** 플랫폼, 정책, 보안, 운영, FDAI 담당자와 대체 가능 인원을 지정합니다.

**발표자 노트:** 고객별 규칙, 정책 오버레이, 공급자 구현, 조치 항목, 배포 값은 지원되는 확장 지점을 사용합니다. 코어 제어 루프 변경은 시범 운영 맞춤 범위에 포함하지 않습니다.

### 26번 장표. 제안하는 다음 의사결정

**의사결정 질문:** 검토 조직은 지금 무엇을 승인해야 합니까?

**핵심 메시지:** 적용 모드를 검토하기 전에 명확한 범위, 측정값, 담당자, 정지 조건을 포함한 기준값 워크숍과 관찰 시범 운영을 승인합니다.

**장표 문안:**

**제안하는 약속**

- 승인된 이벤트 집합 하나와 후보 의사결정 유형 하나입니다.
- 읽기 전용 공급자 접근과 합성 데모 데이터입니다.
- 플랫폼, 정책, 보안, 승인, FDAI 유지관리의 책임 담당자입니다.
- 관찰 시작 전 합의한 기준값과 가드레일입니다.
- 관찰 보고서 이후 별도로 검토하는 적용 결정입니다.

**의사결정 선택지**

| 진행 | 보완 | 보류 |
|------|------|------|
| 범위와 담당자가 준비되었습니다. | 기준값, 담당자, 가드레일을 더 정의해야 합니다. | 필수 신원 또는 증거 경계를 충족할 수 없습니다. |

**시각 구성:** 하나의 의사결정 문장 아래에 간결한 3열 선택표를 배치합니다. 일반적인 감사 인사가 아니라 제안 워크숍 날짜와 담당자로 끝냅니다.

**준비할 근거:** 워크숍 헌장 초안, 참석 역할, 데이터 요청, 관찰 시범 운영 종료 기준을 준비합니다.

**발표자 노트:** 요청하는 결정은 관찰 모드에서 측정할 권한이며 자율 변경을 활성화할 권한이 아닙니다.
