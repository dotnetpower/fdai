# FDAI 제안서 덱 키트

이 키트는 FDAI 이야기를 의사결정 중심의 제안서로 구성합니다. 클라우드 운영 모델을 바꿔야 하는 이유, 15개 에이전트가 고정된 안전 경계 안에서 협업하는 방식, 첫날부터 변경 권한을 열지 않고 FDAI를 도입하는 방법을 설명합니다.

> **제안서 제목:** Forward Deployed 에이전트: 에이전트가 스스로 운영하는 자율 클라우드 플랫폼
>
> **대상:** FDAI 시범 운영을 검토하는 기술 경영진, 클라우드 플랫폼, SRE, 보안, FinOps, 거버넌스 조직입니다.

제안서는 하나의 고정된 목차를 따릅니다. 고객용 변형에서도 다음 섹션 이름과 순서를 유지하세요.

1. 클라우드 운영은 왜 바뀌어야 하는가

4. 15 에이전트 소개

6. 운영 시나리오
7. 사람이 개입하는 순간
8. 운영 자동화 영역
9. 기대 효과
10. 데모
11. 도입 방법

## 제안서 콘텐츠 원칙

- **운영 의사결정부터 설명**: FDAI 기능을 소개하기 전에 현재 운영 제약을 설명합니다.
- **실측 결과와 목표를 구분**: 자동화율, 장애 처리 시간, 비용 절감, 변경 리드 타임은 기준값을 확보하기 전까지 시범 운영 측정 항목으로 제시합니다.
- **권한 분리를 보이기**: Forseti는 판단하고, Thor는 배분하며, Var는 사람 승인을 전달하고, Vidar는 복구하며, Saga는 감사합니다. 하나의 주체가 판단, 승인, 실행, 증거를 함께 소유하지 않습니다.
- **안전한 기본값을 제시**: 새 기능은 관찰 모드에서 시작합니다. 불확실하거나 근거가 부족하거나 승인 채널을 사용할 수 없으면 변경을 실행하지 않습니다.
- **일반화된 근거 사용**: 합성 이벤트, 리소스, 스크린샷, 식별자만 사용합니다. 이 저장소에 고객 데이터를 넣지 않습니다.

## 고객 워크숍 입력

제안서를 조정하기 전에 다음 입력을 수집합니다.

| 입력 | 사용하는 장표 |
|------|---------------|
| 반복되는 운영 이벤트 상위 세 가지 | 문제 정의와 데모 시나리오에 사용합니다. |
| 현재 승인 및 롤백 경로 | 사람 개입과 안전 계약에 사용합니다. |
| 현재 SLO, 변경, 비용 기준값 | 기대 효과와 시범 운영 측정에 사용합니다. |
| 읽기 전용 후보 범위 | 첫 도입 단계에 사용합니다. |
| 정책, 플랫폼, 보안 책임 담당자 | 담당 체계와 적용 모드 전환 검토에 사용합니다. |

고객별 값은 추적되는 덱 원고 밖에서 관리합니다. 승인된 전달용 사본에만 입력하세요.

## 품질 확인

제안서를 게시하기 전에 다음 항목을 확인합니다.

1. 모든 목차 섹션이 명확한 의사결정 결과를 갖는지 확인합니다.
2. 15개 에이전트 이름과 역할이 pantheon 원본과 일치하는지 확인합니다.
3. 측정하지 않은 효과를 가설 또는 시범 운영 목표로 표시합니다.
4. 모든 조치 예시에 정지 조건, 롤백, 영향 범위 제한, 드라이런, 잠금, 재시도 키, 감사 기록이 포함되는지 확인합니다.
5. 변경 적용을 제안하기 전에 관찰 모드를 거치는지 확인합니다.
6. 문서 문장부호, 번역, 링크 검사를 실행합니다.
