# FDAI L100 덱 키트

이 키트는 30장짜리 FDAI 소개 덱(L100)의 문서 원본입니다. 발표 파일이 아니라,
발표자나 디자이너가 슬라이드로 옮기기 위한 장표별 설계서입니다. 누가 발표하든
같은 스토리, 같은 근거, 같은 안전성 주장으로 전달되도록 하는 것이 목적입니다.

이 키트는 세 가지 제약을 기준으로 만들어졌습니다.

- **고객 아웃컴이 먼저입니다.** 덱은 구성도가 아니라 고객이 이미 겪고 있는 운영
  현실로 시작합니다. 모든 장표는 고객이 얻는 결과를 담습니다.
- **에이전트 주도 운영 전환입니다.** FDAI는 감지, 판단, 조치, 증명 루프를 상시로
  돌리는 에이전트 조직입니다. 덱은 무엇이 에이전트로 넘어가고, 무엇이 사람에게
  남으며, 어떤 경계가 그것을 안전하게 만드는지 설명합니다.
- **변경 최소화로 반복 가능한 딜리버리를 만듭니다.** 덱은 제품에서 고정되는 것과
  고객마다 교체되는 것을 명시합니다. 그래서 딜리버리가 별도 개발 프로젝트가 아니라
  온보딩 절차가 됩니다.

## 이 키트를 사용하는 방법

1. 장표 지도, 시간 배분, 커스터마이즈 규칙은 이 페이지에서 확인합니다.
2. 만들려는 장표가 포함된 막(act) 파일을 엽니다. 각 장표는 핵심 메시지, 밀도,
   본문 구성, 비주얼 지시, 스피커 노트, 근거 문서로 이루어진 카드 한 장입니다.
3. [고객마다 바꾸는 자리](#고객마다-바꾸는-자리)에 정리된 슬롯만 채웁니다. 나머지는
   작성된 그대로 두어야 덱이 재사용 가능한 상태로 유지됩니다.

| 막 | 장표 | 역할 |
|----|------|------|
| [1막 - 왜 지금이고 FDAI는 무엇인가](l100-act1-why-ko.md) | 1-10 | 통증을 합의한 뒤 FDAI와 에이전트 주도 아키텍처를 정의 |
| [2막 - 어떻게 동작하고 무엇을 얻는가](l100-act2-how-ko.md) | 11-21 | 제어 루프, 안전 경계, 세 가지 버티컬, 데모 |
| [3막 - 도입, 딜리버리, 측정](l100-act3-adopt-ko.md) | 22-30 | 운영 모델 전환, 딜리버리 키트, 온보딩, 다음 단계 |

## 장표 밀도

각 장표 카드는 밀도를 선언합니다. 간결한 장표와 상세한 장표가 우연이 아니라
의도적으로 섞이도록 하기 위해서입니다.

| 밀도 | 의미 | 장표당 시간 |
|------|------|-------------|
| `간결` | 메시지 하나, 텍스트 최소, 발표자가 끌고 감 | 30-45초 |
| `표준` | 불릿 3-5개 + 비주얼 하나 | 60-90초 |
| `상세` | 표 또는 계층 다이어그램, 읽고 다시 보게 만드는 장표 | 2-3분 |

상세 장표는 밀도가 높아도 됩니다. 배포 자료(leave-behind)를 겸하므로, 발표를 듣지
않은 사람이 읽어도 이해되어야 합니다.

## 시간 배분

| 구간 | 장표 | 45분 세션 | 30분 세션 |
|------|------|-----------|-----------|
| 오프닝과 통증 | 1-5 | 8분 | 6분 |
| 정의와 에이전트 주도 아키텍처 | 6-10 | 9분 | 6분 |
| 제어 루프와 안전 경계 | 11-16 | 9분 | 5분 |
| 버티컬 | 17-19 | 5분 | 3분 |
| 데모와 콘솔 | 20-21 | 6분 | 5분 |
| 운영 전환과 딜리버리 | 22-26 | 7분 | 3분 |
| 측정, 적합성, 질문, 다음 단계 | 27-30 | 5분 | 2분 |

30분 버전에서는 9, 16, 25, 28번 장표를 빼고 17-19번을 아웃컴 한 장으로 합칩니다.
13, 14, 22번은 어떤 버전에서도 유지합니다. 안전성 스토리와 역할 전환을 담고 있고,
이 둘은 모든 청중이 반드시 묻는 질문이기 때문입니다.

## 청중

이 덱은 혼합 청중을 대상으로 하며, 첫 영업 대화에도 그대로 사용할 수 있습니다.

| 청중 | 덱에서 필요한 것 | 담당 장표 |
|------|------------------|-----------|
| 운영과 플랫폼 리더십 | 반복 업무가 어디로 가는지, 팀에 무엇이 바뀌는지, 시작 비용 | 3, 10, 22, 26, 30 |
| SRE와 플랫폼 엔지니어 | 제어 루프, 티어, 안전 계약, 롤백과 감사 | 11-16, 21 |
| 보안과 아키텍처 검토자 | 권한 분리, 단일 작성자 소유권, 아이덴티티 경계 | 7, 9, 15, 23 |
| 구매와 사업 스폰서 | 측정 가능한 아웃컴, 가드 지표, 도입 경로, 반론 대응 | 17-19, 27, 29, 30 |

## 자산 슬롯

덱은 고객별 미디어를 위한 고정 슬롯을 둡니다. 슬롯 정의는 덱에 남고, 미디어 자체는
남지 않습니다.

| 슬롯 | 장표 | 규격 |
|------|------|------|
| 데모 동영상 | 20 | 4-6분, MP4, 소리 없이도 이해 가능, 한국어 자막 삽입, 자동 재생 끔 |
| 데모 대체 스틸 | 20 | 재생 실패 시 같은 스토리를 전달하는 이미지 3장 |
| 콘솔 스크린샷 | 21 | 화면 4개: 결정 상세, 승인 대기, 감사 기록, 담당 체계 뷰 |
| 표지 배경 | 1 | [nebula-2000x1125.png](nebula-2000x1125.png) 또는 고객 중립적인 브랜드 배경 |

스크린샷과 동영상은 데모 데이터만 사용합니다. 실제 테넌트 이름, 구독 식별자, 리소스
이름, 엔드포인트, 사용자 아이덴티티는 덱에 절대 들어가지 않습니다.

## 고객마다 바꾸는 자리

딜리버리마다 바뀌는 것은 아래 슬롯뿐입니다. 나머지는 한 번 검토하면 되는 제품
수준 콘텐츠입니다.

| 슬롯 | 장표 | 채우는 내용 |
|------|------|-------------|
| 통증 인용 | 3 | 사전 인터뷰에서 확보한 한두 문장 |
| 베이스라인 표 | 3, 27 | 고객의 현재 측정값, 아직 없으면 공란 |
| 버티컬 순서 | 17-19 | 고객이 밝힌 우선순위에 맞는 버티컬을 먼저 배치 |
| 데모 시나리오 | 20 | 고객 환경과 가장 가까운 시나리오 |
| 파일럿 범위 | 26 | 첫 관찰 모드 실행 대상 구독, 리소스 그룹, 워크로드 |
| 다음 단계 담당자 | 30 | 실명과 날짜 |

## 덱에 절대 넣지 않는 것

- 고객 식별자, 테넌트 값, 엔드포인트, 구독 식별자.
- 짝지어 측정한 베이스라인 없이 만든 성능이나 절감 수치. 12번 장표의 커버리지
  숫자는 목표치로만 표기하며 결과로 제시하지 않습니다.
- 안전성 검토, 승인 경로, 롤백 경로 없이 FDAI가 조치한다는 식의 주장.
- 경쟁사 실명 비교.
