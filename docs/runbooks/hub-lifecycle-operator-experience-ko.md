# Hub 운영 경험 개선 사항

다음 Release Hub와 Lifecycle Hub 운영 흐름을 설계할 때 이 개선 목록을 사용하세요.
독립적인 신뢰 확인, 고객 승인과 설치 내부 실행 경계는 유지하면서 불필요한 수작업을 줄입니다.

> **범위:** 절차와 소스에 근거한 설계 검토입니다. 전체 시각·접근성 검사는 아닙니다.
> 아래 제안은 이미 제공되는 기능이나 배포 승인이 아닙니다.
> 실제 대상 식별자와 운영 근거는 고객이 관리하는 비공개 기록에 보관합니다.

## 이 문서의 범위

반복 운영 순서는 게시, 검토, 수락, 입력 준비, 계획, 실행, 관찰과 복구입니다.
운영자는 끝난 일, 막힌 일, 다음 담당자와 작업할 위치를 볼 수 있어야 합니다.
완성된 것처럼 보이는 화면 뒤에 엔지니어의 콘솔 조작, 파일 전송이나 실행되지 않는 Agent를 숨기지 않습니다.

P1은 안정적인 안내형 시험을 막는 항목입니다. P2는 반복 운영의 수고를 줄이는 항목입니다.
이 우선순위는 운영 흐름에 관한 것이며 보안 취약점의 심각도가 아닙니다.

## 제공된 항목의 상태

- UXH-01/02/04/05/07/09/10/11/12/13/14/15, 고객 및 공급자 준비·복구 개선(#2532 / #2534 / #2535):
  Release Hub는 트랜잭션 단위 단계 승격(`POST /v1/releases/{id}/promote`), 활성 기능 회수 차단
  표시, 수동 문자열 입력을 없앤 확인 문구 자동 입력을 추가했습니다. Lifecycle Hub는 `AsyncBoundary`의
  유형별 오류 복구 안내, 통합 업데이트 준비 상태 및 다음 단계 패널, 3단계 시간 경계 요약(환경 기준
  시각, 일일 실행 일정, 계획 유효성), 실패·보류·복구 타임라인, 저장된 메타데이터와 검증된 패키지
  서명을 구분하는 Configuration 탭, 작동하는 Commands 및 해시 체인 Audit 화면, 영문·한국어 작업 영역
  전환을 제공합니다.
- UXH-02/04/16, 범위가 제한된 복구: 카탈로그 오류는 임의의 서버 진단을 표시하지 않으면서
  세션 만료, 접근 차단, 충돌, 준비 상태 문제와 시간 초과를 구분합니다. 쓰기가 실패하거나 결과가
  불확실하면 대화상자를 닫고 원본 카탈로그를 조회한 뒤 새 확인을 제공합니다. 조회 실패 시
  쓰기를 차단합니다. HTTP 응답이 성공해도 조회 결과에 정확한 개정 번호, 동작, 대상, 목적지와
  사유가 있는 이벤트가 없으면 변경이 확인되었다고 표시하지 않습니다. 새로 고침은 쓰기를 재실행하지 않습니다.
- UXH-06: 개발용 카탈로그에서는 서명된 내보내기, 방향이 고정된 조회, Rego 정책 채택, **Updates**
  화면으로 리비전과 다이제스트를 옮겨 적는 일이 사라졌습니다. 기존 고정값 흐름은 서명되지 않은
  내보내기와 오프라인용으로 남습니다. 운영용 TUF 역할은 아직 설계 단계입니다.
- UXH-08: `fdai-lifecycle-hub sign-enrollment`와 연결된 설치본 선택으로 파일 경로와 ID를
  옮겨 적는 일이 사라졌습니다. `fdai-lifecycle-agent enroll`은 운영자가 파일을 옮기는 일도
  없앱니다. Agent가 자기 클러스터에서 Entity와 보고 상태를 도출해 승인 대기 요청을 제출하고,
  운영자는 키 ID를 별도 경로로 대조한 뒤 승인합니다. native 증명 전달, 구성 키 보관, 운영 중인
  Hub에 대한 실제 Agent 제출은 열려 있습니다.

### 공급자 화면 개선 범위

Stencil 구현은 보류합니다. 이번 개선은 기존 단일 FDAI Release 작업 영역에 한정되며 기능
카탈로그, 변형, Stencil 사용 허가, 라이선싱 또는 빌드 조정기를 추가하지 않습니다.
설계 가설은 다음 단계 하나와 기본 접기 요소로 경쟁하는 동작을 줄이면서 감사와 정확한 대상
확인을 유지할 수 있다는 것입니다.

설계 비평에서는 브라우저가 채널 소속을 승격 검사 통과로, 요청 수락을 관찰된 변경으로
혼동할 수 있다는 점을 확인했습니다. 수정한 구현은 소속을 기록된 상태로 표시하고, 제공되지
않는 검사 결과는 명시적으로 조회 불가로 남기며, 재조회한 이벤트에서 동작과 사유를 검증합니다.
기존 서버 측 승격 검증기의 원본 채널 소속, 레이블, 카나리, 관찰 시간, 제한 시간과 회수
검사는 바꾸지 않습니다. 수동 채널 편집을 검사가 적용되는 승격으로 이름 붙이거나 표시하지 않습니다.

카탈로그 API는 승격 실행 증적이나 영속적인 빌드·발행 작업 상태를 제공하지 않습니다.
이 항목과 값을 옮겨 적지 않는 발행·승격, 실제 재로그인 복구 및 UXH-16/18의 영속 작업 인계는
#2532의 미완료 범위로 남습니다. 새 필수 승인 단계는 추가하지 않으며 이 결과가 완료되었다고
주장하지 않습니다.

이번 개선의 집중 검증 명령은 다음과 같습니다.

```bash
npm --prefix lifecycle/release-hub/ui test
npm --prefix lifecycle/release-hub/ui run typecheck
npm --prefix lifecycle/release-hub/ui run build
```

실제 Release Hub 경로를 합성 카탈로그 응답으로 검사하며 실제 공급자 발행을 수행하지 않습니다.
데스크톱을 먼저 확인한 뒤 좁은 화면과 모바일을 측정합니다. 인증 공급자 복구와 실제 영속 작업
재개에는 별도 근거가 필요합니다. 제공한 범위와 남은 작업은
[구현 기록](../roadmap-implementation/deployment/lifecycle-releases-and-channels.md)을 참조하세요.
이번 개선은 제품 전체의 UX 점수를 뜻하지 않습니다.

## 이미 잘 되는 부분 재사용

실행 일정과 애플리케이션 지정 양식은 이미 UUID, 현재 Settings digest와 정확한 확인문을
자동으로 만듭니다. 운영자가 기계 값을 계산하게 만들지 말고 이 방식을 재사용하세요.
새로고침·재조회와 쓰기 동작도 계속 구분합니다.

**Refresh catalog**, **Renew catalog freshness**, **Approve exact pin**과
**Import approved catalog**도 분리합니다. 각각 다른 일을 합니다.
안내 흐름으로 연결할 수는 있지만 import나 다운로드가 스스로 권한을 얻도록 만들지 않습니다.

|---------------------|-------------|
| 공개 준비 기록 생성과 독립적으로 얻은 fingerprint 비교 | 설치 신원과 native 소유권 범위 수락 |
| 서명된 입력 전송, 정확한 바이트 검증과 원자적 준비 | 서명 신뢰 설정과 고객 설정 승인 |
| 승인한 불변 이미지의 미러링·검증 | 레지스트리 경계와 소스 적격성 승인 |
| 차단 이유 설명과 UUID/digest/확인문 생성 | 행위자를 기록하는 작업과 정확한 영향 확인 |
| 제한된 Agent 실행 예약과 독립 재조회 수집 | 실행 범위, 유지보수 시간대와 예외 복구 승인 |
| 정리·유지 기록과 알림 생성 | 자원 유지 기간과 suppression 해제 결정 |

TLS나 인증을 끄거나, 모든 출발지 IP를 허용하거나, 관리자·Graph 권한을 부여하거나,
다운로드한 키·pin을 자동 수락하거나, 영속 신원을 초기화하거나, 정상 Pod를 운영 성공으로
간주하는 방식으로 문제를 해결하지 않습니다.

## 다음 설계의 검증 범위

현재 상호작용 공백을 확인할 소스는 다음과 같습니다.

- [공통 Hub 인증](../../lifecycle/hub/ui/src/auth.ts): 조용한 token 획득과 일반적인 실패
  표시를 사용합니다. 복구 설계 공백을 보여 주지만 모든 데이터 조회 실패의 원인을 입증하지는 않습니다.
- [데이터 조회 경계](../../lifecycle/hub/ui/src/components/async-boundary.tsx):
  하나의 일반적인 제목과 재시도 동작을 사용합니다.
- [설치 상세](../../lifecycle/hub/ui/src/routes/installation.tsx):
  제약, Entity, 일정과 앱 패널이 나뉘며 Configuration은 아직 사용할 수 없습니다.
- [탐색 메뉴](../../lifecycle/hub/ui/src/components/nav.tsx): 예정된 기능 일부가 아직 동작하지 않습니다.
- [운영 안내](hub-lifecycle-operator-guide-ko.md): 준비, 입력 전송과 유한 Agent 일정은
  하나의 정식 설치기로 묶여 있지 않습니다.

실제 재설계에는 [UI/UX 기준표](../reference/ui-ux-quality-rubric-ko.md)를 사용하세요.
이 목록은 정보, 상태 명확성과 복구를 다루며 점수를 매긴 시각 검토는 아닙니다.
데스크톱 배치, 키보드 조작, 좁은 화면·모바일, 실제 재로그인 복구와 고객의 작업 완료는
이 문서에서 측정하지 않았습니다.

완료를 선언하기 전에 관련 영문·한국어 경로와 조회 중, 사용 불가, 권한 차단, 만료,
쓰기 결과 불분명, 복구와 재개 상태를 검증하세요. 시나리오마다 `passed`, `failed`,
`needs-human` 또는 `needs-infrastructure`를 기록합니다. 시험하지 않은 상태는 통과가 아닙니다.
데스크톱부터 확인한 후 해당하는 반응형 변경을 검증합니다.
