# GitHub 지식 소스 연결

지식 > GitHub에서 GitHub 저장소 하나를 검증된 읽기 전용 지식 소스로 연결할 수 있습니다.
연결은 코드 보안 스캔, 저장소 쓰기, 검색 가능한 문서 수집을 승인하지 않습니다.

## 설계 한눈에 보기

Owner는 기존 저장소 변경 발신함으로 형식화된 연결 요청을 제출합니다.
Core는 GitHub API로 저장소 메타데이터, 정확한 커밋, 크기가 제한된 README 바이트를
검증한 뒤 소스의 출처 정보를 저장합니다. 같은 저장소에 나중에 별도의 Owner 스캔
권한을 부여할 수 있습니다. Operator는 저장된 레코드를 읽으며 GitHub 자격 증명을 보유하지 않습니다.

## 권한 검토

초기 제안은 스캔을 활성화하는 등록 기능을 재사용했습니다. 그러면 지식 읽기 권한이
스캔 동의로 잘못 바뀝니다. 수정된 계약은 새 지식 소스를 비활성 등록으로 만듭니다.
기존 등록에 연결할 때는 별도로 부여된 스캔 권한을 유지합니다. 지식 연결 해제는 지식
접근만 철회하며 별도로 부여된 스캔 권한은 철회하지 않습니다.
소스는 저장소나 자격 증명 참조를 알림 없이 바꿀 수 없습니다.

버전 검사, 안전하게 재시도할 수 있는 요청 식별자(멱등성), 상태와 감사의 원자적 저장으로
연결 변경을 보호합니다. 공급자 검증이 실패하면 기존 레코드는 그대로 유지됩니다.
대기 중인 요청은 검증된 연결이 아닙니다. 새로 고침으로 적용된 상태를 확인하세요.

## 접근 구성

- **공개 접근:** 익명 공개 접근을 선택합니다. FDAI는 토큰을 발급받지 않으며 저장소가
  비공개라는 공급자 응답을 차단합니다.
- **비공개 접근:** 배포 GitHub App 참조를 선택합니다. 기존
  `FDAI_GITHUB_APP_CLIENT_ID`, `FDAI_GITHUB_APP_INSTALLATION_ID`,
  `FDAI_GITHUB_APP_PRIVATE_KEY`를 배포에서 관리하는 비밀 주입으로 구성합니다.
  Console에 키나 토큰을 입력하지 마세요. 토큰 공급자는 저장소 하나에 대해
  `contents: read`와 `metadata: read`만 요청합니다. 호환용 `FDAI_GITOPS_TOKEN`은
  이 연결에서 허용되지 않습니다.
- **공급자 주소:** 어댑터는 `FDAI_GITOPS_API_BASE`를 사용하며, 없으면 기본 GitHub API를
  사용합니다. 전체 기한, 요청별 시간 제한, 응답 바이트 제한이 적용됩니다.
  리디렉션과 자동 재시도는 하지 않습니다. 호출 제한, 인증 실패, 잘못된 응답,
  README 부재는 명시적인 요청 실패로 나타납니다.

## 연결 및 재사용

1. 지식 > GitHub를 열고 별칭, `owner/repository`, 자격 증명 참조를 입력합니다.
   인증된 Owner만 제출할 수 있습니다.
2. 대기 중인 요청이 완료되면 새로 고침합니다. 소스에서 관측된 정확한 커밋,
   README 다이제스트, 관측 시각, 독립된 스캔 권한 상태를 확인할 수 있습니다.
3. 스캔이 필요하면 코드 보안을 열고 해당 별칭의 스캔을 명시적으로 활성화합니다.
   연결하거나 소스를 보기만 해서는 스캔이 활성화되거나 실행되지 않습니다.

연결기는 현재 기본 브랜치와 README를 검증합니다. 저장소 전체 목록, 지속적인 동기화,
색인된 인용, 관측 시점 이후의 최신성, 스캔 완료를 주장하지 않습니다.
검색 가능한 문서 수집에는 기존 에이전트 소유의 문서 허용 및 색인 절차가 적용됩니다.
