# 클라우드 리소스 지식 운영

이 절차로 검토된 공개 클라우드 문서를 수집하고, 서명된 데이터 전용 패키지를 검사하며,
새 지식 세대를 기존 FDAI 문서 승인 경로에 제출합니다. 수집, 패키지 검증, 반입은
승인 및 검색 활성화와 별개입니다.

> **범위:** 소프트웨어는 범위가 제한된 Azure 출처 컬렉션과 완전한 JSON 패키지를 지원합니다.
> 수집을 활성화하기 전에 출처 이용 권한, 운영용 서명 신뢰, 내부 검토자, 배포 구성을
> 준비하세요. 로컬 테스트가 이러한 승인이나 운영 배포를 대신하지 않습니다.
>
> **구조화 구현:** 원본을 제외한 v2가 기본값입니다. 명시적으로 선택하는 v3가 구현되어 있으며,
> 원문 품질 검증, 독립적인 답변 검토 및 운영 배포는 별도로 남습니다.

## 요청자 적용: 목표와 현재 운영

[목표 흐름](../roadmap/interfaces/cloud-resource-knowledge-lifecycle-ko.md#요청자-직접-적용-목표)은
문서마다 다른 승인자를 지정하지 않고, 승인된 정책 안에서 적격 요청자가 참조 내용을 직접
적용하는 방식입니다. 준비 단계에서 업로더를 알아야 할 필요는 없으며 실제 반입 요청에서
인증된 신원을 기록합니다. 요청 전에도 내용 검토를 시작할 수 있지만 그 자체로 런타임 승인
권한을 부여하지는 않습니다.

이 정책 기반 적용 경로는 **미구현**입니다. 아래 절차는 현재 수동 경로를 설명하며, 모든 미래
갱신에서 다른 사람을 미리 확보해야 한다는 영구 조건은 아닙니다. `Reader`, 반입 성공 또는
패키지 서명을 활성화 권한으로 바꾸는 지원 설정은 없습니다. 목표 동작을 흉내 내기 위해
역할을 바꾸거나 승인 필드를 위조하거나 Var를 비활성화하지 마세요. 구현과 독립적인 승격
이후 적격 요청은 수동 대기 없이 진행하되, 검사, 정책 재검증과 독립적인 색인 완료 검증을
유지해야 합니다.

## 선행 조건

- **서비스:** 기존 Core, Operator, 수집 API, 문서 작업자를 서비스별 데이터베이스 역할과
  정상 문서 이벤트/승인 연결로 실행합니다. 새 서비스는 필요하지 않습니다.
- **스키마:** 정상 배포 절차로 수집 서비스의 `cloud_knowledge_20260914`와 작업자의
  `cloud_knowledge_lexical_20260914` 마이그레이션을 적용합니다.
- **출처:** `SourceRegistryRevision`의 정확한 URL, 컬렉션, 리소스 적용 조건, 라이선스,
  저장/전달 권한, 갱신 주기, 만료를 독립적으로 검토합니다. `azure_network_sources()`는
  비활성 상태의 APIM, VNet, NSG, Private DNS 시작 템플릿을 제공합니다.
- **신뢰:** `KnowledgeTrustPolicy`에 독립적으로 승인한 Ed25519 공개 키와 최신 철회
  근거를 준비합니다. 검사 대상 패키지에서 초기 신뢰를 얻지 않습니다.
- **현재 수동 경로의 검토자:** 요청자와 승인자는 서로 다른 신원이어야 합니다. 기존 Approvals 화면에서
  Var 결정을 전달하며, 업로더는 자신의 내용을 승인할 수 없습니다.
- **검사기:** 정상적인 복제본 내부 ClamAV 서비스와 최신 탐지 데이터를 준비합니다.
  클라우드 참조 검사와 활성화에는 7일 미만의 탐지 데이터베이스가 필요합니다.

## 참여 서비스 구성

다음 값은 배포 구성이며 고객 값을 넣는 소스 코드 예제가 아닙니다. 독립적으로 검토한
정책 파일을 읽기 전용으로 연결하고 상위 디렉터리도 보호하세요.

| 설정 | 서비스 | 의미 |
|------|--------|------|
| `FDAI_CLOUD_KNOWLEDGE_REGISTRY_PATH` | 수집 API, 작업자, Core | 같은 검토된 출처 레지스트리 개정의 경로 |
| `FDAI_CLOUD_KNOWLEDGE_TRUST_PATH` | 수집 API, 작업자, Core | 독립적으로 관리하는 서명 신뢰와 철회 근거 |
| `FDAI_CLOUD_KNOWLEDGE_FORMAT` | 수집 API | 기본값은 `v2`이며 명시적 `v3`는 구조화 형식만 선택합니다. 신뢰, 승인 또는 활성화를 부여하지 않습니다. |
| `FDAI_CLOUD_KNOWLEDGE_NORMALIZER_VERSION` | 수집 API | 기본값은 `2.0.0`입니다. 명시적 `2.1.0`에는 `v3`와 호환 판독기 `3.1.0`이 필요하며 알 수 없거나 호환되지 않는 값은 시작 단계에서 차단합니다. |
| `FDAI_DOCUMENT_COLLECTIONS` | 수집 API | 등록한 모든 지식 컬렉션 포함 |
| `FDAI_DOCUMENT_RETRIEVAL_MODE` | 수집 API, 작업자 | `lexical`은 임베딩 생성과 시작/질의 점검 호출을 피하며, `hybrid`는 기존 기본값 유지 |
| 기존 `FDAI_RCA_DOCUMENT_*` 설정 | Core | 승인된 문서 컬렉션/읽기 저장소를 의미 대화에 연결 |

지식 정책 경로가 둘 다 없으면 기능을 사용 불가로 표시합니다. 하나만 있거나 정책이
잘못되면 구성에 실패합니다. 출처 레지스트리가 바뀌면 연결을 다시 로드해야 합니다.
신뢰와 읽기/활성화 정책은 클라이언트 메타데이터를 믿지 않고 다시 검증합니다.
어느 설정도 리소스 실행 권한을 주거나 문서 검사, 접근, 승인 경계를 바꾸지 않습니다.

선택한 빌드에서 수집기, API/CLI, 작업자 및 Core 읽기 경로의 호환성을 확인한 뒤에만 범위가
제한된 후보에 `FDAI_CLOUD_KNOWLEDGE_FORMAT=v3`를 선택하세요. 이 설정은 보존된 v1/v2 기록을
이행하거나 세대를 활성화하거나 실제 출처/모델 호출을 승인하지 않습니다. 본문 블록, 인용문
파생 및 별도 검색어 검증은 [구조화 설계](../roadmap/interfaces/cloud-resource-knowledge-structured-rag-ko.md)에서
다룹니다.

망분리 환경에서는 모든 출처를 `offline`으로 유지하고 문서 검색을 `lexical`로 설정합니다.
네트워크 경계에서도 공용 DNS/HTTP 통신을 차단하세요. 지식 코덱, 색인 생성, 검색은 모델을
다운로드하거나 만들어 낸 벡터로 대체하지 않습니다. 다른 제품 기능은 자신의 연결 요구사항을
별도로 유지합니다.

## 연결 환경의 수집과 검토

1. **지식 > 전체 현황 > 클라우드 참조 지식 > 원본 상태**에서 출처 정책과 기록된 상태를
   확인합니다. 출처는 비활성 상태로 시작하며, 저장 권한은 명시적으로 승인해야 합니다.
   설정이 완료되지 않았으면 Console에서 정책 파일을 받지 않고 배포에서 관리하는 레지스트리,
   신뢰 및 서비스 연결 사전 조건을 표시합니다.
2. Owner는 **기한이 도래한 원본 확인**을 선택할 수 있습니다. 매일/시작 시 예약 수집도
   같은 작업을 사용하며, 모든 문서가 아니라 주기가 지난 활성 온라인 출처만 확인합니다.
3. 출처별 수집 날짜, 마지막 성공 확인, 최근 시도, 누락, 대기 중인 변경을 검토합니다.
   실패는 원본 경과 시간을 갱신하지 않습니다. HTTP 429/503은 해당 수집 실행을 중단합니다.
4. 컬렉션을 펼쳐 **서명 전 검토 매니페스트**를 내려받거나 완전한 수집 개정본을 검토에
   제출합니다. 일부 수집 실패를 숨기기 위해 매니페스트 범위를 줄일 수 없습니다.
5. 현재 수동 경로에서는 검사, 독립 사람 승인, 색인 생성 단계를 추적합니다. **수집 요청됨**은
   수신을 뜻하며 활성화를 뜻하지 않습니다. 기존 문서 경로가 진행 상태를 소유합니다.
  색인 검증 대기 중에는 사용할 수 없습니다. 별도 읽기 전용 데이터베이스 관측으로
  봉인된 원문과 전체 조각 집합이 일치하는지 확인한 뒤 조건부 공개를 성공으로 기록합니다.
6. 기록된 상태를 다시 로드하여 의도한 활성 버전과 출처 인용을 확인합니다. 런타임 준비도나
   애플리케이션/데이터베이스 성공은 실제 Azure 리소스를 관측한 결과가 아닙니다.

변경 없는 원본 확인은 활성 문서를 교체하거나 다시 임베딩하지 않고, 변경할 수 없는
확인 이력과 같은 본문의 현재 읽기 결과를 갱신합니다. 새 본문은 별도 후보로 남습니다.
운영 기본값은 7일 확인과 최대 30일 미확인 기간이며, 검토 후 참조 프로필에는 30일 확인과
최대 90일 기간을 사용할 수 있습니다.

## 네트워크 없이 보관 원문 준비

새 릴리스를 제안하기 전에 설치된 `fdai_ingestion_api_service.cloud_knowledge.review` 모듈로
기존 수집기 파일을 점검할 수 있습니다. 이 명령은 수집, 서명, 승인, 색인 쓰기 또는 모델 호출을
수행하지 않습니다. 필요한 외부 통신 차단은 운영체제에서 적용해야 합니다. 명령 자체는 호스트
네트워크를 바꾸거나 운영 환경의 격리를 증명하지 않습니다.

스키마 `fdai.cloud-knowledge-review.v1`과 `sources` 배열을 가진 UTF-8 JSON 입력을 준비하세요.
각 항목에는 보존된 정확한 `CloudSourceEvidence`를 `evidence`로 넣고 `title`, 선택한 원문
루트 기준의 `original_path`와 `normalized_path`를 지정합니다. 기존 관측을 보존하고 현재
시각이나 만들어 낸 이용 권한을 넣지 않습니다. 경로는 길이가 제한된 정규 POSIX 이름이며 상위
디렉터리나 심볼릭 링크·하드 링크를 따라갈 수 없습니다. 계획은 원본을 참조할 뿐 포함하지 않습니다.

```bash
python -m fdai_ingestion_api_service.cloud_knowledge.review \
  --input /private/review-input.json --source-root /private/retained \
  --output /private/new-review --normalizer-version 2.1.0 \
  --per-source-seconds 30 --total-seconds 900
```

경로는 자리표시자입니다. 입력·출력의 상위 디렉터리는 미리 준비하고 출력 디렉터리는 새 경로로
지정하세요. 명령은 기존 근거를 덮어쓰지 않는 비공개 파일을 만듭니다. 정규화에 성공한 원문마다
원본을 제외한 구조화 후보를 보존하며, 명시적인 구조 또는 인용문 크기 보류가 있는 후보도
포함합니다. 정규 `report.json`은 정확한 입력 해시, 후보 해시, 처리 식별자, 기존 날짜, 바이트
집계 및 전체 원문 범위를 결속합니다. 입력 실패와 기한 만료도 보류 또는 미처리 행으로 남으며
측정하지 못한 값은 알 수 없음으로 표시합니다.

| 경계 | 상한 |
|---|---|
| 입력 계획 / 원문 수 | 2 MiB / 256 |
| 원본 또는 정규화 파일 각각 / 누적 원문 바이트 | 8 MiB / 64 MiB |
| 후보 각각 / 누적 후보 바이트 | 16 MiB / 64 MiB |
| 자식 프로세스 전송 출력 / 주소 공간 / CPU | 32 MiB / 768 MiB / 30초 |
| 원문별 처리 / 전체 처리 | 30초 / 900초 |

자식 프로세스는 정규화와 전체 인용문 측정을 함께 제한합니다. 진행 상황은 원문이 아니라 건수만
표시합니다. 기한을 넘긴 후보는 성공으로 게시하지 않습니다. 출력 입출력 실패는 실행을 종료하며
진단을 위해 부분 파일을 남깁니다. 네트워크 마운트가 아닌 로컬 일반 저장소를 사용하세요.
처리 기한은 응답하지 않는 파일시스템 호출까지 강제로 종료하는 제한은 아닙니다.

종료 코드 `0`은 선언된 모든 원문이 구조상 처리 가능함을, `1`은 전체 보고서에 보류·미처리가
있음을, `2`는 최상위 입력 오류 또는 출력 실패를 뜻합니다. `0`이어도 이용 권한, 독립 검토,
운영 검증 및 실행 권한은 false로 유지합니다. 후보와 보고서는 바로 반입할 수 있는 릴리스
매니페스트가 아닙니다. 선언된 범위를 독립 검토에 유지하고 이후 기존 통제 제작·서명 경로를 사용하세요.

## 서명된 오프라인 패키지 준비

기본 v2 검토 매니페스트는 정확한 정규화 UTF-8 텍스트, 출처별 원본/정규화 해시,
수집/확인 시각, 적용 조건, 라이선스 참조, 전체 컬렉션 식별 정보를 포함합니다.
v3 형식은 원본이 아니라 본문 블록과 봉인된 인용문 다이제스트를 추가합니다. 원본
HTML/Markdown은 수집기 재개 지점에 보존하며 새 내보내기, 패키지, 수집 제출, 롤백 후보에
넣지 않습니다. 최대 16 MiB 제한을 유지하며 ZIP/TAR, 스크립트, 플러그인, 모델 가중치,
데이터베이스 덤프를 받지 않습니다. 큰 출처 목록은
검증되지 않은 압축 파일 대신 각각 검토한 제한된 컬렉션으로 나누세요.

기본 패키지는 `fdai.cloud-knowledge-package.v2`, 매니페스트 `fdai.cloud-knowledge.v2`, 읽기
버전 `2.0.0`을 사용합니다. 명시적으로 선택하는 v3는 `fdai.cloud-knowledge-package.v3`,
`fdai.cloud-knowledge.v3`를 사용합니다. 정규화기 `2.0.0`에는 읽기 버전 `3.0.0`을 사용하고
문서 하나라도 `2.1.0`이면 읽기 버전 `3.1.0`을 사용합니다. 이전 판독기는 새로운 표현을 처리할 수 없습니다.
API/CLI와 작업자를 함께 업그레이드하고 전달 전에 전체 읽기 경로를 확인하세요. 보존된 v1/v2
바이트와 서명은 바꾸지 않으며 현재 수용 조건에서 계속 검증/반입할 수 있습니다. 서명된
패키지의 필드를 제거하거나 버전을 바꾸지 말고 검토 매니페스트와 서명을 새로 만드세요.
요건을 충족하는 v1/v2 롤백은 더 높은 순번의 v2 후보를 만들며, v3 롤백은 기존 구조를
보존합니다. 두 경우 모두 이전 매니페스트 다이제스트에 연결하고 출처 근거와 수용 만료를 유지합니다.

수신 측은 포함된 텍스트의 SHA-256과 서명을 검증합니다. 원본 SHA-256은 제작자가 서명한
출처 이력이며 수신 측이 없는 원본의 해시를 다시 계산했다는 뜻이 아닙니다. 검증을 위해
원본을 네트워크로 가져오지 않습니다. 원본을 제외해도 텍스트 저장/전달 조건, 저작자 표시와
변경 고지, 내부 검사, 독립 승인은 유지합니다. [이슈 #995](https://github.com/dotnetpower/fdai/issues/995)의
미해결 미디어, 모호한 표 또는 원문별 필수 문맥도 이 변경만으로 검증되지는 않습니다.

독립적으로 승인된 서명 절차는 정확한 정규 매니페스트 바이트 앞에 ASCII 용도
`fdai.cloud-knowledge.release.v1`과 0 바이트 하나를 붙여 서명합니다. 개인 키는 해당
절차 안에 남습니다. 이 용도는 매니페스트에 서명된 스키마 버전과 별개입니다.
서명은 원시 64바이트 Ed25519 값이며, 매니페스트의 바이트 하나라도
바뀌면 새 서명이 필요합니다.

설치된 수집 배포판에는 오프라인 명령 모듈이 있습니다. `assemble`은 정확한 정규 v2 매니페스트,
또는 호환되는 빌드의 v3 매니페스트와 분리된 서명, 키 식별자, 레지스트리, 신뢰 정책 및 새 출력
경로를 받습니다. 원본 본문 필드, v1 조립, 비정규 입력은 차단합니다. 기록 전에 결과를 검증하고
기존 출력을 덮어쓰지 않습니다. 개인 키를 읽거나 생성하지 않습니다. `inspect`는 반입 없이
완전한 패키지를 검증합니다.

```bash
python -m fdai_ingestion_api_service.cloud_knowledge assemble \
  --input /private/review.json --signature /private/review.sig \
  --key-id approved-knowledge-key \
  --registry /approved/source-registry.json --trust /approved/knowledge-trust.json \
  --output /private/knowledge-package.json

python -m fdai_ingestion_api_service.cloud_knowledge inspect \
  --input /private/knowledge-package.json \
  --registry /approved/source-registry.json --trust /approved/knowledge-trust.json
```

위 경로와 키 식별자는 자리표시자입니다. 검증된 패키지, 출처/라이선스 목록, 변경 요약,
조직의 전달 검토 기록을 승인된 매체로 운반합니다. 키, 자격 증명, 배포 구성, 승인 우회
값을 패키지에 넣지 않습니다.

## 제한된 네트워크 내부의 검사와 반입

1. **지식 > 전체 현황 > 클라우드 참조 지식 > 오프라인 패키지**를 열고 서명된 JSON
   패키지를 선택합니다. 파일 선택은 브라우저 로컬에서만 이루어집니다. 서버가 접수 권한을
   보고한 후에만 **선택한 패키지 검사**를 실행합니다.
2. 원본 날짜와 매니페스트 다이제스트를 확인합니다. **검증된 후보**는 패키지 검증만을
   입증하며, 미리 보기의 도착 시각은 반입 증적이 아닙니다.
3. 검사한 정확한 바이트의 제출을 확인하고 **검사한 패키지를 검토용으로 가져오기**를
   선택합니다. 서버는 바이트와 현재 정책을 다시 검증하고 릴리스 순번을 예약합니다.
4. 현재 수동 경로에서 내부 악성코드 검사와 독립 검토를 완료합니다. 오래된 탐지 데이터,
   신뢰/수용 만료, 정책 불일치, 자기 승인은 진행을 차단합니다.
5. 상태를 다시 로드하고 의도한 문서 세대를 확인합니다. 인용은 저장된 문서 절을 열며,
   외부 원본 URL은 출처 이력이지 자동 네트워크 요청이 아닙니다.

같은 요청자/패키지의 반복 요청은 기록된 업로드를 재사용합니다. 다른 바이트로 순번을
재사용하거나, 더 낮은 순번을 제출하거나, 다른 요청자가 기존 기록을 덮어쓸 수 없습니다.
HTTP 응답을 잃었다고 취소된 것은 아니므로, 다시 요청하기 전에 상태를 로드하세요.
읽기 전용 검사에서 거부된 경우 선택한 로컬 패키지를 유지하므로 수정하거나 다시 시도할 수
있습니다. 검사와 서명되지 않은 매니페스트 내보내기는 접수 전이를 커밋할 수 없으므로 기록된
상태를 다시 불러오지 않아도 됩니다. 갱신, 제출, 롤백 및 반입 실패 시에는 서버가 영속 상태를
커밋했을 수 있으므로 다른 요청 전에 계속 다시 불러와야 합니다.

## 복구와 날짜 해석

- **오래된 패키지:** 반입은 원본 날짜를 보존합니다. 현재 서명이나 최근 반입으로 오래된
  문서를 최신으로 만들 수 없습니다. 과거 설명과 현재 RCA의 사용 가능 여부는 다릅니다.
- **대기 후보:** 생성 실패는 이전 세대를 바꾸지 않습니다. 최종 교체 중 새 세대는 독립
  재조회가 성공할 때까지 사용 불가입니다. 재조회 실패는 최종 감사와 함께 사용 불가로
  격리하며 이전 버전을 자동 복원하지 않습니다. 예상 버전 충돌은 전환을 롤백하고,
  프로세스 종료 후에는 영속 효과 기록으로 재개합니다.
- **롤백:** Owner는 보존된 비활성 버전을 롤백 검토에 제출할 수 있습니다. 새 요청은
  더 높은 순번을 사용하고 원본 날짜와 만료를 보존하며 독립 승인이 필요합니다. 철회된
  내용을 되살릴 수 없습니다. 자동 격리는 이러한 복원을 승인하지 않습니다.
- **신뢰 만료:** 승인된 절차로 독립 신뢰/철회 근거를 갱신합니다. 날짜를 바꾸거나 검증을
  끄거나 패키지가 제공한 키를 반입하거나 시계 검증을 우회하지 않습니다.
- **출처 5회 연속 실패:** 수집기가 추가 시도를 보류합니다. 새 레지스트리 개정을 발행하기
  전에 원인과 승인된 출처 정책을 검토하고, 감사/확인 이력을 지우지 않습니다.
- **전문 이용 권한 없음:** 참조 전용으로 유지하며 전문을 내보내거나 반입하지 않습니다.
- **너무 큰 절:** 기존 v1/v2는 제목으로 구분된 완전한 절과 출처 정보가 8 KiB 이내여야 합니다.
  v3는 필수 문맥을 포함한 크기가 제한된 구조적 인용문을 사용합니다. 지원하지 않거나
  크기를 초과하는 최소 단위가 있으면 내용을 누락하지 않고 세대 전체를 보류합니다.
- **현재 안내:** 특정 확인 시점의 운영 설명에는 정확한 리소스 적용 조건과 최신 출처
  근거가 필요합니다. 실시간 최신 요청은 새 관측 필요 상태를 반환합니다. 답변은 출처
  수집을 시작하지 않으며 반입으로 확인 날짜를 갱신하지 않습니다.

## 검증과 근거

운영 배포 전에 실제 서명 루트, 보안 검토자, 검사기, 서비스 역할, 정책을 사용한 완전한
출처 수집과 외부 통신 차단 상태의 패키지-답변 훈련을 기록합니다. 변조, 재전송, 원본 만료,
신뢰 불가, 중복 작업자, 롤백 사례를 포함합니다. 저장소 테스트의 가상 문서와 테스트 전용
서명 키는 이 운영 증적을 대신하지 않습니다.
OS 네트워크 네임스페이스에서 보관 원문을 처리한 로컬 근거는 기록된 네트워크 제한 아래에서
범위가 제한된 준비를 실행했다는 사실만 입증합니다. 내부 반입, 검토자 신원, 저장된 검색,
이중 언어 답변 품질, 서명 신뢰 또는 배포된 네트워크 정책을 증명하지는 않습니다.
