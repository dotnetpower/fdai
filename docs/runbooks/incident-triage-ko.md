# 인시던트 분류 런북

인시던트가 생성되거나 심각도, 범위 또는 담당 체계가 크게 변경될 때 이 런북을
사용합니다. 분류 단계에서는 영향을 받는 대상, 대응의 긴급도, 다음 결정을 책임지는
사람을 정하고, 한정된 범위에서 조사를 시작할 만큼 근거가 최신인지 확인합니다.

> 분류는 근본 원인을 확정하거나 완화 작업에 권한을 부여하는 절차가 아닙니다.
> 신뢰할 수 있는 인시던트 경계와 다음 결정 기한을 정하는 절차입니다.

## 분류를 시작하거나 반복하는 경우

다음 이벤트에서 분류를 실행합니다.

- **새 인시던트**: 하나 이상의 감지된 문제를 상관관계로 묶어 인시던트를 생성합니다.
- **중요 정보 변경**: 영향받는 리소스, 사용자 영향 또는 SLO 오류 예산 소진이 변경됩니다.
- **담당자 배정 실패**: 알림 전달이 실패하거나 배정된 응답자가 인시던트를 수락할 수 없습니다.
- **병합 또는 분리 근거**: 상관관계로 묶인 구성원이 인시던트 범위를 바꿀 만큼 변경됩니다.
- **복구 신호**: 영향이 해결된 것으로 보이며 인시던트를 모니터링으로 이동할 수 있습니다.

## 전제 조건

- **신원**: 인시던트 ID, 상관관계 키, 현재 상태, 구성원 개수입니다.
- **최신성**: 텔레메트리, 인벤토리, 배포, 알림 시각입니다.
- **담당 체계**: 최종 책임 담당자와 사용된 온콜 일정 또는 경로입니다.
- **영향 정보**: 영향받는 사용자 또는 작업, SLO 상태, 지속 시간, 한정된 영향 범위입니다.
- **동시성**: 모든 인시던트 전이의 예상 현재 상태입니다.

출처를 사용할 수 없으면 사용 불가로 표시합니다. 데이터가 없다는 이유로 정상
상태라고 추론하지 않습니다.

## 역할

| 역할 | 책임 |
|------|------|
| 분류 담당자 | 범위, 심각도 판단 근거, 확인되지 않은 사항, 다음 결정 시간을 관리합니다. |
| 응답자 | 알림을 수락하고 한정된 범위에서 조사를 시작합니다. |
| 서비스 담당자 | 가능한 경우 서비스 맥락과 비즈니스 영향을 확인합니다. |
| 감사 담당자 | 구성원, 심각도, 담당 체계, 상태 전이를 기록합니다. |

## 심각도 설정

측정한 영향과 저장소에 설정된 심각도 정책을 사용합니다. 다음 표는 근거
수집을 안내하지만 해당 정책을 대체하지 않습니다.

| 신호 | 기록할 근거 |
|--------|-----------------|
| 사용자 또는 작업 영향 | 사용할 수 없거나 성능이 저하된 기능과 관찰된 영향 대상 |
| SLO 영향 | 목표, 구간, 오류 예산 소진 값, 남은 오류 예산 |
| 범위 | 영향받는 리소스, 지역, 의존성, 제외 대상 |
| 지속 시간 | 최초 관찰 시간, 확인 시간, 영향의 지속 여부 |
| 복구 가능성 | 알려진 임시 해결책, 롤백 준비 상태, 보호 대상 의존성 |

## 절차

1. **인시던트 기록을 확인합니다.** 신원, 상관관계 키, 현재 상태, 구성원
	개수, 가장 최근 구성원의 시각을 검증합니다.
2. **구성원을 검증합니다.** 영향받는 리소스를 확인합니다. 구성원을 추가하거나
	제거할 때는 사유를 명시하고 감사 기록을 남기는 정정 절차만 사용합니다.
3. **영향 범위를 정합니다.** 영향받는 기능, 리소스 범위, 시작 시간, SLO
	상태, 의존성, 알려진 제외 대상을 기록합니다.
4. **심각도를 설정합니다.** 설정된 정책을 측정한 영향에 적용합니다.
	불확실성을 포함해 사용한 근거와 규칙을 기록합니다.
5. **담당자를 지정합니다.** 설정된 경로에서 응답자를 선택하고 다음 결정
	기한을 정합니다. 가능한 경우 서비스 담당자도 확인합니다.
6. **안전하게 전이합니다.** 동시 갱신을 덮어쓰지 않도록 예상 현재
	상태를 사용해 인시던트를 `triaging`으로 이동합니다.
7. **조사를 시작합니다.** 시간 범위, 리소스 범위, 근거 예산, 먼저
	답할 질문을 정의합니다.
8. **알리고 검증합니다.** 영속 알림을 보낸 뒤 전달이 성공했다고 가정하지 않습니다.
	알림 수락, 전달 실패, 대체 경로 전달 중 어떤 결과가 발생했는지 확인합니다.

## 결정 분기

| 조건 | 다음 단계 |
|-----------|-----------|
| 범위와 심각도가 확정됨 | [RCA 근거 수집](rca-evidence-collection-ko.md)을 시작합니다. |
| 알려진 검증된 완화 방법이 준비됨 | [인시던트 완화와 롤백](incident-mitigation-and-rollback-ko.md) 절차로 진행합니다. |
| 근거 출처를 사용할 수 없음 | 심각도를 보수적으로 유지하고 출처 복구를 에스컬레이션합니다. |
| 관련 없는 여러 원인이 있음 | 감사 기록을 남기는 상관관계 정정 절차로 분리합니다. |
| 영향은 없지만 복구가 아직 안정적이지 않음 | 검토 기한이 있는 모니터링으로 이동합니다. |
| 알림이 수락되지 않음 | 구성된 대체 경로를 사용하고 모든 시도를 기록합니다. |

## 중지 조건

신원, 소유권, 범위, 근거 최신성을 확정할 수 없으면 중지하고 에스컬레이션합니다.
예상 인시던트 상태가 변경되면 전이를 중지하고 새로 고침한 뒤 분류를 반복합니다.
데이터가 없다는 이유로 심각도를 낮추지 않습니다.

## 근거와 감사

전이 감사 ID, 담당자, 심각도 판단 근거, 구성원 참조, 조사 ID,
알림 결과, 다음 검토 시간을 기록합니다. 출처 최신성, 확인되지 않은 사항, 제외 대상,
모든 구성원 정정 내역도 기록합니다.

## 완료 기준

인시던트 경계가 검증되고 심각도 판단 근거, 책임 담당자, 한정된 조사 범위,
다음 결정 기한이 정해져 있어야 분류가 완료됩니다. 알림이 수락되었거나
사용 가능한 대체 경로를 모두 시도한 상태여야 합니다.
이러한 사실 중 하나가 크게 변경될 때마다 분류를 반복합니다.
