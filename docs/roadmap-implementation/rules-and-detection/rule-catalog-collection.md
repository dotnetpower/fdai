# Rule Catalog Collection implementation ledger

This delivery ledger preserves reviewable implementation scope, append-only transitions,
and resumable work while the roadmap owner remains focused on normative design.

## Implementation status

### Migrated implementation notes

> **Implementation status**: Source manifest/fetch/snapshot/watcher core; rule, Rego, Azure Policy, and kube-bench parsers; strict Rule/ActionType/resource-vocabulary loaders; collected Azure and kube-bench catalogs; continuous pipeline stages; and CandidateGuard are implemented. `BestPractice` also has a strict schema, loader, typed-reference catalog validation, and all 59 coded recommendations across the five pinned Azure WAF checklist pages. The WARA/APRL snapshot retains all 456 recommendations from 83 pinned source files: 393 active recommendations consumed by WARA and 63 disabled lifecycle records.
>
> Dedicated config-baseline and measurement-baseline schemas, loaders, and repository stores are also implemented; the configuration store now ships one reviewed baseline resolved by the T0 `evaluate_configuration_baseline_control_set` consumer (see [Config Baseline](../../roadmap/rules-and-detection/rule-catalog-collection.md#config-baseline-hardened-reference-set)), and the measurement store still ships empty by design. The versioned MCSB catalog imports all 86 v1 controls and all 81 v2 preview controls, pins every source document, and validates each version's independent implementation crosswalk.
>
> The watcher's durable snapshot mirror and review-only PR delivery are also implemented and wired opt-in into the deployment (see [Remaining work](../../roadmap/rules-and-detection/rule-catalog-collection.md#remaining-work)); live activation, every external connector/parser, and every compliance/threat crosswalk listed below remain open.
