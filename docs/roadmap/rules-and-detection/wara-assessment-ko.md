# WARA 근거 기반 평가

이 설계는 고정된 Azure Well-Architected Reliability Assessment(WARA) 및 Azure Proactive
Resiliency Library(APRL) 목록을 범위를 인식하는 읽기 전용 평가로 전환합니다. 지침, 근거,
권한을 분리하므로 권고는 shadow 점검 결과를 만들 수 있지만 승인, 정책, 위험, 승격, 변경,
실행 권한을 부여할 수 없습니다.

> **범위:** 이 설계는 기존에 고정된 `azure-wara` 프레임워크 카탈로그를 사용합니다. CAF,
> WAF 또는 WARA 원본 카탈로그를 다시 만들지 않습니다.
>
> **초기 모드:** 평가는 shadow 전용입니다. 실제 Azure 관측에는 별도로 권한이 부여된
> 공급자 바인딩과 관리되는 런타임 증적이 필요합니다.

## 설계 요약

평가는 다음 다섯 개의 결정론적 단계를 사용합니다.

1. 고정된 WARA 프레임워크와 내용 주소화 교차워크를 로드합니다.
2. 검토된 리소스 종류 매핑을 기준으로 정확한 워크로드 및 리소스 범위를 확인합니다.
3. 출처, 최신성, 완전성, 충돌, 잘림, 합성 상태가 명시된 제한된 근거만 수락합니다.
4. 활성 권고마다 재현 가능한 결과를 하나씩 만들고 규정 준수 점수 없이 수량을 집계합니다.
5. 읽기 전용 Operator 변환 결과와 감사 이벤트를 만듭니다. 수정 작업은 전송하지 않습니다.

비활성 APRL 권고는 검색 가능한 카탈로그 이력으로 유지되며 평가 집합에는 포함되지 않습니다.

## 교차워크와 적용 가능성

기계 판독 가능 교차워크는 APRL GUID를 키로 사용하며 모든 활성 권고를 정확히 한 번씩
기록합니다. 수량 검사기는 고정된 원본 목록을 기준으로 활성 GUID 393개, 대소문자를 통일한
리소스 종류 80개, 평가에서 제외되는 비활성 GUID 63개, 서로 독립적인 자동화 권고 143개와
비자동화 권고 250개를 고정합니다. 수량, 중복, 누락 또는 원본 다이제스트가 달라지면 안전한
방향으로 실패합니다.

각 레코드는 `automation_available`을 검토된 처리 결과와 독립적으로 유지합니다.

| 처리 결과 | 의미 |
|-----------|------|
| `existing_rule` | 정확히 동일한 의미를 활성 FDAI Rule이 평가합니다. |
| `new_rule_candidate` | 결정론적 평가가 가능하지만 일반 Rule 거버넌스가 필요합니다. |
| `manual_evidence` | 문서, 메트릭, 훈련, 승인 레코드 또는 전문가 평가가 필요합니다. |
| `conditional_not_applicable` | 현재의 형식화된 범위 사실로 권고를 제외할 수 있으며 별도 근거와 승인자가 필요합니다. |
| `ambiguous_or_blocked` | 의미, ID, 쿼리 안전성 또는 근거 요구 사항이 충분하지 않습니다. |

제목의 유사성은 동등성을 증명하지 않습니다. WAF 상위 컨트롤은 명시적 관계 레코드를 통해
APRL 권고와 연결되며 APRL GUID를 대체, 병합 또는 중복 집계하지 않습니다.

대소문자를 통일한 모든 APRL 리소스 종류에는 검토 결과가 하나씩 있습니다. 정식 공급자
매핑과 정확히 일치하면 공급자 중립 리소스 종류를 선택합니다. 나머지는 `unsupported` 또는
`ambiguous`로 유지하며 모든 리소스로 범위를 넓히지 않습니다. 구독 범위 WAF 및 특수
워크로드 권고에는 일치하는 워크로드 태그가 추가로 필요합니다. 부모 및 자식 공급자 ID는
구분해서 유지하며 자식 리소스 권고는 정확히 일치하는 자식 범위에만 적용할 수 있습니다.

## 쿼리 수락

외부 Azure Resource Graph 쿼리 본문은 프레임워크 메타데이터와 별도로 저장하고 SHA-256
다이제스트로 결합합니다. 정적 검토는 변경 또는 제어 명령, 동적 엔드포인트, 선언되지 않은
테이블, 지원되지 않는 조인, 결과 상한 누락을 차단합니다. 수락된 구문은 다음 항목을 포함한
공급자 중립 읽기 계획만 만듭니다.

- APRL GUID 및 쿼리 다이제스트
- 정확한 워크로드 및 리소스 범위
- 선언된 공급자 리소스 종류 및 목록 세대
- 시간 제한 및 최대 행 수
- 필수 완전성, 잘림, 시간 및 출처 필드

정적 안전성은 제품 의미를 증명하지 않습니다. 정확한 평가기가 검토되기 전에는 쿼리가
읽기 전용이어도 권고를 차단 상태로 유지합니다. 쿼리 성공은 관측 증적이며 충족 결과나 운영
성공이 아닙니다.

`automation_available: true`인 143개 레코드는 교차워크 처리 결과와 관계없이 고정된 쿼리
본문 참조 및 다이제스트, 정적 안전 분류, 정확한 평가기 바인딩 또는 차단 사유를 포함합니다.

## 수동 근거 계약

자동화되지 않은 모든 권고에는 형식화된 요구 사항 또는 명시적 차단 사유가 있습니다.
요구 사항은 다음 항목을 기록합니다.

- 근거 종류 및 권위 있는 생성자 슬롯
- 워크로드 및 리소스 범위 계약
- 최신성 상한
- 내용 다이제스트 및 관측 시간
- 완전성, 충돌, 잘림, 합성 상태
- 실패 동작 및 책임 담당자 슬롯

누락되거나 유효하지 않은 근거는 `unknown`을 생성합니다. 자리 표시자, 접근할 수 없는
아티팩트, 오래된 메트릭 또는 미지정 담당자는 충족 결과를 만들지 않습니다.

`automation_available: false`인 250개 레코드는 교차워크 처리 결과와 관계없이 형식화된
수동 근거 요구 사항 또는 명시적인 차단 사유를 포함합니다.

## Shadow 평가 계약

평가 요청은 프레임워크 리비전, 교차워크 다이제스트, 온톨로지 릴리스, 목록 세대, 정확한
워크로드 ID, 리소스 ID, 평가 시각, 근거 증적을 고정합니다. 런타임은 비어 있거나 중복된
범위 및 고정값 불일치를 차단합니다.

각 권고 결과는 다음 상태를 독립적으로 유지합니다.

- 카탈로그 상태: `active` 또는 `disabled`
- 매핑 상태: `full`, `partial` 또는 `unmapped`
- 적용 가능성: `applicable`, `not_applicable` 또는 `unknown`
- 평가: `evaluated`, `not_evaluated` 또는 `blocked`
- 충족: `satisfied`, `failed` 또는 `unknown`

정확한 범위에 대한 완전하고 최신이며 충돌하거나 잘리지 않은 비합성 근거만 `satisfied`
또는 `failed`를 만들 수 있습니다. 공급자 또는 관측 실패는 `not_evaluated` 및 `unknown`을
생성합니다. `not_applicable`에는 검토된 조건부 처리 결과와 별도 승인 증적이 추가로
필요합니다. 다른 모든 경우는 `unknown` 또는 `blocked`로 유지됩니다.

결과에는 출처 및 구현 다이제스트, 평가한 GUID, 근거 참조, 이벤트 및 기록 시각, 집계 수량,
제한 사항, `execution_authority: false`가 포함됩니다. 결정론적 재현은 동일한 요청 및 근거
집합에서 결과 다이제스트를 다시 계산합니다.

## 온톨로지와 권한 경계

검토된 매핑은 명시적인 전체, 부분 또는 미매핑 상태와 함께
`FrameworkControl -> ControlObjective` 링크를 변환할 수 있습니다. 평가 결과는 변환 결과
소유 관측이며 프레임워크 정의를 수정하지 않습니다.

Framework, FrameworkControl 및 WARA 평가 객체는 `AccessGrant`,
`AuthorizationRequirement`, 승인, 위험, 승격, `ActionType` 또는 실행 경로에 연결할 수
없습니다. 카탈로그 매핑, 제품 그룹 검증 플래그, 권고 영향도 또는 쿼리 증적은 이 부정
불변 조건을 넘을 수 없습니다.

## Operator 화면

Operator API는 읽기 전용 WARA 목록과 선택적인 평가 결과를 제공합니다. Console은 리소스
종류, 권고 컨트롤, 영향도, 수명 주기, 제품 그룹 검증, 자동화, 매핑, 적용 가능성, 평가,
충족 상태 필터를 지원합니다.

각 행은 범위, 평가 시각, 출처 리비전, 근거 완전성, 제한 사항을 표시합니다. 카탈로그 존재와
`product_group_verified`는 메타데이터이며 충족 배지가 아닙니다. 선택적 변환 결과가 없으면
사용 불가로 표시하고 잘못되었거나 예상하지 못한 응답은 눈에 띄는 오류로 유지합니다.
초기 카탈로그 변환 결과는 고정된 APRL 출처 URL, 출처 경로, 버전, 리비전, 다이제스트, 가져온
시각, 라이선스, 선택적 Microsoft Learn 링크, 쿼리 다이제스트도 제공합니다. Console은 페이지당
컨트롤 50개를 표시하고 명시적인 이전 및 다음 탐색으로 수명 주기 레코드 456개 전체를
보존합니다. 클라이언트 전용 행 제한 뒤에 나머지 카탈로그를 숨기지 않습니다.

## 검토 전용 원본 갱신

갱신기는 정확한 APRL 커밋과 게시된 WARA 객체를 입력으로 받아 스키마, GUID 고유성, 활성
집합 일치, 출처 다이제스트, 출처 집합 다이제스트, 라이선스, 목록 수량을 검증합니다. 추가,
갱신, 비활성화, 재활성화에 대한 결정론적 의미 차이를 만듭니다.

출력은 실행되지 않는 검토 패키지입니다. 활성 매핑, 평가기 수락 또는 평가 권한을 변경할 수
없습니다. 수집이나 검증이 실패하면 마지막 유효 세대를 보존하고 명시적 실패를 기록합니다.

## 검증 및 릴리스 경계

집중 검사는 스키마, 가져오기 일치, 교차워크 수량, 쿼리 안전성, 수동 근거, 런타임 실패 사례,
재현, 온톨로지 불변 조건, Operator API 디코딩, Console 현지화, 결정론적 갱신 차이를
포함합니다. 전체 카탈로그 검증은 고정된 입력과 파생 아티팩트가 일치함을 증명합니다.

로컬 및 합성 검사는 `implemented` 상태를 증명할 수 있습니다. `validated` 상태에는 대표
다중 리소스 워크로드에 대한 관리되는 실제 Azure shadow 증적이 필요합니다. 이 별도 작업에는
명시적 권한, 공급자 ID, 정확한 범위, 네트워크 접근, 감사 보존이 필요합니다.
로컬과 배포 프로필은 같은 고정 교차워크, 범위가 제한된 읽기 계획, shadow 토픽, Operator
소비자 그룹 및 PostgreSQL 변환 결과를 사용하며 어떤 프로필도 프로바이더 근거를 대체하지 않습니다.
