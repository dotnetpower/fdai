# WAF 및 CAF 근거 기반 평가

이 설계는 고정된 Azure Well-Architected Framework(WAF) 및 Microsoft Cloud Adoption
Framework(CAF) 카탈로그를 범위에 결합되고 재현 가능한 shadow 평가로 전환합니다. 권고
지침, 관측 근거, 사람 승인, 운영 권한을 서로 분리합니다.

> **범위:** 이 설계는 WAF 워크로드 평가와 CAF 클라우드 자산 평가를 담당합니다. 기존 WARA
> 런타임은 APRL 쿼리 및 리소스 종류 계약이 더 특화되어 있으므로 독립적으로 검증된 평가로
> 유지합니다.
>
> **초기 모드:** 모든 평가는 읽기 전용 shadow 작업입니다. 평가 결과는 위험, 승인, 승격,
> 수정, 배포 또는 실행 권한을 부여할 수 없습니다.

## 설계 요약

공유 평가 경계는 다음 여섯 개의 결정론적 단계를 사용합니다.

1. 고정된 프레임워크와 검토를 거친 내용 주소화 근거 명세 카탈로그를 로드합니다.
2. 모든 프레임워크 컨트롤을 명시적으로 다루는 배포 제공 프로필 하나를 수락합니다.
3. 정확한 워크로드 또는 클라우드 자산 범위, 원본 세대, 평가 시간, 근거 기준 시점을 결합합니다.
4. 각 요구 사항을 독립적으로 평가하고 누락되거나 유효하지 않은 근거를 알 수 없음으로 유지합니다.
5. 변경 불가능한 결과를 저장하고 Operator 변환 결과에 비권한 이벤트를 게시합니다.
6. 매핑 및 근거 명세가 독립 검토를 통과할 때까지 원본 변경을 검토 전용 제안으로 유지합니다.

런타임은 근거 수락, 재현, 게시, 변환 결과 생성 방식을 공유합니다. WAF와 CAF는 서로 다른
카탈로그, 범위 계약, 공급자 어댑터, 사용자 설명을 유지합니다.
공유 Operator PostgreSQL 조회기는 관련 없는 다른 운영 기능에도 사용됩니다. 범위가 지정된 AKS
출처 상태와 내용 주소 기반 진단 증적 조회는 WAF 또는 CAF 범위, 근거 수락, 재현, 결과에 들어가지
않습니다. 세대 경계를 확인하는 런타임 호출 관계 디코더도 두 평가 계열의 범위 밖에 있으며 평가
근거에 기여할 수 없습니다. 공유 원본 상태 디코더는 정식 기계 토큰 사유만 허용하며 principal
텍스트나 프로바이더 세부 정보를 어떤 Operator 계열에도 전달할 수 없습니다.
공유 Operator 보낼 편지함 수명 주기 facade는 Incident 개입 작업자도 감독할 수 있습니다. 해당
논리 토픽은 명시적으로 허용 목록에 등록되며, 해당 요청과 준비 상태는 WAF 또는 CAF 범위,
근거 수락, 재현, 결과에 들어가지 않습니다.

## 설계 결정 및 비판

### 채택하지 않음: WARA 런타임 복사

WARA를 WAF용으로 복사하고 다시 CAF용으로 복사하면 최신성, 범위, 충돌, 재현, 감사, 변환
결과 규칙이 중복됩니다. 세 구현은 서로 달라질 수 있으며 안전성 수정이 한 프레임워크만
보호하고 다른 프레임워크를 놓칠 수 있습니다.

개정된 설계는 WAF와 CAF를 위한 하나의 `framework-assessment` 경계를 추가합니다. APRL GUID,
수락된 Azure Resource Graph 쿼리, 정확한 리소스 종류, 일치 행 의미는 일반 프레임워크
개념이 아니므로 WARA는 변경하지 않습니다.

### 채택하지 않음: 브라우저에서 상태 계산

Console은 근거를 결합하거나 준수 여부를 계산하지 않습니다. 서버가 소유하는 변경 불가능한
변환 결과 하나를 표시합니다. 이 경계는 오래된 탭, 일부 페이지만 로드된 상태, 표시 필터가
결정 로직이 되지 않도록 합니다.

### 채택하지 않음: 프레임워크 준수 점수 보고

WAF와 CAF는 권고 지침입니다. 집계 수량은 인증이나 규정 준수가 아니라 근거 범위와 평가 상태를
설명합니다. 외부 점수는 보조 관측으로 유지합니다.

## 평가 카탈로그

각 카탈로그는 프레임워크 버전, 원본 개정 집합, 정의 다이제스트, 근거 명세 다이제스트,
검토자, 검토 상태를 고정합니다. 모든 프레임워크 컨트롤은 정확히 한 번 나타납니다.

### WAF 카탈로그

WAF 카탈로그는 기존 `BestPractice` 레코드 59개에서 컨트롤 명세 59개를 파생합니다. 각 형식화
요구 사항은 정확한 참조를 유지하고 다음 항목을 추가합니다.

- 권위 있는 생산자 또는 명시적으로 차단된 의존성
- 정확한 워크로드 범위 계약과 목록 세대 요구 사항
- 유한한 최신성 상한과 완전성 계약
- 책임 담당자 슬롯과 승인 역할
- `unknown` 실패 동작
- 기한이 있고 별도로 승인된 비적용 계약

현재 목록이 정확한 워크로드 범위를 명시적으로 포함할 때만 Rule 근거가 요구 사항을 충족할 수
있습니다. 공급자 오류, 지원되지 않는 리소스 종류, 불완전한 목록, 잘림, 충돌 또는 오래된 세대를
포함한 깨끗한 Rule 결과는 알 수 없음으로 유지합니다.

### CAF 카탈로그

CAF 카탈로그는 방법론 7개와 랜딩 존 설계 영역 8개를 포함합니다. 각 레코드는 클라우드 자산
범위, 담당자, 주기, 근거 요구 사항, 교차워크 관계를 정의합니다.

Strategy, Plan, Adopt는 각각 절차 근거와 실행 근거를 모두 요구합니다. Azure 구성은 이러한
컨트롤을 보조할 수 있지만 관리되는 사람 프로세스 근거 없이는 충족할 수 없습니다. Ready,
Govern, Secure, Manage는 정확한 클라우드 자산 관측과 프로세스 근거를 결합합니다.

교차워크 레코드는 Rule, WAF, MCSB, `ControlObjective`, Azure Policy, 공급자 관측 또는 수동
근거를 정확히 참조합니다. 각 관계는 `full`, `partial`, `supporting_only`, `unmapped` 중 하나이며
비슷한 문구만으로 동등성을 결정하지 않습니다.

## 배포 제공 프로필

프로필은 카탈로그의 전체 컨트롤 ID 집합을 다룹니다. 모든 컨트롤을 `applicable` 또는
`not_applicable`로 명시합니다.

적용 가능한 항목은 근거 담당자와 검토 주기를 지정합니다. 비적용 항목은 형식화된 사유, 승인
ID, 요청자와 다른 ID, 승인 시간, 만료 시간도 요구합니다. 누락된 근거로 비적용 결정을 만들 수
없습니다.

WAF 프로필은 워크로드와 현재 목록 세대를 결합합니다. CAF 프로필은 클라우드 자산 범위, 관리
계층 세대, 운영 모델, 환경 등급, 규제 맥락, 근거 담당자를 결합합니다. 배포 ID와 값은 상위
저장소 외부에 유지합니다.

## 근거 수락

변경 불가능한 근거 증적 하나는 다음 항목을 포함합니다.

- 프레임워크, 컨트롤, 요구 사항, 근거 종류, 생산자 ID
- 정확한 범위 다이제스트와 목록 또는 계층 세대
- 이벤트 시간, 기록 시간, 최신성 상한, 근거 다이제스트
- 완전성, 충돌, 잘림, 합성, 공급자 오류 상태
- 결정 근거 또는 보조 전용 역할
- CAF 프로세스 컨트롤에 필요한 절차 또는 실행 단계

모든 ID와 세대가 요청과 일치하고 시간에 시간대가 있으며 독립 기준 시점 안에 있고 모든 안전
상태가 유효할 때만 결정 근거 증적을 수락합니다. 수락 가능한 증적이 서로 다르면 명시적 충돌과
알 수 없는 충족 상태를 만듭니다.

보조 전용 근거는 맥락과 제한 사항을 추가할 수 있지만 단독으로 충족을 결정할 수 없습니다. 이
규칙은 Microsoft Well-Architected Review 보고서, Azure Advisor, Defender for Cloud Secure
Score, 프레임워크 교차워크 이웃에 적용합니다.

## 절충안 및 충족 상태

WAF 핵심 영역 절충안은 범위에 결합되고 승인된 변경 불가능한 레코드입니다. 영향받는 컨트롤,
결정 담당자, 근거 다이제스트, 승인 시간, 만료 시간을 지정합니다. 레코드는 결과에 표시되지만
다른 컨트롤의 근거 상태를 다시 쓰거나 숨기거나 낮추지 않습니다.

런타임은 다음 다섯 축을 분리합니다.

- 참조 존재 여부
- 의미 매핑
- 적용 가능성
- 평가
- 충족 상태

완전한 결정 근거만 `satisfied` 또는 `failed`를 만들 수 있습니다. 누락, 오래됨, 접근 불가, 잘림,
충돌, 합성, 만료 또는 잘못된 범위 근거는 `not_evaluated`와 `unknown`을 만듭니다. 승인된
비적용은 충족을 뜻하지 않는 `not_applicable`을 만듭니다.

## 변경 불가능한 스냅샷 및 재현

각 스냅샷은 프레임워크 개정, 정의 및 카탈로그 다이제스트, 프로필 ID와 다이제스트, 온톨로지
릴리스, 범위 다이제스트, 목록 또는 계층 세대, 근거 다이제스트, 평가 및 기록 시간, 승인,
절충안, 컨트롤별 결과, 제한 사항, `execution_authority: false`를 결합합니다.

스냅샷 다이제스트는 결정에 영향을 주는 어떤 필드도 제외하지 않습니다. 재현은 전체 스냅샷을
다시 계산하고 다이제스트 불일치를 차단합니다. 이후 평가는 기존 이력을 수정하지 않고 새
스냅샷을 만듭니다.

## 공급자 및 이벤트 경계

공급자 중립 프로토콜은 형식화된 읽기 전용 관측을 반환합니다. Azure 어댑터는 증적을 만들기
전에 원본 ID, 정확한 범위, 시간, 완전성, 페이지 처리를 검증합니다. 공급자 성공은 수집만
증명하며 결정론적 런타임이 수락 여부를 판단합니다.

평가 서비스는 스키마 버전이 있는 shadow 이벤트를 게시하기 전에 감사 레코드를 추가합니다.
Operator 소비자는 잘못된 형식, 일부만 있는 결과, 잘못된 프레임워크, 권한을 포함한 이벤트를
격리합니다. 평가 모듈은 에이전트, 위험 게이트, 승인 경로, 실행기를 가져오지 않습니다.

보호된 실제 검증 워크플로는 배포 러너에 평가 토픽 전송자 역할이 없으므로 의도적으로 감사
전용 기록기를 사용합니다. Operator 변환 결과를 게시한 것처럼 처리하지 않고
`publication_status: not_requested_validation_only`를 기록하며 정제된 결과물을 유지합니다.

## Operator 화면

Operator API는 최신 변경 불가능한 변환 결과를 제공하며 평가가 없으면 카탈로그 데이터를
유지합니다. Console은 다음 항목을 표시합니다.

- 프레임워크 참조와 정확한 원본 개정
- 선택된 범위와 평가 시간
- 서로 분리된 매핑, 적용 가능성, 평가, 충족 상태
- 근거 참조, 다이제스트, 최신성, 완전성, 충돌, 제한 사항
- 담당자, 주기, 승인된 예외, WAF 절충안 레코드
- 준수 레이블이 없는 사용할 수 없음 및 알 수 없음 상태

WAF는 기존 Controls 보기에 유지합니다. CAF는 동일하게 차분한 읽기 전용 상호 작용 방식을
사용하는 인접 탭을 추가합니다. 브라우저는 근거나 승인을 쓰지 않습니다.

## 원본 변경 거버넌스

원본 감시기는 추가, 제거, 의미 변경, 영향받는 매핑, 오래된 근거 명세를 포함하는 결정론적 검토
패키지를 만듭니다. 제안 세대는 정확한 패키지 다이제스트가 승인될 때까지 대기합니다. 검증이
실패하면 이전의 유효한 세대를 유지하고 실패한 개정과 사유를 기록합니다.

## 검증 및 실제 근거

집중 테스트는 카탈로그 완전성, 프로필 범위, 근거 수락, 프로세스 근거, Rule 기반 부재 주장,
외부 보조 근거, 절충안, 재현, 온톨로지 권한, Operator 디코딩, 지역화, 변환 결과 격리를 다룹니다.
실시간 목록 변경은 선택한 워크로드에 연결된 리소스를 대상으로 할 때만 WAF 실행을 무효화합니다.
관련 없는 구독 변경은 안정적인 워크로드 스냅샷을 무효화하지 않습니다. 다만 더 최신의 실패하거나
중단된 전체 조정 작업이 있으면 평가는 계속 차단됩니다.

로컬 픽스처는 동작 방식만 증명합니다. 검증된 WAF 또는 CAF 상태에는 정확히 푸시되고 필수 CI를
통과한 개정에서 생성된 관리형 실제 Azure shadow 증적 하나가 추가로 필요합니다. 유지되는
증적은 정제된 다이제스트와 수량을 포함하고 독립 검토를 거치며 실행 권한을 부여하지 않습니다.
검증 워크플로는 현재 PostgreSQL 온톨로지에서 topology에 연결된 Workload를 정확히 하나 선택한
후 비공개 러너에서 해당 Workload의 현재 목록 세대와 Azure 관리 계층을 읽습니다. 후보가 없거나
여러 개이면 프로바이더 관측 전에 실패합니다. Terraform apply는 실행하지 않습니다.
