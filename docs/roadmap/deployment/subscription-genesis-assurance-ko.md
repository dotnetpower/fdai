# 구독 초기 구성 보증

이 문서는 구독 초기 구성 실행을 신뢰할 수 있도록 하는 안전, 완전성, 복구, 운영자 경험
통제를 정의합니다. [구독 초기 프로비저닝](subscription-genesis-provisioning-ko.md)의 수명
주기를 보완하고 넓은 단계를 반증 가능한 게이트로 구체화합니다.

> **범위:** 이 통제는 비어 있거나 일부만 구성된 Azure 구독에 적용됩니다. 실제 배포, 모델
> 호출, 할당량 요청, 리소스 변경을 승인하지 않습니다.
>
> **구현 원장:** 전달 근거는
> [구독 초기 구성 보증 구현 원장](../../roadmap-implementation/deployment/subscription-genesis-assurance.md)에서
> 추적합니다.

## 한눈에 보는 설계

모든 실행은 유한한 매니페스트를 컴파일하고, 구독 및 환경별 잠금 하나를 얻으며, 봉인된 단계
계획만 실행하고, 독립적인 사후 조건 근거를 기록합니다. 필수 항목 하나라도 증명할 수 없으면
`ready`가 아니라 `blocked`, `failed`, `cancelled`, `incomplete`로 종료합니다.

## 기반 및 외부 컨트롤 플레인

빈 구독에는 첫 Azure 실행 호스트가 없습니다. 따라서 기반 부트스트랩은 범위가 엄격히 제한된
로컬 컨트롤 플레인 예외를 사용합니다.

- **로컬 경계:** 로그인한 운영자는 리소스 그룹, 비공개 상태 계정, 네트워크, 배포 신원,
  실행 호스트를 만들 수 있습니다. 이 단계는 Key Vault, PostgreSQL, 모델, 애플리케이션
  데이터 플레인에 쓸 수 없습니다.
- **상태 캐시:** 로컬 상태는 `umask 077`, 모드 `0700` 디렉터리, 모드 `0600` 일반 파일,
  심볼릭 링크 금지, 비밀 입력 금지, 제한된 수명을 사용합니다. 실행은 다이제스트만 기록하고
  파일을 근거로 업로드하지 않습니다.
- **안정적인 이름:** 실행은 전역 고유 이름을 한 번 파생하고 이동 가능한 상태에는
  다이제스트만 저장하며 재개 시 같은 이름을 사용합니다. 부분 기반 시도 후 새 상태 계정
  이름을 만들지 않습니다.
- **원격 권위:** 실행기는 추론된 재구성이 아니라 Terraform 상태 이행을 사용하고 계보, 일련
  번호, 주소 집합, 리소스 ID, 관리 개수를 비교합니다. 로컬 캐시를 삭제하기 전에 원격 변경
  0 계획과 상태 버전 관리 사후 읽기가 필요합니다.
- **데이터 보호:** Blob 버전 관리, 일시 삭제, TLS, 키 인증 비활성화, 공개 접근 비활성화,
  비공개 엔드포인트, 비공개 DNS, 상태 임대 경로가 필수 사후 조건입니다. 최선형 활성화로
  기반 단계를 종결할 수 없습니다.

외부 컨트롤 플레인은 일급 의존성입니다.

| 의존성 | 필수 보증 |
|--------|-----------|
| Azure | 정확한 클라우드, 테넌트, 구독, 공급자 등록, 정책 할당, 잠금, 할당량, 약관, 유효 RBAC를 계획 시점에 기록하고 각 변경 전에 다시 확인합니다. |
| 소스 호스트 | 저장소, 변경 불가능한 커밋, 서명된 번들, 의존성 잠금, 이미지 증명이 실행 매니페스트와 일치합니다. |
| 워크플로 호스트 | 저장소 권한, 보호 환경, 승인자, 실행기 레이블, 동시성 그룹, 보존 정책을 검증하며 FDAI 런타임 권한을 부여하지 않습니다. |
| 신원 디렉터리 | 앱 등록, App Role, 그룹, 리디렉션 출처, 소유자, 관리자 동의, 테넌트 일치를 계획하고 다시 읽어 확인합니다. |
| 아티팩트 원본 | 온라인 허용 목록 또는 검증된 오프라인 키트가 모든 wheel, 바이너리, 공급자, 이미지, 서명, 소프트웨어 자재 명세 항목을 포함합니다. |

실행기 등록 토큰, 제거 토큰, 데이터베이스 암호, GitHub 토큰을 Terraform 변수, 상태, 프로세스
인자, Azure Run Command 페이로드, 로그, 채팅에 넣지 않습니다. 목표 구현은 공급자 호스팅
인증과 보호된 입력 채널을 사용합니다. 선택한 전송 방식이 이 조건을 충족하지 못하면 비밀
처리를 약화하지 않고 승인된 기존 호스트를 기다립니다.

저장소 설정은 매니페스트에서 컴파일해 멱등하게 적용합니다. 작업은 누락된 변수와 비밀
참조의 이름만 보고하고 값을 표시하지 않습니다. 데이터베이스 자격 증명은 비공개 실행
호스트에서 생성해 승인된 비밀 공급자에 저장하고 참조로 사용합니다. 온보딩 재실행은 이를
묵시적으로 회전하지 않습니다.

## 계획, 권한, 동시성

- **유한한 의존성 그래프:** 모든 매니페스트 항목은 선행 조건, 소유자, 실행기, 승인 등급,
  멱등성 키, 제한 시간, 무진행 제한 시간, 롤백, 사후 조건 관찰자, 근거 스키마 버전을
  선언합니다. 순환 참조와 알 수 없는 의존성은 계획을 차단합니다.
- **활성 실행 하나:** 클라우드, 테넌트, 구독, 환경, Terraform 루트를 키로 하는 임대가 동시
  초기 구성 또는 해제를 막습니다. 임대를 잃으면 새 작업을 중지하고 재개 전에 운영자 검토가
  필요합니다.
- **시간 권위:** 계획 만료, 승인, 임대, 근거 수명은 인증된 UTC 원본과 선언된 시계 오차
  상한을 사용합니다. 시계 불확실성은 변경을 차단합니다.
- **승인 정책:** 각 변경 확인 지점에는 현재 책임자 한 명 이상의 승인이 필요합니다. 영향이
  큰 기반, 신원, 네트워크, 운영, 해제 계획은 구성된 정족수를 사용합니다. 승인자와 실행
  신원은 분리합니다.
- **예행 연습과 롤백:** 적용 전에 성공한 계획과 롤백 예행 연습이 필요합니다. 파괴적 이행
  또는 도입에는 검증된 백업 및 복원 지점과 별도 승인된 롤백 계획이 필요합니다.
- **취소:** 취소는 새 항목 예약을 멈추고 진행 중인 공급자 호출이 제한된 종결 증적에
  도달하도록 하며, 임대를 해제하고, 사전 승인된 정리만 실행하고, `cancelled` 또는
  `incomplete`로 종료합니다.
- **적용 모호성:** 점유가 없으면 다시 계획할 수 있습니다. 증적 없는 점유는 검증만 재개할
  수 있습니다. 실패하거나 모호한 점유는 자동 재시도할 수 없습니다.

기존 리소스는 명시적인 주소 허용 목록과 변경 불가능한 속성의 정확한 일치가 있을 때만
도입합니다. 관리 잠금, 거부 할당, 정책 수정, 외부 소유권이 있으면 충돌입니다. 해당 변경이
별도로 설계되고 승인되지 않은 한 실행은 잠금 또는 정책 할당을 제거하지 않습니다.

승인 전에 계획은 예상 월별 비용, 일회성 모델 검증 예산, 할당량 사용량, 공개 IP 개수, 송신
프로필, 백업 보존, 0으로 축소되지 않는 리소스를 보고합니다. 프로필 비용 상한보다 높은
계획은 차단합니다.

## 네트워크 및 실행 호스트 보증

계획은 운영 VNet, 애플리케이션 VNet, VPN, 피어링된 VNet, 허브 경로, Private DNS Resolver
범위, 선택한 비공개 엔드포인트 서브넷의 주소 중복을 검사합니다. VPN 접근을 배포 권한으로
취급하지 않으면서 실행기에서 서비스로 가는 경로와 VPN을 통한 운영자 경로를 모두 검증합니다.

선택한 실행 프로필은 다음을 증명해야 합니다.

- 실제 호스트에서 DNS, TCP, TLS, 신원, 관리 플레인, GitHub 또는 수동 전송, 아티팩트, 상태,
  Key Vault, PostgreSQL, Event Hubs, 레지스트리, 모델, 모니터링 경로
- 대상 Azure 클라우드의 유효 경로, 방화벽, 네트워크 보안 그룹, 서비스 태그, 프록시 신뢰,
  비공개 DNS 응답
- 검증된 실행에서 확인되지 않은 `latest` 다운로드를 사용하지 않는 체크섬 고정 도구와 이미지
- 범위가 제한된 송신 또는 완전한 서명 오프라인 키트
- 디스크 모델에 맞는 재부팅 또는 할당 해제 후 정상 실행기 신호

소버린 클라우드는 자체 엔드포인트 접미사, 대상, 서비스 태그, 지원 서비스를 사용합니다.
동등 기능을 지원하지 않으면 공용 클라우드 대체 경로를 사용하지 않고 계획을 차단합니다.

## 데이터베이스 및 의미 보증

데이터베이스 부트스트랩 매니페스트는 인프라, 스키마, 데이터, 런타임 권한을 분리합니다.

| 게이트 | 필수 근거 |
|--------|-----------|
| 서버 | 버전, 지역, 영역 구성, 스토리지, 백업, 보존, 암호화, 비공개 DNS, TLS, 매개 변수, 로캘, 표준 시간대가 프로필과 일치합니다. |
| 복구 | 파괴적 작업 전에 최신 백업 또는 복원 지점이 있습니다. 선택한 운영 등급에 대해 복원을 예행 연습하고 RPO/RTO에 연결합니다. |
| 이행 | 레거시 및 서비스 소유 head, 의존성 순서, 트랜잭션 동작, 잠금, 명령 제한 시간, 도입 기록, 롤백 참조가 정확합니다. |
| 역할 | 이행, 소유자, 런타임, 읽기, Job, 실행기 principal은 선언된 권한만 가집니다. 런타임 신원은 DDL을 실행하거나 이행 권한을 가장할 수 없습니다. |
| 확장 | 모든 필수 확장과 버전이 의존 스키마 또는 카탈로그 작업 전에 존재합니다. |
| 의미 릴리스 | 서명된 번들은 배포 가능한 온톨로지, 규칙, 워크플로, ResourceType, 프롬프트, 제품 기본값을 정확한 버전과 다이제스트로 열거합니다. |
| 변환 결과 | 변경 불가능한 읽기 변환 결과가 릴리스 다이제스트와 일치하고 비교 후 설정 규칙으로 배포 소유 설정을 보존합니다. |

"모든 저장소 카탈로그 항목"이 수집된 모든 참조의 활성화를 의미하지 않습니다. 매니페스트는
항목을 `runtime-required`, `reference-only`, `optional-disabled`, `deployment-overlay`로
분류합니다. 검토된 런타임 필수 항목만 활성 기본값이 되며 모든 작업 모드는 shadow 전용으로
유지합니다.

서비스 활성화는 모든 이행 head, 의미 릴리스 다이제스트, 기본값 집합 다이제스트, 역할
매니페스트, 타임스탬프를 연결하는 하나의 원자적 준비도 표시를 기다립니다. 런타임 principal의
사후 읽기가 이 표시와 일치해야 합니다. 이행 principal은 자체 런타임 접근을 인증할 수
없습니다.

## 모델 보증

모델 계획은 기능 재사용과 집계 할당량을 고려합니다. 여러 기능은 레지스트리가 동일한
게시자, 패밀리, 버전, SKU, 콘텐츠 필터 정책, 데이터 영역, 워크로드 격리 등급을 명시적으로
허용할 때만 하나의 배포를 공유할 수 있습니다. 그 외에는 별도 용량을 받습니다.

용량 계획은 입력 및 출력 토큰, 캐시 토큰 처리, 분당 요청, 동시성, 공급자 SKU 단위, 모델별
할당량, 지역 할당량, 현재 배포, 예비분, 재시도 동작, 예상 버스트를 포함합니다. 생성 직전에
비교 후 적용 검사로 할당량을 예약하며 드리프트가 있으면 다시 계획합니다.

계획은 다음도 검증합니다.

- 계정 소유권과 비공개 엔드포인트 및 DNS 종결
- 게시자 약관, 구독 자격, 콘텐츠 필터링, 책임 있는 AI 정책, 데이터 상주, 미리 보기 제한
- 로컬 키가 없는 배포자, 런타임, Operator 역할
- 정확한 엔드포인트와 배포 연결 및 외부 계정 부재
- 정량적 성공률, 제한, 처리량, 지연, 비용 기준
- 점검에 비용이 발생하고 테스트 내용을 보내므로 명시적인 실제 모델 승인

할당량 증가는 외부의 사람 검토 선행 조건입니다. `fdaictl`은 필요한 용량 근거와 상태를 만들
수 있지만 승인을 가정하거나 무한히 확인하거나 더 작은 배포를 조용히 만들지 않습니다. 일부
모델 생성은 봉인된 정리 계획으로만 정리합니다.

## 인벤토리 완전성 및 진행률 보증

초기 구성은 정확한 구독 루트 하나를 스캔합니다. 최상위 리소스, 매핑된 형식, 매핑되지 않은
공급자 형식, 확장 리소스, ARM 및 Kubernetes와 같이 별도로 범위가 제한된 자식 리소스 원본을
계수합니다. 원본 상한을 성공한 잘림으로 바꾸지 않습니다. 실행은 관측된 상한과 필요한 다음
조치를 포함한 안정적인 차단 사유를 냅니다.

Azure 리소스가 바뀔 수 있으므로 계수 단계와 수집 단계는 트랜잭션상 일치하지 않습니다. 따라서
진행률은 분모를 추정값으로 표시하고 최종 공급자 커버리지 증적으로 완전성을 판단합니다. 수집
중 삭제 또는 생성은 같은 완전한 세대에서 조정하거나, 초기 구성 종결을 차단하는 최신 변경
오버레이를 남깁니다.

대규모 구독은 준비된 배치를 PostgreSQL에 저장하며 선택적 메모리 관찰자가 전체 그래프를
보유하도록 요구하지 않습니다. 객체, 관계, 바이트, 페이지, 요청, 동시성, 시도, 무진행 상한은
서명된 수집 정책에서 가져옵니다. 전체 구독이 승인된 범위에 맞지 않으면 스캔 전에 검토된
분할 전략이 필요합니다.

인벤토리 신원은 선언된 구독의 읽기 역할과 비공개 준비 및 이벤트 표면의 쓰기 권한만 받습니다.
수집 전에 RBAC 전파를 명시적으로 관측합니다. 비공개 AKS 또는 다른 자식 원본은 엔드포인트,
인증서, 대상, 워크로드 신원, 공급자 권한 검사를 통과한 후에만 포함합니다. 그렇지 않으면
선언된 범위가 미완성으로 유지됩니다.

진행률은 완료와 시간을 분리합니다.

- 정확한 단계 및 확인 지점 개수는 완료된 작업을 보고합니다.
- 리소스 및 페이지 분모는 추정값으로 표시합니다.
- 고정 가중치는 완료 비율만 제공하며 경과 시간 예측에 사용하지 않습니다.
- 예상 완료 시간은 최소 표본 구간과 안정적인 속도가 있을 때만 표시하고, 재시도, 제한, 승인
  대기, 분모 변경 시 숨깁니다.
- 모든 이벤트는 스키마 버전, 실행 ID, 시도 ID, 단조 순번, 이전 이벤트 다이제스트, 현재
  카운터, 정제된 사유, 재개 커서 참조를 가집니다.
- CLI, 워크플로 요약, Operator API, Console은 레이블을 지역화하고 화면 읽기 프로그램을
  지원하며 보존 이벤트와 렌더링 텍스트 크기를 제한합니다.

사후 조건 관찰자는 인벤토리 작성 신원과 분리합니다. 승격 후 활성 세대, 커버리지 매니페스트,
최신성, 그래프 개수를 읽습니다. 이 사후 읽기만 최초 스캔을 종결할 수 있습니다.

## 운영 종결 및 검사 매트릭스

준비도에는 이벤트 버스 왕복, DLQ 접근, 카나리 감사 no-op, 런타임 상태, 보호된 처리 준비도,
모델 연결, 데이터베이스 읽기, 카탈로그 다이제스트, 인벤토리 최신성, 모니터링, 예산 경고,
운영자 알림 검사도 필요합니다.

실행은 승인 대기, 무진행 경고, 실패, 취소, 정리 실패, 준비 완료에 범위가 제한된 알림을
게시합니다. 알림에는 실행 및 단계 참조만 포함합니다. 로그와 근거는 바이트, 항목, 보존
상한을 가지며 비밀, 대상 식별자, 공급자 페이로드, 프롬프트, 모델 출력을 제외합니다.

종단 간 매트릭스는 다음을 포함합니다.

- 빈 구독, 수동 부트스트랩 구독, 이전 FDAI 구독, 외부 리소스가 있는 구독
- 공용 Azure, VPN을 사용하는 비공개 Azure, 기존 호스트, 관리형 VM, 서명된 오프라인 키트
- 개발 및 운영 프로필과 정족수 및 백업 요구 사항
- 정책 거부, 관리 잠금, 주소 중복, DNS 실패, 경로 실패, RBAC 지연, 할당량 경쟁, 공급자
  제한, 모델 약관 실패, 이행 실패, 카탈로그 불일치, 인벤토리 잘림, 프로세스 충돌, 임대 손실,
  취소, 정리 실패, 시계 오차
- 모든 외부 효과, 점유 쓰기, 증적 쓰기, 상태 이행 경계의 전후 중단
- 두 번째 실행 변경 없음, 지원되는 이전 매니페스트에서 업그레이드, 롤백, 복원, 해제,
  환경 정리

실제 검증은 전용 승인 구독, 정확히 푸시된 리비전, 성공한 필수 CI, 비용 상한, 만료, 해제
계획을 사용합니다. 고객 환경을 검사 픽스처로 재사용하지 않습니다.
