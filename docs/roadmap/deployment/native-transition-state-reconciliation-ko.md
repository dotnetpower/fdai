# 네이티브 전환 상태 조정

이 설계는 영구 Agent 상태가 밀리초 타임스탬프와 다이제스트를 사용하고 불변 전환 증적은 전체
정밀도 타임스탬프를 보존한 이전 네이티브 전환을 제한적으로 복구하는 방법을 정의합니다. Hub
완료 감사는 전체 정밀도로 다시 생성한 상태 및 전환 증적 다이제스트를 바인딩합니다. 일반 상태
복구나 증적 다시 쓰기는 허용하지 않습니다.

> **구현 원장:** 전달 근거는
> [네이티브 전환 상태 조정 구현 원장](../../roadmap-implementation/deployment/native-transition-state-reconciliation.md)에서 추적합니다.

## 이 문서에서 다루는 내용

불변 전환 증적의 `completed_at`이 상태 관측 시각의 권위 있는 값입니다. Hub 완료 증적의
`completed_at`은 이후 Hub 커밋 시각을 기록합니다. 불변 증적은 바꾸지 않으며, Agent의 영구
현재 상태만 전체 정밀도의 정규 타임스탬프와 다이제스트로 이동할 수 있습니다.

## 승인과 검증

인증된 운영자는 조정 승인 경로에
`fdai.lifecycle-native-transition-state-reconciliation-request.v1`을 제출합니다. Hub는 설치
행 잠금 안에서 원래 완료 감사와 증적, 설치, 이전·신규 Entity 및 범위 다이제스트, 네이티브
승인, 권위 있는 UID 다이제스트, Agent 신원, 현재 상태, 열린 Plan 부재를 검증합니다.

검증에는 서로 독립된 두 가지 정규 형식을 사용합니다.

- 불변 증적의 저장 필드로 원래 `record_digest`를 재현해야 합니다. 증적에 포함된 상태
  다이제스트는 밀리초 `observed_at` 상태로 재현해야 합니다.
- Hub 완료 증적은 자체 `receipt_digest`를 재현해야 합니다. 상태 다이제스트는 불변 증적의
  전체 정밀도 `completed_at`을 사용하며, 전환 증적 다이제스트는 같은 증적 필드에서 해당 전체
  정밀도 상태 다이제스트만 대체한 결과와 같아야 합니다.
- 이전 보고 상태 원본은 저장된 `available_artifact_digests`의 순서와 중복을 그대로 보존하며,
  해당 정규 바이트로 자체 다이제스트를 재현해야 합니다. 원본을 구문 분석할 때 배열을 정규화하거나
  저장된 다이제스트를 바꾸지 않습니다.

로컬 밀리초 상태와 Hub 전체 정밀도 원본은 산출물 이외의 모든 필드가 같고 산출물 멀티셋이
동등해야 합니다. 산출물 순서는 달라도 되지만 각 다이제스트의 중복 개수는 같아야 합니다. 로컬
`observed_at`부터 불변 증적의 `completed_at`까지의 양의 차이는 1밀리초 이하여야 합니다. 설치,
Entity, 범위, UID 재고, 실행 신원, 정확한 완료 감사도 일치해야 합니다. 그 밖의 차이, 변경된
다이제스트, 동시 상태, 다른 재시도, 누락된 감사 기록은 승인을 차단합니다.

권위 있는 대체 상태는 원본의 의미상 산출물 재고를 보존하면서
`available_artifact_digests`를 결정적으로 정렬하고 중복을 제거합니다. 대체 상태 계약은 계속
엄격하므로 정렬되지 않았거나 중복된 대상은 유효하지 않습니다. Hub는 서명된 이전 원본이나
저장된 다이제스트를 바꾸지 않고 새 대상 다이제스트를 계산합니다.

### 만료됐지만 사용하지 않은 승인 갱신

Agent가 로컬 상태를 변경하기 전에 승인이 만료되면 근거 검사를 약화하지 않고 갱신할 수
있습니다. Agent는 정확히 만료된 승인 다이제스트를 지정하고 같은 불변 전환 증적, Hub 완료
증적, 네이티브 승인, 이전 보고 상태를 포함한 갱신 요청을 준비합니다. 로컬 조정 대기, 롤백,
완료 기록에서 이미 시도가 시작됐음을 확인하면 갱신하지 않습니다. `request_id`, `requested_at`,
`expires_at`만 바꿀 수 있습니다.

Hub는 설치 행 잠금 안에서 다음 조건을 모두 확인합니다.

- 대체되는 승인이 해시 체인 감사에 있고 만료됐으며 같은 운영자가 승인했습니다.
- 대체되는 승인이나 해당 전환 증적에 대한 조정 완료 증적 또는 완료 감사가 없습니다.
- 보존된 완료 증적의 인증된 Agent principal, 설치, Entity 및 범위 다이제스트, 권위 있는 UID
  다이제스트, 네이티브 승인과 그 밖의 모든 권한 관련 필드가 바뀌지 않았습니다.
- 현재 Hub 상태가 대체되는 승인의 원본 상태와 같고 열린 Plan이 없습니다.
- 대체되는 승인에 다른 갱신이 없습니다. 같은 갱신 요청의 정확한 재시도는 같은 결과를
  반환하지만 다른 하위 요청은 충돌입니다.

Hub는 새 승인 감사에 `supersedes_approval_digest`를 기록하고 범위가 제한된 새 승인에
서명합니다. 이 승인도 사용하지 않은 채 만료되면 이후 갱신은 이전 승인에서 분기하지 않고
가장 최근 승인을 대체해야 합니다.

**비판 및 수정:** 유효한 승인을 연장하면 기존 권한 범위가 조용히 넓어집니다. 같은 전환
증적만으로 충분하다고 판단하면 Hub 상태, Agent 근거, 운영자 신원의 변경이나 응답을 잃은 완료
처리를 놓칠 수 있습니다. 따라서 갱신은 만료 후에만 새 서명 결정을 만들며 설치 잠금 안에서
현재 상태, 열린 Plan 부재, 신원, 범위, UID, 완료 상태를 다시 확인합니다. 이전 승인을
변경하거나 다시 서명하지 않습니다.

## Agent 조정

Hub는 정확한 전체 정밀도 이전 원본과 엄격한 권위 있는 대체 상태에 서명합니다. Agent는 상태
잠금 안에서 서명, 불변 증적, 산출물 재고 동등성, 범위, UID 재고, 현재 상태, 보고하지 않은
Plan이나 활성 저널 부재를 검증합니다. 원래 바이트를 불변 롤백 기록에 보존하고 현재 상태만
원자적으로 교체합니다.

Agent는 `Agent.Access` 워크로드 신원으로 서명된 대체 상태를 제출합니다. Hub는 신원 또는 상태
변경을 차단하고 정규 상태와 해시 체인 감사를 추가하며 커밋된 상태를 재조회 결과로 반환합니다.
제출이 실패하면 원래 바이트를 복원합니다. 정확한 재시도는 커밋된 Hub 증적을 재사용합니다.
