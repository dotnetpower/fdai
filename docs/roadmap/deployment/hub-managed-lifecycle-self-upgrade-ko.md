# 수명 주기 자체 업그레이드 실패 분석

이 분석은 수명 주기 에이전트, 인프라 에이전트, Target Hub를 두 슬롯으로 교체할 때의 실패와
복구 경계를 정의합니다. #1824의 설계 분석 작업을 완료하지만, 자체 업그레이드 제어기를
구현하거나 적격성을 검증하지는 않습니다.

> **범위:** 슬롯은 실행 가능한 구성 요소 사본 하나입니다. 후보 사본을 시작해도 쓰기,
> 서명, 실행 또는 승격 권한을 부여하지 않습니다. 기존 Plan 승인과 로컬 안전장치가
> 계속 최종 기준입니다.

## 한눈에 보는 설계

후보를 쓰기 권한 없이 시작하는 동안 이전 슬롯을 롤백 대상으로 보존합니다. 정확한 산출물,
호환성 및 상태 검사를 통과한 뒤에만 실행 권한을 세대별로 제한한 논리 역할을 인계합니다.
준비 상태만으로 성공을 확정하지 않고, 독립적인 효과 재확인과 두 번째 무변경 계획이 필요합니다.

| 구성 요소 | 보호할 역할 | 독립 관측 |
|-----------|-------------|-----------|
| 수명 주기 에이전트 | 기존 설치와 네임스페이스 범위의 워크로드 작성자 | 정확한 워크로드 리비전, 상태, 수락 및 사후 조건 기록 |
| 인프라 에이전트 | 기존 정확한 계획 실행기와 Terraform 상태 소유권 | 정확한 계획/상태 계보, 실행 점유, 효과 재확인 및 복구 증적 |
| Target Hub | 카탈로그 수락, Plan 순번, 서명 및 구성 결정 | 영속 카탈로그 하한, 키 세대, Plan/가져오기/감사 이력과 서비스 신원 |

두 사본이 같은 권한 역할을 동시에 소유하지 않습니다. 데이터베이스 포인터나 프로세스 상태
확인만으로 실제 쓰기 경계에서 이전 세대의 실행이 차단됐다고 볼 수 없습니다.

## 현재 소스 경계

[ADR-0003 A20](../architecture/decisions/0003-hub-managed-lifecycle-and-operator-governance.md)은
두 슬롯을 요구하지만 동작하는 인계 제어기를 제공하지는 않습니다.
[수명 주기 에이전트](../../../lifecycle/agent/src/fdai_lifecycle_agent/agent.py)는 준비/적용/복구
상태를 이미 보존하지만, 워크로드 롤백은 구성 요소 자체 교체와 다릅니다.
[Hub 마이그레이션](../../../lifecycle/hub/src/fdai_lifecycle_hub/migrations.py)은 스키마 호환성을
검사하며 [Hub 저장소](../../../lifecycle/hub/src/fdai_lifecycle_hub/store.py)는 Plan과 구성 신뢰를
보존합니다. 이는 향후 제어기의 입력이지, 제어기 구현의 증거가 아닙니다.

워크로드 적용 테스트로 인프라 에이전트나 Target Hub의 자체 업그레이드 결과를 추론하지 않습니다.

## 인계와 중단 조건

향후 제어기는 구성 요소, 설치, Plan/단계 digest, 원본/대상 산출물 digest, 슬롯 신원, 순번과
실행 제한 세대, 멱등성 키, 기한 및 롤백 대상을 묶은 영속 전이 기록 하나를 보존해야 합니다.
설치 밖에는 digest와 수명 주기 메타데이터만 전달합니다. 비공개 키, 원시 구성과 운영 데이터는
전달하지 않습니다.

단계는 다음과 같이 제한합니다.

1. **준비:** 정확한 산출물과 현재 서명, 회수, 수신 대상 및 호환성 입력을 검증합니다.
   이전 슬롯이 계속 작성자입니다.
2. **후보 시작:** 권한 역할을 부여하지 않고 후보의 생존 상태와 읽기 호환성을 확인합니다.
3. **인계:** 새 세대를 원자적으로 보존하고 실제 실행기 경계에서 이전 세대가 쓸 수 없도록
   합니다. 이 차단을 보장할 수 없으면 인계를 보류합니다.
4. **효과 검증:** 선택된 작성자와 기대 효과를 독립적으로 관측합니다. 상태가 잘못됐으면
   준비 상태가 정상이어도 실패 또는 알 수 없음입니다.
5. **확정 또는 복구:** 성공과 무변경 계획을 보존하거나, 보존된 롤백 대상에 대해 이미 승인된
   복구 경로만 실행합니다.

전체, 단계별 및 무진행 기한은 수락한 정확한 Plan과 검토된 구성 요소 정책에서 정합니다.
예산 부재, 남은 허용 구간 부족, 잠금 유실, 신원 변경, 원본 변경, 승인 만료, 모의 실행 실패,
롤백 대상 검증 불가는 인계 전에 보류합니다. 시간 초과가 권한을 부여하거나 대상을 바꾸거나
시도를 조용히 재시작하게 해서는 안 됩니다.

## 실패 분석

| 실패 지점 | 안전한 결과 | 필요한 복구 근거 |
|-----------|-------------|------------------|
| 다운로드, digest 또는 서명 실패 | 이전 슬롯을 유지하고 후보에 역할을 부여하지 않음 | 거절된 정확한 입력과 변경되지 않은 활성 세대 |
| 인계 전 후보 상태 검사 실패 | 후보를 중단하고 이전 역할 소유자를 유지 | 후보 실패와 독립적으로 관측한 이전 슬롯 상태 |
| 회수, 키 철회, 승인 또는 허용 구간 변경 | 다시 검증하고 새 효과를 보류 | 현재 원본, 키 세대와 거절 기록. 이전 권한을 재사용하지 않음 |
| 이전 프로세스가 살아 있거나 네트워크 분리로 보이지 않음 | 이전 세대의 쓰기 차단을 보장하지 못하면 두 번째 작성자를 활성화하지 않음 | 실행기의 세대 거절 또는 명시적인 알 수 없음/운영자 보류 |
| 인계 도중 프로세스 중단 | 응답 유무가 아니라 보존된 세대에서 복구 | 전이 기록과 독립적으로 관측한 실제 역할 소유자 |
| 인계 응답 유실 | 다시 읽어 확인하고 같은 효과를 새 시도로 보내지 않음 | 안정적인 멱등성 신원과 원래 실행 점유/결과 |
| 후보가 요청을 처리하지만 상태가 잘못됨 | 준비 상태만으로 판단하지 않고 두 상태 이력을 보존 | 기대/관측 리비전, digest와 사후 조건 |
| 새 바이너리가 보존된 스키마나 저널을 읽지 못함 | 인계 전 보류 | 명시된 이전/새 리더 호환성과 검증된 복구 경로 |
| 마이그레이션으로 이전 바이너리가 읽지 못함 | 바이너리 전환을 데이터베이스 롤백이라고 부르지 않음 | 순방향 복구 또는 별도로 승인한 검증된 백업 복원 |
| 저장소, 서명 입력 또는 실행 호스트 사용 불가 | 비어 있는 대체 저장소를 만들지 않고 대기/알 수 없음 상태를 보존 | 원래 영속 head, 가용성 실패와 제한된 재시도 결정 |
| 롤백 상태 검사도 실패 | 새 작업을 중단하고 에스컬레이션하며 근거를 보존 | 두 실패 관측, 보존된 잠금/세대 상태와 지정된 복구 담당자 |
| 오프라인 메타데이터가 오래됐거나 회수가 누락됨 | 현재 적격성을 추론하거나 숨은 대체 원본을 가져오지 않음 | 정확한 가져오기 메타데이터와 명시적인 오프라인 제한/보류 |

Target Hub는 슬롯을 바꿔도 카탈로그 하한, 키 세대, 등록/키/범위 결정, 구성 수락/활성화 증적,
Plan 순번 및 감사 계보를 보존합니다. 요청을 직렬화하는 트랜잭션만으로 장기간 서비스 역할의
실행 제한이 구현됐다고 볼 수 없습니다.

## 데이터와 롤백 경계

바이너리 전환은 영속 스키마를 되돌리거나, 중단된 적용을 지우거나, 감사 체인을 초기화하거나,
Trial을 갱신하거나, 이전 키를 현재 키로 바꾸지 않습니다. 두 슬롯은 과거 권한을 복원할 수 있는
슬롯별 사본 대신 권위 있는 보존 기록을 사용합니다.

기존 에이전트의 중단된 적용 복구는 새 작업을 받기 전에 원래 워크로드 시도를 완료하거나
롤백합니다. 향후 자체 업그레이드도 이 우선순위를 유지해야 합니다. 이전 슬롯이 보존 상태를
이해하지 못하더라도 상태 검사를 통과시키려고 기록을 삭제하거나 재초기화하지 않습니다.

[설치에 결속된 사용권과 Trial 연속성](hub-managed-lifecycle-entitlement-ko.md)을 유지합니다.
롤백이나 로컬 기록 부재로 새 설치나 새 Trial을 만들지 않습니다.

## 비판과 수정

| 채택하지 않은 가정 | 수정된 경계 |
|--------------------|-------------|
| 정상 사본 두 개면 고가용성임 | 권한 역할은 하나만 소유하며 세대별 실행 차단을 독립적으로 입증 |
| 포인터 전환이면 이전 작성자가 중단됨 | 실제 쓰기 경계에서 이전 세대를 거절해야 함 |
| 바이너리 롤백이면 데이터베이스도 복원됨 | 인계 전에 호환성을 확인하며 되돌릴 수 없는 데이터 변경에는 명시적 복구가 필요 |
| 응답이 없으면 효과도 없음 | 안정적인 실행 점유와 멱등성 키로 원래 시도를 관측 |
| 복사한 슬롯은 새 사용권을 초기화할 수 있음 | 사용권 상태와 원래 기준 시점은 교체 가능한 슬롯 밖에 보존 |

## 실행 가능한 검증 의무

- [ ] 구성 요소별 제어기를 구현하고 모든 쓰기 경계에서 역할의 세대별 실행 제한을 적용합니다.
- [ ] 세 구성 요소 유형의 모든 영속 전이 직전과 직후에 장애를 주입합니다.
- [ ] 재시작, 중복, 네트워크 분리, 입력 만료, 이전 키, 스키마/저널 및 롤백 사례를 검증합니다.
- [ ] 정확한 연결 설치와 오프라인 Target Hub 효과, 독립 재확인, 이력 보존 및 두 번째
  무변경 계획을 보존합니다.

이는 향후 구현과 적격성 검증 의무입니다. 이 분석을 게시하면서 해당 제어기나 훈련을
실행하지 않았습니다.
