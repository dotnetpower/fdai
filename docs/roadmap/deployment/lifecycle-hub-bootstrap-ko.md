# Lifecycle Hub Bootstrap

Lifecycle Hub의 로컬 Bootstrap 모드에서 웹 화면으로 FDAI의 최초 설치를 준비합니다.
별도의 고객 측 실행기가 기존 배포 CLI와 Terraform을 재사용합니다.
Hub 화면에는 Azure 토큰이나 Terraform 상태가 전달되지 않습니다.

> **범위:** 기존 설치 경로의 진입 화면이며 네 번째 배포 경로가 아닙니다.
> Lite 런타임을 만들거나 설치를 자동으로 등록하거나 Azure 배포를 검증 완료 상태로
> 인정하지 않습니다. 로컬 구현과 실제 환경에서의 설치 수락은 별개입니다.

## 설계 한눈에 보기

하나의 Python 명령이 Hub 설치 화면과 고객 측 실행기를 각각 로컬 프로세스로 시작합니다.
두 프로세스 모두 시작할 때 FDAI Runtime이나 Hub PostgreSQL이 필요하지 않습니다.
비공개 설치 기록은 Hub 데이터베이스, Terraform 상태 또는 설치 원장을 대체하지 않습니다.

| 구성 요소 | 담당 역할 |
|-----------|-----------|
| Hub Bootstrap 화면 | 설치 상태와 정확한 검토 내용을 표시하고 형식이 정해진 요청과 결정을 제출합니다. |
| 고객 측 실행기 | Azure 인증을 관리하고 기존 준비, 승인, 배포, 검증 절차를 실행합니다. |
| 기존 배포 엔진 | 아티팩트 신뢰, 대상 바인딩, Terraform 계획, 마이그레이션, 복구 통제를 유지합니다. |
| 관리형 Lifecycle Hub와 설치 에이전트 | 기존 등록, 소유권, 일정, 업데이트 권한을 유지합니다. |

실행기는 최초 설치를 준비하는 구성 요소이며 수명 주기를 계속 관리하는 별도 주체가 아닙니다.
설치가 완료됐다고 Lifecycle Agent가 자동으로 이를 인수하지 않습니다.
기존 소유권 수락과 상태 인계는 각각 정해진 통제 절차를 따릅니다.

## 로컬 화면 시작

Linux의 Python 3.12 이상과 로컬 브라우저가 필요합니다. 승인된 패키지 공급원에서 검토한
Hub wheel과 선언된 의존성을 설치한 다음 아래 명령을 실행합니다.

```bash
fdai-lifecycle-hub start
```

명령은 사용 가능한 IPv4 루프백 포트를 선택하고 브라우저에서 `/setup`을 엽니다.
유효 시간이 제한된 시작 링크는 한 번만 HTTP 전용 동일 사이트 세션 쿠키로 교환됩니다.
링크를 출력하거나 저장하지 않습니다. `--state-dir`는 비공개 설치 기록 디렉터리를,
`--port`는 특정 루프백 포트를 선택합니다. `--no-browser`는 진단용으로만 시작하며 인증 링크를
출력하지 않습니다. 원격 Hub 구성으로 이 로컬 모드를 활성화할 수 없습니다.

이 소스 변경은 PyPI에 패키지를 게시하지 않습니다. 패키지 이름이나 로컬에서 빌드한 wheel만으로
외부 패키지 인덱스에서 필요한 의존성 버전을 모두 구할 수 있다고 판단하지 않습니다.

## 설치 완료

1. **Azure 로그인**을 선택합니다. 실행기는 운영자의 기본 프로필과 분리된 비공개 Azure CLI
   프로필을 사용합니다. 인증은 Microsoft가 처리하며 토큰은 Hub에 전달되지 않습니다.
2. 접근 가능한 구독, 리전, 월 비용 상한을 선택합니다. 현재 지원 런타임은 Console 프로필을
   사용하는 기존 AKS 구성이며 저비용 Lite 구성은 아닙니다.
3. 서명된 Release Hub 이미지를 선택하고 독립적으로 승인된 Ed25519 공개 키를 제공합니다.
   실행기는 검증한 Release에 명시된 정확한 지원용 체크아웃을 가져올 수 있습니다.
   Terraform과 마이그레이션 지원 소스를 가져오는 것이 서비스 이미지 빌드 권한은 아닙니다.
   명시적 소스 모드는 선택한 깨끗한 체크아웃과 기존 소스 배포 계약을 사용합니다.
4. 준비를 요청합니다. 기존 엔진이 대상, 정책, 용량, 비용, 의존성을 확인합니다.
   선택한 설치 요청에 따라 공급자 등록이 포함될 수 있으므로 외부 변경이 전혀 없는
   Terraform 미리 보기라고 안내하지 않습니다.
5. 실제로 필요한 각 승인 지점을 검토합니다. 결정은 현재 요청, 검토 다이제스트, 만료 시각에
   바인딩됩니다. 삭제나 교체는 정확한 확인 문구를 유지하며 거절은 권한을 부여하지 않습니다.
6. 애플리케이션 초기화와 독립 검증을 기다립니다. Terraform이나 전달 작업이 종료된 때가 아니라
   기존 엔진이 `deployment_ready=true`를 보고한 때만 준비 완료로 표시합니다.

Azure CLI, 소스 도구, 신뢰, 권한, 용량, 아티팩트가 부족하면 차단 사유를 명확히 표시합니다.
화면이 구독 권한을 얻거나 권한 없이 Entra 애플리케이션을 만들거나 신뢰 검사를 약화하거나
알림 없이 소스 빌드로 전환하지 않습니다. 기존 서명된 오프라인 CLI 설치 경로는 그대로 유지하며
이 화면이 오프라인 초기 설정을 지원한다는 뜻은 아닙니다.
선택한 지원용 체크아웃에도 Bootstrap 승인 어댑터가 필요합니다. 해당 프로토콜이 없는 이전
Release는 호환성 문제로 명시적으로 차단하며 터미널 입력을 흉내 내어 진행하지 않습니다.
Hub 이미지 설치는 기존의 최소한의 자체 보고형 Release Hub 배포 요청을 유지합니다.
이 기록이 소유권, 등록 또는 설치 성공을 검증한 것은 아닙니다.

## 실패, 재시작, 복구

브라우저를 닫아도 요청이 다시 제출되거나 실행기가 중단되지 않습니다. 설치 중에는 시작 명령을
실행한 장비를 켜 두세요. 커널 잠금으로 중복 실행을 차단하고 실행기는 작업을 순차 처리하며
현재 프로세스의 하트비트를 게시합니다.

검토 만료, 실행기 종료, 비공개 상태 누락, 검증 실패, 불확실한 외부 변경 결과는 성공이 아닙니다.
재시작하면 요청과 원래 엔진 기록을 보존하되 외부 변경을 자동으로 반복하지 않습니다.
명시적 재개는 저장된 구성과 기존 재조회 및 복구 경로를 사용하며 설치 대상이나 아티팩트 공급원을
바꿀 수 없습니다. 계획이 바뀌면 현재 계획에 대한 결정이 필요합니다.

실패를 지우기 위해 상태 디렉터리를 삭제하지 마세요. 설치 증적과 실행기 전용 인증 자료가
들어 있습니다. 소스 관리 대상에서 제외하고 소유자만 읽을 수 있도록 유지하는 것이 좋습니다.
HTTP API로 원시 Terraform 상태, 자격 증명, 로그를 공개하지 않습니다.
애플리케이션 버전 롤백, 인프라 복구, 데이터베이스 복원은 각각 별개 작업입니다.

검증이 끝나면 Bootstrap을 종료해도 Azure의 FDAI는 계속 실행됩니다. 정기 관리형 업데이트에는
기존 등록, 소유권 수락, 설치 Agent 사전 조건이 여전히 필요합니다.
Bootstrap은 사전 권한이 있는 수명 주기에 버전별 필수 업데이트 버튼을 추가하지 않습니다.

## 설계 비평과 수정

초기 방안은 Hub 서버에 Azure 실행을 포함하고 설치 클릭을 일괄 승인으로 취급했습니다.
또한 설치하려면 무거운 배포 포털부터 준비해야 했습니다. 수정안은 프로세스를 분리하고,
명시적 확인 입력 경로로 기존의 정확한 결정 검증기를 재사용하며, 비공개 상태와 하트비트를
유지하고 런타임 데이터베이스 없이 시작합니다. Release에 고정된 지원 소스 확보와 소스 이미지
빌드는 별개이며 카탈로그 옆에서 내려받은 신뢰 키를 신뢰의 근거로 삼지 않습니다.

로컬 화면은 정확한 루프백 Host/Origin 바인딩, 크기가 제한된 JSON, 인증된 세션, 사이트 간
요청 위조 방지를 사용합니다. 알 수 없는 자산과 요청 필드는 차단합니다.
범위가 제한된 설치 메타데이터만 화면에 전달하며 진단과 자격 증명은 고객 측 실행기에 남습니다.
로컬 설치만으로 네이티브 소유권이나 등록을 추정하지 않습니다.
