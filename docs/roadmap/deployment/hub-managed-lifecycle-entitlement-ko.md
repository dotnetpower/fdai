# Hub 관리형 사용권 연속성

이 결정은 향후 Hub 관리형 설치에 사용권을 전달하되 Hub가 사용권 발급 권한을 갖지 않도록
정의합니다. 업그레이드, 가져오기 및 복구에서도 기존 설치/배포에 결속된 사용권과 원래 Trial
기준 시점을 보존합니다.

> **상태:** 설계 결정만 게시합니다. 이 문서의 Hub 전달, 로컬 인계와 적격성 검증을
> 구현하거나 활성화하지 않습니다.

## 한눈에 보는 설계

사용권 검증과 영속 저장은 설치 내부에 두고 Hub는 전달만 담당하도록 합니다. 기존 사용권은
설치만 읽을 수 있는 암호화 묶음으로 전달할 수 있습니다. Hub는 암호문과 공개 수명 주기
digest만 보며, 비공개 서명 키나 평문 사용권 내용은 보지 않습니다. 설치에 직접 전달하거나
오프라인으로 인계하는 경우도 같은 검증기를 사용합니다.

Release, Plan, 채널 구독, 구성 리비전, Hub 서명 또는 등록은 사용권을 만들지 않습니다.
사용권 적격성은 실행, 승인, 승격 또는 정책 권한을 부여하지 않으며 Release 최대 범위나
헌법의 강제 제약을 넘지 않습니다.

## 기존 권한과 호환성

[소스 배포](source-deployment-ko.md)는 기존 두 결과를 소유합니다. 무결성 서명 키가 없으면
영속적인 30일 Trial 하나를 사용하고, 키를 사용할 수 있으면 설치에 결속된 전체 카탈로그
사용권을 발급합니다. 하나의 키가 무결성과 사용권을 모두 보호하더라도 문서는 용도별로
분리합니다. 키가 있지만 사용할 수 없는 경우 조용히 Trial로 바꾸지 않습니다.

[오프라인 배포](disconnected-deployment-ko.md)는 서명 키트와 독립 검증 경계를 유지합니다.
기존 두 설치 경로에 Hub, 새 서명 키 입력, 게시된 Release 또는 CI 결과를 필수 조건으로
추가하지 않습니다.

[런타임 사용권](../../../services/core-control-plane/src/fdai/runtime/licensing.py)이 설치 조립
경계를 계속 담당합니다.
[영속 Trial 저장소](../../../services/core-control-plane/src/fdai/delivery/persistence/postgres_licensing_trial.py)는
먼저 확정된 활성화 기록을 보존합니다. 행이 없으면 활성화되지 않은 것이지, 읽을 때 활성화해도
된다는 뜻이 아닙니다. 기존 소스 복구도 원래 설치 기준 시점을 보존합니다.

## 전달 결정

| 담당 | 책임 | 허용하지 않는 동작 |
|------|------|--------------------|
| 기존 사용권 발급자/키 보유자 | 승인된 기존 경로로 설치/배포에 결속된 사용권 문서를 발급 | Hub나 고객 구성 서명자가 발급자를 대신함 |
| Hub 또는 Target Hub | 설치만 읽을 수 있는 원본 바이트와 정확한 digest를 전달하고 제한된 가용성을 보고 | 사용권을 발급, 갱신, 확대 또는 재해석 |
| 설치 Agent/인계 어댑터 | 정확한 수신 대상과 전달 용도를 검증한 뒤 원본 바이트를 로컬 사용권 담당자에게 인계 | 전달, 복호화 또는 Plan 서명 성공을 사용권 수락으로 간주 |
| 설치 사용권 담당자 | 발급자, 문서 용도, 결속, 현재 상태와 만료를 독립 검증하고 기존 담당 경계로 저장 | Trial을 초기화하거나 설치/배포 신원을 슬롯/소스/이미지 신원으로 바꿈 |

향후 전달 경로는 용도가 분리된 인증 암호화 묶음을 사용합니다. 설치 암호화 자료는 해당 역할로
독립적으로 준비하며 서명 신원을 암호화 키로 바꾸지 않습니다. 묶음 복호화는 기밀성만
제공합니다. 변경되지 않은 내부 발급자 서명과 로컬 사용권 검사가 적격성을 결정합니다.

원본 문서와 선택된 신뢰 메타데이터를 검증한 뒤 로컬에서 원자적으로 수락합니다. 중복 전달은
같은 신원과 결과를 유지하며, 더 오래됐거나 충돌하는 상태로 새 권위 기록을 교체하지 않습니다.
전달 경로나 비공개 입력이 없으면 사용 불가이며, 전체 사용권이나 새 Trial로 바꾸지 않습니다.

## Trial과 복구 불변 조건

사용권과 Trial은 설치/배포 신원에 결속되며 Release 버전, 소스 커밋, 이미지 digest, Plan 순번,
슬롯 또는 구성 리비전에 결속되지 않습니다. 소스 경로의 설치 생성 기준 시점을 포함해 기존
경로가 정한 원래 Trial 기준 시점과 만료를 보존합니다. 활성화와 시계 안전성 기록은 교체 가능한
슬롯 밖의 권위 있는 설치 저장소에 둡니다.

| 사건 | 필요한 결과 |
|------|-------------|
| 업그레이드, 재시작 또는 채널 변경 | 원래 사용권/Trial을 재사용하고 새 구간을 시작하지 않음 |
| 슬롯 롤백 또는 가져오기 재실행 | 슬롯의 과거 사본이 아니라 현재 권위 있는 사용권 상태를 읽음 |
| 기록이 유실된 동일 설치 복구 | 기존 승인 복구 경로로 검증된 원래 기준 시점과 시계 안전성 상태를 복구. 복구 시각을 생성 시각으로 사용하지 않음 |
| 원래 기준 시점 누락 또는 충돌 | 실행 적격성을 보류하고 새 설치라고 추론하지 않음 |
| 새 설치 또는 배포 신원 | 해당 경로의 명시적인 현재 승인과 독립적으로 유효한 결속을 요구. 등록만으로 적격성을 결정하지 않음 |
| Trial 만료 | 기존 만료 표시와 제한을 유지. 관찰, 진단, 감사 및 내보내기는 소스 소유 문서의 정의를 따름 |
| 수명 주기 단계 중 만료 | 기존 런타임의 거절/허용된 복구 의미를 따르며 대체 사용권을 만들지 않음 |
| 시계 역행 또는 단조 이력 누락 | 기존 시계 차단/알 수 없음 결과를 유지. 복사한 스냅샷으로 해제하지 않음 |
| 수신 대상, 발급자, 용도 또는 결속 불일치 | 유효한 보존 상태를 교체하지 않고 거절 |
| 필요한 신뢰가 철회됐거나 사용 불가/오래됨 | 과거 캐시 주장을 현재 권한으로 수락하지 않고 이유와 함께 해당 적격성을 보류 |

오프라인 수락도 같은 내부 사용권 문서를 검증합니다. 번들 최신성, 회수와 사용권 적격성은
별개이며 새 번들이 Trial을 갱신할 수 없습니다. 오프라인에서 현재 변경을 알 수 없는 상태는
명시적인 제한으로 남기며 숨은 네트워크 대체 경로로 바꾸지 않습니다.

## 비판과 수정

| 채택하지 않은 가정 | 선택한 경계 |
|--------------------|-------------|
| 서명된 Release이면 전체 사용권임 | 별도 사용권 용도와 설치/배포 결속을 검증 |
| 등록하면 Trial이 시작됨 | 기존 승인 활성화 담당자만 원래 기록을 생성할 수 있음 |
| Hub 갱신으로 설치 기간을 늘릴 수 있음 | Hub는 전달만 담당하며 내부 문서나 Trial 기준 시점을 바꾸지 못함 |
| 롤백으로 이전 시계/사용권 기록을 복원할 수 있음 | 현재 공유 설치 상태와 시계 안전성 이력을 보존 |
| 복호화하면 사용권이 입증됨 | 전달 뒤에도 내부 발급자와 적격성을 독립 검증 |
| 오프라인 번들 가져오기는 새 설치임 | 신원, 원래 기준 시점, 만료와 중복 처리 의미를 보존 |

## 남은 구현과 근거

- [ ] Hub 발급자를 만들지 않고 용도가 분리된 전달 경로와 로컬 인계를 구현합니다.
- [ ] 잘못된 키/용도/결속, 재실행, 충돌, 만료, 시계 역행과 사용 불가 사례를 검증합니다.
- [ ] 업그레이드, 슬롯 롤백과 동일 설치 복구에서 원래 기준 시점, 만료 표시, 시계 제한 및
  기존 소스/오프라인 동작을 보존하는지 검증합니다.
- [ ] 저장소에 비공개 키를 두거나 Trial 기록을 만들지 않고 현재 사용권 검증기를 통한
  연결/오프라인 설치 수락을 독립적으로 관측해 보존합니다.

이 결정을 게시하면서 사용권 토큰, Trial 활성화, 서명 키, 배포 또는 권한 전이를 만들지
않았습니다. 이 의무는 설계 작업 완료와 별도로 유지합니다.
