# 노출 추론

이 문서는 CVE, 권고, 제품 결함이 없는 안전하지 않은 외부 도달 가능 리소스 조합을 FDAI가 찾는
방법을 정의합니다. 알려진 시그니처를 대조하는 대신 운영 온톨로지 위에서 추론합니다. 그래서
개발자 포털의 가입 기능을 숨기기만 하고 끄지 않은 API Management처럼 "의도된 동작"으로 분류된
결함도 근거가 있고 설명할 수 있는 발견 사항이 됩니다.

> **권한 경계:** 노출 추론은 읽고 결론을 낼 뿐입니다. 리소스를 승인, 실행, 승격하거나 변경하지
> 않습니다. 모든 결론은 등급이 명시된 증거이고, 모든 교정은 기존 ActionType, 승인, 7대 안전장치
> 경로를 거칩니다.

> **상태:** 제안된 설계입니다. 신규 기능은 shadow 모드로 시작합니다. 구현된 것은 없으며
> [구현 원장](../../roadmap-implementation/operations/exposure-reasoning.md)을 참고하십시오.

## 설계 한눈에 보기

CVE는 "이 제품 버전에 알려진 결함이 있는가?"에 답합니다. 더 어려운 질문은 "이 사실들의 조합이
익명의 상대가 닿아서는 안 되는 곳에 닿게 하는가?"입니다. FDAI는 네 단계로 답합니다.

```text
1. 모델링   Resource -> Endpoint, 도달성, 신원, 데이터 도달 범위를 형식이 있는 사실로 표현
2. 대조     의도(선언된 것)와 시행(실제로 응답하는 것)을 비교
3. 조합     검토된 ExposureMechanism 규칙이 사실을 노출 경로로 결합
4. 결론     holds | refuted | unknown, 증거 등급과 필수 반증 점검 포함
```

예: APIM 인스턴스가 `signup.enabled = false`로 선언합니다. FDAI는 살아 있는 Basic 신원 공급자,
`approvalRequired = false`인 Starter 제품, 공개 개발자 포털 호스트도 관측합니다. 두 메커니즘이
발화하고, 반증 점검에서 Entra 전용이나 승인 게이트를 찾지 못하면 `configuration-inferred` 등급의
`holds`가 됩니다. 허용된 프로브는 이를 `probe-confirmed`로 올릴 수 있습니다.

## 시그니처로 충분하지 않은 이유

| 질문 | 시그니처(CVE, 정책) | 노출 추론 |
|------|---------------------|-----------|
| 알려진 결함이 있는가? | 예 | 대상 아님 |
| 꺼진 것으로 보이는 통제가 실제로는 켜져 있는가? | 아니요 | 예: 의도와 시행 비교 |
| 각각 안전한 설정이 합쳐져 위험한 경로가 되는가? | 아니요 | 예: 조합 |
| 새 서비스 계열이 알려진 결함과 닮았는가? | 아니요 | 예: 구조 지문 |
| 공급자가 "의도된 동작"이라고 하면? | 아무것도 게시되지 않음 | 불변식은 계속 점검 |

FDAI는 모든 미지의 취약점을 발견한다고 주장하지 않습니다. 관측한 사실에 대해 명시한 보안
불변식의 위반을 탐지합니다. 모델링한 불변식을 깨지 않는 결함은 보이지 않습니다.

## 추론 모델

### 다섯 평면

노출된 각 리소스를 다섯 평면으로 기술합니다. 두 평면 사이의 모순이 주된 신호이고, 진입점 뒤에서
도달하는 데이터가 영향을 정합니다.

| 평면 | 질문 | 사실 예시 | 상태 사실 레인 |
|------|------|-----------|----------------|
| 의도 | 소유자가 무엇을 선언했는가? | `signup.enabled = false`, "내부 전용" 태그 | `desired` |
| 시행 | 실제로 무엇이 응답하거나 구성되어 있는가? | Basic 신원 공급자 존재, 리스너 응답 | `observed` |
| 도달성 | 누가 진입점에 닿을 수 있는가? | 공개 호스트, 사용자 지정 도메인, 프라이빗 엔드포인트, 앞단 WAF | `observed` |
| 신원 | 호출자가 어떻게 허용되거나 자격 증명을 발급받는가? | 신원 공급자, 자가 등록, 승인 정책 | `observed` |
| 데이터 도달 | 이 표면이 무엇으로 이어지는가? | 제품 -> API -> 백엔드 -> 데이터 분류 | `derived` |

레인 분리는 기존 상태 사실 메타데이터를 재사용하므로 공급자 관측이 파생 사실로 해석되거나 그
반대가 되는 일이 없습니다.

### 보안 불변식

`ExposureMechanism`은 검토된 불변식 하나를 담습니다. 첫 집합은 다음과 같습니다.

| Id | 불변식 | 위반 패턴 |
|----|--------|-----------|
| `INV-INTENT` | 꺼진 것으로 표시된 통제는 시행 지점에서도 꺼져 있다. | 의도는 끔인데 시행 지점이 여전히 동작을 받는다. |
| `INV-CRED` | 익명 호출자는 보호된 데이터에 대한 자격 증명을 스스로 발급받을 수 없다. | 도달 가능한 자가 등록, 자동 승인, 데이터 도달의 결합. |
| `INV-ORIGIN` | 공유 멀티 테넌트 진입점은 상태를 바꾸는 요청의 출처를 검증한다. | 호스트로 라우팅되는 엔드포인트가 테넌트 결속 없이 쓰기를 받는다. |
| `INV-MGMT` | 관리 평면은 강한 인증 없이 인터넷에서 닿을 수 없다. | 약하거나 기본 신원을 쓰는 공개 관리 또는 SCM 엔드포인트. |
| `INV-DEFAULT` | 기본 신원, 제품, 키가 허용적인 출하 설정으로 남지 않는다. | 출하 시 허용 값을 유지하는 내장 객체. |

### 3값 결론

결론은 `holds`, `refuted`, `unknown` 중 하나입니다. 증거가 없으면 `unknown`이며 안전으로 보지
않습니다. 각 메커니즘은 필수 반증 점검을 나열합니다. 이는
[운영 가설 루프](../rules-and-detection/operational-hypothesis-loop-ko.md)가 인과 주장에 요구하는
방식과 같습니다. 반증 결과가 없는 메커니즘은 `unknown`으로 남습니다.

### 노출 등급

등급은 모델이나 CVSS가 아니라 검토된 결정표에서 나옵니다. 입력은 진입점의 도달성, 자격 증명 획득
방법, 데이터 도달 범위입니다.

| 도달성 | 자격 증명 획득 | 데이터 도달 | 등급 |
|--------|----------------|-------------|------|
| 인터넷, 익명 | 승인 없이 스스로 발급 | 민감 또는 불명 | `critical-potential` |
| 인터넷, 익명 | 승인 없이 스스로 발급 | 공개만 | `medium-potential` |
| 인터넷, 익명 | 승인 필요 | 모두 | `low-potential` |
| 인터넷, 모든 테넌트 | 없음 | 모두 | `informational` |
| 프라이빗 또는 테넌트 범위 | 모두 | 모두 | `not-exposed` |

데이터 도달 범위를 알 수 없으면 민감한 것으로 취급합니다. 등급은 악용이 아니라 잠재적 노출을
나타냅니다. 구성 사실의 상관관계는 누군가 그 경로를 악용했음을 증명하지 않습니다.

## 증거 단계

각 사실은 그것을 뒷받침하는 가장 값싼 단계를 가집니다. 결론은 가장 높은 단계를 기록하며 그 이상을
주장하지 않습니다.

| 단계 | 출처 | 권한 | 비고 |
|------|------|------|------|
| E0 | ARM 및 Resource Graph 구성 | 읽기 전용 | 리소스 속성, SKU, 호스트 이름, 네트워크 설정. |
| E1 | ARM 하위 리소스 읽기 | 읽기 전용 | 신원 공급자, 포털 설정, 제품, 구독. Resource Graph에는 없습니다. |
| E2 | 수동 공개 메타데이터 | 읽기 전용 | 구독이 소유한 이름의 DNS, 인증서, 호스트 이름 확인. |
| E3 | 변경 없는 프로브 | 별도 opt-in 범위 | 소유한 엔드포인트에 대한, 메커니즘이 선언한 부작용 없는 요청. |

E3만 실제 리스너에 닿습니다. 메커니즘은 검토에서 요청이 아무것도 생성, 변경, 삭제하지 않음이
증명된 경우에만 E3를 쓸 수 있습니다. 실제 자격 증명이나 유효한 양식 데이터는 제출하지 않고,
응답은 제한된 분류 결과만 저장합니다. 계정 생성 같은 익스플로잇 단계는 모든 단계에서 범위
밖입니다. 구독이 소유하지 않은 엔드포인트를 프로브하는 일, 인터넷 전체 열거를 포함하여, 은 비목표입니다.

## 온톨로지 추가

[메타모델](../architecture/operating-ontology-metamodel-ko.md)은 고정된 역량 테스트가 기존 객체로
실패한 뒤에만 새 ObjectType을 허용합니다. 이 설계는 `Resource`, `Property`, `Observation`,
`Finding`, `Pattern`, `ConfigurationBaseline`, `ConfigurationDriftFinding`을 재사용하고, 최소한만
shadow와 `projection_owned`로 추가합니다.

| 선언 | 종류 | 목적 | 기존 객체로 부족한 이유 |
|------|------|------|-------------------------|
| `Endpoint` | ObjectType | 도달성 등급, 프로토콜, 평면을 가진 리소스의 외부 주소 지정 가능 진입점. | `Resource`는 독립적으로 도달 가능한 여러 진입점을 담을 수 없습니다. |
| `ExposureMechanism` | ObjectType | 전제, 반증 점검, 검증 축, 프로브 계약을 가진 검토된 불변식. | `DiagnosticMechanism`은 장애 진단을 다루며 안전 불변식을 다루지 않습니다. |
| `resource_exposes_endpoint` | LinkType | `Resource -> Endpoint`. | 새 객체입니다. |
| `endpoint_reaches_resource` | LinkType | 진입점에서 데이터를 가진 리소스까지의 파생된, 시간 범위가 있는 도달. | `routes_to`는 관측된 전달을 나타내며 도달성은 증명하지 않습니다. |
| `finding_instantiates_mechanism` | LinkType | `Finding -> ExposureMechanism`. | 결론 설명에 필요합니다. |

발견 사항은 `Finding`과 기존 `evidence_supports_hypothesis`, `evidence_refutes_hypothesis` 링크를
재사용합니다. `mechanism_validated_by`는 이미 메커니즘을 `BenchmarkValidation` 영수증에 연결합니다.
두 ObjectType 모두 `execution_authority: false`를 설정합니다.

### 역량 질문

고정된 다음 질문이 각 추가의 정당성을 판단합니다.

| Id | 질문 |
|----|------|
| E1 | 인터넷에서 닿을 수 있는 진입점은 무엇이며 어떤 호스트 이름이나 주소를 통하는가? |
| E2 | 선언된 설정이 리소스가 시행하는 것과 모순되는 곳은 어디인가? |
| E3 | 어떤 익명 도달 가능 진입점이 자격 증명으로, 그리고 어떤 데이터로 이어지는가? |
| E4 | 이 결론 중 `unknown`은 무엇이며 어떤 사실이 빠졌는가? |
| E5 | 알려진 결함과 구조 지문이 같은 다른 리소스는 무엇인가? |
| E6 | 왜 이렇게 결론 냈으며 어떤 반증 점검이 실행되었는가? |

## 협업

| 에이전트 | 역할 | 버스 경계 |
|----------|------|-----------|
| Huginn | 진입점과 하위 리소스 증거를 수집하고 정규화합니다. | 이벤트를 게시하며 결론은 내지 않습니다. |
| Heimdall | 보안 관측을 소유합니다. 메커니즘을 평가하고 발견 사항을 게시합니다. | 기존 관측 토픽, shadow. |
| Forseti | 높은 등급의 발견 사항과 교정 제안을 검토합니다. | 판정만 냅니다. |
| Norns | 반복되는 코호트를 후보 메커니즘과 패턴으로 컴파일합니다. | 비활성 후보, 경로 밖. |
| Mimir | 승격 레지스트리를 통해 메커니즘을 승격하거나 강등합니다. | 레지스트리 결과. |

에이전트는 서로를 직접 호출하지 않습니다. 협업은 스키마 검증된 이벤트 버스 토픽만 사용합니다.

## 추론 단계

1. **T0, 결정론.** Rego 규칙이 도달 폐포, 의도와 시행의 모순, 결정표를 위해 온톨로지 사실을
   결합합니다. 기본 단계이며 `holds`를 만들 수 있는 유일한 단계입니다.
2. **T1, 유사도.** 새 서비스 계열을 구조 지문(존재하는 평면, UI로만 막힌 동작과 API로 열린 동작,
   기본 신원, 허용 경로)으로 알려진 메커니즘과 비교합니다. 후보를 제안할 뿐 결론을 내지 않습니다.
3. **T2, 잔여.** 혼합 모델 풀이 어떤 메커니즘도 다루지 않는 역량 그래프에 대해 불변식 위반 후보를
   제안합니다. 후보는 관측된 사실에 대한 점검 가능한 술어로 컴파일되고 결정론적 검증기를 통과할
   때만 인정됩니다. 그렇지 않으면 발견 사항 없이 기록된 가설로 남습니다. T2는 근거에 묶이고, 위험
   게이트와 승인 게이트를 거치며, 코딩 세션은 명시적 요청 없이 이를 위해 실제 모델을 호출하지
   않습니다.

## 사례: API Management 개발자 포털

APIM 인스턴스 하나의 사실과 각 사실을 담는 레인입니다.

| 사실 | 레인 | 단계 |
|------|------|------|
| 서비스 SKU가 classic 티어 계열에 속함 | `observed` | E0 |
| 개발자 포털 호스트가 공개적으로 응답함(프라이빗 네트워크와 IP 제한 없음) | `observed` | E0 |
| `portalsettings/signup.enabled = false` | `desired` | E1 |
| Basic 신원 공급자 존재 | `observed` | E1 |
| Starter 제품이 `subscriptionRequired = true`, `approvalRequired = false` | `observed` | E1 |
| 제품 -> API -> 백엔드 리소스, 데이터 분류 포함 | `derived` | E1 |

1. `INV-INTENT` 발화: 의도는 끔인데 시행 지점에는 살아 있는 등록 공급자가 있습니다.
2. `INV-CRED` 발화: 도달 가능한 포털, 자가 등록, 승인 게이트 없음.
3. `INV-DEFAULT` 발화: 내장 Starter 제품이 허용적인 출하 값을 유지합니다.
4. 반증 점검 실행: Entra가 유일한 공급자인지, 모든 제품에 승인이 필요한지, 도달성이 제한되거나
   프라이빗인지, 백엔드가 자체 인증을 요구하는지 확인합니다. 하나라도 성립하면 경로는 반증됩니다.
5. 반증이 없고 백엔드가 데이터를 가지면 등급은 `configuration-inferred` 등급의
   `critical-potential`입니다. 데이터 분류를 알 수 없어도 `critical-potential`입니다.
6. 인스턴스가 E3를 opt-in했다면, 가입 경로에 보낸 빈 본문 요청이 not-found가 아니라 검증 오류를
   반환할 때 등급이 `probe-confirmed`로 올라갑니다.

티어는 가정이 아니라 모델링된 속성입니다. classic 티어는 포털과 함께 관측됩니다. 포털 동작이
검증되지 않은 티어는 포털 사실이 `unknown`으로 남으므로 인스턴스를 안전으로도 노출로도 표시하지
않습니다.

## 새 CVE 없이 학습하기

새 메커니즘은 검토된 네 출처에서 나옵니다. "의도된 동작"에 대한 권고와 연구, 같은 지문을 가진
플릿 코호트, 인시던트 사후 분석, 검증을 통과한 T2 가설입니다. 각각 Norns의 비활성 `RuleCandidate`가
되어 레이블된 코퍼스를 상대로 shadow에서 실행되고, 측정된 재현율과 거짓 정상 증거로 Mimir의 승격
레지스트리를 거칩니다. 재현율이나 정밀도가 후퇴하면 강등됩니다. 첫 코퍼스 사례는 APIM 가입 결함이며,
Entra 전용 포털과 승인 게이트가 있는 제품 같은 음성 대조군을 함께 둡니다.

## 안전과 경계

- 저장소는 고객 중립을 유지합니다. 메커니즘은 카탈로그 데이터이며 테넌트 값, 엔드포인트, 식별자가
  없습니다. 포크는 코어 코드 수정 없이 카탈로그 데이터로 메커니즘을 추가합니다.
- 프로브는 구독별 opt-in이며 소유한 엔드포인트로 한정되고, 속도 제한, 예산, 감사가 적용되며
  메커니즘이 선언한 안전한 요청으로 제한됩니다. 응답 본문은 저장하지 않습니다.
- 교정은 제안입니다. 신원 공급자 삭제는 파괴적이라 사람 승인이 필요하고, 제품에 승인 필요를
  설정하는 것은 되돌릴 수 있습니다. 둘 다 7대 안전장치를 사용합니다.
- 거짓 양성 예외는 기존 예외 수명 주기를 재사용합니다.
- 불완전하거나 오래된 증거는 정상이 아니라 `unknown` 또는 기록된 공백이 됩니다.

## 제공 계획

| 단계 | 결과 | 종료 증거 |
|------|------|-----------|
| P0 | 역량 질문과, APIM 사례 및 음성 대조군을 포함한 레이블된 코퍼스. | 고정된 테스트가 기존 객체로 실패하여 추가의 정당성을 보여 줍니다. |
| P1 | APIM의 진입점 인벤토리와 E1 하위 리소스 읽기. | 사실이 레인, 단계, 최신성과 함께 나타납니다. |
| P2 | 다섯 불변식의 shadow T0 메커니즘. | 코퍼스 재현율, 음성 대조군에서 거짓 정상 0건. |
| P3 | 프로브 계약과 소유 엔드포인트의 E3. | 변경 없음을 보여 주는 감사 영수증. |
| P4 | 다른 서비스로의 T1 지문 일반화. | 후보를 검토하며 증거 없이 승격하지 않습니다. |
| P5 | T2 가설 경로. | 모든 후보가 검증되거나 가설로 기록됩니다. |

## 비목표

- 경로를 악용하거나, 계정을 만들거나, 실제 자격 증명을 제출하는 일.
- 구독이 소유하지 않은 엔드포인트를 스캔하거나 인터넷 전체를 열거하는 일.
- 모든 미지의 취약점 발견을 보장하는 일.
- CVE, Defender, Azure Policy 평가를 대체하는 일. 그 결과는 입력으로 사용합니다.
- 기존 승인 경로 밖의 자율 교정.
