# FinOps 리소스 효율 및 SKU 결정

이 문서는 FDAI가 구독 전체의 리소스를 분석하고 각 리소스의 크기가 적절한지 판단하며 승인된
변경의 결과를 검증하는 방법을 정의합니다. 별도의 온톨로지, 에이전트 조직 또는 실행 경로를 만들지
않고 상위 FinOps 컨트롤 루프를 구체화합니다.

> **범위:** 이 설계는 구독 분석, 리소스 효율 근거, 서비스 기능군별 크기 조정 프로필,
> 리소스 수준 결정 사례, 절감액 귀속 및 FDAI Console 작업 영역을 소유합니다. 전체 FinOps
> 에이전트 루프는 [FinOps 자율 운영](finops-autonomous-operations-ko.md)에서 다룹니다. 패키지
> 배포와 활성화는 [온톨로지 기반 FinOps 패키지 아키텍처](finops-package-architecture-ko.md)에서
> 다룹니다.
>
> **권한 경계:** 프로바이더 권고, 사용률 점수, 온톨로지 관계 또는 예상 절감액은 결정을
> 뒷받침하거나 자율성을 낮출 수만 있습니다. Forseti가 판단하고, Var가 사람 승인을 기록하며,
> Thor가 실행하고, Heimdall이 효과를 검증하고, Vidar가 복구하고, Saga가 감사 기록을
> 종료합니다.
>
> **현재 상태:** 일반 비용 가드, 크기 조정 `ActionType`, 초기 비용 규칙, Njord 비용 조언,
> Freyr 용량 조언은 있습니다. 이 문서에서 설명하는 구독 분석 변환 결과, 완전한 서비스 기능군
> 프로필, 리소스 효율 결정 프레임, 다중 효과 정산 및 Console 작업 영역은 구현되지 않았습니다.

## 설계 개요

FDAI는 구독을 하나의 범위가 제한된 근거 범위로 분석한 뒤 각 리소스 또는 명시적으로 결합된
대상 집합마다 변경할 수 없는 `DecisionCase`를 만듭니다. 구독은 일괄 실행 대상이 아닙니다. 각
사례는 변경하지 않는 대안과 안전한 대안을 비교하고, 상위 목표를 위반하는 대안을 제거하며,
권위 있는 비용 및 운영 관측으로 예상 효과를 정산한 뒤에만 종료합니다.

```text
subscription evidence scope
  -> resource and relationship coverage
  -> resource or coupled-set DecisionCase
  -> safe ActionOption comparison
  -> judgment, approval when required, and execution
  -> independent operational and cost settlement
  -> subscription-level read-only projection
```

## 분석 범위 및 작업 세분성

### 구독 전체 분석

구독 분석 스냅샷은 다음 항목을 고정하는 것이 좋습니다.

- **식별자:** 구독, 리소스, 리소스 형식, SKU, 지역, 리소스 그룹 및 프로바이더 개정입니다.
- **포괄 범위:** 포함한 리소스 형식, 제외한 형식, 권한, 페이지 구분, 수집 구간 및 명시적
  잘림입니다.
- **관계:** 검토된 링크가 뒷받침하는 서비스, 워크로드, 소유권, 포함, 의존성 및 런타임 호출
  경로입니다.
- **목표:** 하나의 근거 기준 시점에 유효한 비용, 서비스, 복구, 아키텍처, 환경 및 변경 구간
  제약입니다.
- **근거 상태:** 출처 권한, 이벤트 시각, 기록 시각, 최신성, 완전성, 충돌 및 합성 여부입니다.

집계 보기는 비용, 사용률 및 기회 포괄 범위를 보고할 수 있습니다. 이 보기는 범위의 모든
리소스를 변경할 권한을 부여하지 않습니다.

### 리소스 수준 결정

FDAI는 기본적으로 정확한 리소스 하나에 결정 사례 하나를 만드는 것이 좋습니다. VM Scale Set의
SKU와 인스턴스 수처럼 구성원 하나만 독립적으로 변경하면 결과가 유효하지 않은 경우에만 결합
대상 집합을 허용합니다.

모든 결합 집합은 다음 항목을 기록해야 합니다.

- 정확한 리소스 식별자와 개정을 정렬한 목록
- 영향을 받는 전체 집합의 콘텐츠 다이제스트
- 완전성 및 잘림 증적
- 구성된 구성원 수와 영향 범위 상한
- 하나의 인과 순서 및 잠금 계약
- 안전하게 재시도할 수 있는 하나의 멱등성 식별자
- 모든 구성원을 포함하는 테스트된 롤백 계약

결합 집합이 구독 범위에 이르거나, 완전한 구성원 정보를 갖지 못하거나, 하나의 제한된 단위로
롤백할 수 없으면 작업 적격 상태가 아닙니다.

## 온톨로지 프로필

이 기능은 공유 운영 뼈대를 재사용합니다.

```text
BusinessService -> Workload -> Resource -> ResourceType
DecisionCase -> ActionOption -> ExpectedEffect -> ActionRun -> ObservedOutcome
```

FinOps 패키지는 별도 비용 그래프가 아니라 검토된 의미 프로필과 속성 의미를 추가하는 것이
좋습니다. 최소 속성 기능군은 다음과 같습니다.

| 기능군 | 필요한 의미 |
|--------|-------------|
| 비용 기준 | 청구, 상각, 실효 및 정가 비용, 통화, 가격 단위, 약정 포괄 범위 |
| 리소스 구성 | 현재 SKU, 용량, 복제본 수, 자동 확장 범위, 지역, 기능 플래그 |
| 사용률 | 메트릭 식별자, 단위, P50, P95, P99, 최댓값, 관측 구간, 표본 수, 계절성 |
| 서비스 상태 | 지연 시간, 오류율, 제한, 포화도, 여유 용량, SLO 상태, 오류 예산 상태 |
| 권고 근거 | 프로바이더 권고 식별자, 알고리즘 또는 규칙 개정, 분석 기간, 제안 구성, 신뢰도 |
| 예상 경제성 | 예상 비용 변화, 불확실성 범위, 비용 기준 개정, 무효화 조건 |

Azure Advisor 권고는 파생 근거 레인으로 들어갑니다. `Verdict`, `ActionOption`, 승인 또는 현재
리소스에 대한 프로바이더 진실이 아닙니다. Freyr의 크기 조정 조언과 Njord의 비용 조언도 자문
입력으로 유지합니다. Forseti만 완전한 근거를 적격 대안과 최종 결정으로 전환합니다.

첫 release에서는 `Forecast`, `Observation`, `Signal`, `ActionOption`으로 필요한 계보를
보존할 수 있다면 두 번째 영속 `SizingRecommendation` 객체를 만들지 않는 것이 좋습니다. 향후
배부 비율, 방식, 유효 구간 및 정책 개정에 독립적인 수명 주기가 필요할 때만 `CostAllocation`
관계 객체를 추가하는 것이 적절합니다.

## 근거와 권한

| 출처 | 근거 역할 | 증명하지 않는 내용 |
|------|-----------|---------------------|
| Cost Management 내보내기 또는 FOCUS 데이터 집합 | 요금이 적용된 사용량, 비용, 가격 수량, 청구 기간 사실 | 리소스 성능 또는 작업 권한 |
| Azure Resource Graph 및 범위가 제한된 ARM 읽기 | 현재 리소스 식별자, 구성, SKU, 위치, 태그, 프로바이더 관계 | 사용률, 서비스 상태 또는 성공한 변경 |
| Azure Monitor 및 서비스 메트릭 | 용량, 성능, 제한, 가용성, 변경 후 운영 효과 | 최종 청구 절감액 |
| Azure Advisor | 프로바이더가 파생한 최적화 조언과 보조 근거 | FDAI 판단, 승인 또는 안전한 실행 |
| 가격 및 약정 데이터 | 실효 요율, Reservation 또는 Savings Plan 포괄 범위, 시나리오 가격 | 필요한 용량 또는 비즈니스 가치 |
| FDAI 온톨로지 컨텍스트 | 서비스, 워크로드, 소유자, 의존성, 목표, 결정 계보 | 외부 상태 또는 권한 |
| 감사 및 결과 기록 | 결정, 실행, 복구, 검증 계보 | 독립적으로 관측하지 않은 사실 |

일반 분석은 현재 운영 그래프를 먼저 읽습니다. 필수 근거가 오래되었거나, 불완전하거나,
충돌하거나, 사용할 수 없거나, 명시적으로 요청된 경우에만 범위가 제한된 실제 읽기를 수행하는
것이 좋습니다.

## 적격성 및 에이전트 흐름

낮은 비용이 실패한 운영 제약을 상쇄하지 못하도록 결정 순서를 고정합니다.

1. 정확한 대상 식별자와 개정을 확인합니다.
2. 요청 범위의 리소스 및 관계 포괄 범위를 증명합니다.
3. 서비스, 워크로드, 환경, 소유자 및 적용 목표를 확인합니다.
4. `ActionType`, 롤백, 변경 구간, 권한 및 영향 한도를 검증합니다.
5. Njord에 비용 기준과 예상 비용 조언을 요청합니다.
6. Freyr에 용량, 포화도, 여유 용량 및 크기 조정 조언을 요청합니다.
7. Forseti가 강한 제약을 위반하는 모든 대안을 제거하고 최종 결정을 내립니다.
8. 목표가 여전히 충돌하면 Odin이 남은 적격 대안만 순위를 정합니다.
9. 승인된 작업을 Thor를 통해 처리한 뒤 Heimdall과 Saga가 각 예상 효과를 종료합니다.

분류되지 않았거나 매핑되지 않은 리소스도 탐지할 수 있지만 결과는 분석 전용으로 유지합니다.
서비스 및 워크로드 매핑, 환경, 적용 목표, 필수 관계 포괄 범위가 최신이고 완전해질 때까지 변경
대안은 적격 상태가 되지 않습니다. 소유자가 없다고 리소스를 안전하게 변경할 수 있는 것은
아닙니다.

## 근거 복구 및 범위가 제한된 사람 확인

운영 그래프, 권위 있는 프로바이더, 통제된 구성, 승인된 문서 또는 감사 이력에서 결정에 꼭 필요한
사실 하나를 범위가 제한된 복구로 얻을 수 없을 때만 사람에게 묻는 것이 좋습니다. Cost
Optimization 전체 설문을 제시하지 않고 한 번에 하나의 구체적인 질문을 제시합니다.

각 질문은 누락된 사실, 정확한 대상과 개정, 해당 사실이 결정을 차단하는 이유, 응답 가능한 역할,
허용되는 응답 형식, 유효 범위, 만료 시각 및 FDAI가 다시 평가할 결과를 식별해야 합니다. 응답
증적은 응답자, 역할, 대화와 턴, 기록 시각, 유효 구간 및 상관 식별자를 보존해야 합니다.

사람의 응답은 확인 진술입니다. 응답자의 권한과 선언된 범위 안에서 조직 의도, 소유권, 워크로드
우선순위 또는 승인된 운영 구간을 설정할 수 있습니다. 현재 Azure 상태를 단정하거나, 권위 있는
관측을 대체하거나, 작업을 승인하거나, 자율성을 높일 수는 없습니다. 관측과 확인 진술이 충돌하면
명시적인 근거 충돌로 유지합니다.

Forseti는 보류된 결정과 사람 확인이 필요하다는 사실을 소유합니다. Bragi는 질문을 표시하고 대화
포트를 통해 응답을 변환하지만 판단하지 않습니다. 운영자 응답은 운영자 신원으로 타입이 지정된
파이프라인에 다시 들어가며, Forseti는 같은 고정 사례를 재평가하거나 기준 시점이 바뀌면 새
개정을 만듭니다. 이후 실행에 사람 승인이 필요하면 Var가 별도 승인 단계를 수행합니다. 응답이
없거나, 만료되었거나, 응답자에게 자격이 없거나, 근거가 충돌하면 변경 없이 사례를 보류합니다.
FDAI는 사람 확인 과정에서 비밀이나 자격 증명을 요청하지 않습니다.

## 결정론적 서비스 기능군 프로필

하나의 사용률 백분율은 이식 가능한 크기 조정 규칙이 아닙니다. 각 프로필은 검토된 리소스 형식
및 서비스 연결에서 결정론적으로 선택하는 버전 관리 선언 자산입니다. 결정 프레임은 정확한
식별자, 버전 및 다이제스트를 기록합니다. Mimir는 기존 회귀 및 관찰 모드 절차를 통해 승격을
관리합니다.

| 서비스 기능군 | 크기 조정 결정 전 최소 근거 |
|---------------|------------------------------|
| VM 및 VM Scale Sets | CPU, 메모리, 네트워크, 디스크 처리량과 IOPS, 버스트 크레딧, 인스턴스 수, SKU 기능 호환성 |
| Azure SQL 및 PostgreSQL | CPU, 메모리, 데이터와 로그 IO, 연결, 스토리지 증가, 제한, HA, 영역, 백업 요구 사항 |
| AKS 노드 풀 | 요청 및 사용 CPU와 메모리, 대기 Pod, 노드 압력, 중단 예산, 토폴로지, 자동 확장 범위 |
| App Service 및 Container Apps | 요청 동시성, 복제본 사용률, 지연 시간, 오류율, 콜드 스타트, 확장 이벤트, 최소 복제본 |
| Storage | 컴퓨팅 사용률이 아니라 용량, 트랜잭션 구성, 접근 빈도, 중복도, 검색, 복제, 송신 |

프로필은 분석 기간, 집계, 백분위수, 최소 표본, 계절성 제외, 여유 용량 목표, 비호환성 검사 및
반증 조건을 정의하는 것이 좋습니다. 배포 정책은 검토된 의미 경계 안에서 임계값을 제공합니다.

## 결정 분류

운영자용 변환 결과는 허용된 각 리소스를 다음 중 하나로 분류하는 것이 좋습니다.

- **축소:** 더 저렴하고 범위가 제한된 대안이 모든 상위 목표를 충족합니다.
- **유지:** 현재 기준 시점에서 현재 구성이 가장 적합한 적격 대안입니다.
- **확대:** 용량 또는 서비스 목표를 충족하려면 더 큰 용량이나 다른 SKU가 필요합니다.
- **확장 또는 예약 실행:** 자동 확장, 인스턴스 수 또는 운영 일정이 고정 SKU 변경보다
  적합합니다.
- **중지 또는 폐기:** 완전한 근거가 리소스를 사용하지 않음을 증명하고 별도의 적절한
  `ActionType`이 안전한 제거를 통제합니다.
- **검토 필요:** 근거가 불완전하거나, 오래되었거나, 충돌하거나, 결정론적 정책 범위를
  벗어납니다.

이 값은 표시용 분류입니다. 정규 기계 기록은 기존 객체, 결정 및 작업 값을 계속 사용합니다.

## 절감액 귀속 및 효과 정산

절감액은 근거 강도에 따라 분리해야 합니다.

| 단계 | 의미 | 주장 경계 |
|------|------|-----------|
| 예상 절감액 | 변경하지 않는 기준선과 하나의 대안 사이의 예상 차이 | 시나리오 전용이며 실현된 값이 아님 |
| 검증된 실행 요율 절감액 | 비교 가능한 수요 구간으로 정규화한 변경 후 사용량과 성능 | 귀속 근거가 있는 리소스 또는 워크로드 |
| 약정 인식 상각 실행 요율 | Reservation, Savings Plan, Hybrid Benefit, 실효 가격을 반영한 검증된 실행 요율 | 가격 증적이 포괄하는 범위 |
| 청구서 배부 정산 | 최종 청구 데이터로 확인하고 검토된 규칙으로 배부한 비용 차이 | 명시적 리소스 배부 증적이 없으면 계정 기간 또는 cohort |

각 대안은 비용, 여유 용량, 지연 시간 또는 오류, SLO, 종속 워크로드, 복구 가능성에 대해 별도의
예상 효과를 선언하는 것이 좋습니다. Heimdall은 각 효과를 `verified`, `failed`, `censored`,
`unscorable` 중 하나로 종료합니다. 프로바이더 API 성공, 더 낮은 정가 또는 비교 가능한 수요
없이 관측된 비용 감소는 실현 절감액이 아닙니다.

사용량 최적화와 요율 최적화는 같은 기준선을 중복 계산하지 않아야 합니다. 약정 구매는 승인된
리소스 효율 결정을 반영한 뒤 남은 용량을 기준으로 삼는 것이 좋습니다.

## Console 정보 구조

Console은 다섯 개의 안정적인 탐색 도메인을 유지합니다. FinOps는 안정적인 기계 식별자
`cost-governance`와 기존 `/verticals/cost-governance` 경로 기능군을 사용하는 전체 현황 아래의
비용 거버넌스 작업 영역으로 표시합니다. 에이전트별 메뉴나 여섯 번째 Activity Bar 도메인은
추가하지 않습니다.

패키지가 비활성 상태이거나 사용할 수 없어도 탐색 항목은 계속 표시합니다. 설정 > 런타임
정책에서 패키지 상태를 보여 주며, 소유자는 감사되는 활성화 제어를 사용할 수 있습니다. 데이터
접근은 목적과 범위가 제한된 별도 권한으로 유지합니다. 작업 영역이 활성 상태이지만 보존된 신뢰할
수 있는 관찰이 없으면 예시 비용 값을 만들지 않고 빈 근거 상태를 표시합니다.
명시적인 인증 사용자 검토 정책을 사용하면 개발 배포에서 집계 수준으로만 접근할 수 있습니다.
브라우저 Entra 신원은 그대로 유지하며 패키지 활성화 또는 작업 권한을 부여하지 않습니다.

로컬의 신뢰할 수 있는 분석 수집기는 범위가 제한된 Azure Consumption Usage Details, 구독 예산,
Azure Advisor 비용 권고 및 지원되는 Azure Monitor 메트릭을 변경할 수 없는 하나의 스냅샷으로
결합합니다. 가명 처리된 리소스 및 권고 참조, 정확한 원본 시각, 완전성 및 타입이 지정된 제약만
저장합니다. Advisor 레코드는 프로바이더 후보로 유지하며 `DecisionCase`, 승인, 실행 또는 검증된
절감액 레코드가 되지 않습니다.

| 작업 영역 페이지 | 주요 변환 결과 |
|------------------|----------------|
| 개요 | 총비용, 분석 포괄 범위, 예상 기회, 검증된 절감액, 목표 위험, 사용할 수 없는 근거 |
| 리소스 효율 | 리소스 인벤토리, 현재 SKU, 사용률, 결정 분류, 근거 상태, 제안 대안 |
| 최적화 사례 | `DecisionCase`, 대안, 최종 결정, 승인, 작업, 복구 기록의 읽기 전용 상관 |
| 성과 | 예상 효과, 관측 결과, 검증된 절감액, 회귀, 롤백, 해결되지 않은 정산 |

최적화 사례 페이지는 `DecisionCase`를 변경하지 않습니다. 실제 상태는 Saga 감사, Thor 작업,
Var 승인, Vidar 롤백, Heimdall 결과 기록을 소유한 변환 결과에서 가져옵니다. 모든 집계는 가장
좁게 필터링된 근거 경로로 연결합니다. 근거가 없으면 브라우저에서 추론하지 않고 이유와 함께
사용할 수 없음으로 표시합니다.

## 전달 및 승격 게이트

기능을 범위가 제한된 단계로 전달합니다.

| 단계 | 동작 | 종료 근거 |
|------|------|-----------|
| A0 분석 | 읽기 전용 구독 및 리소스 변환 결과 | 정확한 식별자, 출처 포괄 범위, 최신성, 부정 사례 fixture |
| 관찰 모드 | 변경 없이 결정 사례를 만들고 대안을 비교 | F1-F8 역량, 서비스 프로필 재생, 정책 이탈 0건, 측정된 권고 정확도 |
| 비운영 사람 승인 | 승인 후 가역적인 리소스 범위 변경 실행 | 7가지 보호 장치, 롤백 훈련, 완전한 최종 감사, 독립 정산 |
| 범위가 제한된 적용 | 상시 정책 안에서 승격된 저위험 작업만 검토 | 실제 cohort, 목표 회귀 0건, 완전한 정산, 독립적으로 검토된 승격 |

별도로 검토된 작업 프로필과 실제 cohort가 더 좁은 자세를 증명할 때까지 운영 환경의 크기 조정은
사람 승인을 유지합니다. 패키지를 사용할 수 있거나 활성화했다고 작업이 승격되지는 않습니다.

## 외부 설계 입력

이 설계는 외부 지침을 권한 우회가 아니라 검토된 근거로 사용합니다.

| 출처 | 설계 입력 |
|------|-----------|
| [FinOps 사용량 최적화](https://www.finops.org/framework/capabilities/usage-optimization/) | 비즈니스 요구 사항을 보존하면서 낭비, 예약 실행, 확장, 크기 조정, 워크로드 변경을 구분합니다. |
| [FinOps 요율 최적화](https://www.finops.org/framework/capabilities/rate-optimization/) | 리소스 효율과 약정 절감액을 분리하고 중복 계산을 방지합니다. |
| [Azure Advisor VM 및 VMSS 최적화](https://learn.microsoft.com/en-us/azure/advisor/advisor-cost-recommendations) | 백분위수 기반 CPU, 메모리, 네트워크 근거, 조정 가능한 분석 기간, 기능 호환성, 워크로드 특성을 사용합니다. |
| [Azure Cost Optimization workbook](https://learn.microsoft.com/en-us/azure/advisor/advisor-workbook-cost-optimization) | 개요, 사용량 최적화, 요율 최적화를 구분하고 필터와 근거 상세 탐색을 유지합니다. |
| [FOCUS 사양](https://focus.finops.org/) | 프로바이더 관측이나 배부 정책을 대체하지 않고 비용 및 사용량 데이터를 정규화합니다. |

프로바이더 임계값과 권고 알고리즘은 버전 관리되는 근거 입력입니다. 보편적인 온톨로지 경계,
FDAI 정책, 승인 또는 실행 권한이 아닙니다.

## 비목표

- Reservation 또는 Savings Plan 구매, 요율 협상, 약정 포트폴리오 관리
- 예산 집행, 비용 재청구, 공유 비용 배부, 조직 전체 재무 정책
- FinOps 상위 에이전트, 비공개 Workflow 버스, 변경 가능한 사례 저장소, 두 번째 온톨로지 그래프 생성
- 구독을 하나의 변경 대상으로 취급
- 정가 계산, 프로바이더 수락 또는 불완전한 청구 데이터로 절감액 주장
- 모든 Azure 서비스에 하나의 일반 사용률 임계값 적용
