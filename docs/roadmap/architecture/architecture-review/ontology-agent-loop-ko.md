# 온톨로지 기반 ARB 에이전트 루프

이 설계는 FDAI 운영 온톨로지와 고정된 15개 에이전트가 계획된 변경을 검토하는 방식을
정의합니다. 의미, 권한, 실행, 관측, 학습을 서로 다른 책임 경계로 유지합니다.

> **범위:** 이 문서는 ARB 결정 루프를 담당합니다.
> [근거 및 권한 계약](evidence-and-authority-ko.md)은 근거 연결, 승인, 위험, 운영 종료를
> 담당합니다. [전달 계획](delivery-plan-ko.md)은 구현 순서를 정의합니다.
>
> **권한 경계:** 온톨로지는 식별자, 관계, 시간, 근거, 제약 조건을 검증합니다. 온톨로지
> 자체는 판단하거나 승인하거나 실행하지 않으며 자율성도 높이지 않습니다.

## 한눈에 보는 설계

정규화된 `Change` 하나가 범위가 제한된 검토 하나를 시작합니다. Muninn은 현재 운영
컨텍스트를 고정하고, 관련 전문 에이전트는 자신이 소유한 근거를 게시하며, Forseti는 필수
입력을 결합해 변경할 수 없는 `DecisionCase`와 `ImpactEnvelope`를 만듭니다. Odin은 적격한
목표 간 충돌만 해결합니다. Var는 정책이나 잔여 위험 때문에 필요한 경우에만 사람 승인을
요청합니다.

![한눈에 보는 설계. 주요 단계는 Huginn: Change, Muninn: context snapshot, Relevant specialists, OperationalEvidenceBundle, Ontology scenario branch, Forseti: DecisionCase, Mimir: constraints and policies, Odin: arbitration, Var: approval, Decision receipt, Saga: audit and Process projection, Thor: execution입니다.](../../../diagrams/generated/fdai-roadmap-architecture-architecture-review-ontology-agent-loop-01.ko.svg)

## 권위 있는 상태 모델

ARB 읽기 모델은 에이전트가 소유한 레코드에서 파생됩니다. 변경 가능한 점검 상태를 두 번째
원본으로 사용하지 않습니다.

| 레코드 | 권한 | ARB 사용 방식 |
|--------|------|---------------|
| `Change` | Huginn | 정확한 제안 개정, 대상, 행위자, 목표 상태 다이제스트, 상관관계 |
| `OperationalContextSnapshot` | Muninn이 지원하는 변환 결과 | 시간 일관성이 있는 토폴로지, 목표, 담당 체계, 최신성, 충돌 |
| `OperationalEvidenceBundle` | 검증된 공급자 증적 | 변경할 수 없는 온톨로지, 상태, 카탈로그, 문서 근거 레인 |
| `ArchitectureConstraint` 및 `Policy` | Mimir | 유효한 제약 조건과 결정적 평가 규칙 |
| 도메인 관측 | Heimdall, Njord, Freyr, Loki | 신뢰성, 보안, 비용, 용량, 성능, 복구 근거 |
| `DecisionCase` 및 `ImpactEnvelope` | Forseti | 범위가 제한된 선택지, 무조치 기준선, 보호 목표, 불확실성, 영향 한도 |
| `ArbitrationDecision` | Odin | 헌법상 적격한 완화 가능한 목표 절충안 중 선택 |
| `Approval` | Var | 정책상 사람이 필요할 때 현재 범위에 결합된 승인 |
| `Decision` 및 감사 체인 | 소유된 이벤트에 대한 Saga 변환 결과 | 재현 가능한 결정, 조건, 권한 근거, 종료 상태 |
| `ActionRun` | Thor | ARB 결정과 일반 액션 게이트를 통과한 별도 실행 |
| `ObservedOutcome` | Heimdall | 예상 효과에 대한 독립적인 효과 종료 |

`ReviewCase`와 `ReviewCheck`는 읽기 모델로 유지합니다. Process와 Console에 이 레코드를
요약하지만, 자체적으로 결정을 만들거나 근거를 준비 상태로 표시할 수는 없습니다.

## 15개 에이전트 책임 모델

모든 에이전트는 ARB 책임을 가질 수 있지만, 검토 대상의 온톨로지 관계와 활성 목표에 관련된
에이전트만 활성화합니다.

| 에이전트 | ARB 책임 | 활성화 조건 |
|----------|----------|-------------|
| Odin | 적격한 목표 간 충돌을 중재합니다. | 강한 제약 조건 적용 후 적격 선택지 두 개 이상이 충돌합니다. |
| Thor | 별도로 승격된 액션을 실행합니다. | 최종 액션 판정이 모든 액션 게이트를 통과합니다. |
| Forseti | 근거를 결합하고 제약 조건을 평가하며 사례와 결정 권고안을 만듭니다. | 모든 계획된 변경 검토에 참여합니다. |
| Huginn | 정확한 `Change` 개정을 정규화하고 중복을 제거하고 연관 지어 게시합니다. | 계획된 변경이 수신됩니다. |
| Heimdall | 그래프와 원격 분석 상태를 검증하고 효과를 독립적으로 종료합니다. | 신뢰성, 보안, 드리프트, 예측, 종료 결과 근거가 필요합니다. |
| Vidar | 복구 준비 상태를 검증하고 실패 후 복구를 소유합니다. | 제안된 변경에 롤백 또는 복구 근거가 필요합니다. |
| Var | 역할, 정족수, 시간 제한, 자체 승인 금지를 적용합니다. | 정책상 필수이거나 잔여 사람 승인이 필요합니다. |
| Bragi | 운영자 요청을 번역하고 근거에 기반한 결과를 설명합니다. | 대화형 시작 또는 설명 요청이 있습니다. |
| Saga | 감사 의도, 결정 계보, 조건, 종료 상태를 저장합니다. | 모든 검토 전이에 참여합니다. |
| Mimir | 활성 제약 조건과 정책을 제공하고 승인된 카탈로그 변경을 관리합니다. | 제약 조건 평가 또는 승인된 제약 조건 변경이 있습니다. |
| Muninn | 변경 개정을 보존하고 범위가 제한된 컨텍스트를 구체화합니다. | 모든 계획된 변경 검토에 참여합니다. |
| Norns | 반복 검토 결과에서 비활성 규칙 후보를 제안합니다. | 범위가 제한된 결과 집단에 재사용 가능한 패턴이 나타납니다. |
| Njord | 비용 목표와 예산 효과를 평가합니다. | 비용에 민감한 서비스 또는 리소스가 범위에 포함됩니다. |
| Freyr | 용량과 성능 효과를 평가합니다. | 용량 또는 성능 목표가 범위에 포함됩니다. |
| Loki | 스스로 승인하지 않고 복원력 실험을 제안합니다. | 기존 근거만으로 복구 동작을 안전하게 입증할 수 없습니다. |

## 근거 분기 및 결합

에이전트는 형식화된 게시 및 구독으로만 협업합니다. 검토 조정기는 기계적인 역할만 수행하여
기한과 필수 근거 키를 기록합니다. 계속 진행할지, 보류할지, 상향할지는 Forseti가 결정합니다.

1. Huginn은 변경할 수 없는 `Change` 하나를 게시하고 하나의 상관관계 ID와 요청된 온톨로지
   릴리스 digest를 유지합니다.
2. Muninn은 정확한 그래프 릴리스와 근거 기준 시점에 대한 보안이 적용된 스냅샷을 만듭니다.
   인증된 그래프 근거를 만들려면 스냅샷의 관계를 독립적으로 검증해야 합니다.
3. 관련 전문 에이전트는 같은 사례 참조를 사용해 자신이 소유한 객체 토픽에만 게시합니다.
4. Forseti는 해당 exact 스냅샷을 planned-change 그래프 증적으로 변환하고 온톨로지 릴리스를
   요청 digest와 비교한 뒤 기한 안에 정책이 요구한 근거 집합을 결합합니다. 누락, 오래됨,
   인증되지 않음, 충돌, 합성 또는 잘림 상태는 권한 상한을 낮춥니다.
5. 사람에게 요청하기 전에 FDAI는 범위가 제한된 재수집, 대체 권위 원본, 결정적 재평가,
   더 작은 안전 선택지를 시도합니다.

느리거나 실패한 구독자는 관련 없는 작업을 막지 않습니다. 결합 책임자는 침묵을 성공으로
해석하지 않고 누락되거나 늦은 분기를 명시적으로 기록합니다.

현재 런타임 연결도 이 경계를 관찰 전용으로 유지합니다. 전용 비에이전트 consumer group이
소유된 `object.change`, `object.state-snapshot`, 전문 에이전트 토픽, `object.verdict`,
`object.audit-entry`를 읽고 변경할 수 없는 `ArchitectureReviewObservationTrace`를 재생하며,
종료된 observer `gave_up`/`halted` 상태를 성능 저하 근거로 보존합니다. 이 연결은 에이전트를
직접 호출하지 않고 런타임 상태를 변경하지 않으며 실행 권한도 부여하지 않습니다. ARB 단계에
해당하는 고유한 소유 레코드가 아직 없으면 추적은 성공을 합성하지 않고 보류 상태로 남습니다.

## 자율 검토 수준

자율성은 변경보다 검토 작업에 먼저 적용됩니다. 기계 준비 상태는 운영 권한과 같지 않습니다.

| 수준 | 조건 | 결과 |
|------|------|------|
| 자동 적합성 검토 | 정확한 변경, 최신의 완전한 그래프, 활성 목표와 제약 조건, 검증된 근거, 제한된 영향, 충돌 없음 | 범위가 제한된 상시 권한으로 적합 권고안을 기록합니다. |
| 자동 조건부 검토 | 결정적으로 생성한 조건으로 알려진 모든 미비점을 해소할 수 있습니다. | 조건을 기록하고 근거가 바뀌면 자동으로 재평가합니다. |
| 사람 승인 | 정책이 사람을 요구하거나 예외가 요청되거나 영향이 크거나 잔여 모호성이 남습니다. | Var가 정족수와 만료가 있는 범위 지정 승인을 엽니다. |
| 보류 또는 수락하지 않음 | 근거가 불완전하거나 오래되거나 충돌하거나 대상이 일치하지 않거나 강한 제약 조건을 위반합니다. | 변경을 적용하지 않고 이유와 다음 근거 작업을 기록합니다. |

아키텍처 기준선 변경, 운영 승격, 되돌릴 수 없는 변경, 예외는 그래프 결과가 양호하다는 이유만으로
자동 권한을 얻지 않습니다.

## 검토 변환 결과

Console은 하나의 녹색 또는 빨간색 상태 대신 다음 축을 별도로 표시하는 것이 좋습니다.

- **근거 상태:** 완전함, 불완전함, 오래됨, 충돌, 사용할 수 없음.
- **평가 상태:** 적합, 조건부, 위반, 보류.
- **권한 상태:** 관찰 전용, 상시 권한, 승인 필요, 승인됨.
- **실행 상태:** 요청하지 않음, 대기, 실행 중, 검증됨, 실패, 복구됨.
- **학습 상태:** 부적격, 집단 수집 중, 후보 제안됨, 카탈로그 검토됨.

표시되는 모든 상태는 상태를 만든 정확한 `Change`, 컨텍스트 다이제스트, 근거 묶음 다이제스트,
`DecisionCase`, 조건, 승인, 감사 레코드로 연결됩니다.

## 현재 미비점

| 미비점 | 필요한 수정 |
|--------|-------------|
| 계획된 변경 평가가 이제 `ChangeGraphEvidenceReceipt.unavailable()`로 대체됩니다. | 정확한 `OperationalContextSnapshot`에서 증적을 연결해 계획된 변경 검토가 인증된 그래프 개정, 릴리스 일치 여부, 최신성, 잘림 상태를 함께 전달하도록 만듭니다. |
| 워크플로 병렬 분기가 호출자가 제공한 결과를 기록합니다. | 에이전트가 소유한 형식화된 근거로 분기를 구동하고 기한을 명시적으로 기록합니다. |
| ARB 변환 결과가 매니페스트 상태를 직접 읽습니다. | 결정 계보와 검증된 근거에서 `ReviewCase`와 `ReviewCheck`를 파생합니다. |
| `OperationalEvidenceBundle`과 시나리오 분기가 ARB에 구성되지 않았습니다. | Forseti가 검토 `DecisionCase`를 만들기 전에 두 기반을 연결합니다. |
| 운영 의도 인스턴스가 전체 경로에서 입증되지 않았습니다. | 서비스, 복구, 비용, 담당 체계, 제약 조건, 변경 구간 인스턴스와 최신성을 변환합니다. |
| ARB 추적 런타임 연결은 현재 실제로 게시되는 소유 토픽만 다룹니다. | 관찰 전용 런타임 추적이 누락 단계를 합성하지 않고 첫 번째 수직 경로를 닫을 수 있도록 context, evidence bundle, impact envelope, recommendation, 파생 `ReviewCase` 변환 결과에 대한 소유 레코드를 확장합니다. |
