# 온톨로지 추론 커버리지 확장과 현재 경로 수렴

이 문서는 질문 형식 컴파일러가 아직 다루지 못하는 조회와, 현재 판단 경로를 같은 기준으로 끌어올리는
수정을 설계합니다. 각 패키지는 대응하는 추적 결함이나 지원되지 않음 이유, 추가하는 닫힌 계약, 독립
검사가 그것을 확인하는 방법, 작업을 끝내는 근거를 밝힙니다. 이 문서는
[온톨로지 추론 컴파일러](ontology-reasoning-compiler-ko.md)를 확장합니다.

> **상태:** 2026-10-01 제안 설계입니다. 전달 상태와 남은 작업은
> [구현 원장](../../roadmap-implementation/interfaces/ontology-reasoning-coverage-expansion.md)에 있습니다.
> 라이브 종료 조건에는 [승격 프로그램](ontology-reasoning-promotion-program-ko.md#검증-프로그램)에서
> 설명하는 것처럼 Owner의 명시적 요청이 필요합니다.

## 설계 개요

현재 판단 경로는 오늘 프로덕션 턴에 답하는 planner입니다. 질문 형식 경로는 닫힌 질문 형식을 읽어
shadow나 로컬에서 실행되는 컴파일러입니다. 현재 경로 수렴(E1부터 E5)은 그 planner가 컴파일러와 같은
닫힌 의미를 담고, 확인하고, 필요하면 보류하게 합니다. 커버리지 확장(E6부터 E9)은 컴파일러가 지금
거절하는 조회를 다루게 합니다. 어떤 패키지도 단어에서 의미를 읽지 않습니다. 새 조회는 모두 기존
규칙을 지킵니다. 컴파일할 수 없는 제한은 그 목표를 보류하며 답변을 넓히지 않습니다.

| 패키지 | 대응 대상 | 계약 변경 |
|--------|-----------|-----------|
| E1 타입 제약 슬롯 | 현재 경로에서 반영되지 않은 기간, 리전, 인시던트 상태 제한 | 버전 있는 판단과 frame 계약 |
| E2 피연산자 출처 | plan 모델이 지어낼 수 있는 식별자 리터럴(R2의 나머지) | Core 내부의 바인딩 증적 |
| E3 현재 경로의 관계 | 이름 붙은 인스턴스 하나에 대한 관계 질문과 T2 상태 검토 | 없음. 공유 컴파일러 핵심 사용 |
| E4 독립 질문 | 긴 대화 후반에 흐트러지는 독립 질문 | 없음. 라우팅 근거만 사용 |
| E5 턴 예산 예약 | 턴 예산을 소진하는 스키마와 변경 기간 질문 | 경로별 예약 계획 |
| E6 컨테이너 종류별 그룹화 | 리소스 그룹별처럼 그룹마다 세는 개수 | 형식 필드와 탐색 루트 계보 |
| E7 상태 이상, 이력, 수명 주기 | 단일 대상 상태 이상, 상태 이력, 다른 ObjectType의 수명 주기 | 검토된 reader와 도메인 |
| E8 인과 변화 지점 | 변화 지점과 완전한 집계가 필요한 이유 질문 | 검증된 인과 등급 증적 |
| E9 남은 연산자와 의미 | 순위, 비교, 버전, 검증, 진단, 경로, 매핑되지 않은 관계 의미 | 검토된 레시피, 문법, 특성 |

## 현재 경로 수렴

### E1 타입 제약 슬롯

판단 계약에 블라인드 해석이 찾은 제한을 담을 필드가 없어서, 24시간 기간, 리전, 인시던트 상태를 밝힌
추적 턴이 `semantic_constraint_uncovered`로 보류되었습니다.

- 판단과 frame 계약에 블라인드 해석의 `ConstraintRole` 값과 일대일로 대응하는 타입 슬롯을
  추가합니다. 슬롯은 시간 기간, 위치나 속성 조건식, ObjectType별 수명 주기 상태, 그룹 기준 측정값,
  관계 경로, 이전 결과나 서수 참조입니다.
- 각 슬롯 값은 검토된 수명 주기 도메인과 리전 코드를 포함해 컴파일러가 쓰는 개념 카탈로그를 통해
  온톨로지에 대한 닫힌 선택으로 근거화됩니다. 모델이 근거화하지 못한 슬롯은 바인딩되지 않은 채로
  남고 턴을 보류합니다.
- 커버리지 검토는 블라인드 해석을 자유 facet 토큰이 아니라 슬롯과 비교합니다.
- 두 계약은 [H1](ontology-reasoning-result-handles-ko.md#h1-계약)의 롤아웃에 안전한 버전 규칙에 따라
  부 버전을 올립니다. 이전 페이로드는 지금의 동작을 유지합니다.

**종료 조건:** 추적된 기간, 리전, 인시던트 상태 질문에서 두 번 반복하는 동안 반영되지 않은 제약
보류가 0건입니다.

### E2 바인딩 증적을 통한 피연산자 출처

모델 계획의 모든 식별자 피연산자가 발화, 이전 턴, 결속된 문맥에 나타나야 한다는 검사는
철회되었습니다. 정확한 이름 바인딩의 리소스 ID처럼 서버가 근거화한 식별자도 정당하게 모델 계획에
들어가기 때문입니다.

- 판단의 바인딩 단계는 자신이 바인딩한 식별자마다 원본 span, 검토된 조회, 바인딩된 식별자를 담은 타입
  증적을 기록합니다.
- plan 검증기는 span, 이전 턴, 신뢰하는 결속 문맥, 결과 핸들, 또는 그런 증적에서 온 식별자 피연산자만
  받습니다. 그렇지 않으면 턴을 `semantic_operand_without_source`로 보류합니다.
- 인스턴스와 스키마를 구분하는 나머지 절반은 이미 인스턴스에 대한 답변 종류에 선언만 읽는 계획을
  보류합니다.

**종료 조건:** 코호트와 홀드아웃에서 지어낸 식별자 리터럴이 0건이고, 인스턴스 대상에 대한 스키마
답변이 0건입니다.

### E3 현재 경로의 관계

이름 붙은 인스턴스 하나에 대한 관계 질문은 frame으로 표현할 수 없어서 현재 경로가 보류합니다. 판단의
해석이 바인딩된 앵커 하나에 대한 관계이면, planner는 frame 빌더 대신 검토된 side와 V-SEM 관계 검사를
갖춘 공유 관계 컴파일러로 컴파일합니다. 그러면 T2 상태 검토는 facet 토큰 대신 ObjectType, 상태 개념,
극성, 시간 기준 같은 닫힌 의미 축을 비교합니다. 따라서 온톨로지가 답할 수 있는 해석이 두 판독자가
다른 단어를 썼다는 이유로 보류되지 않습니다.

**종료 조건:** 추적된 관계와 상태 검토 질문이 현재 경로에서 답하고, V-SEM이 현재 경로가 내보내는 모든
관계 계획을 수락합니다.

### E4 긴 대화 속 독립 질문

라이브 탐색에서 라우터가 긴 대화 후반의 독립적인 서비스 상태와 Key Vault 질문을 스레드 의존으로
표시한 것이 확인되었습니다. 라우팅은 타입 판단이 바인딩되는 서수, 지시어, 명시적 이전 결과 참조를
인용할 때만 턴을 스레드 의존으로 다룹니다. 대화 길이, 주제 겹침, 이전 답변은 참조를 뜻하지 않습니다.
같은 닫힌 선택이 ObjectType을 읽으므로, 인시던트 언급은 Resource 하위 유형이 아니라 Incident
ObjectType으로 근거화됩니다.

**종료 조건:** 20턴 대화 후반에 한 추적 질문이 두 번 반복하는 동안 새 대화에서와 같은 검증된 답변에
도달합니다.

### E5 턴 예산 예약

현재 경로는 frame 호출 전에 적응형 계획이나 큰 판단에 턴 예산을 쓸 수 있습니다. 각 경로는
[대화 전체에 적용되는 제한](hierarchical-conversation-planning-ko.md#대화-전체에-적용되는-제한)를 따르는 예약 계획을 갖습니다.

- 계획에는 실행될 수 있는 모든 단계가 조건부 단계까지 포함됩니다. 판단, 복구 한 번, 블라인드 검토,
  개념 선택자 두 개, 조건부 방향 판독기, frame, plan, 답변 작성자, 재생성 한 번, 함의 검토, 조각
  합성입니다.
- 각 단계는 호출 전에 호출 수, 입력과 출력 토큰, 경과 시간, 비용, 읽는 행 수의 최악의 경우를
  예약합니다. shadow는 자신의 용량에서 예약합니다.
- 예약하지 못한 단계는 어떤 호출보다 먼저 타입이 지정된 `budget_reserved_exceeded` 보류를
  돌려줍니다. 실패한 예약은 기록으로 남고, 실제 사용량은 단계마다 정산합니다.

**종료 조건:** 테스트가 정확한 예산 경계, 취소, 이어 읽기를 다루고, 추적된 스키마와 변경 기간 질문에서
판단 토큰 예산 이벤트와 적응형 예산 초과 이벤트가 기록되지 않습니다.

## 커버리지 확장

### E6 컨테이너 종류별 그룹화

컨테이너별로 그룹화한 개수는 지금 구성원을 직접 부모로 묶습니다. "리소스 그룹별 VM 수"와 같은 질문에는
한 종류의 가장 가까운 조상이 필요합니다.

- **형식:** `group_by: container` 측정값은 리소스 그룹 유형처럼 ObjectType이나 리소스 유형으로
  근거화되는 언급을 통해 컨테이너 종류를 밝힐 수 있습니다.
- **계보:** 그 종류의 모든 컨테이너에서 시작하는 전이적 `contains` 탐색이, 도달한 구성원마다 루트,
  최소 깊이, 경로 근거, 세대를 담은 계보를 기록합니다. 가장 가까운 루트보다 먼 루트는 버립니다.
- **동점:** 같은 깊이에 가장 가까운 루트가 둘 이상인 구성원은 모든 그룹에서 빼고 별도의
  `ambiguous_membership` 합계로 셉니다. 따라서 그룹 개수와 그 합계를 더하면 읽은 구성원 수와 같습니다.
- **검증:** 형식이 컨테이너 종류를 밝히면 V-SEM이 계보 그룹화를 요구합니다.
- **구현 참고:** 로컬 컴파일러는 타입이 지정된 계보 행 위의 검토된 aggregate 연산으로 계보 그룹화를
  표현합니다. 승격 전까지 shadow/local 범위에 머뭅니다.

**종료 조건:** 직접 루트, 간접 루트, 같은 거리의 가장 가까운 루트에 대한 정확한 정답 테스트가 통과하고,
추적된 그룹별 개수 질문이 보류 대신 리소스 그룹마다 개수 하나로 답합니다.

### E7 단일 대상 상태 이상, 상태 이력, 수명 주기 도메인

- **상태 이상 조회:** 바인딩된 Resource 하나의 상태 이상 질문은 공유 모듈 하나에서 만든, 현재 경로가
  계획하는 것과 같은 모양의 검토된 단일 대상 상태 이상 평가로 컴파일됩니다. V-PROV는 30분 고정 기간과
  검토된 지표 입력 세 개를 다시 계산하고, V-SEM은 평가에 필요한 조회만 정확히 요구합니다. 답변은 검토된
  안내로 고정 기간을 다시 밝힙니다. 상태 이상 근거가 없는 리소스는 `UNKNOWN_INCOMPLETE`로 남습니다.
- **상태 이력:** Resource 하나의 상태 이력은 그 기간의 검토된 모든 전환 유형과 대상 상태에 대해 검토된
  상태 전환 reader로 컴파일됩니다. reader는 커버리지 증명을 돌려주므로, 답변은 그 증명이 기간 전체에
  대해 완전할 때만 완전한 이력이라고 밝히며, 그렇지 않으면 이력은 `UNKNOWN_INCOMPLETE`입니다. 컬렉션의
  상태 이력, 그리고 버전, `as_of`, 두 기간 이력은 타입이 지정된 지원되지 않음 이유를 유지합니다.
- **수명 주기 도메인:** 투영이 정식 상태 열거형을 기록하는 ObjectType마다 검토된 수명 주기 값 도메인을
  두고, 열거형 값을 고정하는 계약 테스트를 둡니다. 대상은 `Incident`, `Process`, `RecoveryPlan`,
  `CausalHypothesis`입니다.

**종료 조건:** `check-reasoning-coverage.py`가 더 이상 `measure_unsupported:health`나
`measure_unsupported:state`를 보고하지 않고, 투영되는 각 ObjectType에 밝힌 상태가 근거화됩니다.

### E8 인과 변화 지점과 근거 등급

아래 요소가 모두 갖춰질 때까지는 인과 맥락을 유지합니다. 인과 맥락은 현재 상태와 기록된 작업을
보여 주며 원인을 지목하지 않습니다.

1. 신뢰할 수 있는 전환 커버리지에서만 읽는 상태 전환 변화 지점
2. [변경 이어 읽기](ontology-reasoning-result-handles-ko.md#h5-변경-이어-읽기)로 페이지를 넘기는 전체
   작업 기간
3. 검토된 메커니즘 카탈로그. 각 메커니즘은
   [인과 인시던트 그래프](../rules-and-detection/causal-incident-graph-ko.md)에 따라 필요한 근거와 반박
   조회를 밝힙니다.
4. 검증된 인과 등급 증적. 등급은 반복 표본, 역방향과 교란 요인 검사, 완전한 기간, 메커니즘 근거, 반박
   집계에서만 나옵니다. 반박 데이터가 없으면 지지가 아니라 알 수 없음입니다.
5. V-CLAIM을 통한 공개. `predictive_precedence` 등급은 확정된 원인이 아니라 등급이 붙은 가설로
   표시하며, [승격 프로그램](ontology-reasoning-promotion-program-ko.md#p3-검증된-답변-작성)의 검증된
   답변 작성 이전에는 어떤 가설도 공개하지 않습니다.

**종료 조건:** 상태 변화에 대한 이유 질문이 변화 지점과 그 기간의 모든 작업을 나열합니다.
`predictive_precedence` 미만에서 원인을 밝히는 답변이 없고, 한 번의 시간상 우연은 인과 맥락으로
남습니다.

### E9 남은 연산자와 관계 의미

커버리지 증적은 아직 아래 작업과 의미에 타입이 지정된 지원되지 않음 이유를 돌려줍니다. 각 항목은
선행 조건이 갖춰질 때만 컴파일됩니다. 그전에는 이유를 유지하며, 다른 작업의 계획을 빌리지 않습니다.
로컬 구현은 커버리지 증적의 누락된 선행 조건 이유를 더 정확하게 만듭니다. 검토된 정렬, 집계, 비교,
이력, 근거, 진단, 경로 또는 특성 선행 조건이 생기기 전까지 새 셀을 컴파일하지 않습니다.
E9b는 첫 컴파일 셀을 추가합니다. 한 검토된 metric의 `compare_windows`가 타입이 지정된 두 기간과
기존 metric comparison node를 사용합니다. Rank와 개수가 아닌 aggregate, compare-entities는 검토된
정렬 및 집계 메타데이터와 정렬된 답변 형태가 생길 때까지 타입이 지정된 선행 조건 이유를 유지합니다.

| 작업이나 의미 | 선행 조건 | 컴파일 결과 |
|---------------|-----------|-------------|
| `rank`와 개수가 아닌 `aggregate` | 한도가 있는 정렬 노드와 측정값별 검토된 집계 | V-SEM 정렬 커버리지가 있는 범위 제한 정렬 조회 |
| `compare_windows`와 `compare_entities` | 검토된 측정값 하나에 대한 두 타입 기간이나 두 바인딩 앵커 | 인과 주장 없는 두 조회와 비교 |
| `diff_versions`, `as_of`, 버전 시간 | 보관된 구성 스냅숏과 토폴로지 이력 | 타입 차이, 또는 이력이 없을 때 타입이 지정된 사용 불가 |
| `verify_evidence` | 보안 투영을 통한 검토된 링크 근거 허용 목록(승인된 결정 7) | 권한, 신선도, 완전성이 있는 링크 근거 |
| `diagnose` | 리소스 유형별 검토된 레시피 | 그 레시피만 사용하며 다른 유형의 레시피를 빌리지 않음 |
| `path`와 전이적 도달 | 검토된 경로 문법 | 한도와 정확한 증적이 있는 타입 경로 |
| 구성, 소유, 권한, 분류 의미 | LinkType 특성 검토 | 오늘의 포함과 의존처럼 검토된 side |

**종료 조건:** 각 행의 셀이 홀드아웃에서 hard zero로 커버리지 증적에 컴파일되거나, 데이터가 없는
곳에서는 타입이 지정된 사용 불가 이유를 유지합니다.

## 안전과 권한

- 모든 패키지는 읽기 전용이며 실행 경로를 추가하지 않습니다. 새 슬롯, 도메인, 레시피, reader는 닫힌
  선택으로 근거화하며, 근거화되지 않은 값은 그 목표를 보류합니다.
- 계약 변경은 롤아웃에 안전한 버전 규칙에 따른 추가 부 버전입니다.
- 새 조회는 모두 답하기 전에 V-SEM과 V-PROV를 통과하며, 새 보류는 검토된 두 언어 안내가 있는 타입
  이유를 씁니다.

## 승인이 필요한 결정

1. E1은 새 계약 계열이 아니라 판단과 frame 계약의 부 버전으로 타입 슬롯을 추가합니다(제안).
2. E6은 같은 거리의 가장 가까운 구성원을 각 그룹에 세지 않고 그룹 개수에서 빼서
   `ambiguous_membership`으로 보고합니다(제안).
3. E8은 `predictive_precedence`를 등급이 붙은 가설을 밝힐 수 있는 가장 낮은 등급으로 유지합니다(제안).

## 비평과 수정

초안에 대한 독립 비평에서 다음 문제가 나왔습니다. 이 설계는 각 수정을 반영합니다.

| 발견 사항 | 수정 |
|-----------|------|
| E8이 `predictive_precedence`를 얻는 방법을 정의하지 않았습니다 | 반복 표본, 반박, 교란 요인 검사가 있는 검증된 인과 등급 증적, P3 이후의 등급 가설만, 부정 종료 조건 |
| R3부터 R8까지의 열린 작업과 의미에 담당이 없었습니다 | E9가 각 항목을 선행 조건과 종료 조건과 함께 담당합니다 |
| E6의 여러 루트 집계가 일관되지 않았습니다 | 가장 가까운 루트 계보, 그리고 정산되는 `ambiguous_membership` 합계로 보고하는 같은 거리 구성원 |
| E5 예약이 실행하거나 반증할 수 없었습니다 | 모든 조건부 단계와 차원에 대한 경로별 예약 계획과 경계 테스트 |
| 연결된 원장이 없었습니다 | 원장이 있으며 이 문서의 남은 작업을 담당합니다 |
