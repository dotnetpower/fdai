# 통제된 문서 형식 정책

이 문서는 FDAI가 통제된 문서 수집에서 허용하는 원본 형식과 워커의 검증, 추출 및 결과 보고
방식을 정의합니다. 클라이언트 안내와 서버의 최종 콘텐츠 검증을 분리합니다.

> 파일 이름, 확장자 또는 브라우저 미디어 형식만으로는 신뢰나 실행 권한을 부여하지 않습니다.
> 워커는 추출 전에 실제 바이트 시그니처를 검증합니다.

## 설계 개요

기능 검색 엔드포인트와 업로드 경계는 하나의 공용 허용 목록을 사용합니다. 파일 이름 확장자와
미디어 형식 힌트는 사용할 수 있는 파서만 선택합니다. 운영 환경은 OCR 공급자가 준비된 경우에만
이미지 원본을 지원 형식으로 알립니다.

## OCR 공급자 제어

로컬 Python OCR이 기본 공급자입니다. **설정 > 통합 > 문서 OCR**에서 Azure Document
Intelligence를 선택할 수 있습니다. 선택 사항을 저장하면 수정 버전으로 보호되는 정책과 보호된
계획 요청을 기록합니다. Terraform을 실행하거나 적용 권한을 부여하지 않습니다.

정책은 실제 공급자와 Azure 리소스 수명 주기를 분리합니다.

| 운영자 의도 | 런타임 공급자 | Azure 리소스 |
|-------------|---------------|--------------|
| 현재 상태 유지 | 마지막으로 적용한 공급자를 유지합니다. | 현재 리소스 상태를 유지합니다. |
| 로컬 OCR 사용 | `local_python` | 기존 리소스를 유지합니다. |
| Azure OCR 사용 | `azure_document_intelligence` | 리소스를 프로비저닝하거나 유지합니다. |
| Azure OCR 제거 | `local_python` | 명시적 프로비저닝 해제를 계획합니다. |

설정 변환 결과는 배포 후 실제 상태를 다시 확인한 다음에만 유효 공급자를 표시합니다. 정책을
저장하거나 계획을 수락했다는 이유만으로 요청한 공급자가 유효해지지는 않습니다.

## 로컬 한국어 OCR

로컬 공급자는 고정된 `kor+eng` 언어 데이터와 Tesseract를 사용합니다. 래스터화와 OCR은 CPU,
메모리, 경과 시간, 페이지 수, 픽셀 수, 줄 수, 문자 수 및 프로세스 간 출력 제한이 적용된 별도
프로세스에서 실행됩니다. PDF 페이지는 `pypdfium2`로 래스터화하고 PNG, JPEG 및 TIFF 프레임은
Pillow로 처리합니다. 런타임 언어 다운로드는 지원되지 않습니다.

공급자 준비 상태 검사는 한국어와 영어 언어 데이터가 모두 있는지 확인합니다. 데이터 누락, 파서
오류, 시간 초과 및 출력 제한 위반은 문서 텍스트를 로그에 남기지 않고 공급자 사용 불가 결과를
생성합니다.

## Azure Document Intelligence 수명 주기

Azure 모드는 관리 ID를 통해 `prebuilt-read` 모델을 사용합니다. 보호된 Terraform 워크플로는
로컬 인증이 비활성화된 `FormRecognizer` 계정, 진단 설정, 프라이빗 엔드포인트 및 프라이빗 DNS를
프로비저닝할 수 있습니다. 수집 워커에는 선택한 리소스의 `Cognitive Services User` 역할을
부여합니다.

워크플로는 기본적으로 계획만 생성합니다. `document_ocr_action` 입력은 `preserve`,
`use_local_retain`, `use_azure_provision` 또는 `deprovision_use_local` 중 하나의 명시적 작업을
보호된 배포 요청에 연결합니다. 적용하려면 정확한 보호 계획과 별도 승인이 필요합니다. 이후
배포는 OCR 작업으로 명시적으로 변경하지 않는 한 이전에 적용한 리소스와 공급자를 유지합니다.

설정에서 시작한 요청의 경우 보호된 러너는 `plan-ocr-<proposal>-<digest>` 좌표를 PostgreSQL의
최종 제안 저장소와 대조합니다. 제안, 현재 정책, 계획 요청 상태, 환경, principal, 멱등성 키 및
다이제스트가 모두 일치할 때만 작업을 수락합니다. 그런 다음 워크플로에서 전달한 공급자 값을
신뢰하지 않고 정책에서 Terraform 작업을 도출합니다.

## 접수 및 처리 표

| 원본 | 접수 | 처리 |
|------|------|------|
| UTF-8 텍스트, Markdown, RST, JSON, YAML, XML, CSV, Terraform, Rego | 허용 | 범위가 제한된 텍스트로 디코딩하고 문단 위치를 기록합니다. |
| PDF | 허용 | 격리된 프로세스에서 기본 텍스트를 분석하고 빈 페이지나 스캔 페이지에는 OCR을 사용합니다. |
| DOCX | 허용 | 문단, 제목, 표 및 포함된 래스터 이미지를 추출합니다. |
| PPTX | 허용 | 슬라이드 도형, 문단, 표, 발표자 노트 및 포함된 래스터 이미지를 추출합니다. |
| XLSX | 허용 | 시트 이름, 셀, 공유 문자열 및 포함된 래스터 이미지를 추출하며 수식을 실행하지 않습니다. |
| PNG, JPEG, TIFF | OCR이 구성된 경우 허용 | OCR이 필요하며 이미지 바이트는 인덱스나 감사 기록에 넣지 않습니다. |
| DOC, PPT, XLS 및 기타 OLE 바이너리 | 허용하지 않음 | 원본 애플리케이션에서 최신 OOXML 또는 PDF 버전으로 저장합니다. |
| ZIP 및 기타 일반 압축 파일 | 허용하지 않음 | 압축 파일 확장은 업로드 형식으로 사용하지 않습니다. |

## 추출 및 실패 동작

포함된 이미지는 범위가 제한된 패키지 구성원 추출과 유효 OCR 공급자를 사용합니다. 기본
텍스트가 있는 최신 Office 문서는 포함된 이미지 OCR을 사용할 수 없을 때
`ready_with_warnings`로 완료될 수 있습니다. 이미지만 있는 문서, 스캔 PDF 또는 이미지만 있는
Office 패키지는 위치가 확인된 OCR 텍스트 없이는 준비 상태가 될 수 없습니다. 추출 결과가
비어 있으면 검색 가능한 빈 문서로 만들지 않고 타입이 지정된 실패로 처리합니다.

잘못된 패키지, 확장자와 시그니처 불일치, 암호화된 파일, 지원하지 않는 이미지 인코딩 및 파서
예산 위반은 서로 다른 정제된 실패 코드를 생성합니다. FDAI는 구형 형식을 최선 노력으로
변환하거나 수식 또는 매크로를 실행하거나 외부 관계를 따라가거나 바이너리 파일을 텍스트로
처리하지 않습니다.
