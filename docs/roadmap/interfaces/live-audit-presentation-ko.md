# Live와 감사 로그 화면

이 문서는 Live 화면과 감사 기록 검토 작업 영역의 읽기 전용 표시 계약을 정의합니다.
정적 시안은 레이아웃의 기준이며, 운영 사실이나 권한의 근거가 아닙니다.

> **경계:** Sample 시나리오는 런타임에 들어가지 않습니다. 측정, 결정, 독립 관측 또는
> 무결성 검사가 없으면 사용 불가나 검증되지 않음으로 명시합니다.

## 설계 개요

두 경로는 데스크톱에서 1232px 콘텐츠 격자를 사용합니다. Live는 시간 순서의 카드 작업
영역을 유지하고, 감사 로그는 높이가 제한된 기록 목록 옆에 선택한 기록을 표시합니다.
더 적은 기록을 보여 주는 합성 시안에 맞추려고 불러온 근거를 잘라내지 않습니다.

## Live 카드와 컨트롤

- 제어 카드는 기록된 파이프라인 단계를 3px 막대로 표시합니다. 경과 시간이나 검증된
  효과를 표시하는 비율이 아닙니다. 소스 읽기 카드에는 단계 진행률을 만들어 넣지 않습니다.
- 격자와 목록은 카드 내용, 선택 및 우측 상세 패널을 공유합니다. 상태가 갱신되어도
  보존 중인 이벤트의 순서를 바꾸지 않습니다. 색이나 애니메이션 없이도 상태 문구를 읽을 수 있습니다.
- KPI 카드는 공통 글꼴 역할, 간결한 SVG 게이트 링과 티어 막대를 사용합니다. 처리량은
  제어 단계 메시지와 소스 읽기를 계속 구분하며, 합성 값에 맞추려고
  [지표의 분모](live-cockpit-metrics-ko.md)를 바꾸지 않습니다.
- 전체화면은 활동 작업 영역만 확장합니다. 브라우저 전체화면과 명시적인 확장 보기 모두
  키보드 조작, Escape 종료 및 포커스 복원을 유지합니다. 상세 패널과 툴팁은 활성
  전체화면 요소 안에 표시합니다.

## 반복 가능한 Sample 비교

Sample 다시 재생은 승인 대기, 자동 결정, 판단 보류, 거부, 실패 예시를 포함하는 대표 시나리오
12개를 복원합니다. 리소스와 작업 식별자는 선언된 카탈로그를 사용하며, 현지화된 표시 이름은
명시적으로 선택한 Sample 모드에서만 적용합니다. 합성 60초 지표 초기화는 카드 풀과 별개로
모델링된 루프 180개를 유지합니다. 이후 Sample 루프는 초당 두 번 시작하고 T0(결정론적 규칙),
T1(유사성 재사용), T2(근거 기반 추론)별로 각각 2.4초, 3.4초, 4.8초에 걸쳐 단계를 표시합니다.
다시 재생하면 이전 타이머와 대기 프레임을
취소하고 측정값과 선택을 초기화하며 현재 필터는 유지합니다. 런타임 근거를 읽거나 쓰지 않습니다.

## 감사 기록 검토

1440 x 900 화면에서 검토 작업 영역은 1232 x 620px이며 기록 목록 폭은 290px입니다.
데스크톱에서는 목록과 상세 패널이 제한된 작업 영역 안에서 스크롤되므로 뒤쪽 기록을 선택해도
상세 내용이 페이지 위쪽에 남지 않습니다. 불러온 모든 행에 접근할 수 있고, 다음 페이지는
기존 기록을 교체하지 않고 추가합니다. 좁은 화면에서는 두 패널을 세로로 배치하고 기록 목록의
높이를 제한하며, 상세 내용은 일반 페이지 스크롤을 따릅니다.

맥락 정보, 검색 컨트롤 및 기록 상세에는 출처와 검색 범위 설명을 유지합니다. 저장된 해시만으로
원장 무결성을 검증할 수 없으며, 소스 근거만으로 독립적으로 검증된 효과를 주장하지 않습니다.

Operator API는 감사 요약과 기록 맥락 변환 결과를 추가로 제공합니다. 감사 작업 영역만
요약을 명시적으로 요청하고 Incident, Agent Activity 및 Trace 소비자는 범위가 제한된 페이지
읽기만 유지합니다. 요약 수치는 불러온 페이지만이 아니라 보존 중인 전체 조회 범위를 대상으로
합니다. 체인 상태는 Core에 보존된 최신 `audit.chain` 시작 증적과 현재 저장된 해시 연결의
구조 검사를 함께 사용합니다. Console은 그 증적 이후에 추가된 행의 해시까지 모두 다시
계산했다고 표현하지 않습니다.

기록 맥락은 기록 종류를 구분합니다. 읽기 전용 관측 소스 전이는 소스, 캠페인 상관관계, 영역,
담당자 및 기록된 상태를 표시합니다. 작업 티어, 롤백, 전달 또는 효과 검증 필드는 누락된 값으로
표시하지 않습니다. 기존 캠페인 기록은 저장된 `campaign_id`, `source_id`, `status`에서 맥락을
변환하고, 새 기록은 표준 상관관계, 대상, 결과, 모드 및 멱등성 필드도 기록합니다. 이 호환성
변환은 불변 원장을 다시 쓰지 않으며 소스 준비 상태를 관리 리소스의 효과 근거로 바꾸지 않습니다.
