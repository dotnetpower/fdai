# 적용 승인을 거치는 타입 선택 읽기

이 설계는 타입 기반 인스턴스 답변의 제한된 비동기 모델 단계, 불변 읽기 근거, 적용 승인을
거치는 기능 결속을 정의합니다. #2034와 #2256의 하위 작업 #2275에서 선택한 A 경계이며,
활성화나 현재 모델의 적격성을 주장하지 않습니다.

> 기존의 결정적이고 네트워크를 사용하지 않는 5초 후보 Function은 바뀌지 않습니다.
> hosted 추론을 결정적이거나 시드로 재현 가능하다고 선언하지 않습니다. 일반 Function
> 레지스트리 안에서는 모델을 호출하지 않습니다.

## 설계 개요

| 단계 | 책임과 경계 | 필수 출력 |
|------|-------------|-----------|
| 적격성 수용 | 독립 검증기, Forseti 판단 | 정확한 소스/모델/프롬프트/정책/범위에 결속한 적격성 근거. 사용 불가나 실패는 보류합니다. |
| 사람 승인 | Var, 기존 타입 승인 수명주기 | 정확한 불변 요청과 책임 주체가 명시된 현재 승인. |
| 적용 승인 | Thor, 등록된 거버넌스 ActionType | 영속 CAS 읽기 기능 포인터. 승인 확정 전에는 사용하지 않습니다. |
| 모델 읽기 | Bragi 책임의 Function 호출 전 비동기 준비 | 최대 2회 호출, 호출당 20초 이하, 전체 기한 24초. |
| 근거 소비 | 결정적인 버전 Function | 정확한 일회용 principal/질의/소스/모델/리비전/만료 결속과 현재 보안 멤버십. |
| 적용 해제 | Vidar, 타입 회수/회귀 및 스크립트 롤백 | 더 높은 비활성 리비전과 적격성 철회 영구 경계. |
| 감사 | Saga, 기존 의도/최종 감사 | 책임 주체를 추적할 수 있는 적용 승인, 보류, 적용 해제. |

## 권한과 근거

읽기 포인터는 비활성으로 시작합니다. 결속에는 정확한 코드 리비전, 온톨로지 매니페스트,
principal 범위, 모델/요청/프롬프트 식별 정보, 문맥 프로토콜, 데이터 처리 정책이 들어갑니다.
적격성은 이 정확한 결속에 대해 독립적으로 수용합니다. 호출자가 제공한 불리언은 게이트가
아닙니다. 현재 원시 임베딩 적격성은 실패했으며 이전 Sol 고정값으로 mini를 검증할 수 없습니다.

적용 승인은 기존의 정확한 검토 증적과 타입 Forseti/Var/Thor/Saga 수명주기를 사용합니다.
승인 레이블, 모델 이름, 전송된 요청, 과거 성공 증적만으로 답변 사용 권한을 얻을 수 없습니다.
회수나 회귀는 Vidar를 통해 권한을 낮춥니다. 과거 적용 승인은 더 높은 리비전 경계를 넘거나
철회한 적격성을 재사용할 수 없습니다.

모델 제안, 알림 전달, 보고 관계는 이 읽기 기능을 승인하거나 활성화할 수 없습니다.
런타임 지원 매니페스트는 조건부 소스 연결만 기록하며 설치 환경의 효과 증적이 아닙니다.
이 경로는 채널, 수신자, 알림 권한을 추가하지 않으며 실제 채널 검증을 주장하지 않습니다.

## 선택한 A 실행 경계

프로덕션 Function 노드 처리기는 일반 레지스트리를 호출하기 전에 읽기 근거를 준비합니다.
모델 단계는 원문을 보존한 전체 문맥을 사용하고 합의를 검증한 뒤에만 불변 근거를 저장합니다.
취소, 불일치, 적격성 사용 불가, 만료, 소스/모델 변경은 보류하며 소비 가능한 근거를 만들지 않습니다.

새 결정적 Function은 모델을 호출하지 않습니다. 현재 포인터와 정확한 principal, 질의,
소스, 모델, 코드 리비전, 만료를 다시 확인하고 현재 보안 멤버십을 검증한 뒤 근거를 한 번
소비합니다. 준비와 소비 사이에 적용을 해제하면 해제가 우선합니다. 결과는 비완전한 후보로
유지하며 실행 권한을 갖지 않습니다. 원시 벡터 순위 지정을 켜지 않으며 전체 enum 값 500개와
멤버십 1,000행이라는 기존 한도도 명시적으로 유지합니다.

## 사전 등록한 실제 적격성 검증

새 `governed-read-window.v1.json` 자산은 독립적으로 작성하고 별도로 검토한 64개 사례를
포함합니다. 기존에 사용한 모든 calibration, holdout 및 shadow runtime window와 겹치지 않습니다.
각 사례는 실제 Function 전 준비 단계와 결정적 소비 경로에서 네 번 판단합니다. 부정, 모호,
적대적 사례는 후보 근거를 만들지 않고 보류해야 통과하며, 답이 있는 사례는 정확한 현재 멤버십
집합을 반환해야 합니다.

`governed-typed-selection-answer-window.v1` 프로토콜은 위험한 추가 선택이 없어야 하며, 전체
단측 95% 상한 2%, 언어별 상한 3%, 언어별 답이 있는 사례의 정답률 0.95 이상, provider 사용
불가율 2% 이하를 요구합니다. `governed-typed-selection-answer-latency.v1` 프로토콜은 관찰
256개, p50 8초 이하, p95 15초 이하, p99 25초 이하, provider 사용 불가율 2% 이하,
이벤트 루프 지연 p99 100 ms 이하를 요구합니다. 사용 불가 관찰은 30초 기한 값으로 계산합니다.

실제 결정 시작 시점은 최소 12초 간격을 두며 캠페인 전체 기한은 90분입니다. 이 대기 시간은
측정한 결정 지연 시간에 포함하지 않습니다. 모든 시도는 비공개로 보존합니다. HTTP 429, 세 번
연속된 provider 사용 불가 또는 사용 불가 결정이 다섯 건을 넘으면 품질 결과나 재시도 없이
중단합니다. 통과 보고서에도 production, 승격 또는 실행 권한이 없습니다.

독립적인 현재 원본 검증은 모든 문서와 세대를 다시 만들고 비교합니다. 관측 기준 시각이
projection 식별자에 포함되므로 후속 검증의 projection digest는 staged digest와 다를 수 있습니다.
두 digest를 모두 검증 증적에 결속하며, 콘텐츠, 세대, 매니페스트, principal 범위, 원본 세대의
동일성은 계속 필수입니다.

## 구현 전 비판 검토와 수정

검토한 가설은 Function 안의 숨은 네트워크 호출, 진행 알림과 권한의 혼동, 허위 시드 재현,
적격성 검증 전 호출, 호출 중 소스/모델 변경, 취소 뒤 근거 생성, 요청 간 재사용, 만료나
시간대 없는 시각, 동시 적용 해제, 승인 직접 우회, 롤백에 의한 과거 권한 복원, 역할/스키마
우회입니다.

수정안은 기존 Function 전 처리기와 정확한 검토 디스패처를 사용하고, 일반 실행기의
네트워크/자격 증명 차단을 유지하며 근거를 권위 있는 포인터 리비전에 결속하는 것입니다.
새 실행 분류, 역할 소유자, 암묵적 적격성을 추가하지 않습니다.
초기 45초 단계 제안은 24초로 줄였습니다. 준비와 5초 결정적 Function이 기존 질의 노드의
30초 한도 안에 들어가도록 한 수정입니다. 병렬 호출 중 하나가 실패하면 나머지도 취소합니다.
