# 클라우드 리소스 지식 수명 주기

이 설계는 클라우드 리소스 공식 문서의 수집, 갱신, 전달, 수용, 인용을 관리합니다.
인터넷에 연결된 환경의 수집과 보안 검토를 거친 오프라인 문서 패키지에 같은 근거 계약을
적용하여, 오래된 스냅샷을 현재 지침으로 제시하지 않도록 합니다.

> **구현 경계:** 계약, 범위가 제한된 수집, 서명 패키지 반입, 통제된 문서 활성화,
> 날짜를 명시한 어휘 검색에 로컬 구현 근거가 있습니다. 운영용 신뢰 설정과 실제 수집/
> 망분리 배포는 별도 선행 조건입니다. 첫 수집 대상은 Azure이며, 다른 클라우드 서비스
> 공급자(CSP)는 별도 승인이 필요합니다.
>
> **권한 경계:** 공개 참조 지식은 실제 리소스 관측 상태도, 실행 권한도 아닙니다.
> 패키지는 데이터만 포함하며 실행 가능한 규칙, 프롬프트, 플러그인, 배포를 포함하지 않습니다.

## 한눈에 보는 설계

등록된 출처에서 변경할 수 없는 문서 개정본과 추가 전용 원본 확인 증적을 생성합니다.
온라인 갱신과 오프라인 패키지는 모두 기존의 통제된 문서 수집 경계를 거칩니다.
수용된 컬렉션 세대만 검색 증강 생성(RAG)에 사용합니다. RAG는 답변을 생성하기 전에
근거 구절을 검색하는 방식입니다. 각 답변은 근거 기준 시점의 세대, 인용, 수집 시각,
확인 증적, 최신성 정책을 고정합니다.

## 설계 검토와 수정

| 초기 접근 | 검토 결과 | 수정한 결정 |
|-----------|-----------|-------------|
| 문서 시각을 하나만 사용 | 최근 반입 시각이 오래된 원문을 가릴 수 있으며, 변경 없음 확인은 다운로드와 다름 | 원본, 수집, 확인, 패키지, 반입, 활성화, 답변 시각을 분리 |
| 주기에 따라 사용 중인 색인을 교체 | 불완전한 다운로드, 위험한 내용, 변경된 적용 조건이 즉시 노출됨 | 후보를 수집한 뒤 검증, 검토를 거쳐 제한된 세대를 원자적으로 활성화 |
| 서명된 압축 파일을 신뢰 | 서명만으로 원본의 진실성, 내부 승인, 최신성을 보장할 수 없음 | 독립적으로 설정한 신뢰, 정확한 내용 검증, 내부 보안 검토, 현재 읽기 검증을 적용 |
| 검색 결과에서 가장 최근 날짜만 표시 | 최근 구절 하나가 오래된 의존 근거를 가릴 수 있음 | 주장별 인용과 가장 취약한 필수 근거로 답변 가능 여부를 판단 |
| 답변 중 갱신 완료를 기다림 | 오프라인 출처 때문에 대화가 무기한 대기할 수 있음 | 기준 시점이 명확한 답변이나 종결된 갱신 필요 결과를 반환하고, 갱신은 별도로 추적 |
| 원자적 색인 커밋을 검증된 성공으로 보고 | 트랜잭션은 자신의 커밋 결과를 독립적으로 관찰할 수 없음 | 정확한 저장 색인을 별도로 재조회하는 동안 세대는 사용 불가로 유지하고 검증 후 공개와 최종 성공을 기록 |
| 모든 릴리스에 원본 본문 포함 | HTML/Markdown 반복 전달은 크기를 늘리며, 서명된 필드를 임의로 빼면 식별 정보가 깨짐 | 정규화 텍스트만 담은 v2를 생성하고 수집 원본은 로컬에 보존하며, 기존 v1은 바이트를 바꾸지 않고 검증 |

## 출처 레지스트리와 범위

`SourceRegistryRevision`은 검토와 버전 관리를 거치는 배포 구성입니다.
지정된 출처 책임자만 변경을 요청할 수 있으며, 새 원본 위치, 라이선스, 접근 방식,
수집 범위 확대에는 독립적인 보안 승인이 필요합니다. 패키지는 이 레지스트리나 신뢰 정책을
수정할 수 없습니다. 범용 스키마와 검토된 공개 출처 템플릿은 업스트림에 포함할 수 있지만,
비공개 지식, 접근 목록, 배포 값, 승인자 신원은 이 저장소 밖에서 관리합니다.

- **식별 정보:** CSP, 공급자 고유 리소스 유형, 기준 URL, 확인 가능한 원본 개정, 언어입니다.
- **적용 조건:** 서비스 세대, SKU, API 버전, 지역, 배포 모드, 기능 제공 상태, 유효 구간입니다.
  누락된 조건은 모든 대상에 적용되는 것으로 간주하지 않고 알 수 없음으로 유지합니다.
- **수집 정책:** 허용된 HTTPS 원본 위치와 경로, 리디렉션 정책, 출처 책임자, 수집 범위,
  갱신 프로필, 보존, 바이트/페이지 한도, 수동 또는 사전 승인 활성화를 지정합니다.
- **이용 권한:** 저장, 임베딩, 내부 전달, 재배포 권한을 각각 기록합니다.
  참조만 허용된 출처를 별도 확인 없이 전문 오프라인 패키지에 넣지 않습니다.
- **수집 범위:** 리소스 유형별로 등록, 수집, 수용, 최신, 실패, 미지원 주제를 추적합니다.
  스키마 목록이나 성공한 수집 작업만으로 운영 지식의 완전성을 입증할 수 없습니다.

예: [Azure API Management(APIM) 네트워크 요구사항](https://learn.microsoft.com/en-us/azure/api-management/virtual-network-injection-resources)은
Developer/Premium과 Premium v2를 구분합니다. 문서 조각은 이 구분과 상위 제목, 표 머리글,
각주, 예외를 이어받습니다. 유형 이름이 비슷하다는 이유로 적용 조건을 무시할 수 없습니다.

## 시각과 근거 레코드

| 필드 또는 레코드 | 의미 |
|--------------------------|------|
| `DocumentRevision` | 변경할 수 없는 원본 식별 정보, 원문 SHA-256, 정규화 SHA-256, 절 좌표, 적용 조건, 추출기 버전 |
| `source_updated_at` | 게시자가 선언한 수정 시각으로, 없을 수 있으며 독립적으로 검증한 수집 시각은 아님 |
| `collected_at` | 원본 본문을 실제로 가져온 시각으로, 변경할 수 없는 가져오기 증적에 기록 |
| `SourceCheckReceipt` | 출처와 요청 식별 정보, 선택된 내용 다이제스트, UTC 확인 시각, 결과, 변경 확인자 연결, 수집기 신원/버전, 출처 이력 다이제스트 |
| `last_successful_check_at` | 선택한 본문이 원본과 일치함을 확인한 가장 최근 수용 증적의 변환 결과 |
| `last_attempt_at` | 실패를 포함한 마지막 시도이며, 최신성 갱신으로 취급하지 않음 |
| `package_created_at` | 서명된 지식 릴리스를 조립한 시각으로, 각 원본 시각을 보존 |
| `imported_at`, `activated_at` | 내부 도착 시각과 검색 공개 전환 시각을 각각 기록 |
| `answered_at`, `evidence_cutoff` | 신뢰할 수 있는 답변 시각과 해당 답변에 수용할 근거의 고정 기준 시점 |

신뢰할 수 있는 UTC와 RFC 3339 타임스탬프를 사용하고 시간대를 표시합니다.
수집/확인 이력이 없거나, 시계를 신뢰할 수 없거나, 시각 차이가 지나치거나, 증적의 시간
순서가 잘못되면 알 수 없음 또는 보류로 처리하며 날짜를 만들어 내지 않습니다.
게시자 수정 시각만 없는 것은 허용됩니다. 검증된 가져오기/확인은 원본이 제공한 내용을
입증할 수 있지만, 작성자가 언제 수정했는지까지 입증하지는 못합니다.

동일한 본문을 완전히 다시 가져오는 데 성공하면 문서 조각을 다시 만들지 않고 가져오기/확인
증적을 추가합니다. HTTP 304는 확인 증적만 추가합니다. 정확한 원본 위치, 표현 형식,
요청 변경 확인자가 사용 가능한 완전한 본문과 이미 연결된 경우에만 유효합니다. 그렇지 않으면
제한된 전체 가져오기를 수행하거나 알 수 없음으로 기록합니다. ETag의 강도, Last-Modified,
요청 연결, 응답 결과를 보존합니다. 기본 30일마다 조건 없는 전체 가져오기도 수행하여
신뢰하기 어려운 캐시 변경 확인자를 탐지합니다.
동등성의 근거도 기록합니다. 약한 ETag나 날짜 기반 변경 확인자는 서버의 선언이며 바이트
동일성을 뜻하지 않습니다. 운영용 확인에는 강한 변경 확인자 또는 전체 본문 해시 비교가
필요하며, 그렇지 않으면 본문 전체를 가져옵니다.

다른 본문을 발견하면 후보를 생성하며, 이전 본문의 확인 시각을 갱신하지 않습니다.
나중에 동일한 본문을 다시 가져와도 과거 답변은 원래 증적을 유지합니다.
미러 동기화, 재패키징, 서명 갱신, 반입, 색인 생성, 롤백은 원본의 최신성을 갱신하지 않습니다.
미러는 내부 수정 시각만이 아니라 신뢰할 수 있는 원본 확인 증적을 제공해야 합니다.

## 갱신과 답변 정책

다음 프로필은 배포 정책 선택 사항이며 최신성을 보장하지 않습니다. 기본 계약은 운영
프로필을 사용하며 변경은 배포별로 승인합니다. 하루는 24시간이며 월간은 길이가
달라지는 달력상의 한 달이 아니라 30일을 의미합니다.

| 프로필 | 주제 예시 | 확인 주기 | 최대 미확인 기간 |
|--------|-----------|-----------|------------------|
| `operational` | 네트워킹, DNS, 할당량, SKU 제약, 보안 구성 | 7일 | 30일 |
| `reference` | 서비스 개념과 비교적 안정적인 아키텍처 설명 | 30일 | 90일 |
| `advisory` | 명시적으로 활성화한 보안 권고와 긴급 지원 중단 안내 | 1일 | 7일 |

경과 시간은 반입 시각이 아니라 선택한 개정본의 수용된 `last_successful_check_at`을
기준으로 계산합니다. 최신성, 연결 상태, 업데이트 존재 여부, 수용, 색인 공개 여부는
독립된 축으로 유지합니다. 수집기를 비활성화해도 임계값이나 오래된 내용의 최신성은 바뀌지 않습니다.

| 최신성 | 조건 | 답변 동작 |
|--------|------|-----------|
| `fresh` | 경과 시간이 확인 주기 미만 | 날짜와 인용을 포함해 설명하고, 실시간 최신이 아니라 확인 시점 기준이라고 표시 |
| `refresh_due` | 경과 시간이 확인 주기 이상이고 최대 기간 미만 | 승인된 확인을 예약하고, 갱신 경고와 날짜를 명시한 설명을 허용 |
| `stale` | 경과 시간이 최대 기간 이상 | 접근과 수용 조건이 여전히 허용하는 경우에만 과거/참조 설명을 제공하며 현재 운영 결론은 내리지 않음 |
| `unknown` | 적절한 증적 또는 신뢰할 수 있는 시각이 없음 | 부족한 근거와 검토/갱신 필요 사항을 반환 |

새 내용이 있음을 알면 `update_pending`을 설정하고, 이전 증적이 최근 것이더라도 현재
지침이라고 주장하지 않습니다. 질문 용도 정책은 위 상한보다 더 이른 최신성 확인을 요구할
수 있습니다. 실시간 최신 지침 요청에는 `fresh` 표시만이 아니라 자격을 갖춘 새 원본
관측이 필요합니다. 해당 관측을 확보할 수 없으면 `refresh_required` 또는
`evidence_unavailable`로 종결하고, 선택적으로 과거 설명을 별도 표시합니다. 다음 수집 주기까지
기다리지 않습니다. 부분 답변은 뒷받침되는 주장과 누락된 의존 근거를 명시합니다.

원본이 오래됐다는 것은 악성코드, 철회, 삭제와 다릅니다. 반대로 철회, 무결성 실패,
접근 거부, 수용 기간 만료 상태의 자료는 과거 자료라고 표시해도 사용할 수 없습니다.
최신성이 신뢰나 접근 검증 실패를 해결하지 못하며, 유효한 서명도 오래된 근거를 최신으로
만들지 못합니다. 적용되는 조건 중 가장 엄격한 조건이 사용 여부를 결정합니다.

## 연결 환경의 수집

상시 폴링 서비스를 추가하지 않고 범위가 제한된 예약 수집을 사용합니다. 매일 실행하는 도래
확인과 시작 시 누락 작업 확인으로, 마지막 성공 확인 이후 프로필 주기가 지난 출처를
예약합니다. 매일 작업을 실행한다고 모든 문서를 매일 다운로드하지는 않습니다.
기존 증적이 없는 출처는 즉시 확인 대상이 됩니다. 공개 원본, 승인된 미러, 오프라인 모드는
출처별로 명시하며, 네트워크 연결 가능 여부를 권한으로 간주하지 않습니다. 출처 접근과
과금되는 모델 사용에는 각각 유효한 별도 승인이 필요합니다.

1. 지속적으로 기록되는 임차 기간, 예상 정책 개정, 안정적인 시도 키로 도래한 출처를 선점합니다.
2. 원본 위치/경로 허용 목록, TLS, 리디렉션과 DNS 검증으로 서버 측 요청 위조를 방지하고,
   출처별/전체 요청, 페이지, 바이트, 동시성 한도를 적용합니다. 등록 범위 밖의 문서 링크를
   따라가거나 스크립트/외부 이미지를 불러오거나 검색한 내용을 지시로 취급하지 않습니다.
3. 조건부 가져오기, 해시 비교, 변경할 수 없는 관측 기록을 수행합니다. 정규화가 필요하면
   단락, 표, 제목, 적용 조건, 원본 절 경계를 보존합니다.
4. 변경된 개정본, 원문 차이, 수집 누락, 보안 관측을 후보로 준비합니다. 변경되지 않은 승인
   산출물은 같은 컬렉션과 접근 경계 안에서만 재사용합니다.
5. 공통 수용 및 활성화 흐름을 요청합니다. 수집 성공은 활성화 성공이 아닙니다.

초기 작업 한도는 요청당 30초, 실행당 15분, 진행 없는 시간 2분이며, 측정된 처리 능력과
더 엄격한 배포 정책을 따릅니다. 완료 항목은 재개 지점으로 기록합니다. HTTP 429/503,
기한 도달, 권한 상실은 해당 시도를 종료합니다. 이후 예약 시도는 Retry-After, 제한된
재시도 간격 증가, 시점 분산을 따르며, 설정된 실패 상한에 도달하면 운영자 검토가 필요합니다.
즉시 반복 재시도하지 않으며, 실패 시 마지막 성공 확인 시각을 갱신하지 않습니다.

| 관측 | 지속적으로 기록할 결과 |
|------|------------------------|
| 변경 없는 본문 또는 유효한 304 | 감사된 확인 증적을 추가하고 문서 조각과 임베딩은 유지 |
| 내용, 적용 조건, 권한, 추출 의미 변경 | 새 검토 후보를 만들고 현재 세대는 덮어쓰지 않음 |
| 인증 실패, 시간 초과, 불완전한 목록 | 정확한 누락을 포함한 실패/부분 실행으로 기록하고 원본 삭제를 추론하지 않음 |
| 404/410 또는 목록 항목 소실 | 삭제 후보로 기록하며, 신뢰된 경로의 완전한 목록이나 독립적으로 확인한 철회 근거가 있어야 삭제 표시 |
| 확인된 보안 철회 | 영향을 받는 활성 참조와 캐시를 통제된 절차로 신속히 차단하고 감사 |

부분 실행은 성공한 후보를 준비할 수 있지만, 기본 활성화는 해당 갱신 범위에 선언한 모든
대상이 검증된 결과에 도달해야 가능합니다. 범위를 줄이려면 새 매니페스트를 검토해야 하며,
실패 후 임의로 범위를 축소하지 않습니다. 마지막으로 정상임을 확인한 세대도 자신의 현재
접근, 최신성, 수용 조건을 충족할 때만 계속 사용할 수 있습니다.

## 오프라인 지식 패키지

지식 릴리스는 애플리케이션 배포 키트 및 규칙 카탈로그와 별도로 버전을 관리하는 데이터
전용 산출물입니다. 버전 2는 선택한 컬렉션이나 서비스 묶음별로 정규화 텍스트만 담은
완전한 패키지를 사용합니다. 원본 HTML/Markdown은 새 패키지가 아니라 수집기 재개 지점에
보존합니다. 변경분 전달은 후속 작업입니다. 수용된 기준 다이제스트와 결과 전체
매니페스트를 고정하고, 추가, 교체, 삭제 표시를 명시해야 합니다.

| 패키지 구성 요소 | 필요한 근거 |
|------------------|-------------|
| 서명된 매니페스트 | 스키마, 릴리스 식별/순번, 생성 시각, 출처 정책 참조, 읽기 프로그램 호환성, 정확한 파일 목록, 항목별 크기/미디어 유형/SHA-256 |
| 정규화 내용과 출처 이력 | 정확한 정규화 UTF-8 텍스트, 원본/정규화 SHA-256, 기준 URL, 적용 조건, 수집/확인 시각, 라이선스 참조, 기존 정규화 도구 버전이며 원본 본문은 제외 |
| 확인 증적과 수집 범위 | 문서별 원본 확인 결과/다이제스트, 수집/확인 시각 범위, 실패/제외 항목, 명확하고 제한된 수집 대상 분모 |
| 검토 자료 | 출처/라이선스 목록, 기계가 읽을 수 있는 차이, 변경된 제약, 검사 이력, 사람이 읽을 수 있는 검토 요약 |
| 선택적 수치 임베딩 | 정확한 입력 해시, 모델/개정, 차원, 문서 조각 분할 설정, 유한값/스키마 검증 |
| 철회 근거 | 명시적으로 검토한 삭제 표시이며, 패키지에 없다는 이유로 삭제를 허용하지 않음 |

실행 파일, 모델 가중치, 플러그인, 실행 가능한 프롬프트, SQL, 직렬화 객체 로더,
데이터베이스/색인 덤프, 실행 가능한 규칙/온톨로지 선언은 포함하지 않습니다. 반입은
용도가 제한된 전용 패키지 파서를 사용하며, 업로드 서비스의 임의 압축 파일 기능을
활성화하지 않습니다. 서명은 제작자의 주장과 정확한 바이트를 인증하며, 게시 내용의 진실성을
보증하지는 않습니다.

검증은 독립적으로 설정한 신뢰 루트와 위임된 지식 릴리스 신원을 사용합니다.
같은 패키지가 제공한 키, 새 원본 위치, 승인 주장, 완화된 한도를 신뢰하지 않습니다.
[오프라인 신뢰 설정 절차](../../runbooks/offline-trust-ceremony-ko.md)의 원칙을 재사용하되
지식 산출물 용도를 별도로 연결합니다. 운영용 신뢰 초기 설정은 구현 선행 조건이며,
이 계획만으로 확보한 기능이 아닙니다.

네트워크 접근 없이 서명된 메타데이터, 해시, 닫힌 파일 목록, 호환성, 만료, 재전송 방지
순번을 검증합니다. 경로 탈출, 절대 경로, 심볼릭 링크/하드 링크, 중복되거나 충돌하는
이름, 추가 항목, 압축 해제 폭탄, 미지원 내용은 기존 파서 상한에 따라 차단합니다.
신뢰 교체/철회는 별도로 관리하는 신뢰 갱신으로 전달하며, 문서 패키지가 자신의 신뢰를
갱신할 수 없습니다. 마지막으로 신뢰한 철회 정보의 시각을 명시합니다.

갱신 메타데이터가 만료되면 새 수용이나 활성화를 차단합니다. 이미 수용한 내용은 내부
수용 유효 기간, 철회 정책, 접근, 원본 최신성 제한을 따릅니다. 패키지 만료는 수집 날짜를
바꾸거나 유효한 과거 기록을 자동으로 철회하지 않습니다. 필요한 철회 근거가 없으면
철회가 없다고 가정하지 않고, 영향을 받는 사용을 차단합니다.

### 정규화 텍스트 전용 v2 호환성

`CloudKnowledgeDocument`는 두 본문 해시를 모두 검증하는 수집기 로컬 스냅샷으로 유지합니다.
`CloudKnowledgeTextDocument`는 `original_text` 필드가 없는 별도의 닫힌 전달 레코드이며,
빈 문자열이나 null 자리표시자도 넣지 않습니다. 변환은 로컬 스냅샷을 먼저 검증한 뒤 원본을
제외합니다. 정규화 텍스트, 출처 날짜, 적용 조건, 라이선스, 추출기 버전은 바꾸지 않습니다.
수신 측은 포함된 정규화 바이트와 서명된 출처 이력을 검증합니다. 빠진 원본의 해시는
제작자의 선언이지, 수신 측이 원본 바이트나 추출 품질을 검증했다는 증거가 아닙니다.
검증기가 대안으로 원본을 다운로드하거나 재구성하지 않습니다.

새 매니페스트는 `fdai.cloud-knowledge.v2`, 읽기 버전은 `2.0.0`, 묶음은
`fdai.cloud-knowledge-package.v2`를 사용합니다. 산출물 용도와 서명 영역은
`fdai.cloud-knowledge.release.v1`로 유지하고 서명된 매니페스트에 스키마 버전을 연결합니다.
묶음/매니페스트 버전 불일치와 v2의 원본 본문 필드는 차단합니다. 이전 읽기 프로그램은 v2를
처리할 수 없으므로 API/CLI와 작업자를 함께 업그레이드하세요. 전체 컬렉션, 이용 권한,
16 MiB 패키지, 정규화 UTF-8 바이트, 서명, 철회, 재전송, 승인, 독립 활성화 검증은 유지합니다.

읽기 경로는 과거 다이제스트를 바꾸지 않고 v1 검증과 저장된 작업자 입력 호환성을 유지합니다.
새 내보내기, 서명, 분리 서명 조립, 수집 후보 제출, 더 높은 순번의 롤백은 v2만 생성합니다.
사용 가능한 v1에서 롤백하면 원래 수용된 매니페스트 다이제스트를 고정하고, 출처 근거와
수용 만료는 유지한 채 정규화 텍스트 전용 후보를 새로 만듭니다. 기존 서명 바이트에서
원본을 직접 제거하지 않습니다. 이 전달 형식 변경은 [이슈 #995](https://github.com/dotnetpower/fdai/issues/995#issuecomment-5667579564)에
기록한 실제 문서의 숨겨진 화면 요소, 링크, 여러 절에 걸친 주의사항 문제를 해결하지 않습니다.

## 내부 검토와 활성화

1. **격리:** 봉인된 패키지를 받고 도착 시각, 전달 신원, 다이제스트를 기록합니다.
   도착만으로 검색에 공개하거나 외부에서 내용을 가져오지 않습니다.
2. **검사:** 신뢰 체인과 모든 항목을 검증하고, 정책이 승인한 검사기 및 악성코드 탐지
   데이터 버전으로 내부 악성코드/내용 검사를 수행합니다. 보안 선행 조건이 오래됐거나
   없으면 보류합니다. 제작자의 검사 보고서가 내부 검토를 대신하지 못합니다.
3. **검토 준비:** 활성 세대와 비교하여 변경된 절, 권한, 적용 조건, 날짜, 누락, 철회를
   제시합니다. 요청자와 독립된 보안 검토자가 제안한 내용 범위를 수락하거나 차단합니다.
4. **비공개 색인 생성:** 통제된 작업자가 수락한 내용으로 비활성 색인을 생성합니다.
   승인된 정규화 바이트를 보존하고 변환으로 의미가 바뀌면 다시 검토합니다. 선택적으로
   반입한 벡터에는 정확히 일치하는 승인된 질의 임베딩 모델이 필요합니다. 그렇지 않으면
   사용 가능한 승인된 내부 모델로 해당 색인 전체를 다시 임베딩하거나, 명시적으로 허용한
   어휘 검색 전용 방식을 사용합니다. 호환되지 않는 벡터 공간을 섞거나 대안으로 인터넷에서
   모델을 가져오지 않습니다.
5. **정확한 대상 승인:** 최종 권한은 패키지/내용 다이제스트, 색인 입력 다이제스트,
   대상 컬렉션, 독자 범위, 용도, 정책 개정, 검토자, 만료, 예상 활성 개정에 연결됩니다.
   반입 시뿐 아니라 활성화 시에도 이 조건과 현재 검사기/신뢰 근거를 다시 확인합니다.
6. **활성화:** 수용, 필요한 승인, 예행 실행, 영속 감사 의도 기록 이후 논리적 대상 잠금
   아래에서 비교 후 교체 방식으로 활성 컬렉션 포인터를 변경합니다. 부분 세대는 노출하지 않습니다.
7. **검증:** 독립적으로 승인된 재조회로 활성 세대와 예상 검색/제외 인용을 확인합니다.
   이 결과로만 성공을 종결하며, 색인 생성 완료만으로 성공을 보고하지 않습니다.

온라인 후보도 같은 조건을 적용합니다. 초기 기본값은 독립적인 수동 활성화입니다.
변경 없는 확인 관측은 내용 재승인 없이 승인된 원본 확인 정책에 따라 수용할 수 있습니다.
자동 내용 활성화에는 명시적이고 제한된 상시 승인과, 별도 테스트 및 관찰 모드 평가를 거친
승격이 필요합니다. 수집기를 켜는 것은 어느 권한도 부여하지 않습니다.

후보가 실패해도 유효한 활성 세대는 유지합니다. 활성화/재조회 실패는 검증된 롤백으로
사용 가능한 이전 세대를 복원하며, 안전한 대상이 없으면 사용 불가 상태로 전환합니다.
롤백은 더 높은 활성화 순번을 갖는 새로운 감사 대상 활성화입니다. 릴리스 신뢰의 최대
수용 순번을 낮추거나 철회된 내용을 되살리지 않습니다. 이전 시각과 인용 식별 정보를
보존합니다. 보존, 법적 보류, 삭제 표시 우선 공개 차단, 완전 삭제는 독립적인 정리
메커니즘이 아니라 기존 [문서 수명 주기](document-lifecycle-governance-ko.md)를 따릅니다.

## 담당 체계와 저장소 경계

기존 [문서 수집 담당 맵](document-ingestion-agent-ownership-ko.md)을 재사용합니다.
Huginn은 수신, Heimdall은 검사 사실, Forseti는 수용 판단, Var는 사람 승인,
Muninn은 색인 생성, Saga는 감사, Vidar는 복구를 담당합니다. 기계적인 작업자는 문서
저장소 권한만으로 Muninn의 색인 명령과 통제된 복구 명령을 적용합니다. 수집기, 반입기,
Console, 작업자에 Thor의 관리 리소스 신원을 부여하지 않으며, 문서가 `ActionRun`
요청으로 바뀌지 않습니다.

상시 서비스를 새로 만들기보다 기존 서비스 소유 메타데이터, 객체 저장소, PostgreSQL
검색 저장소를 확장합니다. 수집 API는 수신 기록, 문서 작업자는 내용/색인 산출물,
Core는 에이전트 판단과 최신성 정책 평가를 소유합니다. 타입이 지정된 이벤트는 개정 참조를
전달하며, 공유 가변 작업 흐름 상태나 문서 본문을 전달하지 않습니다. Operator API와
Console은 승인된 변환 결과와 요청만 제공합니다. 영속 변경에는 중단 조건, 검증된 복구,
제한된 영향 범위, 예행 실행, 잠금, 멱등성, 2단계 감사, 효과 검증을 유지합니다.

## 답변과 운영자 경험

통제된 근거 계약의 클라우드 출처 정보는 각 주요 주장을 원본 URL과 절, 문서 개정, 가져오기/확인
증적, 컬렉션 세대, 답변 기준 시점, 최신성 정책 개정에 연결합니다. 순위를 매기기 전에
후보의 접근을 승인하고 필터링하며, 출력 전에 활성/수용/철회 상태를 다시 확인합니다.
정확한 리소스/적용 조건 필터에 어휘 검색과 선택적 의미 검색을 결합합니다. 원본 조건이나
필수 의존 근거를 알 수 없으면 검색 점수로 호환성을 추론하지 않습니다.

서버가 소유한 표시 경로는 항상 수집 날짜, 마지막 성공 원본 확인, 최신성 상태, 출처 이력을
보여 줍니다. 패키지/반입/활성화 날짜는 별도 상세 정보이며 이를 대체하지 않습니다.
여러 출처는 인용별 날짜를 유지하고, 가장 최근 날짜만이 아니라 날짜 범위와 가장 취약한
필수 상태를 요약합니다. 어휘 검색 전용 방식의 제한을 포함하여 실제 검색 모드를 명시합니다.
과거 답변 증적은 변경하지 않으며, 다시 열 때 접근을 재확인하고 현재 경고는 별도로 추가합니다.
오프라인 인용은 저장된 원본 절을 열며, 외부 URL은 실행되지 않는 출처 이력 표시로 유지합니다.

가상 날짜 예: "2026-08-25 수집, 2026-09-14 원본 확인, 변경 없음.
이 설명은 해당 원본 확인 기준이며, 사용자의 APIM 인스턴스를 실시간 관측한 결과가 아닙니다."

가상 날짜 예: "2026-08-01 수집 및 마지막 확인, 2026-09-10 반입.
2026-09-14 기준으로 운영 프로필의 30일 제한을 초과했습니다. 과거 참조용이며,
현재 네트워크 요구사항에는 승인된 갱신이 필요합니다." 반입으로 원본 확인 후 44일이
지났다는 사실을 가리지 않습니다.

지식 작업 공간은 출처 모드, 정책, 활성/후보 릴리스, 수집/확인 날짜, 다음 도래 시각,
마지막 시도 결과, 검토 대기, 패키지 신뢰, 수집 범위를 표시합니다. 갱신, 내보내기,
검사, 검토, 활성화, 롤백 요청을 분리하고 현재 역할 기반 접근 제어(RBAC)를 적용합니다.
기한 초과/오래된 자료 비율, 변경/변경 없음/실패 수, 검토 지연, 검증 실패,
저장/임베딩 비용, 검색 품질, 보류된 답변을 추적합니다. 알림은 범위를 제한하고 중복을 제거합니다.

## 의존성 순서의 제공 계획

### 구현된 v1 경계

수집 API는 출처 재개 지점, 추가 전용 확인 증적, 릴리스 순번 예약과 인증된 상태 조회,
갱신, 서명 전 검토 자료 내보내기, 패키지 검사/반입, 수집 후보 제출, 롤백 요청을 소유합니다.
기존 호스트가 매일 범위가 제한된 수집을 시작하며 기한이 도래한 온라인 출처만 처리합니다.
재시작 시 도래 여부를 다시 확인하며 이미 성공한 다운로드를 반복하지 않습니다.

각 제한된 컬렉션 릴리스는 하나의 변경할 수 없는 관리 문서 버전입니다. 별도 승인 시스템
대신 기존 Huginn, Heimdall, Forseti, Saga, Var, Muninn 경로를 재사용합니다.
`cloud_reference`는 서명이 유효해도 독립 검토가 필요합니다. 원문과 색인 행은 예상 버전
확인을 거쳐 반영합니다. 별도 읽기 전용 연결에서 활성 버전과 모든 저장 조각이 봉인된
원문과 정확히 일치하는지 확인할 때까지 새 세대는 사용 불가입니다. 두 번째 조건부
트랜잭션에서 조각 공개, 사용 가능 상태와 최종 감사를 함께 반영합니다. 검증 실패 시
대기 세대를 자동으로 사용 불가 상태로 격리하며 이전 버전을 다시 승인하지 않습니다.
롤백은 여전히 사용할 수 있는 보존 버전으로 더 높은 순번의 검토 요청을 만들고 날짜를
보존하며 선언된 철회 출처를 되살리지 않습니다.

패키지는 일반 압축 파일이 아닌 최대 16 MiB의 정규 JSON입니다. 새 v2는 원본 없이 정확한
정규화 UTF-8 텍스트와 출처 이력을 포함하며 기존 v1도 읽을 수 있습니다. 두 형식 모두
용도에 결속된 Ed25519 서명과 독립 설치한 신뢰를 사용합니다. 오프라인 CLI는 두 버전을
검사하지만 v2 분리 서명만 조립하며 개인 키를 읽지 않습니다.
클라우드 검색은 임베딩 없이 어휘 검색 전용으로 유지합니다.
추출은 표와 각주를 포함한 제목 단위의 절을 보존합니다. 절과 출처 정보가 8 KiB를
초과하면 적용 조건이나 예외를 잘라내지 않고 보류합니다.
`FDAI_DOCUMENT_RETRIEVAL_MODE=lexical`은 문서 서비스 시작 시 임베딩 점검 호출도 제거합니다.

Console 지식 전체 현황은 신뢰 가능한 날짜 범위, 출처 결과, 검토/반입, Owner 전용 롤백
요청을 제공합니다. 의미 답변 표시 경로는 민감 값 제거 후에도 날짜를 보존하며, RCA는
오래됐거나 업데이트 대기이거나 적용 조건을 확인하지 못한 원본 근거를 보류합니다.
타입이 지정된 의미 대상은 현재 발화의 정확한 원문 구간으로 공급자, 리소스 유형, 세대,
SKU, API 버전, 지역과 배포 모드를 연결합니다. 누락 조건을 호환성으로 간주하지 않습니다.
조회 입력은 제한된 단일 값과 문자열 배열 선택자이며 근거 객체를 직접 전달하지 않습니다.
객체형 FunctionType 근거 입력은 의존 조회 결과로만 받으며 선택자가 관측 상태를 주장하지 않습니다.
발화에 정확한 문서 참조가 있으면 순위 계산 전에 승인된 해당 버전과 클라우드 선택 조건을
함께 적용합니다. 결합 조회 기능이 없으면 컬렉션 전체로 넓히지 않고 보류합니다.
정규 의미 값 `cloud_as_of`는 최신이며 조건이 맞는 근거를 요구하고, `cloud_current`는
답변 중 외부 수집을 하지 않고 새 관측 필요 상태로 종료합니다. 출처/신뢰 정책이 없으면 테스트 키나
샘플 데이터로 대체하지 않고 사용 불가로 표시합니다.
[운영 절차](../../runbooks/cloud-resource-knowledge-ko.md)를 따르세요.

남은 목표 동작은 구현으로 주장하지 않습니다. 이전 세대 자동 재활성화, 독립 운영 효과
증적, 자연어 적용 조건의 더 넓은 별칭 지원, 미러 원본 확인 증적, 전체 온라인 출처 등록,
선택적 임베딩/변경분 전달에는 구현 원장에 기록된 추가 근거와 결정이 필요합니다.

| 작업 패키지 | 선행 조건 | 산출물과 관찰 가능한 완료 조건 |
|-------------|-----------|-------------------------------|
| K1: 계약과 정책 | 설계/보안 합의 | 타입이 지정된 레지스트리, 개정, 증적, 릴리스, 승인, 답변 계약과 가상 시계 테스트로 7/30일 경계, 반입 시각 비갱신, 304 연결, 알 수 없는 시각 검증 |
| K2: 연결 환경 수집 | K1 | Azure APIM과 검토된 네트워크 의존 문서, 조건부/기한 도래 수집, 재시작 재개 지점, 정확한 부분 결과, 목록/인증 실패 시 삭제하지 않음 검증 |
| K3: 오프라인 산출물과 신뢰 | K1 | 완전한 데이터 전용 패키지, 독립 신뢰 초기 설정, 내용 목록, 오프라인 검증기, 내부 검토 증적과 변조/재전송/신뢰 만료/위험한 압축 파일 차단 |
| K4: 공통 수용과 활성화 | K2 및 K3 | 기존 에이전트/작업자 통합, 비활성 세대 생성, 정확한 승인, 원자적 교체, 독립 재조회, 철회, 실행기 권한 없는 검증된 롤백 |
| K5: 검색과 운영자 화면 | K4 | 날짜를 명시한 이중 언어 답변, 적용 조건 필터, 혼합 출처 상태, 무네트워크 어휘/임베딩 모드, 최신성/설정 표시, 개정 안전 요청 |
| K6: 수용 검증과 단계적 확장 | K5 | 연결 환경 및 외부 통신 차단 환경의 통합 훈련 후, 서비스 묶음 추가나 자동 활성화 전에 제한된 수집 범위와 실패 근거 공개 |

K1 이후 K2와 K3는 독립적으로 진행할 수 있지만, 공통 계약과 K4 통합은 순차적으로
진행합니다. APIM과 VNet, NSG, DNS, 비공개 네트워크 의존 문서부터 시작하며 전체 Azure
지원이라고 주장하지 않습니다. 비-Azure 어댑터, 변경분 전달, 더 넓은 자동 활성화는
별도의 후속 결정입니다. 출처 목록, 법적 검토, 신뢰 선행 조건, 측정된 처리 비용을
확인하기 전에는 제공 날짜를 약속하지 않습니다.
[구현 원장](../../roadmap-implementation/interfaces/cloud-resource-knowledge-lifecycle.md)은
이 계획과 실제 구현을 분리해서 기록합니다.

### 수용 검증표

| 시나리오 | 필요한 결과 |
|----------|-------------|
| 주간/월간 임계값, 정확한 경계, 프로세스 재시작 | 결정론적인 도래/오래됨 상태이며 활성 작업 중복이나 재시도에 따른 최신성 갱신이 없음 |
| 304, 동일 본문 200, 변경 본문 200, 잘못된 변경 확인자 | 올바른 개별 증적, 내용이 바뀐 경우에만 새 색인, 재현 가능한 과거 인용 |
| 부분 수집, 빈 목록, 로그인 페이지, 404, 429/503 | 명시적 누락/보류, 제한된 시도, 사용 가능한 이전 세대 유지, 대량 삭제 없음 |
| 오래된 패키지를 오늘 반입, 유효한 서명이지만 오래된 원본 | 원래 날짜와 올바른 오래됨 경고를 유지하고 현재 운영 결론을 내리지 않음 |
| 변조된 항목, 바꿔 넣은 키, 위험한 압축 파일, 만료된 신뢰 또는 검사 데이터 | 공개 전에 차단/보류하며 권한이나 외부 대체 경로를 얻지 못함 |
| 승인 만료, 정책 변경, 동시 활성화, 프로세스 종료 | 재검증과 이전 작업 차단으로 활성 세대는 최대 하나이며 지속적으로 기록되는 복구 수행 |
| 새 버전 발견, 출처 철회, 롤백, 활성 질의/캐시 | 업데이트 대기를 표시하며 철회된 결과, 혼합 세대, 오래된 캐시 우회, 신뢰 순번 롤백이 없음 |
| 다른 SKU/API 세대, 여러 근거 시각, 내부 임베딩 모델 부재 | 호환되지 않는 답변이 없으며 출처별 날짜와 명시적 보류/어휘 검색 전용 결과 제공 |
| 외부 통신이 차단된 반입, 색인 생성, 검색, 인용 열기 | 외부 DNS/HTTP/모델 호출이 없으며 접근 정책에 따라 내부 저장 인용을 열 수 있음 |
