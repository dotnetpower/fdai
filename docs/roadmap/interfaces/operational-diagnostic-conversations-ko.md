# 운영 진단 대화

이 계약은 읽기 전용 운영 대화의 네 가지 유형과 관찰 가능한 수락 기준을 정의합니다.
완전한 답변과 안전한 판단 보류, 구성 요소 구현과 대화 경로 검증 근거,
구성 변경과의 상관관계와 입증된 원인을 구분합니다.

> **범위:** 인벤토리 문서, GPT 배포 구성 비교, Application Gateway
> (AppGW) 지연 시간 비교, API Management (APIM)와 GPT 오류 비교를 다룹니다.
> 이 설계는 실행 권한을 부여하지 않으며 에이전트나 상태 기록 주체를 추가하지 않습니다.
>
> **2026-09-07 기준 상태:** 현재 구성 요소 범위의 테스트 1,237개가 통과했습니다. 집중 비평 및
> 강화 검토 12회에서도 43개 사례와 프롬프트 범위 검사가 통과했습니다. 이 과정에서 Medium
> 문제 네 건을 수정했습니다. APIM
> 게이트웨이 측 `429`와 `503` 관측 누락, Metrics API 오류의 공급자 응답 본문 노출, 현재
> 32,865자인 프레임 프롬프트를 거부하던 32,768자 플래너 한도라는 Medium 문제 세 건을
> 수정했습니다. 알려진 운영 유형은 별도의 2,173자 프롬프트를 사용하고, 기존 범용 프롬프트에는
> 33,000자 상한을 적용합니다. 첫 번째 턴의 명시적 운영 요청은 11-16초가 걸린 Adaptive 계획
> 단계를 우회하고 서술자 308개를 최대 5개로 축소합니다. 이러한 검사는 전체 경로 통과를
> 입증하지는 않습니다. 보존된 표준 대화
> 경로의 문서 요청은 약 39.9초 후 다운로드 결과물 없이 작업 초안을 반환했고, 게이트웨이
> 질문은 `semantic_frame_unavailable` 사유로 보류되었습니다.

## 설계 한눈에 보기

기존 스키마 검증을 거치는 의미 판정으로 요청 전체를 해석합니다. 형식이 지정된 목표, 대상,
허용 범위, 시간, 출력 형태를 권한이 적용된 `ObjectSet` 읽기(권한에 따라 필터링한 컬렉션),
형식이 지정된 경로의 증적(허용된 속성 탐색의 근거), `MetricWindowProvider`(기존의 권위 있는
메트릭 구간 인터페이스)에 연결합니다. 근거를 검증한 후 기존 대화 표시 계층과 문서 내보내기
기능으로 결과를 제공합니다.

## 시나리오 수락 기준

모든 행에는 아래의 공통 경계가 적용됩니다. 근거 부족을 정확히 밝히는 판단 보류는 안전성
경계를 충족하지만, 요청한 답변의 수락 기준을 충족하는 것은 아닙니다.

| 유형 | 필요한 답변 또는 결과물 | 관찰 가능한 수락 기준 |
|------|-------------------------|-----------------------|
| F1: 범위가 지정된 완전한 리소스 인벤토리 문서 | 확인된 허용 컬렉션의 다운로드 문서입니다. 작업 초안이나 이전 답변의 내보내기가 아닙니다. | 결과물을 현재 턴과 principal에 연결하고, 반환된 모든 읽기 가능 리소스와 지원 속성을 포함합니다. 제외 항목과 관찰 시각을 밝히고 원본 및 내보내기의 완전성을 입증합니다. 페이지 누락이나 출력 제한이 있으면 완전한 다운로드라고 표시하지 않습니다. |
| F2: GPT 배포 구성 변경 | 정확한 배포와 요청 구간에 대한 읽기 전용 변경 전후 비교입니다. | 읽기 가능한 변경 경로, 이전/이후 값, 원본, 유효/기록 시각, 과거 데이터의 누락 범위를 표시합니다. 배포 용량 단위는 분당 토큰 수(TPM), 할당량, 관찰된 토큰 사용량과 구분합니다. 변환을 추측하거나 구성을 변경하지 않습니다. |
| F3: AppGW와 백엔드 지연 시간 및 변경 | 시간 구간을 맞춘 게이트웨이/백엔드 메트릭과 해당 범위의 구성 변경입니다. | 총 시간, 백엔드 연결 시간, 첫 바이트 시간, 마지막 바이트 시간을 구분합니다. 원래 정의, 단위, 집계, 차원, 데이터 범위, 토폴로지 근거를 보존합니다. 전후 차이와 같은 시기의 변경을 표시하되, 원인을 단정하거나 게이트웨이 자체 처리 지연을 만들어 내지 않습니다. |
| F4: APIM과 GPT HTTP 500 및 변경 | 시간 구간을 맞춘 APIM 게이트웨이, APIM 백엔드, 확인된 GPT 배포의 근거와 해당 범위의 구성 변경입니다. | `429`, `500`, `503`에 대해 `GatewayResponseCode`와 `BackendResponseCode`를 구분하고 GPT 측 관찰도 별도로 유지합니다. 비율의 분모와 계정/배포 범위를 보존합니다. APIM 500만으로 GPT 500이나 요청 제한을 입증할 수 없습니다. 범위가 제한된 APIM 프로필은 이제 게이트웨이 측 `429`와 `503`을 생략하지 않고 게이트웨이/백엔드 상태 조합 6개를 모두 읽습니다. |

## 근거 및 안전성 경계

- **정확한 범위:** 인증된 principal과 서버가 확인한 리소스 컬렉션을 사용합니다.
  모든 읽기, 탐색, 증적, 집계, 내보내기에서 범위를 다시 확인합니다. 계정 전체 데이터를
  배포 데이터 대신 묵시적으로 사용하지 않습니다. 전체 이력의 참조를 범위가 제한된 출력에
  첨부하지 않습니다.
- **모호성:** 확인되지 않은 배포, 백엔드, 컬렉션, 표준 시간대 또는 "전후"의 의미를
  명확히 요청합니다. 해결되지 않으면 형식이 지정된 사유로 보류합니다. 이름이나 모델
  키워드로 추측하지 않습니다.
- **정확한 시간:** 절대 시작/종료 시각, 표준 시간대, 집계 구간, 경계의 의미를 기록합니다.
  유효 시각, 이벤트 시각, 관찰 시각, 기록 시각을 구분합니다. 정렬된 동일 길이 구간을
  비교하고 오래된 샘플, 누락, 늦게 도착한 관찰, 기준 구간 선택을 밝힙니다.
- **원래 메트릭 의미:** 공급자 메트릭, 상태 차원, 집계 방식, 표본 집단, 단위를 보존합니다.
  문서화된 단위만 변환합니다. 평균을 백분위수나 최솟값으로 취급하지 않습니다. 별도로
  집계한 총 시간과 백엔드 시간의 차감으로 게이트웨이 처리 시간을 입증할 수 없습니다.
- **용량:** 배포 용량 설정은 TPM이 아닙니다. 지원되는 변환도 모델, 버전, 배포 유형에
  맞는 권위 있는 근거가 필요합니다. 근거가 없으면 TPM은 알 수 없음으로 표시합니다.
  토큰 사용량은 측정값이며 구성된 용량이 아닙니다.
- **완전성:** 원본 열거, 페이지 처리, 중복 처리, 행/열/바이트 한도, 과거 데이터 범위,
  표시 잘림을 각각 추적합니다. 반환된 행을 모두 내보낼 수 있어도 원본이 완전하다는
  뜻은 아닙니다. 완전한 빈 인벤토리와 읽기 실패를 구분합니다.
- **누락 데이터:** 관찰된 0, 샘플 없음, 지원되지 않는 차원, 접근 차단, 과거 이력 없음,
  공급자 실패, 불완전한 결과를 서로 다른 상태로 유지합니다. 사용할 수 없는 근거를
  0으로 바꾸거나 범위 내 전체 이력 없이 "변경 없음"이라고 주장하지 않습니다.
- **인과관계 단정 방지:** 구성 차이와 같은 시기의 메트릭 변화는 연관성만 보여 줍니다.
  다른 설명 가능성을 남겨 둡니다. 토폴로지나 요청 간 연결 근거가 없으면 게이트웨이/
  백엔드 귀속을 단정하지 않습니다. 오류 수가 비슷하다는 이유로 같은 요청이라고 보지 않습니다.
- **변경 금지:** 진단과 문서 생성은 리소스, 할당량, 정책, 승인 상태, 실행 모드를 바꾸지
  않습니다. 별도 변경 요청에는 기존 초안 및 승인 경계를 적용합니다. 이 작업에서는 실제
  읽기와 모델 질문이 허용되지만 TPM 축소와 장애 주입은 허용되지 않습니다. 허용되었다는
  사실만으로 검증이 실행되었다고 볼 수 없습니다.
- **실행 한도:** 기존의 전체, 단계별, 진행 정체 제한 시간과 진행 신호를 유지합니다.
  예기치 않은 모델 대체, HTTP `429`/`503`, 공급자 시간 초과, 기한 만료가 발생하면 해당
  시도를 종료합니다. 새 가설이나 명시적 허용 없이 실제 요청을 반복하지 않습니다.
- **대화 지연 시간:** 검증된 첫 답변 `token` frame은 5초 안에 도착하는 것이 좋습니다. 상태,
  접수 확인 및 검증되지 않은 초안은 첫 토큰 도착 시간(TTFT)을 충족하지 않습니다. 최종 답변이
  나중에 성공하더라도 더 느린 턴은 대화 수락 기준을 통과하지 못합니다.

## 설계 비평 및 수정

이 설계 수준의 검토는 공식 강화 검토 횟수에 포함하지 않습니다.

| 초안 접근 방식의 위험 | 필요한 수정 |
|-----------------------|-------------|
| "문서", "GPT", "500" 같은 표현으로 경로를 선택합니다. | 모델 기반의 형식이 지정된 판정과 결정론적 기능 검증을 사용합니다. 키워드 라우팅이나 고정된 예시 문장 일치는 사용하지 않습니다. |
| 모든 문서 요청을 변경으로 취급하거나 이전 결과를 내보냅니다. | 새 인벤토리 읽기와 이전 결과의 서식 변경을 구분하고, 결과물을 검증된 현재 턴에 연결합니다. |
| 표시 행만 필터링한 뒤 전체 스냅샷/이력 참조를 첨부합니다. | 근거 집계와 출력 전에 읽기 가능한 객체/경로의 출처를 필터링합니다. 참조에도 값과 같은 범위 격리를 적용합니다. |
| 게이트웨이와 모델에 일반 지연 시간 또는 오류 메트릭을 공통 적용합니다. | `MetricWindowProvider`를 통해 검토된 공급자 고유 개념을 사용하고 차원, 범위, 시간, 단위, 완전성을 정확히 유지합니다. |
| 진단 에이전트, 이력 기록 주체, 직접 에이전트 호출을 추가합니다. | 기존의 보안 쿼리, 메트릭, 대화, 이벤트 경계를 재사용합니다. 실행 권한, 에이전트, 상태 기록 주체를 추가하지 않습니다. |

## 현재 근거와 남은 수락 조건

권위 있는 전달 이력입니다. 다음은 범위가 제한된 상태 요약이며 새로운 실행 환경 인증이
아닙니다. 현재 구성 요소 결과는 체크포인트 `6ba5c91d3` 기반의 격리 작업 트리에서 다시
실행했습니다.

|------|-----------|------------------------|
| F1 문서 구성 요소 | 구현되었습니다. 최종 구성 요소 테스트 1,237개와 강화 검토 행렬 43개에 포함되었습니다. | 관찰한 표준 대화 요청은 약 39.9초 후 결과물 없이 작업 초안을 반환했습니다. 통합 후 같은 턴에 연결된 다운로드 성공 증적을 남겨야 합니다. |
| F3/F4의 공급자 고유 메트릭 구성 요소 | 구현되었습니다. 메트릭 및 게이트웨이 집중 테스트 137개가 통과했고, 이어서 최종 구성 요소 테스트 1,237개가 통과했습니다. | 현재 공급자 데이터에 대한 표준 대화 경로 근거를 보존해야 합니다. 서로 겹치는 테스트 수는 합산하지 않습니다. |
| F2/F3/F4의 범위가 제한된 구성 비교 | 구현되었습니다. 원본 범위 분리, 이중 시간 경계, 범위가 지정된 비교 사례가 강화 검토 행렬과 최종 구성 요소 검사에서 통과했습니다. | 사용 가능한 이력에 대한 표준 대화 경로의 변경 전후 증적을 보존해야 합니다. |
| F3/F4의 복합 게이트웨이 질문 | 구성 요소 경계에서 구현되었습니다. APIM은 최대 74회 읽기 범위 안에서 게이트웨이와 백엔드의 `429`, `500`, `503` 건수를 유지합니다. | 보존된 표준 게이트웨이 질문은 `semantic_frame_unavailable` 사유로 보류되었습니다. 표준 대화 경로에서 메트릭/구성 조합을 입증해야 합니다. |
| 공식 비평 및 강화 검토 | 구현되었습니다. 12회를 완료했고 Medium 문제 네 건을 수정했으며, 해결되지 않은 Medium 이상 구성 요소 문제는 확인되지 않았습니다. | 표준 대화 경로와 공급자 근거의 미비점은 별도로 남아 있으며 통과로 계산할 수 없습니다. |

나열한 모든 미비점을 계약에서 다룬다고 해서 모두 수정되었다는 뜻은 아닙니다. 네 유형
모두 전체 경로 수락 기준을 아직 충족하지 못했습니다. 구현 기록에 관찰 가능한 재개
조건을 남깁니다.
