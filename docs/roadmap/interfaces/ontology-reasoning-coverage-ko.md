# 온톨로지 추론 커버리지

이 문서는 온톨로지에 근거한 질문 답변에서 100% 커버리지가 무엇을 뜻하는지 정의하고, 지금 이를 막는
측정된 용량, 카탈로그, 데이터 한도를 기록하며, 달성 가능한 보장에 도달하는 완결 프로그램을 담당합니다.
이 문서는 [온톨로지 추론 컴파일러](ontology-reasoning-compiler-ko.md)를 확장합니다.

> **상태:** 2026-09-28에 제안된 계획입니다. Owner가 같은 날 컴파일러 결정 여덟 가지를 승인했습니다.
> 이 문서 끝의 결정은 아직 승인이 필요합니다. 이 문서의 어떤 부분도 구현되지 않았습니다.
>
> **정직성 경계:** FDAI는 모든 질문이 완전하고 올바른 답을 받는다고 주장하지 않습니다. 커버리지 보장은
> 선언 집계, 컴파일 규칙, 최종 처리 동작에 적용됩니다. 지원 비율과 답변 커버리지는 코호트별로 보고하는
> 측정값입니다.

## 설계 개요

| 보장 | 목표 | 증명 |
|------|------|------|
| G1 선언 집계 | 100% 집계 | 적용되는 모든 선언과 차원이 `supported`, 관리 절차를 거친 `excluded`, `missing` 중 하나이며, `missing`은 0이어야 하고 지원 비율을 보고 |
| G2 형식 완결 | 100% 집계 | 수용 가능한 모든 요인 칸이 컴파일되거나 타입이 지정된 지원되지 않는 사유를 반환하며, 계열별 지원 비율을 보고하고 후퇴를 허용하지 않음 |
| G3a 최종 결과 불변 조건 | 100% | 검증기가 내보내는 모든 최종 결과에서 피연산자 출처, 수준 일치, 제한 원자 차단, 인과 주장 규칙, 실행 권한 0을 증명 |
| G3b 해석 충실도 | 관측 0, 상한 보고 | 다른 질문에 대한 답변을 수용된 온톨로지 턴에서 `0/n`과 단측 95% 상한으로 보고 |
| M1 답변 커버리지 | 측정 | 답할 수 있는 질문 중 올바르게 답한 비율을 영역, 언어, 근거 코호트별로 측정 |

답변 커버리지는 설계상 100%가 될 수 없습니다.

1. **모델 분류**: T1 형식 정확도는 통계적이며, 같은 구성도 측정 실행마다 달랐습니다.
2. **데이터와 reader**: 인스턴스 원본이 없는 객체에 대한 질문에는 답이 없습니다.
3. **보존 기간과 범위**: 제공자 이력 보존 기간, 아카이브 경계, 인벤토리 범위, principal 가시성이 모든
   답을 제한합니다.
4. **열린 언어**: 바꿔 말하기는 끝이 없고, 카탈로그는 영어와 한국어만 있습니다.
5. **권한**: 액션 요청은 실행된 답이 아니라 관리되는 초안으로 끝납니다.

G3a는 이 영역의 모든 실패를 눈에 보이는 제한 사항, 명확화, 보류로 바꿉니다. G3b는 진짜 0을 증명할 수
없으므로, 해석 재진술로 남은 오해석을 드러내고 표본 감사로 상한을 둡니다. 사교, 지식, 조언 턴은 G3b
분모에 넣지 않고 `not_applicable`로 표시합니다.

## 커버리지 차원

`ReasoningCoverageReceipt`는 구조 커버리지 증적을 확장합니다. release, 역할, 목적, 언어별로 만들며,
적용되는 선언과 차원마다 `supported`, `excluded`, `missing`, `not_applicable` 중 하나의 상태를
기록합니다. 적용 여부는 선언 종류에서 정해지므로 D3는 LinkType에만, D5는 FunctionType에만 적용됩니다.

| 차원 | 적용 대상 | 지원 조건 | 대표적인 제외 |
|------|-----------|-----------|---------------|
| D1 서술자 | 모든 선언 | principal 범위의 서술자가 있음 | 해당 역할에서 읽을 수 없음 |
| D2 언어 표면 | ObjectType, LinkType 역할, Interface, ActionType, 운영자가 쓰는 Property | 검토된 영어와 한국어 용어가 있음 | 내부 타입의 `no_operator_surface` |
| D3 관계 의미 | LinkType | 특성, 양방향 역할, 전이성, 카디널리티가 검토됨 | `relation_internal` |
| D4 인스턴스 원본 | ObjectType | 인스턴스 저장소, 전용 reader, 소유자 변환 결과 중 하나에 바인딩됨 | 담당 설계와 함께 `schema_only` |
| D5 함수 계약 | FunctionType | 모든 인자가 출처 `span`, `anchor`, `handle`, `server`, `default` 중 하나를 선언하고, 앵커는 적용 가능한 타입을 선언함 | `not_conversational` |
| D6 속성 의미 | Property | 타입, 연산자, 단위, 값 영역이나 자유 텍스트 여부가 선언됨 | `not_filterable` |
| D7 근거 의미 | 인스턴스 원본 | 완전성 증명, 신선도, 시간 축, 보존 경계가 선언됨 | 없음, 미비하면 D4를 막음 |
| D8 표시 | 출력 종류 | 이중 언어 렌더러가 그 종류, 잘림, 이어 보기를 처리함 | 없음 |

제외 관리는 G1을 정직하게 유지합니다.

- **예산**: release마다 새 제외의 기본 예산은 0이며, 예산을 올리려면 검토된 카탈로그 변경이
  필요합니다.
- **기록**: 제외마다 사유, 담당 설계, 만료를 적고, 원본 소유자와 작성자에게서 독립된 검토자의 승인을
  받습니다.
- **감사**: release마다 제외의 10%를 무작위로, 최소 20개 또는 전체가 그보다 적으면 전부 감사하고,
  근거가 없는 제외는 되돌립니다.
- **보고**: 증적은 차원별 지원 비율, 즉 적용 대상 중 지원된 비율을 공개하며, 제외는 지원으로 세지
  않습니다.

커버리지 작업은 카탈로그 코드 방식이며, 각 변경은 권한을 주지 않는 검토된 선언 리비전입니다.

상호작용을 테스트합니다.

| 주체 범위, 요구, 시간 종류별 연산 | 16 x 4 x 4 x 7 = 1,792 | 노드 패턴 또는 타입이 지정된 지원되지 않는 사유 |
| 운영자가 쓰는 속성별 필터 역할 | 속성과 역할마다 한 칸 | 조건식 템플릿 또는 `not_filterable` |
| 측정과 앵커 타입별 함수 | 함수 39개와 적용 가능한 타입 | 함수 노드 또는 `no_applicable_function` |
| 상호작용 | 모든 요인 쌍, 위험 기준으로 고른 세 요인 조합, 목표 최대 4개의 모든 의존 구조 | 노드 32개와 출력 8개 이내의 계획 하나, 또는 `question_too_complex` |

모든 형식은 정규화된 형식 식별자에 대응하므로, 분할 조각과 요인 표가 수용 가능한 공간을 빠짐없이
나눈다는 것을 증명할 수 있습니다. 표는 입출력 없이 모든 카탈로그와 컴파일러 변경의 집중 게이트에서
실행되며, 자기 칸이 없는 새 선언은 게이트에서 실패합니다. 계열마다 지원되지 않는 칸 예산과 후퇴 금지
규칙이 있으므로, 모든 칸을 지원되지 않음으로 돌려서는 통과할 수 없습니다.

`draft_action`은 G2 밖에 둡니다. 이 연산은 기존의 관리되는 액션 초안 전달로만 컴파일되며, 검토된
이중 언어 액션 용어와 대상 타입 호환성으로 ActionType을 고르고, 모호하면 명확화하며, 초안은 실행
권한을 주지 않습니다.

### 질문 분류 체계 완결

질문 400개로 이루어진 질문 은행이 경험적 분모입니다. 이 중 300개에 결과 형태가, 335개에 시간 범위가
있으며, 나머지는 문장으로 주석을 답니다.

| 질문 은행 형태 또는 범위 | 개수 | 형식 대응 |
|--------------------------|------|-----------|
| 평가 | 124 | 건강과 상태 측정을 쓰는 `diagnose` 또는 `lookup` |
| 목록 | 84 | `select` |
| 순위 목록 | 48 | `rank` |
| 그래프 | 20 | `traverse` 또는 `path` |
| 비교 | 12 | `compare_entities` 또는 `compare_windows` |
| 시간순 기록 | 12 | `history` |
| 과거 범위 | 94 | `history`, `diff_versions`, `compare_windows` |
| 예측 범위 | 33 | `forecast` 측정과 `future` 시간을 쓰는 `lookup` |

주석자 두 명이 모든 질문에 형식 하나, 복합 경로, 온톨로지 밖 경로(일반 지식, 관리 문서, 조언, 사교,
액션 초안), `unmapped` 중 하나를 독립적으로 붙입니다. 복합 경로는 실시간 데이터에 근거한 권고처럼
형식에 문서나 조언 목표를 결합합니다. 최적화와 시뮬레이션 질문은 선언된 `optimize`와 `simulate` 논리
기능을 검토된 조언 경로로만 쓰며, 그 경로가 생기기 전에는 `unmapped`입니다. 목표는 `unmapped` 질문
0개이며, 범위 개수와 언어 전환도 주석의 커버리지 축입니다.

### 질문 공간 분할

유한 질문 공간은 분할 조각마다 10,000건 상한을 유지합니다. 조각은 선언 종류, 관점 또는 연산 계열,
언어로 나누며, 루트 증적이 모든 조각의 다이제스트를 묶습니다. 전체 완결에는 모든 조각의 통과한 인식
상태 증적이 필요합니다. 캠페인 선택은 실행마다 100건을 유지합니다.

## 보정된 수용

- **재진술**: 컴파일된 모든 답변은 수용된 형식을 운영자 언어로 결정론적으로 재진술하며 시작합니다.
  독립적인 형식 대 텍스트 검사가 모든 원자가 두 언어 모두에 나타나는지 증명합니다.
- **대체 계층**: 정확도는 칸, 연산 계열과 언어, 전체 순서로 추정합니다. 단측 95% 하한 0.97에는 오류
  없는 판정 사례가 약 100개 필요하므로, 칸은 자기 사례가 최소 30개가 될 때까지 계열 추정치를 씁니다.
- **확인 우선**: 적용되는 하한이 위험 등급의 기준보다 낮은 칸은 결과 대신 재진술과 확인 하나를
  반환합니다. 운영자의 확인은 기록하지만 정답으로 세지 않습니다.
- **초기 시작**: 새 칸은 직접 답하기 전에 shadow 근거를 모읍니다.
- **비율 상한**: 한 계열에서 확인 우선이 수용된 턴의 15%를 넘으면, 확인이 잦은 경험을 내보내지 않고
  그 계열을 shadow에 둡니다.

## 용량 전략

| 방식 | 계약 |
|------|------|
| 집계 pushdown | 보안 게이트웨이가 접근 정책으로 정점, 링크, 조건식, 그룹 키를 먼저 거른 뒤 고정된 세대에서 저장소 안에서 세고, 권한 범위 안의 정확한 개수를 반환 |
| 경로 pushdown | 저장소가 호출마다 검토된 경로 문법 하나를 권한이 확인된 고정 세대 하나에서 실행하고, 루트별 계보를 유지하고, 단계별 확산과 메모리 한도를 적용하고, 완전성을 보고하며, 과거 경로는 보존된 토폴로지 리비전을 읽음 |
| 비간섭 | 숨겨진 객체는 합계와 연결에 기여하지 않고, 답변은 권한 범위 안의 완전성만 밝히며, 숨겨진 개수나 가려진 개수는 드러내지 않음. 숨겨진 데이터만 다른 principal 사이의 차등 테스트로 확인 |
| 페이지 | 결과 핸들은 고정된 세대 하나 안에서 이어 보기를 지원하고, 세대가 바뀌면 타입이 지정된 `result_generation_changed` 상태로 커서를 끝내며, 모든 목록은 표시 수와 전체 수를 밝힘 |
| 근거 매니페스트 | 버전이 지정된 최종 계약이 타입 `goal_manifests`와 `document_refs`를 담고, 매니페스트는 principal, 목적, 목표, 계획, 세대, 보존을 묶으며, 말단 증적은 턴과 핸들보다 오래 보존하고, 조회는 다시 인가하며 말단이 없으면 보류 |
| 한정 언급 | 언급이 한정자 언급과 관계 의미를 가리킬 수 있으며, 한정자, 관계, 대상은 권한이 확인된 고정 세대 하나에서 바인딩 |
| 출력 예산 | 대안은 원자 차이이며 최대 3개, 각각 원자 최대 6개이고, 6 KiB가 넘는 형식은 `question_too_complex`를 반환 |

용량 테스트는 로컬 그래프의 열 배 규모인 합성 고정 그래프를 씁니다. 합성 데이터는 동작 방식만
증명하며 실시간 준비 상태의 근거가 되지 않습니다.

## 완결 프로그램

레인은 컴파일러 라운드를 전체가 아니라 연산 계열별로 제한하므로, 한 계열은 승격하고 다른 계열은
카탈로그나 reader 작업을 기다릴 수 있습니다.

| 레인 | 작업 | 끝나야 하는 시점 | 시작 시점 | 종료 조건 |
|------|------|------------------|-----------|-----------|
| L1a 계약 설계 | 위협 검토를 거친 근거 매니페스트, pushdown, 한정 언급, 출력 예산, 핸들 계약 | R1 전 | R0 뒤 | 검토된 계약과 위협 모델 |
| L1b 용량 구현 | pushdown, 매니페스트, 페이지, 임계 경로 예산 | R5 전 | R1 뒤 | 로컬 그래프 열 배 규모의 용량 테스트가 조용한 잘림 없이 통과 |
| L2 카탈로그 완성 | 계열별 D2, D3, D5, D6 작성과 검토 | 그 계열의 R4, R5 전 | R0 뒤 | 그 계열의 `missing` 칸 0개 |
| L3 reader와 데이터 | 계열별 위 reader 프로그램 | 그 계열의 R6, R7 전 | R1 뒤 | 그 계열의 D4, D7 `missing` 칸 0개 |
| L4a 코퍼스와 정답 | 코호트, 홀드아웃, 분류 체계 주석, 고정 그래프 | R0 전 | 승인 뒤 | 주석자 두 명이 판정한 정답 |
| L4b 완결 기반 | 커버리지 증적, 요인 표, 분할된 질문 공간 | R3 전 | R1 뒤 | 지원 비율과 함께 G1, G2 집계 |
| L4c 보정 | 수용 대체 계층, 재진술 검사, 실시간 감사 | R9 전 | R3 뒤 | G3a 증명과 상한을 붙인 G3b 보고 |
| L5 기존 경로 제거 | 어휘 신호, 선택기에 의존하는 판단, 레시피 컴파일러 | 릴리스 전 | R9 뒤 | 승격된 계열의 어휘 경로 0개 |

한 계열은 자기 선언과 조각에서 G1, G2, G3a가 성립하고, G3b를 상한과 함께 보고하고, 자기 영역의 M1을
보고할 때만 커버리지를 주장합니다.

## 승인이 필요한 결정

1. 제외 관리와 함께 G1, G2, G3a, G3b, M1을 채택하고, 답변 커버리지 100%는 주장하지 않습니다.
2. 비간섭 계약 아래 보안 게이트웨이에 집계 pushdown과 경로 pushdown을 추가합니다.
3. 최종 근거 필드 겸용을 버전이 지정된 계약의 타입 목표 매니페스트와 문서 참조로 바꿉니다.
4. 한정 언급, 원자 차이 대안, 6 KiB 형식 상한, 컴파일 시점 계획과 기한 예산, 분류 체계 추가를
   반영합니다.
5. 컴파일된 답변의 재진술, 보정된 대체 계층, 확인 우선 15% 비율 상한을 요구합니다.
6. 적용되는 모든 선언에 이중 언어 용어, 관계 의미, 함수 출처, 속성 의미를 작성하고, 나머지는 관리되는
   제외로 처리합니다.
7. 질문 공간을 분할하고 요인과 상호작용 완결 테스트를 채택합니다.
8. 새 reader는 수요, 준비 상태, 위험, 비용 순으로 만들고 각각 책임 에이전트를 하나 둡니다.
