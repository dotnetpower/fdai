# 온톨로지 추론 커버리지

이 문서는 온톨로지에 근거한 질문 답변에서 완전하고 정확한 커버리지가 무엇을 뜻하는지 정의하고,
지금 이를 막는 측정된 한도를 기록하며, 완결 프로그램과 Azure SRE Agent 품질 기준을 담당합니다. 이
문서는 [온톨로지 추론 컴파일러](ontology-reasoning-compiler-ko.md)를 확장합니다.

> **상태:** 2026-09-28에 제안된 계획입니다. Owner가 같은 날 컴파일러 결정 여덟 가지와 아래 지시 네
> 가지를 승인했습니다. 이 문서 끝의 결정은 아직 승인이 필요합니다. 이 문서의 어떤 부분도 구현되지
> 않았습니다.
>
> **정직성 경계:** FDAI는 모든 질문이 완전하고 올바른 답을 받는다고 주장하지 않습니다. FDAI가 주장하는
> 것은 내놓는 모든 답이 정확하고 검증되었으며, 모든 공백을 밝힌다는 점입니다.

## 답을 온톨로지에서 가져오는 이유

최신 LLM에 검색 증강 생성(RAG)을 붙이면 답은 매끄럽지만, 사실은 검색한 텍스트와 모델의 기억에서
나오므로 개수, 식별자, 관계, 원인을 증명할 수 없습니다. FDAI는 모델로 질문을 이해하고 답변 문장을
쓰며, 모든 사실은 온톨로지에서 가져옵니다. 즉 권위 있는 관측에서 얻은 타입 식별자, 관계, 상태,
시간을 주장 하나하나 검증합니다. 목표는 정확하고, 검증된 범위 안에서 완전하며, 환각이 없고, 같은
질문에서 Azure SRE Agent보다 못하지 않은 답입니다.

## 설계 개요

| 보장 | 목표 | 증명 |
|------|------|------|
| G1 선언 집계 | 100% 집계 | 적용되는 모든 선언과 차원이 `supported`, 관리 절차를 거친 `excluded`, `missing` 중 하나이며, `missing`은 0이어야 하고 지원 비율을 보고 |
| G2 형식 완결 | 100% 집계 | 수용 가능한 모든 요인 칸이 컴파일되거나 타입이 지정된 지원되지 않는 사유를 반환하며, 계열별 지원 비율을 보고하고 후퇴를 허용하지 않음 |
| G3a 최종 결과 불변 조건 | 100% | 검증이 내보내는 모든 최종 결과에서 피연산자 출처, 수준 일치, 제한 원자 차단, V-CLAIM, 인과 주장 규칙, 실행 권한 0을 증명 |
| G3b 해석 충실도 | 관측 0, 상한 보고 | 다른 질문에 대한 답변을 수용된 온톨로지 턴에서 `0/n`과 단측 95% 상한으로 보고 |
| M1 답변 커버리지 | 측정 | 답할 수 있는 질문 중 올바르게 답한 비율을 영역, 언어, 근거 코호트별로 측정 |
| M2 SRE Agent 동등성 | 같거나 더 나음 | 두 언어의 모든 짝 질문과 계열에서 동등성 평가 기준 v1이 성립하고, FDAI의 절대 실패는 0 |

답변 커버리지는 설계상 100%가 될 수 없습니다.

1. **모델 분류**: T1 형식 정확도는 통계적이며, 같은 구성도 측정 실행마다 달랐습니다.
2. **데이터와 reader**: 인스턴스 원본이 없는 객체에 대한 질문에는 답이 없습니다.
3. **보존 기간과 범위**: 제공자 이력 보존 기간, 아카이브 경계, 인벤토리 범위, principal 가시성이 모든
   답을 제한합니다.
4. **열린 언어**: 바꿔 말하기는 끝이 없고, 카탈로그는 영어와 한국어만 있습니다.
5. **권한**: 액션 요청은 실행된 답이 아니라 관리되는 초안으로 끝납니다.

G3a는 이 영역의 모든 실패를 눈에 보이는 제한 사항, 명확화, 보류로 바꿉니다. G3b는 진짜 0을 증명할 수
없으므로, 모델이 쓴 해석 재진술로 오해석을 드러내고 표본 감사로 상한을 둡니다. 사교, 지식, 조언 턴은
G3b에서 `not_applicable`입니다.

## Owner 지시

Owner가 2026-09-28에 다음 지시를 정했습니다.
[대화 근거화 지침](../../../.github/instructions/conversation-grounding.instructions.md)이 이를 코드에
구속력 있는 규칙으로 만듭니다.

1. **하드코딩이나 템플릿 답변 금지**: 모델이 모든 답변과 재진술을 검증된 근거로 쓰고, V-CLAIM이 모든
   주장을 검사합니다. 모델 없이 표시되는 것은 카탈로그 알림과 검증된 데이터 보기뿐이며, 이들은 운영
   사실을 더하지 않습니다.
2. **어휘적 의미 금지**: 정규식, 키워드, 별칭, 문구 표, 어휘 순위는 의미를 정하지 않습니다. 모델이
   전체 카탈로그에서 정하고 코드는 검증합니다.
3. **한도로 빠지는 항목 금지**: 모든 유한 집합을 정확한 집계와 함께 범위가 제한된 묶음으로 처리합니다.
4. **SRE Agent 기준**: 답변은 Azure SRE Agent와 같거나 더 나아야 하며, 세션 브라우저에서 질문, 도출
   과정, 답변을 나란히 비교해 확인합니다.

| 단계 | 모델 | 코드 |
|------|------|------|
| 질문 이해 | 원문 구간과 함께 논리 형식을 제안 | 스키마, 구간, 열거형을 검증 |
| 개념과 값 선택 | 전체 카탈로그 조각에서 스키마 개념과 값을 고름 | 식별자, 영역, 수준을 검증하고 모든 조각을 집계 |
| 식별자와 범위 바인딩 | 없음 | principal, 범위, 정확한 조회로 찾은 인스턴스, 핸들, LinkType, 경로, FunctionType을 바인딩 |
| 시간 정규화 | 원문 구간과 함께 타입 시간 값을 제안 | 신뢰할 수 있는 시각을 계산하고 한도를 확인 |
| 참조 해석 | 언급을 타입 결과 핸들에 연결 | 핸들 범위와 위치를 검증 |
| 계획과 실행 | 컴파일된 형식에서는 없음 | 컴파일, 검증, 실행 |
| 답변 작성 | 근거에서 구조화된 주장과 문장을 작성 | V-CLAIM을 실행하고 모든 행을 집계 |
| 검토 | 독립 모델이 도출 관계를 확인 | 보류하거나 한 번 다시 생성 |

## 빠짐없는 범위 제한 처리

모든 한도는 묶음 크기가 됩니다. 처리할 때마다 무엇을 다뤘는지 기록하며, 처리 수가 전체 수와 같거나
타입이 지정된 후속 실행이 나머지를 밝힐 때만 턴이 끝납니다.

| 유한 집합 | 한도 | 처리 규칙 | 집계 |
|-----------|------|-----------|------|
| 근거화할 영역 카탈로그 | 근거화 프롬프트 예산 | 모든 후보를 조각으로 제시하고 모든 조각을 평가 | 조각 다이제스트가 영역 다이제스트를 정확히 덮음 |
| 한 질문의 목표 | 판단 한 번에 목표 4개, 언급 16개 | 남은 목표에 대해 판단을 이어서 수행 | 모든 목표가 수용된 형식을 하나씩 가짐 |
| 계획 노드 | 계획마다 노드 32개, 출력 8개 | 순서 있는 계획 묶음 뒤 범위가 제한된 후속 실행 | 모든 목표가 최종 상태를 가짐 |
| 결과 행 | 읽기마다 1,000행, 표 보기마다 40행 | pushdown 개수, 페이지 읽기, 문서로 제공하는 전체 표 | 표시 수와 남은 수의 합이 전체 수 |
| 근거 참조 | 최종 참조 12개 | 타입 목표 매니페스트 | 모든 말단 증적이 보존되고 도달 가능 |
| 답변 근거 | 작성 호출 한 번 | 조각별로 작성한 뒤 종합 | 모든 행이 한 번씩 이름, 집계, 목록 중 하나로 다뤄짐 |
| 질문 공간 | 조각마다 10,000건 | 루트 증적 아래의 조각 | 모든 조각이 통과한 증적을 가짐 |
| 질문 은행 주석과 동등성 실행 | 묶음마다 질문 10개 | 카탈로그가 끝날 때까지 묶음 반복 | 모든 질문이 기록을 가짐 |

턴마다 작업 전에 예산을 먼저 확보하며, 최악의 경우가 들어맞을 때만 묶음을 시작합니다.

| 단계 | 확보하는 모델 호출 | 비고 |
|------|------------------:|------|
| preflight | 1 | 변경 없음 |
| 형식 판단 | 판단 한 번마다 2 | 호출 한 번과 최대 한 번의 스키마 복구 |
| 개념 선택 | 조각마다 1 | 한 영역의 조각은 동시에 실행 |
| 답변 작성 | 조각마다 2 | 작성 호출 한 번과 최대 한 번의 재생성 |
| 독립 검토 | 답변마다 1 | 표시 전에 필수 |

확보한 예산이 90초 요청 수명이나 턴당 모델 상한에 들어가지 않으면, 턴은 검증된 부분과 함께 principal,
범위, 스냅샷 기준 시점, 카탈로그 다이제스트, 커서, 만료, 남은 개수를 고정한 후속 실행을 반환합니다.
자동 후속 실행은 턴당 전체 상한 안에서만 계속되며, 그 이상은 운영자가 명시적으로 이어서 실행합니다.

## 커버리지 차원

`ReasoningCoverageReceipt`는 구조 커버리지 증적을 확장합니다. release, 역할, 목적, 언어별로 만들며,
적용되는 선언과 차원마다 `supported`, `excluded`, `missing`, `not_applicable` 중 하나의 상태를
기록합니다. 적용 여부는 선언 종류에서 정해집니다.

| 차원 | 적용 대상 | 지원 조건 | 대표적인 제외 |
|------|-----------|-----------|---------------|
| D1 서술자 | 모든 선언 | principal 범위의 서술자가 있음 | 해당 역할에서 읽을 수 없음 |
| D2 언어 표면 | ObjectType, LinkType 역할, Interface, ActionType, 운영자가 쓰는 Property | 검토된 영어와 한국어 이름과 설명이 모델 맥락으로 있음 | `no_operator_surface` |
| D3 관계 의미 | LinkType | 특성, 양방향 역할, 전이성, 카디널리티가 검토됨 | `relation_internal` |
| D4 인스턴스 원본 | ObjectType | 인스턴스 저장소, 전용 reader, 소유자 변환 결과 중 하나에 바인딩됨 | 담당 설계와 함께 `schema_only` |
| D5 함수 계약 | FunctionType | 모든 인자가 출처 `span`, `anchor`, `handle`, `server`, `default` 중 하나를 선언하고, 앵커는 적용 가능한 타입을 선언함 | `not_conversational` |
| D6 속성 의미 | Property | 타입, 연산자, 단위, 값 영역이나 자유 텍스트 여부가 선언됨 | `not_filterable` |
| D7 근거 의미 | 인스턴스 원본 | 완전성 증명, 신선도, 시간 축, 보존 경계가 선언됨 | 없음, 미비하면 D4를 막음 |
| D8 표시 | 출력 종류 | 답변 작성이 두 언어로 그 종류, 잘림, 이어 보기를 처리함 | 없음 |

제외 관리는 G1을 정직하게 유지합니다. release마다 새 제외의 기본 예산은 0입니다. 제외마다 사유, 담당
설계, 만료를 적고, 원본 소유자와 작성자에게서 독립된 검토자의 승인을 받습니다. release마다 제외의
10%를 무작위로, 최소 20개 또는 전체가 그보다 적으면 전부 감사하고, 증적은 차원별 지원 비율을
공개하며, 제외는 지원으로 세지 않습니다. 커버리지 작업은 카탈로그 코드 방식이며 권한을 주지 않습니다.

## 형식 완결

완결 테스트는 문법의 곱집합 대신 각 요인을 빠짐없이 나열하고 요인 사이의 상호작용을 테스트합니다.

| 요인 표 | 칸 | 각 칸의 결과 |
|---------|----|--------------|
| 앵커 ObjectType과 위치별 관계 의미 | 89 x 9 x 3 = 2,403 | LinkType 방향 또는 `no_link_of_sense` |
| 주체 범위, 요구, 시간 종류별 연산 | 16 x 4 x 4 x 7 = 1,792 | 노드 패턴 또는 타입이 지정된 지원되지 않는 사유 |
| 운영자가 쓰는 속성별 필터 역할 | 속성과 역할마다 한 칸 | 조건식 템플릿 또는 `not_filterable` |
| 측정과 앵커 타입별 함수 | 함수 39개와 적용 가능한 타입 | 함수 노드 또는 `no_applicable_function` |
| 상호작용 | 모든 요인 쌍, 위험 기준으로 고른 세 요인 조합, 목표 최대 4개의 모든 의존 구조 | 각각 노드 32개와 출력 8개 이내의 계획 묶음 |

모든 형식은 정규화된 형식 식별자에 대응하므로, 분할 조각과 요인 표가 수용 가능한 공간을 빠짐없이
나눈다는 것을 증명할 수 있습니다. 표는 입출력 없이 집중 게이트에서 실행되며, 자기 칸이 없는 새 선언은
게이트에서 실패합니다. 계열마다 지원되지 않는 칸 예산과 후퇴 금지 규칙이 있습니다. `draft_action`은
G2 밖에 두고 관리되는 액션 초안 전달로만 컴파일하며, 모델이 전체 ActionType 카탈로그에서 ActionType을
근거화하고 모호하면 명확화합니다.

### 질문 공간 분할

유한 질문 공간은 분할 조각마다 10,000건 상한을 유지합니다. 조각은 선언 종류, 관점 또는 연산 계열,
언어로 나누며, 루트 증적이 모든 조각의 다이제스트를 묶습니다.

## 보정된 수용

- **재진술**: 컴파일된 모든 답변은 수용된 형식을 운영자 언어로 모델이 재진술하며 시작하고, V-CLAIM이
  모든 형식 원자가 나타나는지 증명합니다.
- **대체 계층**: 정확도는 칸, 연산 계열과 언어, 전체 순서로 추정합니다. 단측 95% 하한 0.97에는 오류
  없는 판정 사례가 약 100개 필요하므로, 칸은 자기 사례가 최소 30개가 될 때까지 계열 추정치를 씁니다.
- **확인 우선**: 위험 등급의 기준보다 낮은 칸은 결과 대신 재진술과 확인 하나를 반환합니다. 운영자의
  확인은 정답으로 세지 않습니다.
- **비율 상한**: 한 계열에서 확인 우선이 수용된 턴의 15%를 넘으면 그 계열을 shadow에 둡니다.

## 용량 전략

| 방식 | 계약 |
|------|------|
| 집계 pushdown | 보안 게이트웨이가 접근 정책으로 정점, 링크, 조건식, 그룹 키를 먼저 거른 뒤 고정된 세대에서 저장소 안에서 셈 |
| 경로 pushdown | 저장소가 호출마다 검토된 경로 문법 하나를 권한이 확인된 고정 세대 하나에서 루트별 계보, 확산과 메모리 한도, 완전성과 함께 실행 |
| 비간섭 | 숨겨진 객체는 합계와 연결에 기여하지 않고, 답변은 숨겨진 개수나 가려진 개수를 드러내지 않으며, 숨겨진 데이터만 다른 principal 사이의 차등 테스트로 확인 |
| 페이지 | 핸들은 고정된 세대 하나 안에서 이어지고, 세대가 바뀌면 `result_generation_changed`로 커서를 끝냄 |
| 근거 매니페스트 | 버전이 지정된 최종 계약이 타입 `goal_manifests`와 `document_refs`를 담고, 말단 증적은 턴과 핸들보다 오래 보존되며, 조회는 다시 인가함 |
| 한정 언급 | 한정자, 관계, 대상은 권한이 확인된 고정 세대 하나에서 바인딩 |

용량 테스트는 로컬 그래프의 열 배 규모인 합성 고정 그래프를 씁니다. 합성 데이터는 동작 방식만
증명하며 실시간 준비 상태의 근거가 되지 않습니다.

| 정답 | 검토자 두 명이 형식 원자, 근거화한 개념, LinkType 집합과 방향, 노드 종류, 인식 상태, 금지 결과를 판정 |
| 수준 | L1은 실시간 T1 형식과 근거화 정확도를 측정하고, L2는 고정 그래프에서 수용, 컴파일, 실행, V-CLAIM을 수행 |
| 절대 0 | 조용한 의미 손실, 출처 없는 피연산자, 잘못된 수준의 답변, V-CLAIM 누락, 근거 없는 인과 주장, 인가되지 않은 실행 |

세션 안에서만 쓰던 68개 사례 코퍼스는 수준, 금지 함수, 필수 원자 검사를 더해 저장소로 옮깁니다. A/A
실행이 1.5점 차이를 보였으므로 짝 비교는 반복 3회, 부트스트랩 신뢰 구간, 3점 잡음 구간을 씁니다.

### SRE Agent 동등성

Azure SRE Agent는 최신 모델과 실시간 Azure 도구로 답하므로 유용성의 외부 기준이 됩니다.
[SRE Agent 동등성 스킬](../../../.github/skills/sre-agent-parity/SKILL.md)이 절차이며,
[비교 원장](../../internals/sre-agent-comparison-ledger.md)에는 이미 시드 질문 120개에 대한 비교
실행 39건이 있습니다.

- **준비**: Azure SRE Agent 하나가 Owner가 지정한 FDAI와 같은 구독과 리소스 범위를 읽기 전용 역할
  할당으로 다루고 액션 승인은 하지 않습니다. 운영자가 세션 브라우저에 로그인하며, 평가자는 자격 증명을
  다루지 않습니다.
- **짝 실행**: 질문마다 새 SRE Agent 스레드와 새 FDAI 대화에 같은 언어로 몇 분 안에 묻습니다. 두
  답변과 두 도출 과정을 모두 기록합니다. SRE Agent는 도구 단계와 조회를, FDAI는 재진술, 근거화, 계획,
  증적, 주장을 기록합니다.
- **정답**: 두 답변 직후 읽기 전용 정답 조회를 실행하거나 독립 검토자가 판정합니다. 두 실행 사이에
  관련 상태가 바뀐 질문은 결론 없음으로 기록합니다.
- **시도 횟수**: 동등성 실행마다 각 제품은 질문마다 한 번씩 답하며, FDAI 안정성은 반복하는 L1 코호트
  실행에서 측정합니다.
- **기록**: 가린 실행 기록은 평가 기준 버전과 함께 원장에 이어 쓰고, 원시 기록은 비공개로 보관하다가
  만료시키며, SRE Agent 출력은 FDAI 근거가 되지 않습니다.

동등성 평가 기준 v1은 두 제품을 기준마다 0에서 4점으로 채점하며, 근거 없거나 지어낸 주장은 절대
실패입니다.

| 기준 | 4점의 의미 | 동등성 규칙 |
|------|------------|-------------|
| 정확성 | 모든 중요한 주장이 독립 정답과 일치 | 어떤 질문에서도 FDAI가 낮지 않음 |
| 완전성 | 요청 범위의 모든 항목과 정확한 전체 수가 있음 | 어떤 질문에서도 FDAI가 낮지 않음 |
| 신선도 | 시간에 민감한 주장이 현재 근거를 쓰고 관측 시각을 밝힘 | 어떤 질문에서도 FDAI가 낮지 않음 |
| 근거 무결성 | 모든 주장이 독자가 추적할 수 있는 이름 있는 원본에 연결됨 | 어떤 질문에서도 FDAI가 낮지 않음 |
| 안전성 | 읽기와 액션 권한이 명시되고 제한됨 | 어떤 질문에서도 FDAI가 낮지 않음 |
| 과정 투명성 | 도출 과정이 보이고 기록된 단계로 재현 가능함 | 계열 평균이 같거나 높고, 어떤 질문도 1점 넘게 낮지 않음 |
| 실행 가능성 | 필요할 때 유용한 다음 확인이나 관리되는 액션을 제시함 | 계열 평균이 같거나 높고, 어떤 질문도 1점 넘게 낮지 않음 |
| 명료성 | 답이 직접적이고 잘 구조화되었으며 요청한 언어로 자연스러움 | 계열 평균이 같거나 높고, 어떤 질문도 1점 넘게 낮지 않음 |

한 계열의 M2는 두 언어의 모든 짝 질문에서 FDAI 절대 실패가 없고 모든 동등성 규칙이 성립할 때
성립합니다. 결론 없음인 질문은 통과로 세지 않습니다.

## 완결 프로그램

레인은 컴파일러 라운드를 연산 계열별로 제한하므로, 한 계열은 승격하고 다른 계열은 기다릴 수 있습니다.

| 레인 | 작업 | 끝나야 하는 시점 | 시작 시점 | 종료 조건 |
|------|------|------------------|-----------|-----------|
| L1a 계약 설계 | 위협 검토를 거친 근거화, 근거 매니페스트, pushdown, 한정 언급, 주장, 핸들 계약 | R1 전 | R0 뒤 | 검토된 계약과 위협 모델 |
| L1b 용량 구현 | pushdown, 매니페스트, 페이지, 계획 묶음, 임계 경로 예산 | R5 전 | R1 뒤 | 로컬 그래프 열 배 규모의 용량 테스트가 조용한 잘림 없이 통과 |
| L2 카탈로그 완성 | 계열별 D2, D3, D5, D6 작성과 검토 | 그 계열의 R3에서 R5 전 | R0 뒤 | 그 계열의 `missing` 칸 0개 |
| L3 reader와 데이터 | 계열별 reader 프로그램 | 그 계열의 R6, R7 전 | R1 뒤 | 그 계열의 D4, D7 `missing` 칸 0개 |
| L4a 코퍼스와 동등성 기준선 | 코호트, 홀드아웃, 분류 체계 주석, 고정 그래프, SRE Agent 기준선 실행 | R0 전 | 승인 뒤 | 판정된 정답과 기준선 동등성 기록 |
| L4b 완결 기반 | 커버리지 증적, 요인 표, 분할된 질문 공간 | R3 전 | R1 뒤 | 지원 비율과 함께 G1, G2 집계 |
| L4c 보정과 동등성 | 수용 대체 계층, 재진술 검사, 실시간 감사, 동등성 재실행 | R9 전 | R3 뒤 | G3a 증명, G3b 상한, M2 충족 |
| L5 기존 경로 제거 | 어휘 신호, 정규식, 선택기에 의존하는 판단, 레시피 컴파일러, 템플릿 렌더러 | 릴리스 전 | R9 뒤 | 승격된 계열의 어휘나 템플릿 경로 0개 |

한 계열은 G1, G2, G3a, M2가 성립하고, G3b를 상한과 함께 보고하고, 자기 영역의 M1을 보고할 때만
커버리지를 주장합니다.

## 승인이 필요한 결정

1. 제외 관리와 함께 G1, G2, G3a, G3b, M1, M2를 채택하고, 답변 커버리지 100%는 주장하지 않습니다.
2. 비간섭 계약 아래 보안 게이트웨이에 집계 pushdown과 경로 pushdown을 추가합니다.
3. 최종 근거 필드 겸용을 타입 목표 매니페스트와 문서 참조로 바꿉니다.
4. 한정 언급, 원자 차이 대안, 연속 판단, 범위가 제한된 후속 실행을 갖춘 계획 묶음, 분류 체계 추가를
   반영합니다.
5. 모델이 쓰는 재진술, 보정된 대체 계층, 확인 우선 15% 비율 상한을 요구합니다.
6. 적용되는 모든 선언에 모델 맥락용 이중 언어 이름과 설명, 관계 의미, 함수 출처, 속성 의미를 작성하고,
   나머지는 관리되는 제외로 처리합니다.
7. 질문 공간을 분할하고 요인과 상호작용 완결 테스트를 채택합니다.
8. 새 reader는 수요, 준비 상태, 위험, 비용 순으로 만들고 각각 책임 에이전트를 하나 둡니다.
