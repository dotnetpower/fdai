# 구조화된 클라우드 문서 검색

이 설계는 재현 가능한 본문 추출, 크기가 제한된 구조적 인용문, 별도로 평가하는 이중 언어
검색으로 클라우드 참조 지식을 확장합니다. 별도의 RAG 서비스를 만들지 않고 기존 에이전트
소유의 반입 승인과 활성화 경로를 유지합니다.
기존 텍스트와 구조화된 문서의 조합 테스트는 같은 실제 에이전트 처리기를 사용하며 자기 승인
차단, 감사 이후 색인, Thor 실행 없음 및 영어·한국어 원문 날짜를 확인합니다.

> **범위:** Issue #1019에서 소스 구현을 요청했습니다. 운영 검증, 원문 사용 권리, 운영 신뢰,
> 독립된 사람 검토자와 실제 모델 평가는 Issue #995의 별도 선행 조건입니다. 구현 테스트는
> 운영 승인이 아닙니다.

## 설계 결정

| 초기 선택지 | 비평 | 결정 |
|---|---|---|
| 기존 정규화기를 조용히 변경 | 서명된 v1/v2 식별자로 파생 청크를 설명할 수 없게 됨 | 기존 계약과 추출을 보존하고 별도의 구조화된 v3 세대 사용 |
| 인용문 상한 확대 | 텍스트가 커져도 분리된 표 조건은 복구되지 않음 | 출처를 포함한 8192바이트를 유지하고 지원되는 구조로만 분할하거나 보류 |
| 서명된 패키지는 모두 승인 | 서명은 바이트를 인증할 뿐 반입 적합성이나 의미의 정확성을 보장하지 않음 | Forseti, Var, Saga, Muninn 단계와 독립된 색인 읽기 검증 유지 |
| 영어 원문만으로 한국어 검색을 지원한다고 판단 | 답변 표시 현지화는 검색 성공의 근거가 아님 | 크기가 제한된 모델 판단 검색어를 적용 조건과 분리해 연결하고 두 언어 측정 |
| 원문 바이트가 바뀔 때만 재색인 | 새 파서, 청킹 규칙이나 정책도 의미를 변경함 | 내용과 처리 식별자를 원문 확인 시각과 별도로 추적 |

## 구조화된 릴리스

버전 3은 기존 16 MiB 상한 안에서 완전한 정규 JSON을 유지하며 원본을 포함하지 않습니다.
정규화된 본문 하나를 크기가 제한된 구조 블록, 비활성 링크, 필수 문맥, 정규화기 식별자와
설치된 결정론적 청킹 규칙에 연결합니다. 원문 근거에는 정확한 수집·확인 날짜와 원본·정규화
다이제스트가 유지됩니다. 실행 가능한 규칙, 모델, 벡터, 데이터베이스 덤프나 패키지가 주장하는
승인은 포함하지 않습니다. 알 수 없는 버전과 청킹 규칙은 차단합니다.

V1과 v2의 서명 및 정규 바이트는 변경하지 않습니다. 과거 정규화 내용은 기존 절 추출기로
처리합니다. 운영 환경에서 구조화 후보를 만들기 전에 수집기, API/CLI, 워커와 Core에 새 읽기
기능이 준비되어야 합니다. 보관된 원문을 다시 처리하면 새 후보와 별도 파생 시각을 만들며,
원문을 다시 가져오거나 확인한 것처럼 기록하지 않습니다.

## 추출과 청킹

파서는 콘텐츠를 실행하지 않으며 바이트, 중첩, 노드 및 구조 단위 수를 제한합니다. 실제 본문을
선택하고 실행 콘텐츠와 사이트 제어 요소를 제외합니다. 숨겨진 문서 탭을 일괄 삭제하지 않습니다.
지원하지 않는 구조, 해결되지 않은 필수 의존성 및 표현할 수 없는 최소 단위는 선언된 세대
전체를 보류합니다. 원문 범위를 줄이려면 새 검토가 필요합니다.

제목 경로, 순서가 있는 단계, 표 머리글·단위, 주의사항과 링크 주소를 보존합니다. 문단과 표의
행은 최소 단위이며, 큰 표는 머리글과 필수 문맥을 반복해서 제공할 수 있을 때만 분할합니다.
표 데이터 행은 같은 제목 계층의 앞선 문단·목록 문맥도 유지하며 일반 문장에 적용 제한이 있는지
추측하지 않습니다. 의존성은 같은 원문 안의 명시적 참조이며 권한을 추론하지 않습니다. 블록별 및 문서 전체 필수
문맥은 설치된 단일 단계 규칙으로 완전히 표현할 수 없는 중첩 의존성을 차단합니다.
본문 영역을 선택할 때 인접한
문단이나 예외를 조용히 제외하지 않습니다. 설명되지 않은 구조적 본문이 있으면 후보를 보류합니다.
각 인용문은 원문 식별자를
포함하며 UTF-8 기준 8192바이트 이내입니다. 텍스트와 메타데이터 제한은 독립적입니다. 안정된
식별자는 원문 버전, 블록 식별자, 청킹 규칙 및 바이트에 연결됩니다.
인용문별 제한과 함께 전체 세대의 확장 텍스트를 16 MiB 및 8192블록으로 제한합니다.
필수 문맥 반복으로 입력이 크기 제한 없는 색인으로 늘어나지 않습니다.

워커는 Saga가 감사한 Var 승인과 Muninn의 색인 명령 이후에만 봉인된 청크 목록을 재현합니다.
별도의 읽기 전용 트랜잭션이 저장된 전체 행을 확인한 뒤 동시성 보호가 적용된 가시성 전환을
수행합니다. 이는 저장 결과를 증명할 뿐 공유 파서의 정확성을 증명하지는 않습니다. 원문과
주장의 품질을 평가하려면 독립적으로 정한 기대 근거가 필요합니다.
기존 세대와 구조화된 세대는 본문·출처 변조, 재조회 이후 변경, 대기 행 비노출 및 정확한
버전·적용 조건 차단을 다루는 저장 결과 테스트 행렬을 함께 사용합니다.

## 검색과 수명 주기

주체 범위가 적용된 PostgreSQL 어휘 검색을 재사용합니다. 정확한 문서 참조, 컬렉션 접근,
보존, 반입 승인, 철회 및 리소스 적용 조건이 순위 계산 전에 후보를 제한합니다. 필수 문맥은
선택한 인용문과 함께 전달되며 검색 점수가 호환성을 증명하지 않습니다. 검색 시 정규화 식별자,
적용 조건, 정책 및 원래 수집 정보는 승인된 원문과 일치해야 하며 별도로 검증한 확인 증적만
겹쳐 표시할 수 있습니다. 근거가 부족하면
범위가 제한된 보류 결과를 반환하며, 범위 없는 재검색이나 실시간 원문 수집으로 대체하지 않습니다.
클라우드 컬렉션 버전은 일반 문서의 두 개 인용문 제한 대신 요청된 전체 인용문 예산을 사용하며
상한은 여덟 개입니다. 접근 통제와 검색 후보 제한은 유지합니다.

스키마로 검증한 모델 기반 검색어 변환은 길이가 제한된 검색어를 제공할 수 있습니다. 원래
의도, 대상 조건, 독자나 권한을 바꿀 수는 없습니다. 변환 기능이 없으면 사용 불가 상태를 유지하며,
키워드 의도 라우팅이나 자동 외부 번역으로 대체하지 않습니다. 영어와 한국어 검색 결과는 별도로
평가합니다. Bragi는 인용, 날짜 및 부족한 근거를 표시합니다. T2 운영 추론은 별도의 혼합 모델
및 검증 단계를 유지합니다.

내용이 같은 수집·확인은 기존 수집일을 보존하고 변경되지 않은 파생 내용을 재사용할 수 있습니다.
정규화 바이트, 청킹 규칙, 적용 조건이나 권리 결정이 바뀌면 중요한 변경 후보를 만듭니다.
관찰 시각만 바뀌었다고 내용 변경을 만들지는 않습니다. 오래된 구조 체크포인트가 새 원문을 가리지
못하도록 파생 상태보다 원문 식별자를 먼저 비교합니다. 처리 전용 실행은 기존 임대 아래 보관
바이트의 변환을 저장하고 기존 확인 증적을 재사용하며 재처리 건수를 별도로 보고합니다.
내보내기에는 이 영속 체크포인트가 필요합니다. 만료·철회 콘텐츠는 보존 정책에 따른
정리 전에 사용 불가 상태가 됩니다. 404나 반입은 권리나 원문 최신성을 갱신하지 않습니다.
이전 세대를 자동으로 복구하는 기능은 계속 별도 범위로 남깁니다.

## 검증

측정 전에 선언된 원문과 질문 범위를 고정합니다. 수집, 품질 검토, 승인, 색인 및 답변 검증 수를
별도로 보고합니다. 가이드 중심 컬렉션부터 시작하며, 실패한 컬렉션에서 큰 참조 표나 해결되지
않은 원문 권리를 조용히 제외하지 않습니다.

초기 평가 목표는 최소 80개 의미 사례의 영어·한국어 질문 쌍, 분리된 개발·평가 집합 및 언어별
완전한 근거 재현율입니다. 근거 없는 중요 주장과 접근·권한 우회는 종합 점수와 관계없이
검증을 막습니다. 보고 결과는 문서 집합, 질문, 정확한 소스 버전, 청킹 규칙과 환경에 연결됩니다.
합성 관찰은 표시를 바꾸는 것만으로 실제 관찰, 독립 검토나 운영 근거가 될 수 없습니다.

최소 열 번의 범위가 제한된 비평 라운드를 수행합니다. 가설, 재현, 심각도, 수정 또는 오탐 판정,
집중 검증과 남은 발견 사항을 기록합니다. 확인된 범위 내 Medium 이상 문제가 없을 때에만
구현 캠페인을 끝냅니다. 외부 선행 조건은 명시적으로 차단 상태를 유지하며 이 기준을 맞추려고
심각도를 낮추지 않습니다.
